## Summary

A two-study controlled comparison by Subham Panda of how three spec-driven development frameworks enforce traceability — traceSDD's mandatory per-line requirement citations, Spec Kit's artifact-level spec-plan-tasks chain, and OpenSpec's post-hoc external trace maps — run across Claude Sonnet 4.6 and GLM-5-turbo. Its finding is a trade-off replicated across both models: inline citations significantly reduce output determinism, yet are the only mechanism that enables automated hallucination detection, at 86.4% and 88.0% traceability detection with no false positives against 0% for every alternative. It is unusually candid about its own limits, including that hallucinations were injected with fake requirement IDs and that a model omitting citations entirely for hallucinated code bypasses the check, which its own Claude data showed happening about 12% of the time.

traceSDD and OpenSpec did not become pages. Each is described here only as a comparison condition, by a paper that finds one of them strongest and states no affiliation either way, so their material is recorded on the paper's own page; the finding about Spec Kit, which already has a page, was added there as an attributed third-party measurement.
