## Summary

This technical report is a practitioner's guide to spec-driven development (SDD), the practice of treating specifications rather than code as the source of truth. It defines three levels of specification rigor — spec-first, spec-anchored, and spec-as-source — along with a four-phase workflow (Specify, Plan, Implement, Validate), a survey of supporting tools ranging from BDD frameworks to AI-assisted toolkits, and case studies drawn from API, enterprise, and embedded development. It concludes with a decision framework for when SDD adds value and when simpler approaches suffice.
