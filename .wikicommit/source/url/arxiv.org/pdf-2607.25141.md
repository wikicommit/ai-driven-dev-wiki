## Summary

This paper tests whether a frontier LLM can generate Dockerfiles and Docker Compose configurations for three multi-service applications from repository contents alone, validating the results with end-to-end HTTP oracles and manual comparison with developer-authored artifacts. All three environments became operational (one after a Rust base-image fix), but network segmentation, multi-stage builds, production serving, restrictive port exposure and similar deployment intent were consistently omitted, which the authors use to motivate Specification-Driven DevOps and derive a minimal explicit deployment specification.
