## Summary

A two-phase empirical study at WirelessCar Sweden AB, combining an exploratory field study of existing code review practice with a field experiment on two LLM-assisted review prototypes: an AI-led co-reviewer that summarises a pull request before the reviewer starts, and an interactive assistant that answers only when asked, both backed by a retrieval-augmented pipeline over diffs, source files and Jira tickets. Interviews surfaced delayed reviews, oversized pull requests, context switching and missing context as the main pain points; in the experiment the AI-led mode was generally preferred, especially for large or unfamiliar pull requests, though preference depended on codebase familiarity and the severity of the change, and trust, false positives, latency and integration friction remained concerns.
