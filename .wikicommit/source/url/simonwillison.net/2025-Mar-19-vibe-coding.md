## Summary

Simon Willison argues that "vibe coding" -- coined by Andrej Karpathy in early February 2025 -- should keep its narrow original meaning of building software with an LLM without reviewing the code it writes, rather than being diluted to cover every use of AI assistance in programming. He contrasts it with responsible professional LLM-assisted development, where the developer reads and tests the code and can explain what it does to someone else, and defends vibe coding's own value for low-stakes prototypes, for newcomers, and for experienced developers building intuition about what LLMs can and cannot do. The post sets out the conditions under which vibe coding is acceptable (low stakes, care with secrets and private data, being a good network citizen, billing limits) and points to sandboxing, as implemented in Claude Artifacts, as the main design direction for making it safer.
