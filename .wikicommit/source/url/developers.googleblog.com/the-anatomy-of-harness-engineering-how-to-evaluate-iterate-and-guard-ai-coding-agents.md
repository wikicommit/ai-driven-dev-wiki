## Summary

A Google for Developers post arguing that teams engineering an agent harness should complement end-to-end benchmarks with behavioral evaluations — fast, deterministic, unit-style assertions on discrete observable actions such as which tool an agent called or which file it modified. Its case is that composite benchmark scores move without saying why, whereas behavioral evals show whether expected behaviours occur and whether a change is progress or regression. It places evaluation in a second phase after developer instinct and dogfooding, gives a three-step starting loop, and concludes that macro benchmarks and micro behavioural evals are complementary rather than substitutes.
