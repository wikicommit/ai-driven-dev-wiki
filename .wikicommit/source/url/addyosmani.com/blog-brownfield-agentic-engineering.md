## Summary

This post describes how to apply coding agents to long-lived brownfield codebases, where the repository no longer fully describes how the system behaves. It recommends zoning the codebase by risk, writing down only what the code cannot convey, preserving research as durable comprehension memos, turning repeated corrections into harness mechanisms, locking current behavior with characterization tests before changes, migrating in complete units, and parallelizing only once a single unit has a dependable judge and recovery path.
