## Summary
An introductory guide by Nakahara Kodai on Sreake's blog to cc-sdd, an npm package that installs a
spec-driven development workflow into AI coding agents. It argues that structuring a specification
before implementation is what stops repeated regeneration from drifting and losing its rationale,
then walks through cc-sdd's six slash commands — steering, spec initialisation, EARS-format
requirements, technical design, task breakdown and implementation — and what each phase writes to
disk. It closes on treating specifications as living documents committed alongside the code, and on
the cases where the overhead is not worth paying: typo-scale fixes, one-off questions, and
exploratory work with no clear goal.
