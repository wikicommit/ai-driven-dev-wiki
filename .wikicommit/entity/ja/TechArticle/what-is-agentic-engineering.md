これは『Agentic Engineering Patterns』の冒頭の章である。このガイドの掲げる目標は、コーディングエージェントとともに働くためのパターンのうち、目に見えて結果を出し、かつツールが進歩しても古びにくいものを特定し記述することである。この章の仕事は定義することにある。著者が [[DefinedTerm/agentic-engineering]]、[[DefinedTerm/coding-agent]]、そして「エージェント」で何を意味しているかを確立し、この実践を [[DefinedTerm/vibe-coding]] から切り分ける。

## 主要な実践

**定義を順に。** *エージェンティックエンジニアリング*とは「コーディングエージェントの支援を得てソフトウェアを開発する実践」である。*コーディングエージェント*とはコードを書くことと実行することの双方ができるエージェントであり、人気のある例として Claude Code、OpenAI Codex、Gemini CLI が挙げられる。そして*エージェント*には、著者が LLM の分野で受け入れるに至ったと述べる定義が与えられる。**エージェントは目標を達成するためにループの中でツールを走らせる**——プロンプトとツール定義の集合とともに LLM を呼び出し、LLM が要求したツールを何であれ呼び出し、その結果を返し戻すソフトウェアである。この語を定義することは少なくとも1990年代から AI 研究者を悩ませてきた、と著者は注記している。

**コードの実行が、定義的な能力として特定されている。** コードを走らせる能力がなければ、LLM が出力するものの価値は限られる。それがあれば、エージェントは目に見えて動くソフトウェアへ向けて反復できる。

**人間に何が残されるか**がこの章の中心的な論証である。コードを書くことはソフトウェアエンジニアの唯一の活動であったためしがなく、その技芸は常に*どの*コードを書くかを見極めることだった。どんな問題にも異なるトレードオフを持つ数十の潜在的な解があり、特定の状況と要求に合うようそれらを渡っていくことが仕事である。実践的には、それはエージェントに必要なツールを供給すること、問題を適切な詳細度で指定すること、そして結果が頑健で信じるに足るものになるまで検証し反復することを意味する。

**学習はモデルからハーネスへ移される。** この章の定式化は、LLM は自らの過去の誤りから学ばないが、コーディングエージェントは学べる——ただし人間が学ばれたことを反映するよう指示とツールのハーネスを意図的に更新するならば、というものである。

**バイブコーディングとの区別**は、元々の定義の意図的な擁護として述べられている。バイブコーディングは2025年2月に、LLM にコードを書かせながら「コードが存在することさえ忘れる」ことを記述するために造られた語であり、この章はそれが偶然にも Claude Code の最初のリリースの3週間前であったことを記録する。この語を LLM が生み出したコード一般に拡張することは誤りだとされる。レビューされていない、プロトタイプ品質の LLM 生成コードを、著者が本番相当の水準まで仕上げたコードから区別する語が必要だから、という理由である。
