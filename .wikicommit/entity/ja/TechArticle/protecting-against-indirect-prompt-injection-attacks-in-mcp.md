「Protecting against indirect prompt injection attacks in MCP」は2025年4月28日に Microsoft の開発者ブログへ掲載された記事であり、Microsoft のプリンシパルセキュリティアドボケイトである Sarah Young と、プリンシパルプロダクトエンジニアである Den Delimarsky によるものである。[[DefinedTerm/model-context-protocol]] の導入におけるプロンプトインジェクションを緩和するためのガイドラインを提示し、Microsoft が顧客のためにこのリスクへ対処してきた手順を記述している。

MCP についてのその枠づけは、プロトコル寄りというより開発者寄りである。MCP は Anthropic が主導するオープンなプロトコルとして記述され、アプリケーションと LLM のあいだで文脈を受け渡すための一貫した API 契約、ツール呼び出しとデータ取得のための構造化された手法、そして LLM の入出力のための共通の形式を提供するものとされる。実装の観点からは、モデルのプロバイダを切り替えたり文脈取得の関数を更新したりするたびに統合のコードを書き直す必要を解消し、定型コードを減らし、アプリケーションのロジックを AI の推論層から分離する。

## 主な実践

- **この攻撃の類型を認識する。** 記事は [[DefinedTerm/indirect-prompt-injection]]——クロスドメインプロンプトインジェクション、XPIA とも呼ばれる——を、文書、ウェブページ、電子メールといった外部のコンテンツへ埋め込まれた悪意ある指示であり、AI システムがそれを正当なユーザーの命令と取り違え、データの流出、有害または誤解を招く出力、あるいはその後のやり取りの操作につながるものとして定義している。
- **[[DefinedTerm/tool-poisoning]] をその部分集合として扱う。** ここでは悪意ある指示が MCP ツールの説明の中に潜む。LLM はそのメタデータを使ってどのツールを呼び出すかを決めるため、汚染された説明はセキュリティの制御を迂回する意図しないツール呼び出しを引き起こしうるうえ、ユーザーからは見えないままである。記事はホストされたサーバをより鋭い事例として指摘する。承認後に定義を書き換えて悪意あるコンテンツを加えることができ——一部の研究者が「ラグプル」と呼ぶ手口だとしている——、いったん承認されたツールが宣言されていない行為を実行できるようになるからだ。
- **AI Prompt Shields を導入する。** 直接・間接双方のインジェクションに対する Microsoft のソリューションとして記述され、4つの仕組みによって働く。外部コンテンツ内の悪意ある指示を機械学習によって検知しフィルタすること。**スポットライティング**——入力テキストを変換し、モデルが正当なシステムの指示と信頼できない外部の入力とをよりよく区別できるようにすること。**区切り記号とデータマーキング**——システムメッセージ内で区切り記号を用いて入力テキストの位置を示し、特別なマーカーによって信頼できるデータと信頼できないデータの境界を定めること。そして新しい手口に対する Shields の継続的な監視と更新である。
- **サプライチェーンセキュリティを AI の構成要素へ広げる。** 記事は、セキュリティの原則は変わらず、変わるのはサプライチェーンとして何が数えられるかだけだと論じる。いまやそこには基盤モデル、埋め込みサービス、文脈のプロバイダが含まれ、従来の依存関係と同じく厳格な検証を必要とする。GitHub Advanced Security のシークレット・依存関係・CodeQL のスキャンが Azure DevOps および Azure Repos に統合されていることを挙げ、Microsoft がこれらの実践を社内でも適用していると述べている。
- **まず基本を正しくする。** あらゆる AI の実装は組織の環境の既存のセキュリティ態勢を受け継ぐため、AI に固有のことに取りかかる前に全体の態勢を改善することが推奨される。セキュリティ研究についての記事自身の読みによれば、最も重要な実践は MFA を有効にすること、最小権限を適用すること、デバイス・インフラ・アプリケーションを最新に保つこと、そして重要なデータを守ることであり、これらがあらゆる種類の侵害に対する最も効果的な保護として提示されている。

## 適用範囲と留保

記事は脅威の分類体系ではなく指針である。2つの攻撃の類型と2つの緩和戦略を名指すが、MCP の脅威を体系的に列挙してはいない——それについては [[Report/model-context-protocol-security]] を参照。またベンダーの立場に置かれたものでもあり、AI と AI エージェントを安全に使う道筋として Microsoft 自身の Prompt Shields、GitHub Advanced Security、Azure AI Foundry の組み込みのプラットフォーム保護を推奨することで、それを暗に示している。前提そのものについての記事自身の留保は、これらの脆弱性が「業界にとって新しいものではない」ものの、MCP と AI ベースのワークロードへの当てはまり方はより仔細に見る価値がある、というものである。そして AI を使うことでアプリケーションの攻撃面が広がりうることも認めている。
