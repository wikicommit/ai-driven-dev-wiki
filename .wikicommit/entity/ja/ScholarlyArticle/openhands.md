"OpenHands: An Open Platform for AI Software Developers as Generalist Agents" は、Xingyao Wang と Graham Neubig が率いる大規模で複数機関にまたがる著者グループにより ICLR 2025 で発表された会議論文であり、[[SoftwareApplication/openhands]]——旧 OpenDevin——を導入するものである。その設計上の前提は、インターフェースについての論証として述べられている。ソフトウェアは現在人間が世界と関わる最も強力な手段であり、したがってその開発・利用・デプロイをめぐる既存のツール群を踏まえれば、それは「AI エージェントが複雑なしかたで世界と関わるための理想的なインターフェースを提供する」。

## 主要な知見

プラットフォームのエージェント抽象は、その中核をなす**イベントストリーム**——エージェント自身の行動とユーザーとのやり取りを含む、過去の行動と観測の時系列の集まり——を鍵となる構成要素とする**状態（state）**の構造の上に成り立つ。状態はまた、LLM 呼び出しの累積コストや、マルチエージェントの委譲を追跡するメタデータといった補助情報も担う。

行動空間は意図的に小さく、プログラミング言語に基づいている。CodeAct を踏まえ、`IPythonRunCellAction` と `CmdRunAction` は、安全に隔離された Linux オペレーティングシステムと記述されるサンドボックス環境の内部で、エージェントが任意の Python コードと bash コマンドを実行することを可能にする。一方 `BrowserInteractiveAction` はドメイン固有言語を通じてウェブブラウザを操作する。著者らは、これらのプリミティブが人間のソフトウェアエンジニアやアナリストが行うタスクの大半を覆っており、言語に基づく行動空間は「異なる形式のツールを用いて任意のタスクを遂行できるほど強力で柔軟」でありながら信頼でき保守しやすいと論じる。加えて、ユーザーはツールを通常の Python 関数として定義できるため、従来のツール呼び出しとも互換である、という性質もある。

**AgentSkills** は、著者らがエージェント・コンピュータ・インターフェースの発想に帰する保守上の問題に対する論文の答えである。多数の特化したツールを作り、保守し、配布することは手ごわいエンジニアリング上の課題であり、それらが異なるエージェント実装をまたいで動作しなければならない場合はなおさらである。その解は、エージェントの IPython 環境に自動的に読み込まれるユーティリティ関数の Python パッケージであり、ツールを定義することは Python 関数を定義することになる。掲げられている採用基準は意図的に厳しい——スキルが追加されるのは、LLM が直接コードを書くことが容易には達成できない場合か、外部モデルの呼び出しを伴う場合に限られる——著者らは、pandas で CSV を読む方法をエージェントに改めて教えたりはしない、という明確な反例を挙げている。記述されているスキルには、SWE-Agent と Aider から取り入れたファイル編集のユーティリティ、ファイルの異なる部分を見るためのスクロール関数、画像や PDF から情報を抽出するマルチモーダルのリーダーが含まれる。

**エージェントの委譲**は専用の `AgentDelegateAction` によって扱われ、あるエージェントがサブタスクを別のエージェントへ手渡すことを可能にする——論文の例は、ウェブ閲覧のサポートが限られた汎用の CodeActAgent が、特化した BrowsingAgent へ委譲するというものである。コミュニティが寄与したエージェントは AgentHub に置かれ、デフォルトの汎用エージェントは CodeActAgent である。各ステップでそれは、明確化や確認を求めるために自然言語で会話するか、タスクを遂行するためにコードを実行するかのいずれかを選べる。

評価について、論文は15のベンチマークタスクにわたる結果を報告している。SWE-Bench Lite——著者らがコスト上の理由からデフォルトとする300件の標準的な部分集合であり、完全な 2,294 件を実行すると控えめに見て1件あたり3ドルとして約6,900ドルかかると注記している——では、claude-3.5-sonnet を用いた CodeActAgent v1.8 が 26% の解決率に達しており、論文はこれを他のオープンソースの SWE 特化エージェントと競合しうるものと述べている。すべての結果はベンチマークの「ヒントテキスト」なしで報告されている。HumanEvalFix では、エージェントは Python の分割において 79.3% のバグを修正した。著者らはこれがエージェンティックでないアプローチのすべてより有意に良く、StarCoder2-15B のほぼ倍だと述べる。SWE-Agent のより高い 87.7% にも触れているが、その評価はモデルに完全な成功デモンストレーションの軌跡を与えていたのに対し OpenHands は 0-shot で評価されているため、比較は公平でないと注意を促している。

## 背景

論文は OpenHands を、研究成果物であるだけでなくコミュニティのプロジェクトとして提示している。寛容な MIT ライセンスのもとで公開され、学術界と産業界にまたがり、執筆時点で188名を超えるコントリビュータによる 2,100 を超える貢献がある。著者リストは UIUC、CMU、イェール大学、UC バークレー、Contextual AI、KAUST、ANU、HCMUT、Alibaba、All Hands AI にまたがる。

他のエージェントフレームワークやベンチマークについての比較的な主張は論文自身のものであり、執筆時点で組み込まれていたベンチマークに基づいている。また SWE-Bench Lite の結果は、完全なベンチマークではなく、費用の面から選ばれた部分集合に対して報告されたものである。
