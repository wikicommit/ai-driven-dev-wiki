本論文は、アジャイル、カンバン、Shape Up といった従来のソフトウェア開発方法論が人間中心のチームに向けて設計されたものであり、自律的な AI エージェントが計画、コーディング、テスト、継続的な学習に寄与する環境ではますます不十分になっていると論じる。著者らが方法論上のギャップと呼ぶもの——AI エージェントが互いに、また人間の監督者と、ライフサイクル全体でどのように体系的に協働すべきかを定義する形式的なプロセスモデルの不在——に対処するため、AI エージェントが第一級の協働者として動作するエコシステムのための枠組み [[DefinedTerm/agentsway]] を提示する。

この方法論は、単一の人間のオーケストレーターが専門特化したエージェント群と働くチームアーキテクチャを定義する。人間は主として、高レベルの事業目標の解釈、ステークホルダーとのやり取り、エージェントが生成した成果物の検証、そしてガバナンスと倫理面の監督に責任を負い、計画、プロンプト、コーディング、テスト、ファインチューニングは専用のエージェントへ委譲される。

際立った特徴は、この方法論がデリバリのループだけでなく学習のループも閉じる点である。各開発サイクルの後、Fine-Tuning Agent がタスクのデータ、プロンプト、生成されたコード、テストのフィードバックを収集し、それを用いて事前学習済みの LLM を漸進的に洗練させる。本論文がレトロスペクティブな学習プロセスと呼ぶものである。著者らは、モデルの訓練、ファインチューニング、データ交換のすべてが安全な組織的・規制的境界の内側で行われる、プライバシー・バイ・デザインのアーキテクチャを強調している。

## 主な貢献

本論文は自らの貢献を4点にまとめている。Agentsway 方法論そのものの提案。人間が主たるオーケストレーターとして振る舞いつつ専門特化した機能を自律エージェントへ委譲する、ヒューマンインザループのオーケストレーションモデルの導入。開発サイクル全体にわたる異なるエージェントからのフィードバックによって駆動される、LLM ファインチューニングのための継続的改善の仕組みの開発。そして法務案件処理の自動化に向けたエージェンティック AI ワークフローに焦点を当てた実世界のユースケースによる適用可能性の実証である。

責任ある AI は、単一のモデルではなくアンサンブルの配置によって扱われる。本論文は、専用の推論 LLM とともにコンソーシアムとして動作する複数のファインチューニング済み LLM を記述している。エージェントは自らのプロンプトを複数のファインチューニング済みモデルへ配り、多様な応答を得る。次いで推論モデルがそれらの入力を統合し検証して、最終的な判断または成果物を生み出す。著者らは、このアンサンブルベースの推論がエージェント的な判断の正確さと説明責任の双方を高めると論じている。

評価は法務案件処理のユースケースの文脈で3つの構成要素を扱っている。Planning Agent は、抽象的な目標を実行可能なタスクへ分解し構造化されたピッチを生み出す能力について評価された。本論文は、生成されたピッチが一貫性、正確さ、実装準備性について5段階のリッカート尺度で平均4.7の評価を得たと報告している。Prompting Agent は、下流のコーディングエージェント向けに実装可能なプロンプトを生成する能力について評価された。ファインチューニングの評価は訓練損失と検証損失の曲線を検討しており、著者らは損失の差が一貫して正であることが一部のステップにおける過学習の兆候を示唆すると述べている。

本論文はまた、Agentsway をウォーターフォール、アジャイル、カンバン、リーン、スパイラルモデル、XP、Crystal、Shape Up と対比する比較表も含んでいる。その表において Agentsway は AI を対象とすることについて「Yes」と記された唯一の項目であり——アジャイルは「Partial」、その他は「No」である——、また LLM のファインチューニングをサポートすると記された唯一の項目でもある。

## 注記

著者らは、知る限りこれは AI エージェントベースのソフトウェアエンジニアリングチームのために明示的に設計された専用の方法論を導入した最初の研究であると述べている。また、本論文はソフトウェア開発プロジェクト内で AI エージェントを管理することに焦点を当てているが、その基礎にある原則は AI エージェントを組み込む他の協働的でチームベースの環境へも拡張しうると指摘し、この手法のスケーラビリティと領域適応性の今後の評価対象として法務、観光、サイバーセキュリティを挙げている。
