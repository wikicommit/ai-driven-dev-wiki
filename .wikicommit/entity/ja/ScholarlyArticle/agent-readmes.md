「Agent READMEs: An Empirical Study of Context Files for Agentic Coding」は、Worawalan Chatlatanagulchai、Hao Li、Yutaro Kashiwa、Brittany Reid、Kundjanasith Thonglek、Pattara Leelaprute、Arnon Rungsawang、Bundit Manaskasemsak、Bram Adams、Ahmed E. Hassan、Hajimu Iida による研究であり、カセサート大学、奈良先端科学技術大学院大学、クイーンズ大学にまたがる。同論文は自らを、エージェント用コンテキストファイルについての初の大規模実証研究と称し、1,925 のリポジトリから 2,303 件のファイルを分析してその構造、保守、内容を特徴づけている。掲げられた動機は実務的なものである。すなわち、これらのファイルを作成するためのアクセスしやすい文書が著しく不足しており、著者たちによればそれが歴史的に、開発者をエージェントの設定における非効率な試行錯誤へと追いやってきた、というものである。

## 主な知見

**これらは静的な文書ではない。** 同論文の中心的な特徴づけは、エージェント用コンテキストファイルが「静的な文書ではなく、頻繁で小さな追加を通じて設定コードのように進化する、複雑で読みにくい成果物である」というものである。保守についての証拠は、Claude Code のコンテキストファイルの過半——67.0%——が複数のコミットにまたがって変更されていることであり、同じパターンは GitHub Copilot（59.8%）と OpenAI Codex（59.4%）ではやや頻度が低く、Claude Code のファイルはそのいずれよりも有意に多くのコミットを受けている。著者たちは保守が、短く急速なバーストとして、小さな漸増的な内容の追加によって駆動されて生じ、内容の削除は無視できるほど少ないと述べている。彼らの要約は、しばしば「一度書いたら終わり」と特徴づけられる従来のソフトウェア文書とは異なり、これらのファイルは進化する設定成果物として振る舞う、というものである。

**長さはタスクの複雑さとは独立に、ツールによって異なる。** GitHub Copilot のファイル（中央値 535.0 語）と Claude Code のファイル（中央値 485.0 語）は長さが似ており、両者の間に統計的に有意な差はない。そして双方とも OpenAI Codex のファイルより大幅に長い——著者たちはこの差をタスクの複雑さとは独立であると報告し、開発者がそれら2つのエージェントに対してはるかに大量の自然言語の指示を与えていることの現れと読んでいる。構造については、同論文は単一の H1 見出しに支えられ、H2 と H3 の小節が主要な話題を定める、一貫して浅い階層を報告しており、それが開発者に文書を素早く読み解き保守させる助けになっている可能性が高いと示唆している。可読性については率直である。これらの文書は複雑であり、多くが著者たちが高校レベルの教材になぞらえる「難しい」カテゴリに落ちる。

**内容は機能面に偏っている。** 手作業による分類は16の異なる指示カテゴリを特定した——うち2つ、保守とデバッグは著者たちの以前の研究に対して新しいものである。最も多かったのはテストで75.9% を占め、自動テストの手順を扱っている。続いて実装の詳細が70.8% でコードスタイルなどの開発上の指針を扱い、アーキテクチャが68.1% で高レベルのシステム設計を記述している。ファイルのおよそ半数はシステムの概観を含み、24.1% は AI 統合のラベルを持つ。そこでは開発者がプロジェクト内でのエージェントの役割と責任——たとえばレビュアー——を明示的に定義している。

**隔たりは非機能要件にある。** 性能はファイルの14.5%、セキュリティは14.8%、UI/UX は8.7% に現れる。著者たちはその含意を直接述べている。開発者はコンテキストファイルをエージェントを機能させるために用いるが、「エージェントが書いたコードが安全であることや高性能であることを保証するガードレールはほとんど与えていない」のであり、そのためエージェントは機能的にコードを「どう」作るかについては広く導かれているが、「品質特性に関して『どうすればうまく作れるか』については必ずしもそうではない」。

## 背景

分類は自動化ではなく人手のラベル付けに依拠している。4年から17年のプログラミング経験を持つ検査者たちが80.3% の一致率に達し、第三の検査者がすべての不一致を協議による合意で解消して、最終的に 2,069 件のラベル割り当てが得られた。同論文は別途、これらのファイルの自動分類が実現可能で有望であるとも報告しているが、これは内容についての知見が依拠する結果ではなく、今後の方向として枠づけられている。

各パーセンテージは、あるカテゴリの指示を少なくとも1つ含むファイルの割合を述べたものであり、ファイルの内容のうちそれに割かれた割合ではない。したがってカテゴリは設計上大きく重複する。コーパスはオープンソースのリポジトリであり、ツールごとの比較は具体的に Claude Code、GitHub Copilot、OpenAI Codex 向けに書かれたファイルの間のものである。
