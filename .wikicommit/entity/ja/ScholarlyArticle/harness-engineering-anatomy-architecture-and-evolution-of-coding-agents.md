Wavestone AI Lab と Inclusive Brains に所属する著者らによるこのプレプリントは、[[DefinedTerm/harness-engineering]] に本番環境のソースコードに根ざしたリファレンスを与えることを目指している。出発点は「エージェントとはモデルにハーネスを加えたものである」という定義であり、[[DefinedTerm/agent-harness]] をモデル以外のすべて、すなわちループ、ツール、コンテキスト、安全性の制御、オーケストレーション、拡張のサーフェスを通じて言語モデルを世界と結びつけるランタイムとして扱う。対象は 2026 年 7 月のリリースに固定した 11 のシステムである。4 つのプロバイダー純正のフラッグシップ（[[SoftwareApplication/claude-code]]、[[SoftwareApplication/openai-codex]]、[[SoftwareApplication/gemini-cli]]、[[SoftwareApplication/mistral-vibe-cli]]）と、7 つのオープンソースシステム（[[SoftwareApplication/openhands]]、Aider、[[SoftwareApplication/mini-swe-agent]]、[[SoftwareApplication/hermes-agent]]、Pi、[[SoftwareApplication/opencode]]、[[SoftwareApplication/openclaw]]）であり、[[SoftwareApplication/omnigent]] は [[DefinedTerm/meta-harness]] として別途分析されている。Claude Code の分析は公式リリースではなく、2026 年 3 月に出回ったソースのスナップショットに基づいており、著者らはこれを再現性における最も弱い部分と呼んでいる。

本論文は、各システムをベンチマークしたり順位づけたりはせず、それらがどのように作られているかを記述すると述べている。各システムは、エージェントループ、LLM との統合、ツールとアクション、メモリとコンテキスト、安全性と権限、オーケストレーション、拡張性という 7 つのサブシステムに沿って分解され、それぞれについてコーパス内で観察された最小限の実装と最大限の実装が示される。システムのうち 8 つは 2026 年 4 月版の研究ですでに調査されており、入れ替えるのではなくバージョンを固定し直したため、本論文は同じハーネスを四半期にわたって追った縦断的な比較も報告している。最後に 18 の設計上の推奨事項と、そのうち 10 を直接実装していると著者らが述べる、約 90 行の Python による最小限の実用的なハーネスの骨組みを示して締めくくっている。

## 要点

- 7 つのサブシステムは、ハーネスの標準的な解剖として提示されており、2 つの横断的なサーフェス、すなわちインターフェース層（TUI、CLI、IDE プロトコル、HTTP サーバー、SDK）とセッション基盤（トランスクリプト、永続化、再開とフォーク）が併せて示されている。
- 本論文は、ハーネスと混同されがちな 4 つのものを区別している。スキャフォールド（ループやレジストリのような構造的なコードを指すのに用いられるほぼ同義の語。[[DefinedTerm/agent-scaffold]] を参照）、エージェント型フレームワーク（その中で作業するランタイムではなく、エージェントを構築するためにインポートされるライブラリ）、SWE-bench のような評価ハーネス（モデルではなくエージェントを包むもの）、そしてオーケストレーターまたはメタハーネス（上位からハーネスを協調させ、自身では編集ループを実装しないもの）である。
- Python、TypeScript、Rust の約 400 万行にわたって、著者らは、LangChain、LangGraph、AutoGen のような汎用のエージェント型フレームワークをインポートしているエージェントランタイムは 1 つもなく、ベクトル埋め込みでコードを検索しているものも 1 つもないと報告している。検索は ripgrep、tree-sitter、glob、そして自動的に発見される Markdown のコンテキストファイルに依拠している。著者らはこの知見を構造的に控えめなものだと述べている。依存関係のマニフェストとインポートの検索に基づいており、動的インポートや内部フォークまでは追跡していないからである。
- SKILL.md 形式のスキルは 11 システム中 9 つで、MCP は 8 つで確認されたと報告されており、本論文はスキルが今や採用において MCP を上回っていると結論づけている。4 月時点では同数だったこの変化は、スキルを実装しつつ MCP を採用していない Pi によるものだとされる。
- 11 システム中 7 つが閾値をトリガーとする LLM によるコンパクションを用いていると報告されており、本論文は、誰がメモリを書き、誰がそれをレビューするかで設計が分かれる永続メモリが、コンパクションに代わってコンテキスト管理の最前線になったと論じている。
- OS レベルのサンドボックス化は、コーパスの中で最もコード量を要する機能の 1 つとされながらも、規模の帰結ではなく選択として説明されている。最大級のシステムのうち 2 つ、Hermes と OpenCode は、OS レベルの隔離の仕組みを一切備えていない。
- Agent Client Protocol は 6 つのシステムで確認され、3 つ目の役割、すなわちハーネス全体をホストする役割を獲得したと報告されている。たとえば OpenHands は Claude Code、Codex、Gemini CLI を交換可能なバックエンドとして実行する。一方 A2A は、コーパスの中では Gemini CLI だけの機能にとどまっている。
- 縦断的な比較は、収束が模倣へと変わりつつあることを示すと説明されている。Codex は Claude Code のフックイベントの語彙をそのまま採用し、そのセッションと設定のインポーターを提供しており、OpenHands は Claude Code のプラグイン形式を読み込む。また、振る舞いのポリシーはプロンプトの文章から設定へと移りつつある。4 月版の 3 つの観察はその場で改訂された。
- 本論文の主張は、2026 年前半にコーディングハーネスがツールからプラットフォームへの転換を完了したというものである。ハーネスがインポート可能な SDK になる一方でフレームワークのベンダーがハーネスを出荷し、マーケットプレイスやガバナンス層が登場し、今やメタハーネスが 1 つの API の背後でベンダーのハーネスをオーケストレーションしている。
- 著者らは「スキャフォールドと能力のフロンティア」、すなわち固定されたモデルとタスク分布のもとでスキャフォールドの複雑さとタスクの成功率との間にほぼ凹型の関係があるという考えを、結果としてではなく、検証されるべき指針となる直観として明示的に提案している。

## 補足

著者らは自ら妥当性への脅威を挙げている。分析は実行時の測定ではなくソースコードの読解に基づいていること、定性的な採点には判断が伴うこと、引用したベンチマークの数値は各システムが異なるモデルと日付で自己申告したものであること、そして Anthropic が公開しているエージェント設計のガイダンスと観察されたアーキテクチャとの対応は、因果的ではなく示唆的なものにとどまることである。また、ツールの数やバージョンの固定といった、数週間で古くなると予想される目録的な主張と、ループの分類、サブシステムの解剖、そして「存在しないもの」に関する、長く持続すると予想される構造的な主張とを区別している。本論文は、Claude Code CLI を介した Anthropic の Claude の大幅な支援を受けて書かれたこと、それがソースコードの分析と草稿の作成の両方に用いられたこと、そして知見は参照したコードベースと照合して検証されたことを開示している。
