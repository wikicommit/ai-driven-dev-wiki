この論文は、イーストロンドン大学の建築・計算機・工学スクールに所属する Sabry E. Farrag によるものであり、AI 支援開発に関する実証的な記録の中の矛盾を調停しようとする。冒頭の観察は、統制された研究群が範囲の明確なタスクにおいて 20〜56% の個人の生産性向上を報告する一方で、著者が最も厳密とみなすランダム化比較試験は、成熟したコードベースにおける経験豊富な開発者の 19% の減速を記録しており、1万人を超える開発者にわたるテレメトリは、マージされたプルリクエストの 98% の増加が、レビュー時間の 91% の増加および横ばいの組織的デリバリー指標と同時に生じていることを示している、というものである。

その方法は、2022年1月から2026年4月までに公表された67の情報源——査読済み研究29件、プレプリント18件、構造化された産業レポート12件、グレーリテラチャー8件——を対象とした多声的系統的文献レビューであり、SPACE フレームワークと取引費用経済学という二重のレンズを通して分析される。論文のテーゼは「AI 支援ソフトウェアの信頼性にとって拘束的な制約は、モデルの能力ではなく仕様の規律である」というものである。

## 主要な貢献

論文は4つの貢献を挙げている。

1. **[[DefinedTerm/productivity-reliability-paradox]]**——この現象の形式的な定義であり、レビューされた証拠に基礎づけられ、3つの調整変数——タスクの抽象度、コードベースの成熟度、開発者の経験——を通じて調停される。
2. **[[DefinedTerm/ai-augmented-methodology-taxonomy]]**——確立された6つの手法（TDD、BDD、DDD/DDT、アジャイル、ウォーターフォール、DevOps）が、AI 統合の3つの段階にわたってどう変容するかの分類。
3. **[[DefinedTerm/specification-governance-model]]**——[[DefinedTerm/spec-driven-development]] を取引費用経済学に基礎づけるものであり、論文は、SDD が合理的なガバナンス上の応答として現れる理由についての最初の形式的な経済学的理論化であると主張する。
4. **2つの具現化の評価**——[[SoftwareApplication/spec-kit]] と [[DefinedTerm/test-driven-ai-agent-definition]] のパイプライン——に加えて、3つのフルスタック Web チームにわたる4か月の例示的なパイロット研究。

パラドックスの原因ではなくそれを増幅するものとして、2つの機構が名指されている。**コンテキストウィンドウの制約**——現在のモデルは、非自明なプロジェクトのコードベース、テストスイート、アーキテクチャ文書、会話履歴のすべてを同時には保持できないため、生成されたコードがウィンドウの外のファイルで確立された規約に違反しうるし、多段階の自律的な実行は、後のステップが先の決定と矛盾することで漂流しうる。その結果は、システム全体の一貫性を犠牲にした局所的な正しさへの偏りである。**コードレビューのボトルネック**——レビューを加速させずに生成を加速させれば、利得を吸収する待ち行列が生じる。論文はこれをゴールドラットの制約理論を通じて読む。ボトルネックでない工程を最適化してもシステムのスループットは改善しない。コードを書きテストすることは SDLC 全体のおよそ 25〜35% にすぎないため、AI ツールは少数派の取り分を最適化しつつ多数派の取り分への負担を増やしている、と指摘する。

論文はまた、このパラドックスを時間軸のうえに位置づけ、これは生産性の [[DefinedTerm/ai-adoption-j-curve]] の底を表すと論じる。ツールは採用されたが、それを補完する無形の投資——仕様の規律、検証の実践、ガバナンスの枠組み——が遅れているのである。

## 覚え書き

パイロット研究は、統制されたものではなく例示的なものとして明示的に提示されている。3つのプロジェクトにまたがる14名のエンジニアが2か月のベースライン期間に続いて2か月の Spec Kit 介入期間を過ごした。チームレベルでの被験者内の前後比較設計であり、ジュニアの開発者は意図的に除外されている。計測は遡及的であり、並行する対照群はなかったため、著者は数値を効果量の推定ではなく指標的な大きさとして報告している。機能あたりのリードタイムの中央値は 8〜12 営業日から 6〜9 営業日へ、スプリントあたりの後工程でのホットフィックスは 3〜5 件から 1〜2 件へ、月あたりのロールバックは 2〜4 件から 0〜1 件へ、短期のコードチャーンは変更行の 12〜18% から 6〜10% へ、開発者が自己申告する自信は5段階のリッカート尺度で 3.1 から 3.9 へ動き、これに対して中規模の機能あたり 45〜90 分の仕様執筆のオーバーヘッドがある。

論文はその中心的なツールの事例についても率直である。2026年4月時点で Spec Kit はバージョン 0.8.x にあり、小規模ながら成長しつつある採用者コミュニティを持ち、独立した学術的評価の対象になったことがなく、ソフトウェアチームの大多数には採用されるどころか出会われてすらいないと述べ、それを「実証済みの解としてではなく、SGM の理論的原則の最も完成度の高い既存の具現化として」評価している。

理論上の但し書きが1つ、著者自身によって提起されている。ウィリアムソンの取引費用経済学は機会主義的な自己利益を持つ主体を前提とするが、AI のコード生成器はそれを持たない。ここでガバナンスを動機づける行動上の不確実性は、代わりに非決定性から生じる。論文は、検証を要する予測不能な出力は、監視を要する予測不能な振る舞いと実践的には等価であるため、この区別はガバナンスの設計にとって機能的には重要でないと論じ、「機会主義的な自己利益」を「確率的な信頼性の欠如」で置き換える修正版の枠組みを今後の理論的な課題として掲げている。

これは単著のプレプリントであり、自身の造語をいくつも提示している。このパラドックス、タクソノミー、ガバナンスモデルは、この分野で確立された用語ではなく、この論文の提案である。
