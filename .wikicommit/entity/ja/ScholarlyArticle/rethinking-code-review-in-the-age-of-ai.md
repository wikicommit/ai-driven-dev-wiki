アンカラ大学、Microsoft、ビルケント大学の著者らによるこのビジョン論文は、コードレビューこそが AI 支援開発のコストが着地する地点であると論じる。その枠づけとなる主張は、AI はコードの生産を助けるだけではない——そのコードが通らねばならないレビューのプロセスに跳ね返ってくる、というものである。論文は、コーディングアシスタントが個人のコーディングタスクを 50% 超加速させる一方で、統合のための調整時間が個人の産出よりも速く増大し、AI が生成した貢献が人間の書いたものより多くのレビューの反復を要していることを引く。ここからの結論は、「コードレビューはもはや生産性のボトルネックであるだけではない。それは AI が生み出したコードの品質と説明責任のための第一の制御面である」というものである。

既存の AI 支援に対する診断は断片化である。ツール群はレビュアーの推薦、PR 説明の生成、コメントの提案といった孤立したタスクに取り組んでおり、段階ごとの進歩はそれ自体では組み合わさらない——有益なレビューコメントは、その理由が書き留められた PR に依然として依存しているし、レビュアーのマッチングは行動的な文脈がレビュアーに届くことに依拠している。論文の応答は、レビューの有効性を全ライフサイクルの帰結として扱い、段階の境界をまたいで文脈を運ぶ枠組みを提案することである。

この論文は、評価されたシステムではなくビジョンと研究アジェンダとしての貢献である。枠組みを提案し、未解決の課題を特定し、研究アジェンダを提示するが、枠組みそのものの実装や実証的な結果は報告していない。

## 主要な貢献

**レビュー実践の5つの時代の歴史**——アドホック、形式的インスペクション、軽量なピアレビュー、統合されたコードレビュー、そして自動化支援——であり、ツールではなく実践者が実際にどうレビューを行ってきたかを軸に整理されている。

**5段階のエージェンティックな枠組み**であり、[[DefinedTerm/agentic-code-review]] のもとで記述され、各移行点に明示的な human-in-the-loop の品質ゲートを備える。

- **PR 作成**——PR Detail Generation Agent が diff からタイトルと説明を書く。Issue Linking Agent がトレーサビリティのリンクを確立するか、適合するものがなければ Issue を作成する。Automated Code Review Agent がドラフトの diff を検査する。Fix Suggestion Agent が、何を変え何をそのまま残すかを明示したうえで具体的なパッチを提案する。そのうえで著者が正式に提出する前に、自然言語で対話的に修正する。
- **PR 拡充**——diff とリンクされた Issue の文脈に対して4つのエージェントが並行して走る。要求の充足を exact、tangling、missing、missing-and-tangling に分類する Alignment Analysis Agent。過去の欠陥密度、コードチャーン、ホットスポットのファイルからリスクを採点する Bug Proneness Analysis Agent。サンドボックス内でコードを実行してログと実行トレースを収集する Runtime Analysis Agent。そしてモジュール横断の依存関係を評価する Impact Analysis Agent である。続いて Summary Generation Agent がそれらの出力を、検証可能な主張の構造化された要約へと総合する。
- **レビュアー選定**——従来のレビュアー推薦のツールが、専門性、過去のレビュー経験、現在の作業待ち行列、変更への習熟度から候補を順位づけする。著者はそのリストから選び、招待を送る。
- **AI 支援コードレビュー**——PR Review Agent が中心的な自然言語インターフェースとして働き、Explanation Agent、Automated PR Review Agent、Fix Suggestion Agent、Toxicity Measurement Agent、Usefulness Measurement Agent へ委譲する。これらはすべて [[DefinedTerm/diff-map]] を介して相互作用する。
- **PR レトロスペクティブ**——レビューの要約が実装とレビューの文脈をリポジトリのメモリとして捉え、レビューの指標が算出されて継続的なプロセス改善へ供給される。

**責任ある採用のための未解決の課題の目録**——LLM の予測におけるバイアスと不正確さ、プロジェクトをまたぐ一般化の限界、マルチエージェントのパイプラインにおける誤差の蓄積、エージェントの評価、透明性、説明責任、プライバシー、自動化バイアス、知識共有の劣化、そして隠れた経済的コストである。

## 覚え書き

論文が自ら特定したリスクのうち2つは、自身の設計に切り込むがゆえに注目に値する。**誤差の蓄積**については、具体的な連鎖を辿ってみせる。PR Detail Generation Agent が認可の変更を通常の業務ロジックと読み違えて不正確な説明を生み、それがレビュアー選定にセキュリティの専門家ではなくバックエンドの専門家を割り当てさせ、セキュリティ上の欠陥が検査されないまま通る。緩和策は人間のゲートそのものであり、論文はそれを「誤差の蓄積に対する自然なファイアウォール」と記述する——著者が生成された説明を検証することが、連鎖を早い段階で断ち切る。

**自動化バイアス**については、続いて、それらの人間のゲートが本質的に頑健であると仮定すること自体が「根本的な欠陥」だと論じる。示される事例は、著者が誤った Issue のリンクをそのまま通してしまい、それが欠陥のある分析を下流のレビュアー割り当てへ伝播させるというものである。論文は、開発者が初めは容易に受け入れるにもかかわらず、最終的に AI が生成した提案の 52% しか残さないという観察を引き、依存を前提とするのではなく明示的な品質の指標が必要だと論じる。

第三のリスクは、欠陥の検出を超えてレビューが*何のためにあるか*に関わる。論文は、知識の移転とチームの認識が同等に決定的な帰結であること、そして説明をエージェント経由にすることが「暗黙のメンタリング」を押しのける恐れがあることを指摘し、オープンソースプロジェクトのプルリクエストの 27.41% に教育的な指導が埋め込まれているという知見を引く。提案される緩和策は、マージのブロックが解除される前に人間のレビュアーがアーキテクチャ上の洞察かメンタリングの覚え書きを寄せることを求める、必須の「PR Critique」チェックポイントである。
