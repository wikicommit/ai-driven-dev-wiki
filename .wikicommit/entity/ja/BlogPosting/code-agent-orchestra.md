この記事は O'Reilly AI CodeCon で行われた講演を書き起こしたものであり、AI 支援コーディングが「指揮者」モデル、すなわち同期的に導かれ、単一のコンテキストウィンドウに制約される 1 つのエージェントから、「オーケストレーター」モデル、すなわち開発者がそれぞれ独自のコンテキストウィンドウとファイルスコープを持つ複数の非同期エージェントを調整するモデルへと移行しつつあると論じる。記事は段階的に高度になる 3 つのマルチエージェントパターン（サブエージェント、[[DefinedTerm/agent-teams]]、そして大規模なオーケストレーションプラットフォーム）、その出力を信頼するために必要な品質ゲート、そして結果として得られるワークフローを生産ラインとして運用するための「ファクトリーモデル」を示す。

記事は、この移行においてボトルネックはコード生成から検証へと移ったと論じ、明確な仕様、品質ゲート、そして何を自分の手元に残し何を委任するかを見極めることといった必要な規律こそが、「エージェントの軍団」が進歩を積み重ねるのか、それとも誤りを積み重ねるのかを決めると主張する。

## 要点

- 単一エージェントの 3 つの制約がマルチエージェントへの移行を動機づける。コンテキストの過負荷（大きなコードベースは 1 つのコンテキストウィンドウを圧倒する）、専門化の欠如（汎用のエージェントは特化したエージェントよりも質の低いコードを書く）、そして調整の欠如（起動されたヘルパーはタスクリストを共有したり依存関係を解決したりできない）である。
- Claude Code の実験的機能である [[DefinedTerm/agent-teams]] は、依存関係の追跡を備えた共有タスクリストと、チームメイト同士のピアツーピアのメッセージングを追加する。記事は、これがサブエージェントだけでは解決されないまま残る調整の問題を解決したと評価している。
- 記事は、2026 年のオーケストレーションツールの状況を 3 層に分けて報告する。プロセス内のサブエージェント／チーム（単一のターミナルで、追加のツールは不要）、Conductor、Vibe Kanban、Claude Squad などのローカルオーケストレーター（隔離されたワークツリーで 3〜10 個のエージェントを動かし、ダッシュボードを備える）、そして Claude Code Web、GitHub Copilot Coding Agent、Jules などのクラウドの非同期エージェント（タスクを割り当てると、プルリクエストとして返ってくる）である。
- 記事は、Agent Teams ではチームメイトは 3〜5 人が最適だと報告されていると述べる。トークンコストはチームの規模に比例して増え、焦点を絞った小さなチームのほうが散漫な大きなチームよりも成果を上げると報告されているからである。
- 記事は、専用の読み取り専用の「@reviewer」チームメイト（Claude Opus 4.6 で動作し、lint／テスト／セキュリティスキャンのツールに制限される）を置き、タスクが完了するたびに自動的に起動させることを推奨している。これによりリードは常にレビュー済みのコードだけを統合することになる。
- 記事は [[DefinedTerm/ralph-loop]] パターン（Geoffrey Huntley と Ryan Carson によるものとされる）を、夜間の自律的な開発のための、選択／実装／検証／コミット／リセットの 5 ステップのサイクルとして説明している。安全策として、3 回以上のイテレーションで行き詰まったエージェントを停止して再割り当てすることや、ロールごとのトークン予算が挙げられている。
- AGENTS.md に関する研究（Gloaguen ら、ETH Zurich）を引いて、記事は LLM が生成した AGENTS.md ファイルには利点がなく、成功率をおよそ 3% 下げる一方で推論コストを 20% 以上増やしうるのに対し、開発者が書いたコンテキストファイルはおよそ 4% の改善をもたらすと報告している。
- 記事は、エージェント型開発のための 6 ステップの「ファクトリーモデル」の生産ライン、すなわち計画（Plan）、起動（Spawn）、監視（Monitor）、検証（Verify）、統合（Integrate）、振り返り（Retro）を提案する。あわせて、仕掛かり作業を 3〜5 個のエージェントに制限することや、行き詰まったエージェントを停止する基準を定めることといった実践的な限度も示している。
- 記事は、大規模な環境では仕様の質が出力の質を左右する主要な手段だと論じる。曖昧な仕様の誤りは並列エージェントの群れ全体に増幅される一方で、精密な仕様は精密な実装へと増幅される。

## 背景

記事は、それが触れるトピックの参考資料として、仕様の質と、エージェント型開発の「ファクトリーモデル」についての著者の別の文章へのリンクを示している。また、講演の内容（レベル 5 から 8）が基盤とする枠組みとして Steve Yegge による AI 支援コーディングの 8 段階のはしごを引用しているが、それぞれのレベルが何であるかは改めて述べていない。
