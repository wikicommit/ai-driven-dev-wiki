これは [[DefinedTerm/agent-skills]] の製品発表である。デザインパターン、アーキテクチャ、開発のベストプラクティスについては [[BlogPosting/equipping-agents-for-the-real-world-with-agent-skills]] のエンジニアリング側の解説に読者を案内し、自らは何が出荷されたかに話を限っている。あちらの記事がなぜこの形式がこのような形をしているのかを説明するのに対し、こちらは何がどこで出荷されたかを述べる。スキルは、関連する場合に Claude が読み込む、指示・スクリプト・リソースのフォルダーとして説明されており、手元のタスクに合致したときにだけアクセスされる。

発表はスキルを、専門知識をパッケージ化したカスタムのオンボーディング資料になぞらえて位置づけ、ユーザーはすでにスキルが働いているところを目にしていたと指摘している。Claude アプリでのファイル作成の振る舞い（スプレッドシートやプレゼンテーション）は、自分でスキルを作成できるようになる前から、すでにスキルとして実装されていたのである。

2025 年 12 月 18 日に追加された注記は、その後の 3 つの追加を記録している。スキルの組織全体での管理、パートナーが構築したスキルのディレクトリ、そしてクロスプラットフォームの移植性のための Agent Skills のオープンスタンダードとしての公開である。

## 要点

- Claude は作業中に利用可能なスキルを走査し、合致するものがあれば必要最小限の情報とファイルだけを読み込むと説明されている。発表が述べるその理由は、Claude を高速に保ちつつ、専門的な知見にアクセスできるようにすることである。
- 4 つの特性が主張されている。スキルは組み合わせ可能である（積み重ねることができ、どれが必要かを Claude が見極めて連携させる）、移植可能である（Claude アプリ、Claude Code、API で 1 つの形式）、効率的である（必要なものだけを、必要なときに読み込む）、そして強力である（トークン生成よりも従来のプログラミングのほうが信頼できるタスクのために、実行可能なコードを含めることができる）。
- Claude アプリでは、スキルは Pro、Max、Team、Enterprise のユーザーが利用できるとされ、一般的なタスクのための Anthropic 提供のスキル、カスタマイズ可能な例、そして独自のスキルを作成する機能が用意されている。Team と Enterprise では、管理者がまず組織全体でスキルを有効にする必要がある。
- Claude アプリでの呼び出しは手動ではなく自動であり、発表によれば、スキルは Claude が作業する際に Claude の思考の連鎖の中に現れる。
- `skill-creator` スキルは、作成のための対話的なガイダンスを提供するものとして説明されている。Claude がワークフローについて質問し、フォルダー構造を生成し、`SKILL.md` ファイルを整形し、リソースをまとめるので、手作業でファイルを編集する必要はない。
- Claude Developer Platform では、スキルを Messages API のリクエストに追加でき、`/v1/skills` エンドポイントによってカスタムスキルのバージョン管理と管理をプログラムから制御できる。スキルには Code Execution Tool のベータが必要とされており、これはスキルの実行に必要な安全な環境を提供するものと説明されている。
- API 向けに Anthropic が作成したスキルとしては、数式を含む Excel スプレッドシート、PowerPoint プレゼンテーション、Word 文書、入力可能な PDF の読み取りと生成が挙げられている。開発者は Claude Console を通じてスキルのバージョンを作成、閲覧、アップグレードできる。
- [[SoftwareApplication/claude-code]] では、スキルは `anthropics/skills` マーケットプレイスからプラグイン経由で、あるいは `~/.claude/skills` に追加することで手動でインストールされ、関連する場合に自動的に読み込まれ、バージョン管理を通じてチームと共有できる。[[SoftwareApplication/claude-agent-sdk]] は、カスタムエージェントを構築するために同じ Agent Skills のサポートを提供するとされている。
- 発表は、この機能によって Claude がコードを実行できるようになると述べ、そのため信頼できるソースに限定するよう勧めている。
- 今後の取り組みとして述べられているのは、スキル作成のワークフローの簡素化と、チームをまたいでスキルを配布するためのエンタープライズ全体への展開機能である。

## 背景

これは技術的・評価的な記述ではなく製品のコミュニケーションである。どの窓口で何が利用できるか、そして Anthropic がこの形式について何を主張しているかを述べ、設計の根拠は同社のエンジニアリング記事に委ねている。効率性や能力に関する主張について、Anthropic 自身は測定結果を示していない。

この発表は、スキルが内部の実装の詳細からユーザーが作成する形式へと移行したことの記録でもある。発表自身の位置づけがその移行を明示している（ユーザーが目にしていた文書作成の振る舞いはすでにスキルだった）ため、この発表は、内部の仕組みが他の人々がそれに対して構築するインターフェースになった時点に位置づけられる。

発表ではパートナー組織の顧客による 4 つの声明が引用されており、文書生成、エージェントのカスタマイズ、金融のワークフローにおける意図された利用や初期の利用が説明されている。そのうち 2 つは実際に効果を数字で示している（1 つは 1 日かかっていた作業が 1 時間になったと主張し、もう 1 つは何時間もの労力を節約したとしている）が、これらは各社自身の数字であり、ローンチの一環として提供されたもので、どちらにも方法論は示されていない。
