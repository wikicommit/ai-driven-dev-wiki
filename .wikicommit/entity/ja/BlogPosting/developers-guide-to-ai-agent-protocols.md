2026 年 3 月 18 日に Google の開発者ブログで公開された『Developer’s Guide to AI Agent Protocols』は、同記事が「頭字語であふれかえった」と呼ぶ状況を整理しようとするものである。著者らは 6 つのプロトコル、すなわち [[DefinedTerm/model-context-protocol]]（MCP）、[[DefinedTerm/agent2agent-protocol]]（A2A）、[[DefinedTerm/universal-commerce-protocol]]（UCP）、[[DefinedTerm/agent-payments-protocol]]（AP2）、[[DefinedTerm/agent-to-user-interface-protocol]]（A2UI）、[[DefinedTerm/agent-user-interaction-protocol]]（AG-UI）を取り上げ、それぞれが、エージェントが関わるものの一部分について、開発者がカスタム統合コードを書いて保守する手間を省くと論じている。

記事の方法は、1 つの具体例を通して説明することである。[[SoftwareApplication/agent-development-kit]]（ADK）を使って、卸売の食材を発注するレストランのキッチンマネージャー・エージェントを構築する。出発点は「あらゆることをハルシネーションする」素の LLM であり、セクションごとに 1 つずつプロトコルを追加していくと、最終的にエージェントは実際の在庫を確認し、専門エージェントから見積もりを取り、注文を出し、支払いを承認し、インタラクティブでストリーミングされるダッシュボードを描画できるようになる。著者らがこのシナリオを選んだのは、食材の発注にはこれらすべての能力が同時に必要になるからである。すべてのコードサンプルは ADK を使っており、記事は Google 自身の開発者ブログに掲載されている。

## 要点

- MCP は、エージェントをシステムやデータに接続する問題を扱う。API エンドポイントごとにカスタムツールを 1 つずつ用意するのではなく、サーバーが自らのツールを公開し、エージェントがそれらを発見する。記事はさらに、MCP サーバーは基盤となるシステムを構築したチーム自身によって保守されるため、開発者が統合コードを更新しなくても、エージェントは最新のツール定義を得られると付け加えている。
- A2A は、異なるチームによって、異なるフレームワークやサーバー上に構築されている可能性のあるリモートエージェントが持つ専門知識の問題を扱う。各 A2A エージェントは、名前、能力、エンドポイントを記述した Agent Card を既知の URL で公開するため、リモートエージェントの追加はその URL を追加するだけで済む。
- UCP は、サプライヤーごとにチェックアウトの API が異なるという問題を扱う。UCP はショッピングのライフサイクルを、強く型付けされたリクエストとレスポンスのスキーマを持つモジュール化された能力へと標準化し、それらのスキーマは接続が REST、MCP、A2A、組み込みプロトコルのいずれを経由する場合でも同じままである。
- AP2 は、誰が購入を承認したのかという問題を扱う。AP2 は、否認できない意図の証明を提供し、設定可能なガードレールを強制する型付きのマンデートを追加し、UCP に拡張として組み込まれる。記事は、AP2 は v0.1 の段階にあり、ADK のコアではなく別パッケージとして提供されていると注記している。
- A2UI は、インターフェースが必要な場面で結果がプレーンテキストになってしまう問題を扱う。エージェントは、18 個のコンポーネントプリミティブからなる固定のカタログから宣言的な JSON 形式でレイアウトを組み立て、クライアント側のレンダラーがそれをネイティブの UI に変換する。
- AG-UI は、エージェントのイベントをフロントエンドにストリーミングするための定型コードの問題を扱い、フレームワークの生のイベントを、型付きイベントからなる標準化された server-sent events のストリームに変換する。
- 具体例では、1 つのリクエストで 6 つすべてが使われる。MCP と A2A が情報を集め、UCP と AP2 が取引を完了させ、A2UI と AG-UI が結果を提示する。
- 記事の助言は、各プロトコルがどの問題を解決するのかを把握すること、要件が求めるときにだけプロトコルを追加すること（記事によれば、ほとんどのエージェントはデータアクセスのための MCP から始まる）、構築する前に ADK 統合、公式 SDK、サンプルコードがあるか確認すること、そして標準はまだ成熟途上であっても早期に採用することである。これらの標準が共有するパターン（既知の URL による発見、型付きスキーマ、標準のイベントストリーム）によって、エージェントは成長しつつあるエコシステムと互換性を持てるからである。

## 背景

記事は 6 つのプロトコルを競合するものではなく層として位置づけている。記事の一行の要約によれば、MCP はエージェントをツールとデータに接続し、A2A はエージェントを他のエージェントに接続し、UCP はコマースを標準化し、AP2 は支払いの承認を扱い、A2UI は何を描画するかを定義し、AG-UI はそれをどうストリーミングするかを定義する。この記事は Google 自身のフレームワークのチュートリアルでもある。記事中のすべてのコードサンプルは ADK を使っており、プロトコルを扱うセクションのほとんどは、そのプロトコルの ADK 統合を案内している。例外は AP2 で、記事はこれが ADK のコアに組み込まれていないと注記している。したがって、ADK 統合から始めるべきだという記事の推奨は、発行元が自社のツールを推奨しているものである。
