この記事のタイトルは「真の AI エージェント型コーディングツール：Claude-Code」と訳せるもので、SK Telecom が運営する開発者コミュニティブログ DEVOCEAN 上で、韓国の開発者向けに書かれた [[SoftwareApplication/claude-code]] の入門ガイドである。記事は以前の AI コーディングツールとの対比を軸にしている。Copilot や Cursor などのツールは自動補完やスニペットの提案に重点を置いていると説明される一方、Claude Code は「エンジニアのように」コードベース全体を探索、分析、編集し、コミットやプッシュまで行うツールとして示されている。記事はこれをエージェント型コーディングと呼び、AI がコードを提案するだけでなく、自ら計画し、実行し、問題を解決するものだとしている。

記事の大部分は実践的な内容である。インストールと認証、Claude Code が初回起動時に表示するヒント、空のプロジェクトディレクトリで `/init` コマンドが何をするか、3 つの作業モード、MCP サーバーの接続、そして 1 つの詳細なプロンプトをパーミッションの確認をオフにして実行し、テスト済みの FastAPI の CRUD API を作成して GitHub にプッシュする実例を扱っている。最後に、ベストプラクティスの表、インストールコマンド付きの MCP サーバーの一覧、パーミッションの許可リストの例、キーボードショートカットとスラッシュコマンドの参照表を載せている。

## 要点

- 記事はエージェント型コーディングを、AI がタスクを計画し、実行し、問題を自律的に解決することと定義し、これをコード提案を中心としたツールに対する Claude Code の際立った強みとして示している。
- `/init` スラッシュコマンドはコードベースを分析し、今後の Claude Code のセッションのためのガイダンスを記した `CLAUDE.md` ファイルを書き出すと説明している。著者自身が空のディレクトリで試したところ、ツールはファイルを見つけられず、プロジェクトが初期状態にあると判断して、コマンド、アーキテクチャパターン、データベースのマイグレーション、環境変数を扱う FastAPI の CRUD プロジェクト向けの汎用的なガイドを書き出した。
- Shift+Tab で切り替える 3 つの作業モードを説明している。行動する前に計画を説明して承認を待つ Plan、提案されたすべてのアクションを受け入れる Auto Accept、そしてデフォルトで、各アクションについて承認を求める Normal である。
- 実例では、無人実行を想定したプロンプトを組み立てている。作成、読み取り、更新、削除を独立した単位に分けて並列に処理すること、プランモードの承認を省くこと、すべての変更を Git にコミットしてプッシュすること、コードの各ブロックを書く前に「ultra think」を適用すること、pytest と httpx のテストを生成して失敗を自動的に修正すること、そして中断後に作業を再開できるよう、進捗、エラー、次のステップを `PROGRESS.md` ファイルに記録することである。
- そのプロンプトを承認待ちなしで実行できるよう、著者は `--dangerously-skip-permissions` を付けて Claude Code を起動し、エージェントがコミットとプッシュを行えるよう `claude mcp add` で GitHub の MCP サーバーを追加した。記事によれば、実行は約 10 分で完了し、テストは 10 件中 10 件が成功し、2 つのコミットが公開リポジトリにプッシュされた。これは著者の 1 回の実行による結果である。
- 記事は、`--dangerously-skip-permissions` はほとんどのパーミッション要求を省略するものの、一部の機微な操作は内部的に依然として承認を必要とする場合があると指摘し、その対策として、ツールとコマンドの許可リストをあらかじめ設定しておくことを推奨している。付録では `allow` と `deny` のリストを使った例を示している。
- ベストプラクティスのセクション（探索、計画、コーディング、コミット。テストを先に書く。スクリーンショットと照らし合わせて反復する。CI のためのヘッドレスモード。別々の Git ワークツリー上で複数の Claude インスタンスを並列に実行する）は、Claude Code を使うためのガイダンスとして示されており、英語で名前が付けられたワークフローの分類を韓国語で言い直したものである。記事自体、監督なしで実行する「safe YOLO mode」は、インターネットにアクセスできないコンテナ内でのみ使い、機微な作業には決して使わないよう警告している。
- 記事は、Claude Code を使う開発者は開発速度を平均 150% 向上させ、バグ率を 83% 削減したと主張しているが、その根拠は出典を示さない「最近の統計」とするのみである。
- 最後のセクションでは、コードレビュー、デバッグ、ドキュメント作成、テスト生成、自動化スクリプト、学習にわたる生産性の事例を、それぞれ改善率とともに列挙している。これらは著者が測定したものではなく、Anthropic や第三者のユーザーによるリンク先のページに帰属させている。

## 背景

この記事はベンダーの立場からではなく、ツールを紹介する個人の実務家の立場から書かれており、実践的なセクションは著者自身のセッションの記録に基づいている。定量的な主張は性質が異なる。見出しとなる速度とバグ率の数値には出典が示されておらず、事例の数値は他のページから伝えられたものなので、記事が立証したことではなく、それらのページが報告していることを述べているにすぎない。

結論はツールの将来性について公然と宣伝的である。Claude Code は GitHub Copilot と並んで業界標準の AI コーディングツールになる可能性が高く、今この変化を体験しておくことが開発者の将来の競争力を確保する、というものだが、記事はこれらを発見ではなく期待として示している。
