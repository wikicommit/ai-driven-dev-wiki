「Introducing the Model Context Protocol」は 2024年11月25日付の発表記事であり、[[Organization/anthropic]] が [[DefinedTerm/model-context-protocol]] を「AI アシスタントを、コンテンツリポジトリ、業務ツール、開発環境をはじめとする、データが存在するシステムへ接続するための新しい標準」としてオープンソース化したものである。掲げられた狙いは、フロンティアモデルがより良く、より適切な応答を生み出せるようにすることにある。

なぜ標準が必要なのかという記事の論拠は、一つの食い違いに置かれている。業界はモデルの能力に多大な投資を行い、推論と品質において急速な進歩を遂げてきた。それにもかかわらず、最も高度なモデルでさえデータからの孤立によって制約され続けている——「情報のサイロとレガシーシステムの背後に閉じ込められて」おり、新しいデータソースはどれも独自の実装を必要とするため、真に接続されたシステムをスケールさせることが難しい。MCP はこうした断片化した連携を単一のプロトコルで置き換えるものとして提示され、そのアーキテクチャは単純明快だと説明される。開発者は自らのデータを MCP サーバーとして公開するか、あるいはそうしたサーバーに接続する AI アプリケーション（MCP クライアント）を作るかのいずれかである。

## 要点

- ローンチ時に提供された3つの構成要素は、仕様と SDK、Claude デスクトップアプリでのローカル MCP サーバーのサポート、そして MCP サーバーのオープンソースリポジトリである。
- Google Drive、Slack、GitHub、Git、Postgres、Puppeteer 向けの構築済みサーバーが公開され、記事は Claude 3.5 Sonnet が MCP サーバーの実装を素早く作ることに長けていると述べている。
- 初期の採用者として名指しされたのは Block と Apollo であり、開発ツールの企業である Zed、Replit、Codeium、Sourcegraph が自社プラットフォームの強化のために MCP に取り組んでいるとされる。その利点として挙げられているのは、AI エージェントが関連情報をより良く取得してコーディングタスクを取り巻く文脈を理解し、より機微を捉えた、機能するコードをより少ない試行で生み出せるようになることである。
- Block の最高技術責任者である Dhanji R. Prasanna の言葉が引かれている。「Model Context Protocol のようなオープンな技術は、AI を現実世界のアプリケーションへつなぐ橋であり、イノベーションが誰にでも手の届く、透明で、協働に根ざしたものであることを担保する」。そして Block はこれを使って、「機械的な作業の負担を取り除き、人々が創造的なことに集中できるようにする」エージェンティックなシステムを作れることを楽しみにしている、と述べている。
- 将来を見通した主張は機能についてではなくアーキテクチャについてのものである。エコシステムが成熟するにつれ、AI システムは異なるツールやデータセットの間を移動しながらコンテキストを保ち、断片化した連携をより持続可能なアーキテクチャで置き換えていく、というものだ。
- ローンチ時の提供状況については、Claude.ai のすべてのプランで Claude デスクトップアプリへの MCP サーバーの接続がサポートされ、Claude for Work の顧客は社内システムに対してローカルにサーバーを試すことができ、Anthropic はリモートの本番サーバーをデプロイするための開発者向けツールキットを近く提供するとしていた。
- 記事はプロトコルの成り立ちについても記している。「MCP は Anthropic で [[Person/david-soria-parra]] と [[Person/justin-spahr-summers]] によって作られた」。

## 背景

記事は明示的にオープンなコミュニティの枠組みで締めくくられている。MCP を協働的なオープンソースのプロジェクトとエコシステムとして育てていくという約束と、AI ツールの開発者、既存のデータを抱える企業、そして初期の採用者のいずれに対しても向けられた参加の呼びかけである。この枠づけは、決着のついた立場ではなく出発点として読むのがよい。同じプロトコルはのちに独立した財団へ寄贈され、そのセキュリティ上の性質は独立した分析の対象となった。この2つの展開はいずれも [[DefinedTerm/model-context-protocol]] で扱われている。
