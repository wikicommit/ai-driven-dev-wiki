「Introducing Codex」は、[[Organization/openai]] が 2025年5月16日に公開した、Release と Product のタグが付されたローンチ記事であり、[[SoftwareApplication/codex]] をリサーチプレビューとして——「codex-1 を基盤とする、多数のタスクを並行して処理できるクラウドベースのソフトウェアエンジニアリングエージェント」として——発表するものである。現在この記事の冒頭には内容が古い旨の告知が置かれ、読者は現行の Codex 製品ページと ChatGPT Work へ案内される。また 2025年6月3日付の更新も付されており、Codex が ChatGPT Plus ユーザーにも提供されるようになったこと、そしてタスク実行中に Codex へインターネットアクセスを与えられるようになったことが記録されている。

## 要点

- **何をするのか。** 機能の実装、コードベースについての質問への回答、バグの修正、そしてレビュー用のプルリクエストの提案であり、各タスクはユーザーのリポジトリがあらかじめ読み込まれた専用のクラウドサンドボックス環境で実行される。
- **モデル。** `codex-1` は、OpenAI o3 をソフトウェアエンジニアリング向けに最適化したバージョンだと説明されている。多様な環境における現実のコーディングタスクで強化学習によって訓練されており、人間のスタイルとプルリクエストの慣習に沿ったコードを生成すること、指示を正確に守ること、そしてテストが通るまで反復的に実行することを狙いとしている。
- **インタラクションのモデル。** ChatGPT のサイドバーからアクセスし、**Code** でタスクを割り当て、**Ask** でコードベースについて質問する。各タスクは隔離された環境で独立に処理され、そこでエージェントはファイルを読み書きし、テストハーネス、リンター、型チェッカーを含むコマンドを実行する。所要時間はおおむね1分から30分で、進行状況はリアルタイムに観察できる。
- **設計目標としての検証可能性。** 完了時にエージェントは自身の環境で変更をコミットし、「ターミナルログとテスト出力の引用を通じて、自らの行動の検証可能な証拠」を提供するため、各ステップを追跡できる。記事は、ユーザーが引用、ターミナルログ、テスト結果によって作業を確認できること、そして不確かなときやテストが失敗したときにはエージェントが問題を明示的に伝えることを述べる一方で、「統合と実行の前に、エージェントが生成したすべてのコードをユーザーが手作業でレビューし検証することは依然として不可欠である」と念を押している。
- **[[DefinedTerm/agents-md]] によるリポジトリの案内。** これは「README.md に類する」テキストファイルとして説明され、コードベースをどう辿るか、テストにどのコマンドを実行するか、プロジェクトの標準的な作法にどう従うかを Codex に伝えるものだとされる。記事はさらに、人間の開発者と同じように Codex のエージェントも「整備された開発環境、信頼できるテスト構成、明確なドキュメントが与えられたときに最も良く働く」と付け加えつつ、`codex-1` はそれらがなくても評価で高い性能を示すと主張している。
- **サンドボックス化。** エージェントは、実行中はインターネットアクセスを無効化した安全な隔離クラウドコンテナの中で完全に動作し、GitHub リポジトリ経由で提供されたコードと、ユーザーのセットアップスクリプトで事前インストールされた依存関係だけに限定され、外部のウェブサイト、API、サービスにはアクセスできなかった。
- **不正利用の防止。** OpenAI は、正当な作業を支援しつつ、悪意あるソフトウェアの開発を狙った要求は識別して的確に拒否するよう Codex を訓練したと述べ、低レイヤのカーネル開発のような有益な用途との緊張関係があることを明示的に認めたうえで、これらの評価を反映した o3 システムカードの補遺を公開したとしている。
- **OpenAI 社内での初期利用。** 記事は、OpenAI のエンジニアが Codex を最も多く使っているのは、リファクタリング、リネーム、テストの作成といった、繰り返しが多く範囲の明確なタスクを手放すためだと報告している。あわせて機能のスキャフォールディング、コンポーネントの結線、バグ修正、ドキュメントの草稿にも使われており、オンコールの課題のトリアージ、一日の始めのタスク計画、バックグラウンド作業の委譲を行っているチームもあるという。
- **提供開始時の提供範囲と価格。** ChatGPT Pro、Enterprise、Business のユーザーに世界規模で順次展開し、Plus と Edu も近日提供とされた。当初は追加費用なしで十分な利用枠が与えられ、その後はレート制限付きのアクセスとオンデマンド購入に移行する。`codex-mini-latest` は Responses API で入力 100万トークンあたり 1.50 ドル、出力 100万トークンあたり 6 ドルの価格で、プロンプトキャッシュによる 75% の割引が設定された。
- **明記された制約。** フロントエンド作業のための画像入力がないこと、タスクの途中でエージェントを軌道修正できないこと、そしてリモートのエージェントへ委譲することは対話的な編集よりも時間がかかるという指摘である。

## 背景

記事はあわせて [[SoftwareApplication/codex-cli]] の変更も発表している。OpenAI によれば、これはその前月にターミナル上で動作する軽量なオープンソースのコーディングエージェントとして公開したものである。変更点は、o4-mini から派生した `codex-1` の小型版を CLI のデフォルトモデルとして、また API では `codex-mini-latest` として利用可能にしたこと、手動での API トークン設定に代わる ChatGPT アカウントでのサインイン、そして Plus と Pro のユーザー向けの期間限定の無料 API クレジットである。

将来を見通した節は、報告ではなく予測であり、実際そのように読める。OpenAI は、AI ツールとのペアリングは「急速に業界の常識になった」としたうえで、「ChatGPT の Codex が導入した非同期のマルチエージェントなワークフローが、エンジニアが高品質なコードを生み出す事実上の方法になる」と信じていると書く。そして、リアルタイムのペアリングとタスクの委譲という2つのモードは、最終的には IDE や日常のツールをまたいだ一つのワークフローへ収束するだろうとしている。名指しされたロードマップの項目は、タスク途中での指示、実装方針についての協働、進捗の能動的な報告、そして Codex CLI、ChatGPT デスクトップ、課題トラッカー、CI システムからのタスク割り当てである。締めくくりでは、エージェントの広範な採用が開発者のワークフローとスキル形成に何をもたらすのかを理解するため、OpenAI がパートナーと協働していることに触れている。

付録では `codex-1` のシステムメッセージが公開されている。OpenAI がこれを示すのは、開発者がモデルの既定の振る舞いを理解し、それに合わせて調整できるようにするためであり、その例として、システムメッセージは AGENTS.md ファイルに記載されたすべてのテストを実行するよう Codex に促しているが、時間の限られたユーザーはそれを省くよう指示できる、と挙げられている。
