*Introducing Codex* は、[[SoftwareApplication/openai-codex]] のリサーチプレビューについての OpenAI の発表であり、2025 年 5 月 16 日に公開され、まず ChatGPT の Pro、Enterprise、Business のユーザーに提供された。記事は Codex を、多数のタスクを並行して処理できるクラウドベースのソフトウェアエンジニアリングエージェントとして提示している。機能の作成、コードベースに関する質問への回答、バグの修正、プルリクエストの提案を行い、各タスクはユーザーのリポジトリがあらかじめ読み込まれた独自のクラウドサンドボックスで実行される。

記事は、これが完成品ではなく初期の反復的なリリースであることを明言しており、ここで読んだ版のページには、ローンチ記事の内容が古くなっていることを告げ、現在の Codex の製品ページへ読者を案内する後日の告知が掲載されている。2025 年 6 月 3 日付の更新では、Codex が ChatGPT Plus のユーザーにも利用可能になったこと、そしてタスク実行中のインターネットアクセスが有効化されつつあることが記録されている。

## 要点

- Codex は codex-1 によって動いている。codex-1 は、ソフトウェアエンジニアリング向けに最適化された OpenAI o3 の一版と説明されており、現実のコーディングタスクで強化学習により訓練されている。そのため、人間のスタイルや PR の好みに近いコードを生成し、指示に正確に従い、テストが通るまで反復できる。
- 各タスクは隔離された環境で独立して処理され、Codex はそこでファイルの読み取りと編集、そしてテストハーネス、リンター、型チェッカーを含むコマンドの実行を行える。所要時間は通常 1〜30 分である。
- 検証可能性は意図的な設計上の選択として提示されている。Codex はターミナルのログとテストの出力を引用するので各ステップをたどることができ、不確実性やテストの失敗を明示的に伝える。OpenAI は、エージェントが生成したすべてのコードを、統合と実行の前にユーザーが手動でレビューし検証することが引き続き不可欠だと述べている。
- Codex はリポジトリ内の [[DefinedTerm/agents-md]] ファイルによって導くことができるが、OpenAI は、codex-1 がそうしたファイルやカスタムのスキャフォールディングがなくても、コーディングの評価や社内のベンチマークで高い性能を示したと報告している。
- ローンチ時点ではエージェントはインターネットアクセスを無効にした状態で動作し、接続された GitHub リポジトリ内のコードと、ユーザーが用意したセットアップスクリプトで事前にインストールされた依存関係に限定されていた。OpenAI は別途、これはローンチ時の構成のみを説明したものだと注記している。
- 悪用について OpenAI は、Codex が悪意のあるソフトウェアの開発を狙ったリクエストを識別して的確に拒否しつつ、低レベルのカーネルエンジニアリングのように類似の技術を用いる正当な作業は引き続き支援するよう訓練されたこと、そしてそうした境界を強化するためにポリシーの枠組みと安全性の評価を強化したことを述べている。
- OpenAI は、自社のエンジニアが Codex を主に反復的で範囲のはっきりしたタスク（リファクタリング、名前の変更、テストの作成）の肩代わりに使っていると報告し、リリース前に協力した少数の外部テスターのグループから 4 社の名前を挙げている。それらの話は独立に報告されたものではなく、OpenAI が伝えたものである。
- そうした初期のテスターから学んだことに基づき、OpenAI は、範囲のはっきりしたタスクを複数のエージェントに同時に割り当て、さまざまな種類のタスクやプロンプトを試してみることを勧めている。
- クラウド製品と並んで、o4-mini から派生した codex-1 の小型版を、Codex CLI の新しいデフォルトモデルとして、また API では `codex-mini-latest` として発表しており、低レイテンシのコードに関する Q&A と編集に最適化されている。

## 背景

締めくくりの議論は製品についてではなく、業界の向かう先についてである。OpenAI は、AI ツールとのペアリングは急速に業界の標準になったと書く一方で、Codex が ChatGPT に導入する非同期のマルチエージェントのワークフローが、エンジニアが高品質なコードを生み出す事実上の標準的な方法になり、リアルタイムのペアリングとタスクの委任はやがて 1 つのワークフローに収束すると予測している。記事は当面受け入れている制約（フロントエンドの作業のための画像入力がないこと、タスクの途中でエージェントの軌道を修正する手段がないこと、リモートのエージェントに委任することに伴うレイテンシ）を挙げ、タスクの途中でのガイダンス、実装戦略についての協働、そして能動的な進捗報告を計画していると述べている。これはベンダーによる自社の製品カテゴリーについての予測であり、独立した評価ではない。

付録では、開発者がモデルのデフォルトの振る舞いを理解できるよう codex-1 のシステムメッセージが公開されており、その多くは、エージェントが従うルールとして述べられた AGENTS.md の契約である。そうしたファイルのスコープはそれが置かれたディレクトリを根とするディレクトリツリーであること、衝突した場合にはより深くネストしたファイルが優先されること、システム、開発者、ユーザーからの直接の指示はそれらより優先されること、そしてファイルが指定するプログラム的なチェックはすべてのコード変更の後に実行しなければならないことである。残りの部分は、git の規約と、最終的な応答の中でファイルパスやターミナルの出力を参照するための引用形式を扱っている。
