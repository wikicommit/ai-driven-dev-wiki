この記事は、Google が 12 月にコンテキスト駆動開発をターミナルにもたらすために導入した Gemini CLI 拡張機能である [[SoftwareApplication/conductor-gemini-cli-extension]] に、Automated Review 機能が加わったことを発表するものである。記事が述べる元の拡張機能の位置づけは、プロジェクトについての認識を一時的なチャットログから、永続的でバージョン管理された Markdown ファイルへと移すというものであり、記事はそれが、開発者が構築する前に計画するのを助けたと評価している。

新機能の目的は、Conductor を計画と実行の先の検証にまで広げることで、AI 支援エンジニアリングをより安全で予測可能なものにすることだとされている。コーディングエージェントがタスクを完了すると、Conductor は、コード品質と、開発者が定義したガイドラインへの準拠についての実装後レポートを生成できる。

記事の締めくくりの議論は、この機能が強制しようとする分業についてのものである。このレベルの詳細さは「『エージェント型』の開発が『監督なし』の開発を意味しないことを保証する」ものであり、AI が労働を提供し、開発者が自動化された検証に裏付けられた高レベルのアーキテクチャ上の監督を提供するワークフローを生み出す、と記事は述べる。

## 要点

- Automated Review は、開発ライフサイクルに「検証」ステップを加えるものとして提示されており、実装中ではなく、コーディングエージェントが作業を終えた後に実行される。
- レポートの機能として、コードレビュー、計画への準拠、ガイドラインの強制、テストスイートによる検証、基本的なセキュリティレビューの 5 つが挙げられている。
- コードレビューの機能は、新たに生成されたファイルに対する深い静的解析とロジック解析であり、構文を超えて、非同期ブロックにおける競合状態、潜在的なヌルポインタのリスク、ランタイム例外につながりうるロジックエラーといった複雑な問題を先回りして指摘すると説明されている。記事はこれらを網羅的な一覧としてではなく例として挙げている。
- 計画への準拠は、新しいコードをプロジェクトの `plan.md` と `spec.md` に照らしてチェックし、ロードマップのすべてのフェーズが扱われ、中核的な要件が抜け落ちていないことを確認するものと説明されている。
- テストスイートによる検証は、手動での実行に頼るのではなく、関連するユニットテストと統合テストをレビューのワークフローの中で実行し、その結果とカバレッジのデータを最終レポートに取り込むものと説明されている。
- セキュリティレビューは、コードがマージされる前に重大な脆弱性をスキャンし、ハードコードされた API キー、個人を特定できる情報の漏洩の可能性、アプリケーションをインジェクション攻撃にさらしうる安全でない入力処理といった高リスクの問題を自動的に指摘するものと説明されている。これらもまた例として挙げられている。記事はこれを包括的なものではなく「基本的な」セキュリティレビューと呼んでいる。
- 指摘事項は重大度によって High、Medium、Low に分類され、正確なファイルパスが付される。それらを修正するためのトラックを Conductor の中で開始できる。
- これらは Google が自社の拡張機能について述べた主張であり、計測された結果ではなく機能として述べられている。記事は 5 つのチェックのいずれについても、評価、ベンチマーク、エラー率を報告していない。

## 背景

記事はこの機能を新製品としてではなく、12 月の Conductor の導入に続くものとして位置づけ、この拡張機能を「急速に進化している」と説明している。このリリースのバージョン番号は述べられておらず、Automated Review 機能の提供開始日についても、記事自体の公開日以上のものは示されていない。

記事が掲げる目標は、AI による開発を「安全で、予測可能で、アーキテクチャ的に健全な」ものにすることであり、最後にインストール手順を示して終わる。拡張機能のリポジトリは <https://github.com/gemini-cli-extensions/conductor> であり、コマンドは `gemini extensions install https://github.com/gemini-cli-extensions/conductor` である。
