GitHub のオープンソースプログラム担当ディレクターが書いた GitHub ブログの記事で、2026 年 2 月 12 日に公開され、翌日に更新された。Usenet 時代の用語「終わらない九月」（Eternal September）を借りて、オープンソースの現状を描いている（[[DefinedTerm/eternal-september]] を参照）。コラボレーションは信頼の上に成り立っており、その信頼はかつて貢献に伴う摩擦によって守られていた。生成 AI はその摩擦の多くを取り除いたため、プルリクエスト、イシュー、セキュリティ報告が数秒で生成できるようになった一方、それをレビューするコストは下がっていない。

記事は、ほとんどのコントリビューターは善意で行動しており、雑多なインバウンドは新しいものではないと慎重に述べている。記事が指摘する問題は、メンテナーのレビュー能力よりも速く増えていく量である。続いて、[[Organization/github]] がメンテナー向けにリリースしたものと検討中のものを挙げ、コミュニティが自ら構築しているアプローチを概観し、答えは壁ではなく、より良いシグナルとツールだと論じている。

## 要点

- 摩擦はバランスの問題として捉えられている。多すぎれば人やアイデアを締め出し、少なすぎればオープンソースが依存する信頼に負担をかける。プルリクエストと「Good First Issues」は摩擦を下げたものであり、著者はそれを良いことだとしている。
- 生成 AI によってコントリビューションを作るコストは下がったが、レビューするコストは下がっていない。量がレビュー能力を上回ると、善意による提出でさえメンテナーを圧倒しうる。
- 著者は、低品質な、あるいは「AI スロップ」のコントリビューションは新しい現象ではないと論じ、Linux カーネルの信頼の網（web of trust）の考え方と Developer Certificate of Origin、Mozilla や GNOME の正式なトリアージの仕組み、そしてかつての自動スキャナーによる報告の波を挙げている。
- 記事が指摘する不均衡は利益の不均衡である。コントリビューターはクレジットや CVE、知名度を得るかもしれないが、メンテナーが得るのは保守の負担である。AI 生成のセキュリティ報告が急増した後に curl がバグバウンティを終了したこと、Ghostty が招待制のコントリビューションに移行したこと、AI 生成のコントリビューションに関する明示的なルールを採用するプロジェクトが現れていることを、合理的な対応として挙げている。
- GitHub がリリース済みだとする機能には、プルリクエストの作成をコラボレーターに限定したりプルリクエストを無効にしたりするリポジトリ単位の制御、イシューへのコメントのピン留め、「+1」コメントを控えるよう促すバナー、プルリクエストの差分表示とイシュー間の移動の高速化、一時的なインタラクション制限がある。UI からのプルリクエストの削除は近日提供予定とされている。
- GitHub がメンテナーとともに検討中だとする方向性は、プルリクエストを開く前にリンクされたイシューを必須にするといった基準ベースのゲーティングと、自動トリアージを用いて `CONTRIBUTING.md` などプロジェクト独自のガイドラインに照らしてコントリビューションを確認しうる、改良されたトリアージツールである。記事は、これらは判断を置き換えるのではなく支援するべきものであり、制限は善意の初回コントリビューターに最も重くのしかかりうるので、これらの制御は任意であると述べている。
- 挙げられているコミュニティの対応には、招待制のワークフロー、コントリビューターのトリアージや評判スコアリングのための独自の GitHub Actions、信頼管理プロジェクトの [[SoftwareApplication/vouch]]、そして Python や Kubernetes などのコミュニティにおける教育やオンボーディングの取り組みがある。
- 著者は、ブロックや禁止だけを築くこと（「バザールではなく要塞」）に反対し、GitHub はイシューのトリアージやドキュメントといったコード以外の貢献を信頼のシグナルとして可視化したいと述べ、WordPress の「props」によるクレジットをモデルとして挙げている。

## 背景

この記事はプラットフォームベンダーとしての GitHub の立場から書かれており、GitHub 自身のプロダクトロードマップを説明している。リリース済みの機能や検討中の方向性の一覧は、GitHub による自らの取り組みの説明である。記事はメンテナーのフィードバックを集めるためにコミュニティディスカッションを開いている。記事が触れている AI 生成のコントリビューションに関する明示的なルールは、[[DefinedTerm/ai-contribution-policy]] で扱われている。
