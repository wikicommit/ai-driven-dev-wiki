Habr の Yandex Cloud & Yandex Infrastructure 企業ブログに掲載されたこの記事は、[[SoftwareApplication/vibecraft]] を紹介するものである。開発者ツール SourceCraft を手がけるチームに属する著者は、汎用コーディングエージェントで行われる [[DefinedTerm/vibe-coding]] の欠点から話を始める。エージェントは自信満々に何時間もかけてコードを書いてはテストし、その挙げ句に、2 ページしかないペットプロジェクトを可観測性付きの Kubernetes クラスターにデプロイしようと提案してくる。

記事の主張は次のとおりである。現在のコーディングアシスタントは、プロジェクトを理解し、結果を確認でき、次のステップを言葉にできる有能な開発者を前提としている。そして、コードを書くことはプロダクトを世に出すことの一部にすぎず、誰かがサーバーを借り、環境、データベース、ドメインを設定し、稼働させ続けなければならない。技術的な素養のない人はそうした作業が存在することすら知らないかもしれず、そのためアシスタントとのやり取りは、記事のたとえを借りれば、魔人（ジーニー）との対話のようになる。願いは正確に、しかも自明でない多くの条件を付けて述べなければならず、さもなければ結果は依頼どおりでありながら実際には役に立たない。VibeCraft はこれに対するチームの答えとして示されている。ユーザーはプロダクトに集中し、デプロイはプラットフォームが引き受ける。

## 要点

- チームは 2026 年初頭に、マーケター、経理担当者、アナリストといったプログラミング以外の分野の人々が自分のプロダクトを作れるところまで技術が到達したと結論づけた。これが VibeCraft の出発点とされている。
- VibeCraft は、プログラマーが Claude や Codex などのエージェントを使うやり方と対比されている。プログラマーは、まずアーキテクチャ、詳細な計画、仕様、テストのルールを練り上げ、それから複数のエージェントに長時間反復させる。記事はこのやり方を経験豊富な開発者向けのものと位置づけ、VibeCraft のやり方を、アイデアから動くプロトタイプまでの短いループを反復的に磨いていくものと説明している。
- 内部は 2 エージェントのシステムである。マネージャーエージェントはユーザーと対話し、依頼を分割し、確認のための質問を行い、編集可能な計画を提示する。プログラマーエージェントはコードを書き、環境を構築し、実行して動作を確認する。
- 記事は、言語モデルを物語として捉える説明によってエージェントの振る舞いを説明している。言語モデルはデータの中で最も尤もらしい物語を続けるため、限界を認めるよりも、できないことをツールを組み合わせて試み続ける。また、文字どおりの指示よりも最も目立つシナリオに従う。したがってチームが掲げる目標は、望ましい物語がすでにコンテキストの中に存在するようにコンテキストを構築することである。
- 具体例として挙げられているのはマネージャーエージェントである。大量のバックログを把握できるようにファイルを読む能力を与えたところ、ファイルを編集したがるようにもなった。お前はマネージャーだと告げるプロンプトでは止められなかった。事前学習された「自分はプログラマーだ」という物語のほうが指示よりも重いからである。解決策は、「ファイル書き込み」スキルを与え、それが常に、お前はマネージャーであり、そのタスクは開発者に割り当てるべきだと告げるエラーを返すようにすることだった。
- 回復の仕組みとしては、チャットを作り直して新しいエージェントに作業の状態を再構築させることと、支離滅裂な出力を打ち切って生成をやり直すループ検出器がある。
- 生成されるアプリケーションは Node.js によるフルスタック TypeScript である。人気のあるスタックのほうがモデルの学習データに多く含まれているため選ばれた。ストレージにはサーバーレスの YDB を使い、データベースサーバーを運用する必要がないようにしている。
- 記事によれば、シンプルなプロトタイプは 7〜10 分、タスクリストのサービスは 20〜30 分でできあがり、最初のメッセージから動作するタスクトラッカーまではおよそ 40 分だった。

## 背景

これはベンダーが自社製品について述べたものであり、所要時間や設計の根拠はチーム自身の説明である。著者はこの分野を、まだ時の試練を経たレシピのない新しい分野だと述べ、フィードバックを呼びかけている。
