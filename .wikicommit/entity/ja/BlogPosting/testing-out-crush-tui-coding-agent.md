この記事で Graham Helton は、[[Organization/charm]] がターミナルで動作するものとしてリリースした AI コーディングエージェント [[SoftwareApplication/crush]] を試している。題材は、自身の個人用静的サイトに Open Graph 画像の生成機能を追加することで、これは各記事のフロントマターをプレスリリース風の HTML ページとしてレンダリングし、PNG として保存するツールである。彼がこのタスクを選んだのは、以前に他のツールで同じことをしたことがあり、リスクが低く、必要なメタデータがすでに各記事の YAML フロントマターに含まれていたからである。彼は、大きなつまずきもなく機能を完成させ、サイトのビルドスクリプトに組み込めたと報告している。

この記事は、1 人の開発者が 1 つのプロジェクトで得た一次的な体験談であり、その結論も彼自身のものとして述べられている。彼はこのツールの使い心地を気に入ったものの、API 利用にかかった費用を理由に、GPU を自前でホストできるようになるまでは日常的なコーディングには使わないとしている。

## 要点

- 著者は、Crush が Charm に期待していたとおりのものだと感じた。すなわち、Charm らしい見た目と操作感を備えた TUI のコーディングエージェントであり、[[SoftwareApplication/claude-code]] を使ったことがある人には馴染みやすいものである。
- 彼は neovim の中の専用のサイドペインで Crush を動かした。これにより、Crush が何をしているかを見ながらその変更を許可したり拒否したりでき、手作業で作業するときにはすぐに閉じることもできた。一方で、neovim のウィンドウ内で動かすと表示上のバグがいくつかあったと報告している。
- 差分の UI は最初は違和感があったが、比較的ピンポイントな編集を行うプロンプトであれば十分使えると感じた。
- 彼は、Crush の変更ファイルの一覧、使用中のモデルとそれにかかるコストの表示、そして `ctrl-p` のオプション、とりわけモデルの素早い切り替えとセッションの要約を、評価した機能として挙げている。
- 彼の見方では、TUI 以外で Crush の最も重要な点は、モデルに依存せず、使用するモデルをユーザーが選べることである。彼はローカルでホストしたモデルで試してみたいと考えており、これは Claude Code のようなツールでは不可能だと述べている。
- 彼の報告によれば、この機能の実装には API 料金として 23.04 ドルかかり、重い作業には主に Sonnet 4 を、ちょっとした編集やドキュメントの更新には Gemini Flash を使った。所要時間は約 45 分で、手作業なら 2 日ほどかけて数時間かかっただろうと彼は見積もっている。
- 彼は、[[SoftwareApplication/cursor]] のようなツールには、API 料金を直接支払う場合と比べて 2 つの価格面での優位性があると主張する。キャッシュを含め、モデルに送る内容を徹底的に最適化していること、そしてモデルプロバイダーとの提携による規模の経済である。そのため、この 1 つの機能に API 料金として支払ったのとほぼ同じ額で、Cursor のサブスクリプションなら、より大きなモデルに対して非常に多くのプロンプトを送れるという。これは彼自身の評価であり、何らかの計測ではなく、自分の利用状況ダッシュボードに基づくものである。
- それでも彼は、比較的単純なコードベースについての質問に答えたり、ホームラボにちょっとした変更を加えたりといった、高価なモデルを必要としない小さなタスクには Crush を使うつもりだとしている。

## 背景

著者は、Crush を試したかった理由として、Cursor の VS Code 中心の UI を使う体験がどうにも気が進まないことを挙げており、また自分のサイトは効率のためではなく個人的な楽しみのためのものだと書いている。
