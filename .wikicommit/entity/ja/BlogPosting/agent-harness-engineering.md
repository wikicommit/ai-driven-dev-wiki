この記事は「エージェント = モデル + ハーネス」（Viv Trivedy によるものとされる定式化）であり、有能なコーディングエージェントを構築するうえでのてこの大部分は、モデルの選択ではなくハーネスにあると論じる。記事はハーネスを、モデルに状態、ツール実行、フィードバックループ、強制可能な制約を与える、モデルの周囲にあるあらゆるコード、設定、実行ロジックと定義し、その構成要素を概観している。ファイルシステムと Git、bash とコード実行、サンドボックス、メモリと検索、コンテキストロットに対抗する手法、長期タスクの実行パターン、フック、そして `AGENTS.md` である。

記事の中心的な主張は、モデルにできることと、ユーザーが目にするモデルの働きとの間にある今日のギャップは、主としてモデルのギャップではなくハーネスのギャップだというものである。記事はハーネスの各構成要素を、基盤となるモデルがまだ単独ではできない何かについての前提を符号化したものとして扱う。そのため、モデルがその特定の点で改善されれば構成要素は不要になり、逆にモデルが新しい能力を獲得すれば、それに応じた新しい足場が必要になる。

## 要点

- 「エージェント = モデル + ハーネス。あなたがモデルでないなら、あなたはハーネスだ」。記事は Viv Trivedy によるものとするこの定式化を用いて、モデルは稼働中のエージェントへの入力の 1 つにすぎず、それ以外（プロンプト、ツール、コンテキストのポリシー、フック、サンドボックス、サブエージェント、フィードバックループ、回復経路）がハーネスであると論じる。
- 記事の報告によれば、Terminal Bench 2.0 において、同じモデルが Claude Code 自身のハーネス内で動作した場合はカスタムのハーネス内で動作した場合よりはるかに低いスコアとなり、また Viv Trivedy のチームはモデルを変えずハーネスだけを変えることで、あるコーディングエージェントを Top 30 から Top 5 に引き上げた。
- ハーネスエンジニアリングは、エージェントのあらゆる誤りを一度きりのものではなく恒久的なシグナルとして扱うことだと説明されている。失敗は `AGENTS.md` のルール、フック、またはレビュアー役のサブエージェントのチェックとして符号化され、ルールが削除されるのは、より有能なモデルがそれを不要にした場合に限られる。
- コンテキストロットに対抗する手法として 3 つが挙げられている。コンパクション（ウィンドウが埋まるにつれて古いコンテキストを要約し退避させる）、ツール呼び出しの退避（大きなツール出力は先頭と末尾だけをコンテキストに残し、残りはファイルシステムに書き出す）、そして段階的開示を伴うスキル（タスクが必要とする場合にのみ指示とツールを読み込む）である。
- 記事は Ralph Loop のパターンを説明している。フックがモデルの終了の試みを捕捉し、元のプロンプトを新しいコンテキストウィンドウに再投入する。そのため各イテレーションはまっさらな状態から始まるが、前のイテレーションの状態をファイルシステム経由で読み取ることができ、単一セッションのエージェントがマルチセッションのエージェントに変わる。
- 生成と評価を別々のエージェントに分離すると自己評価よりも優れた結果が出るという主張について、Anthropic 自身が公開しているハーネス設計の取り組みを引用している。その理由は、モデルは自身の仕事を、独立した評価者がつけるよりも一貫して甘く採点するからである。
- 「Harness-as-a-Service」（Viv Trivedy によるものとされる）を、LLM の補完 API の上に構築することから、Claude Agent SDK、Codex SDK、OpenAI Agents SDK といったハーネス API の上に構築することへの移行として位置づけている。これらの API は、ループ、ツール、コンテキスト管理、フック、サンドボックスのプリミティブを、一から構築するのではなくカスタマイズするランタイムとして提供する。
- 記事は、モデルが改善されてもハーネスは縮小せず、移動するのだと論じる。ある箇所で得られた能力（たとえば Opus 4.6 が不安に駆られた早すぎる切り上げを減らしたこと）は一部の足場を不要にする一方、新たに手が届くようになったタスクはそれ自身の新しい足場を必要とする。

## 背景

記事は、同じ転換について複数の人々が独立に示した枠組みをまとめたものとして自らを位置づけている。Viv Trivedy の「Anatomy of an Agent Harness」という文章（「ハーネスエンジニアリング」という用語を生み出したとされる）、エージェントの失敗を設定の問題（「スキルの問題」）として捉える HumanLayer の枠組み、長時間稼働する作業のためのハーネス設計について Anthropic 自身が公開しているエンジニアリングのガイダンス、そしてそれがユーザーの視点からどう見えるかについての Birgitta Böckeler の説明である。著者の Addy Osmani は、Terminal Bench や「スキルの問題」の観察を含むこの総合を、自身の独自の研究成果としてではなく、これらの他の情報源から引き出したものとして提示している。
