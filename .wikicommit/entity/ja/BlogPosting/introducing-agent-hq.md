この記事は、GitHub Universe 2025 で行われた、GitHub 自身による Agent HQ と呼ぶものの発表である。その立場は、コーディングエージェントは開発プラットフォームに後付けされるのではなく、開発者がすでに使っているフローにネイティブなものとされるべきだというものである。記事が冒頭で展開する議論は、現在の AI の状況では能力がばらばらのツールやインターフェースに分断されており、GitHub は歴史的にこうした形の問題に取り組んできた（Git を使いやすくし、プルリクエストによってコードレビューを体系化し、Actions によってデプロイを自動化した）というものである。

具体的な約束は、Anthropic、OpenAI、Google、Cognition、xAI のコーディングエージェントが、それぞれ独自の窓口を通じて利用されるのではなく、有料の GitHub Copilot サブスクリプションの一部として、今後数か月のうちに GitHub 内で直接利用できるようになるというものである。その周囲に、それらを指揮するためのコマンドセンター、エージェントの振る舞いを計画しカスタマイズするためのエディター側の機能、そしてエージェントのアクセスを統制するための管理機能が配置される。この記事は GitHub 自身の視点で書かれた製品発表であるため、プラットフォームの方向性に関する主張は、出荷済みの振る舞いについての独立した記述ではなく、GitHub が表明した意図である。

## 要点

- GitHub は、Anthropic、OpenAI、Google、Cognition、xAI のコーディングエージェントが、発表に続く数か月のうちに、有料の Copilot サブスクリプションの一部として GitHub 内で直接利用できるようになると述べている。これはロードマップについての GitHub 自身の将来予測である。
- Agent HQ が変え*ない*ものは、変えるものと同じくらい重要なものとして提示されている。プリミティブは Git、プルリクエスト、Issue のままであり、計算資源は GitHub Actions またはセルフホストランナーのままである。
- 発表の週から、Copilot Pro+ のユーザーは VS Code Insiders で [[SoftwareApplication/openai-codex]] を使えるようになった。GitHub はこれを、独自のネイティブな窓口を越えてエディターにまで広がった最初のパートナーエージェントだと説明している。
- Mission control は、単一の行き先ではなく、GitHub、VS Code、モバイル、CLI にまたがる一貫したインターフェースとして説明されており、開発者はそこから複数のエージェントに並行して作業を割り当て、その進捗を追跡できる。
- GitHub はエージェントのアイデンティティを、人間の共同作業者のそれと同じ種類のアクセス制御の問題として捉えている。どのエージェントがタスクを構築しているかを制御するためのアイデンティティ機能を備え、アクセスとポリシーはチームの他の開発者と同じように管理される。
- 発表と同時に VS Code に導入された Plan Mode では、コードが書かれる前に Copilot が明確化のための質問をして段階的なアプローチを組み立てる。GitHub が述べる根拠は、コンテキストを事前に与えることで、ギャップ、欠けている決定、プロジェクトの不備が早い段階で表面化するというものである。
- VS Code のカスタムエージェントは [[DefinedTerm/agents-md]] ファイルによって設定される。GitHub はこれを、「このロガーを優先する」や「すべてのハンドラーにテーブル駆動テストを使う」といったルールやガードレールを収めた、ソース管理される文書だと説明しており、振る舞いを毎回プロンプトで指示し直す必要がなくなる。
- エージェント型の環境におけるコードレビューについて GitHub が述べる問題は、「LGTM」が必ずしもコードが健全であることを意味しないという点である。レビューを通過しながらも、コードベースを長期的な技術的負債へと劣化させていることがありうる。当時パブリックプレビューだった GitHub Code Quality は、これに対する組織全体の可視化とレポートとして提供されている。
- Copilot コーディングエージェント自身のワークフローの中にコードレビューのステップが追加され、[[SoftwareApplication/github-copilot-coding-agent]] は人間がコードを見る前に一次レビューを受けて問題に対処するようになった。
- コントロールプレーンは、エンタープライズの管理者向けのエージェントガバナンスレイヤーとして提示されている。セキュリティポリシー、監査ログ、アクセス管理を一か所で扱い、どのエージェントを許可するか、それらがどのモデルに到達できるかも含まれる。

## 背景

この記事はベンダーの発表であり、実際にそのように読める。締めくくりの節では、AI ツールはこれまでコンテキストの切り替え、子守り、サブスクリプションを増やすことを意味してきたと論じ、Agent HQ をそれに対抗するものとして位置づけている。能力に関する主張は GitHub 自身のものであり、そのいくつかは利用可能なものではなく今後提供されるものとして述べられている。

パートナー企業からの引用は、本文ではなく画像のキャプションとして記事に掲載されている。OpenAI、Anthropic、Google Labs のプロダクトリードがそれぞれ統合を支持しており、Anthropic のものはエージェントが「他の共同作業者と同じようにチームと並んで」働くと表現している。これらはパートナーが発表のために GitHub に提供したものであり、独立した評価ではない。

単一のコントロールサーフェスから指揮される、並行して働く専門化されたエージェントの群れという記事の構図は、[[DefinedTerm/factory-model]] や [[DefinedTerm/conductor-and-orchestrator-modes]] と同じ形をしているが、記事自体はそれらの用語を使っていない。
