[[SoftwareApplication/google-antigravity]] を紹介する Google の発表記事であり、記事はこれを単なるエディタではなくエージェント型開発プラットフォームだと説明している。記事の枠組みとなる主張は、前の世代のツールは開発者がコードをより速く書くのを助けたが、次の世代のツールはコードをオーケストレーションするのを助ける必要がある、というものである。そのためこのプラットフォームは、記事の言う、より高次のタスク指向のレベルで作業するように設計されている。

記事の中心的な設計上の主張は、エージェントはサイドバーのチャットボットであるべきではなく、専用の空間を持つべきだというものである。記事の言葉では、エージェントは「サイドバーの単なるチャットボットであるべきではない」。そのために 2 つのサーフェスが導入されている。同期的な作業のための、馴染みのある AI 搭載エディタと、複数のエージェントを起動し、それらがワークスペースをまたいで非同期に作業する様子を観察するための Manager サーフェスである。2 つ目の主張は検証に関するものである。作業を委任するには信頼が必要であり、生のツール呼び出しをスクロールして眺めても信頼は築けない。記事はこれに対して、エージェントがレビューのために生成する具体的な成果物である Artifacts で応えている。

## 要点

- 記事はエージェント型開発を、コードをより速く書くことからコードをオーケストレーションすることへの転換として捉え、エージェントはサイドバーの単なるチャットボットであるべきではなく、作業のための専用の空間を持つべきだという設計上の信念を述べている。
- 2 つの対話サーフェスが提供される。ハンズオンの同期的な作業のための、タブ補完とインラインコマンドを備えた Editor View と、複数のエージェントを起動し、オーケストレーションし、それらが異なるワークスペースをまたいで非同期に作業する様子を観察する Manager サーフェスである。
- エージェントは 1 つのタスクの中でエディタ、ターミナル、ブラウザをまたいで動作すると説明されている。記事の例では、エージェントが機能を実装し、ターミナルからアプリケーションを起動し、次にブラウザを操作してコンポーネントが動作することを検証する。その間、人間が同期的に介入することはない。
- 検証はログではなく Artifacts を通じて行われる。タスクリスト、実装計画、スクリーンショット、ブラウザの録画であり、記事によれば、これらによって開発者はエージェントのロジックを一目で確認できる。
- フィードバックは、ドキュメントにコメントするのと同じ要領で Artifact に直接残す。記事によれば、エージェントは実行の流れを止めることなくその入力を取り込む。
- 記事によれば、このプラットフォームは学習を中核的なプリミティブとして扱い、エージェントが有用なコンテキストやコードスニペットをナレッジベースに保存して、以後のタスクの改善に役立てられるようにしている。
- 発表時点では、プラットフォームは個人向けに無料のパブリックプレビューとして macOS、Windows、Linux で提供され、Gemini 3 Pro に加えて Anthropic の Claude Sonnet 4.5 と OpenAI の GPT-OSS をサポートしていた。これらはローンチ時点で示された条件とモデルの一覧である。

## 背景

これは Google 自身の開発者ブログに掲載された当事者による製品発表であり、プラットフォームの機能に関する主張は、独立した評価ではなくベンダー自身の説明である。記事は利用データ、ベンチマーク、ユーザー調査を報告していない。

Artifacts を通じた検証という主張は、自律的なエージェントを人間が実質的に制御し続けるための他の取り組みと同じ難しさに、エージェントが人間に読ませるものを変えることで取り組んでいる。[[DefinedTerm/human-in-the-loop]] と [[DefinedTerm/review-bottleneck]] を参照のこと。非同期の Manager サーフェスは、このプラットフォームを [[DefinedTerm/long-running-agent]] の作業と [[DefinedTerm/outer-loop]] を中心に組み立てられたツール群の中に位置づけている。
