2025 年 9 月 11 日に公開され、2026 年 1 月 14 日に更新された GitHub ブログの入門記事で、[[SoftwareApplication/github-copilot-coding-agent]] を扱う。記事はこのエージェントを、割り当てられたタスクを完了するためにバックグラウンドで独立して動作するソフトウェアエンジニアリングエージェントであり、同僚の開発者に似たものだと説明している。タスクを渡されると、GitHub Actions を基盤とするカスタマイズ可能な開発環境を立ち上げ、issue からプルリクエスト、レビューと承認に至るまで追跡できる。

記事の位置づけは、このエージェントが、バグの修正、機能の段階的な実装、リファクタリング、テストカバレッジの改善、ドキュメントの更新といった、退屈で複雑さが低〜中程度の作業を引き受けることで、開発者は自分の関心のある仕事に集中でき、しかもプルリクエストのレビューを通じて主導権を保ち続けられる、というものである。

## 要点

- エージェントにタスクを渡すには、github.com または GitHub Mobile で GitHub issue を Copilot に割り当てる、Visual Studio Code から GitHub Pull Requests 拡張機能を通じて委任する、あるいは github.com のエージェントパネルから委任する、という方法がある。IDE の Copilot Chat や、MCP に対応した任意のツールから指示することもできる。
- タスクを渡されると、エージェントは作業の追跡に用いる `[WIP]` タグ付きのドラフトのプルリクエストを開き、作業を進めながらコミットをプッシュし、主要なステップをログに記録する。完了すると、プルリクエストのタイトルと説明を更新し、開発者をタグ付けしてレビューを依頼する。
- フィードバックは、プルリクエストに `@copilot` をタグ付けしたコメントを残すことで行い、エージェントはそれを用いて反復する。
- 作業を行うために、エージェントは関連する issue、プルリクエストでの議論、カスタム指示を含むリポジトリのコンテキストを確認する。
- エージェントは、インターネットへのアクセスが制限され、リポジトリの権限も限定された、GitHub Actions 上のサンドボックス化された一時的な環境で動作する。その環境は、プロジェクトが必要とするツールや依存関係に合わせてカスタマイズできる。
- 記事が挙げる組み込みの保護は次のとおりである。エージェントは自ら作成したブランチ（`copilot/*` など）にしかプッシュできない。自身のプルリクエストを承認したりマージしたりすることはできない。GitHub Actions の CI/CD チェックは人間の承認なしには実行されない。エージェントのコミットは追跡可能性のために共同作成者付きとなる。そして既存の組織ポリシーとブランチ保護が自動的に適用される。
- 開発者が依然としてブランチを作成し、コミットメッセージを書き、プルリクエストを開き、レビューを管理する従来の IDE アシスタントと比べて、coding agent は GitHub のプルリクエストのワークフローの中で動作してそれらのステップを自動化し、すべてのステップがログに記録されてチームから見えるようになっている。
- 記事はこれをエージェントモードと区別している。coding agent は GitHub Actions 上で動作する非同期の協働者であるのに対し、エージェントモードは VS Code、JetBrains、Eclipse、Xcode などの IDE の中で開発者と同期的にペアを組む。
- Playwright と GitHub の MCP サーバーが組み込まれた状態で提供され、リポジトリの管理者はリポジトリ設定の JSON 構成を通じて他のサーバーを追加できる。エージェントのインターネットアクセスはファイアウォールによって制限されており、そのデフォルトのルールは、GitHub とのやり取りや依存関係のダウンロードに必要なホストを許可している。
