これは GitHub による [[SoftwareApplication/github-copilot-coding-agent]] の発表であり、2025 年 5 月に公開され、同月中に更新された。中心的な主張はインターフェースに関するものである。エージェントに作業を委任する方法は、チームメンバーに issue を割り当てるのとまったく同じように、GitHub の issue を Copilot に割り当てることであり、その後エージェントはバックグラウンドで作業し、成果をドラフトのプルリクエストとして届ける。

記事のもう 1 つの強調点は、エージェントへの委任がリポジトリの既存の統制を緩めることを必要とすべきではないということである。記事はデフォルトのポリシー群、すなわちブランチの制限、依頼者がエージェントのプルリクエストを自ら承認することの禁止、限定されたインターネットの許可リスト、そして人間の承認なしには実行されない CI ワークフローを示し、これらを、セキュリティ態勢を弱めることなくエージェントをチームに加えられる理由として提示している。

## 要点

- エージェントは、github.com、GitHub Mobile、GitHub CLI から 1 つ以上の GitHub issue を Copilot に割り当てることで起動される。GitHub 上や VS Code の Copilot Chat からプルリクエストを開くよう依頼することもできる。
- 割り当てられると、エージェントは目の絵文字のリアクションを付け、仮想マシンを起動し、リポジトリをクローンし、環境を構成し、GitHub のコード検索を用いた検索拡張生成によってコードベースを分析する。
- エージェントは変更を git のコミットとしてドラフトのプルリクエストにプッシュし、作業を進めながらプルリクエストの説明を更新していく。その推論と検証のステップはセッションログで確認できる。
- GitHub は、このエージェントが、十分にテストされたコードベースにおける低〜中程度の複雑さのタスク、すなわち機能の追加、バグの修正、テストの拡充、リファクタリング、ドキュメントの改善に優れていると述べている。これは範囲についての主張であって、測定結果ではない。
- [[DefinedTerm/model-context-protocol]] サーバーをリポジトリの設定で構成することで、GitHub 自身の MCP サーバーを含め、GitHub の外にあるデータや機能へのアクセスをエージェントに与えることができる。
- ビジョンモデルのサポートにより、エージェントは割り当てられた issue に添付された画像を読み取れるため、バグのスクリーンショットや機能のモックアップをタスクの一部にできる。
- 作業を終えると、エージェントは依頼者をレビューにタグ付けし、レビューコメントを自動的に拾い上げ、それに応じたコードの変更を提案する。
- 計算レイヤーとして GitHub Actions を選んだ理由として GitHub が挙げるのは規模である。2018 年に導入された Actions は世界最大の CI/CD エコシステムと説明されており、GitHub Marketplace には 25,000 を超えるアクションがあり、平日には毎日 4,000 万を超えるジョブが実行されている。
- 4 つのデフォルトのポリシーが適用される。エージェントは自ら作成したブランチにしかプッシュできない。プルリクエストを依頼した開発者はそれを承認できないため、既存の必須レビューのルールが守られる。エージェントのインターネットアクセスはカスタマイズ可能な信頼済みリストに限定される。そして GitHub Actions のワークフローは人間の承認なしには実行されない。
- 発表時点で、エージェントは Copilot Enterprise と Copilot Pro+ の顧客が利用でき、リポジトリごとにオプトインする形で、Enterprise には追加の組織ポリシーがあった。2025 年 6 月 4 日からは、モデルへのリクエスト 1 回につき 1 回のプレミアムリクエストを消費する予定とされた。

## 背景

この記事は GitHub 自身による製品発表であるため、エージェントの強みについての特徴づけはベンダーのものである。記事には発表のために提供された 2 つの顧客の声が含まれている。EY の DevEx リードは、このエージェントによって開発者はより深い作業の妨げとなる作業を割り当てられるようになると述べ、Carvana のエンジニアリング担当バイスプレジデントは、仕様を数分で本番コードに変換するものだと述べている。これらは独立に報じられたものではなく、GitHub によって伝えられたものである。

このエージェントは、記事が Project Padawan と呼ぶ社内の取り組みの延長として、また GitHub が自社製品を通じて引く一本の線上の一点として示されている。その線とは、コード補完、次の編集の提案、チャット、エージェントモード、そして今回のバックグラウンドエージェントである。
