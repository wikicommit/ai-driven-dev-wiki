記事の中でオープンソースの AI コーディングツール AutoDev の作者と自己紹介している Phodal Huang は、この年末総括を、ある中国の AI コーディングツールについて読んだ事例紹介を軸に組み立てている。その事例紹介は、行き詰まっているプログラマーをエージェントが慰め、励ますという「付加価値」にかなりの紙幅を割いていた。これに対する著者の反応は 1 つの問いである。モデルやツールが本当に十分強いのなら、なぜその体験を慰めで補う必要があるのか。問題が解決しないときにプログラマーが必要としているのは、仕事をやり遂げてくれるシステムだと著者は論じる。

記事はそのうえで、中国のエコシステムに重点を置きつつ、著者が 2025 年の AI コーディングに見た 6 つのトレンドを示す。そして、2026 年に開発者が必要としているのは「頑張って」と言ってくれるチャットボックスではなく、深夜 2 時にシステムの欠陥を見つけて黙って修正を提出してくれる「デジタルパートナー」であり、AutoDev 自身の道は「情緒的な寄り添い」に費やされていた帯域を「エンジニアリング上の確実性」に振り向けることだ、と述べて締めくくっている。

## 要点

- 中国のコーディングモデルは、主力のテキストモデルのコーディング能力とエージェント的な振る舞いを強化するという Claude の路線をたどり始めている。年末に MiniMax M2.1 と GLM 4.7 を試した著者は、明確なタスク計画、適切なツール呼び出し、複数ステップにわたるエンジニアリング作業といった、しっかりしたエージェント的な振る舞いを報告している。一方で、長い会話の後にモデルが焦点を失ったレガシーシステム移行のシナリオにも触れ、リーダーボードの高いスコアがあらゆるシナリオに通用するわけではないと注意を促している。
- 多くのモデルベンダーは自前の AI コーディングツールの開発を徐々に諦め、代わりに既存の成熟したツールの中で自社モデルを使えるようにしている。これにより開発者は、最も成熟したツールと交換可能なモデルの組み合わせを手にできる。たとえば [[SoftwareApplication/cursor]] や [[SoftwareApplication/claude-code]] の中で使われる中国製モデルがそうである。
- [[DefinedTerm/context-engineering]] の試行が続くのと並行して、仕様が復権しつつある。著者は、[[DefinedTerm/model-context-protocol]] の台頭と、それに続く Skills、[[DefinedTerm/agents-md]]、[[DefinedTerm/spec-driven-development]] の台頭をひとまとめにして、コーディングツールがより良いコンテキストエンジニアリングのあり方を模索している動きと捉えている。年末に Claude Code がコンテキスト収集のために LSP サポートを追加したことを挙げ、ファイル操作に基づくエージェント型 RAG はコストが高すぎ、重要なコンテキストを見落としやすいと述べている。
- エンドツーエンドのツールを作るハードルは下がりつつある。著者は、Atlassian の Rovo Dev CLI とその Jira・Bitbucket との統合、GitHub Copilot の GitHub.com とのより深い統合、Augment Code のレビュー製品、そして Cursor による 12 月のコードレビュー企業 Graphite の買収を挙げ、競争は単一の能力からエンドツーエンドのクローズドループへと移りつつあると結論づけている。
- 著者が自己検証の時代と呼ぶ状況の中で、ツールは自らの出力に責任を持ち始めている。つまり、コードが動くかどうかだけでなく、タスクが実際に完了したかどうかを判断するようになっている。著者は、Playwright のネイティブエージェントや ScenGen のように OODA に似たループを用いるテストエージェントや、失敗したステップを再生して修正を生成する Playwright の Healer Agent を挙げている。
- AI はあらゆる技術スタックへの参入障壁を下げる。著者によれば、これは AI が反復的でテンプレート化可能な仕事を置き換えつつあることも意味する。残る価値ある仕事は、複雑なシステムの設計、エンジニアリングのデリバリー計画、上流・下流のプロセスの調整である。

## 背景

この記事は、著者自身によるツールやモデルの試用に基づく意見記事であり、計測結果は報告していない。コードレビューについて著者は、Augment のチームから提供されたエンタープライズ向けのアクセスを通じて、AI 時代のコードレビューエージェントが行うべきだと考えることを同チームに示したと述べている。それは、変更全体の構造化された要約、断片的なコメントではなく図のレベルでの概観、そして変更のライフサイクル全体にわたる継続性である。著者は、その製品が現在これを実装していると記しているが、その方向性が自分のフィードバックから生まれたとは主張していない。
