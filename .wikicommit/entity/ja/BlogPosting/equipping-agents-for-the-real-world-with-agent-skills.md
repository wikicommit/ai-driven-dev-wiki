このエンジニアリング記事は、[[DefinedTerm/agent-skills]] を、著者らが何らかの欠点からではなく能力の向上から生じるものとして捉える問題への答えとして紹介している。汎用エージェントが完全なコンピューティング環境を操作できるようになると、未解決の問いは、ドメイン固有の専門知識をいかにして組み合わせ可能で、スケーラブルで、可搬な形でエージェントに持たせるかになる。記事が提案する答えは、形式としては意図的に控えめなもの、すなわちエージェントが自ら発見して読み込む、指示・スクリプト・リソースを整理したフォルダである。著者らは、この単純さこそが、組織・開発者・エンドユーザーがカスタマイズしたエージェントを構築し、新たな能力を与えることを容易にするのだと主張する。

記事の指針となる比喩は、スキルを作ることは新入社員向けのオンボーディングガイドをまとめることに似ている、というものである。ユースケースごとに個別に設計したエージェントを構築するのではなく、誰でも手続き的な知識を共有可能なパッケージにまとめることで汎用エージェントを特化させられる。この比喩の背後にある技術的な中身が [[DefinedTerm/progressive-disclosure]] であり、著者らはこれを形式を柔軟かつスケーラブルにする中核的な設計原則と呼び、Claude の文書編集能力を支える PDF スキルを通じて例示している。

2025 年 12 月 18 日に記事に追記された注記によれば、Agent Skills はその後、クロスプラットフォームでの可搬性のためのオープン標準として公開された。

## 要点

- スキルとは `SKILL.md` ファイルを含むディレクトリであり、その YAML フロントマターには必須の 2 つのフィールド `name` と `description` がある。同梱される指示・スクリプト・リソースは、この最小構成に対する任意の追加である。
- 段階的開示（Progressive Disclosure）は形式の中核的な設計原則として 3 つのレベルで示される。インストールされたすべてのスキルの `name` と `description` は起動時にシステムプロンプトへ事前に読み込まれ、`SKILL.md` の本文はエージェントがそのスキルを関連すると判断したときにのみ読まれ、さらに同梱されたファイルは必要に応じてのみ参照される。
- ファイルシステムとコード実行を持つエージェントはスキルを全部読む必要がないため、著者らは、スキルに同梱できるコンテキストの量は実質的に無制限であると述べている。
- スキルには、エージェントが自らの判断でツールとして実行するコードを含めることができる。記事は、これがコストの面（トークン生成でリストをソートするのは、ソートアルゴリズムを実行するよりはるかに高価である）と決定性の面（多くのアプリケーションはコードでしか得られない信頼性を必要とする）の両方で正当化されると論じる。PDF スキルの場合、同梱された Python スクリプトがフォームのフィールドを抽出し、スクリプトも PDF もコンテキストに入らない。
- 示される作成のガイダンスは、評価から始めること、すなわち代表的なタスクでエージェントを動かして能力のギャップを特定し、エージェントがどんなコンテキストを必要とするかを予測するのではなく、観察された不足に対してスキルを段階的に構築することである。
- 扱いにくくなった `SKILL.md` への推奨される対処は、その内容を参照される別ファイルに分割することである。記事はさらに、コンテキストが相互排他的であるか一緒に使われることがまれな場合は、それらのパスを分けておくことでトークン使用量が減ると付け加えている。
- 著者らは、スキルの `name` と `description` を特に注意を払うべきものとして挙げている。エージェントがそもそもスキルを起動するかどうかを判断する際に使うのがそれらだからである。
- 推奨される作成ループの 1 つは、エージェント自身に成功したアプローチやよくある誤りをスキルとして記録させ、軌道を外れたときには自己反省を求めることであり、エージェントが実際に必要とするコンテキストを発見する方法として示されている。
- セキュリティについて、記事は、悪意のあるスキルは使用される環境に脆弱性をもたらしたり、エージェントにデータの持ち出しや意図しない行動を指示したりしうると述べ、信頼できるソースからのみスキルをインストールし、信頼性の低いものは使用前に監査することを推奨している。その際には、コードの依存関係、同梱されたリソース、信頼できない外部ネットワークソースに接続する指示に特に注意を払うべきだという。
- 著者らは、公開時点で Skills が Claude.ai、[[SoftwareApplication/claude-code]]、[[SoftwareApplication/claude-agent-sdk]]、Claude Developer Platform でサポートされていると述べている。

## 背景

この記事はベンダー自身が設計した形式について自ら説明したものであり、利点に関する主張は独立した知見ではなく著者ら自身のものである。記事の中で評価や測定は報告されていない。唯一の定量的に聞こえる主張、すなわち同梱されたコンテキストが「実質的に無制限」であるというものは、ファイルシステムを備えたエージェントが読む必要のないものについてのアーキテクチャ上の議論であって、測定結果ではない。

2 つの将来に向けた立場は、出荷済みの挙動ではなく意図として述べられている。著者らは、外部ツールを伴うワークフローをエージェントに教えることで Skills が [[DefinedTerm/model-context-protocol]] サーバーをどのように補完できるかを探りたいと述べ、またエージェントが自らの行動パターンを再利用可能な能力として体系化し、Skills を自ら作成・編集・評価できるようにしたいとしている。

記事のセキュリティの節は、自らの形式の手軽さに反する議論をしている点で注目に値する。スキルを共有しやすくしているのと同じ性質、すなわちそれがエージェントが従って行動する指示とコードのフォルダであるという性質こそが、信頼できないスキルを危険なものにしており、推奨される対処は形式自体が提供する仕組みではなく手作業による監査である。
