2025年3月19日付のこの記事で、[[Person/simon-willison]] は、[[Person/andrej-karpathy]] が [[DefinedTerm/vibe-coding]] という語を造ってからわずか6週間で、その「定義はすでに本来の意図から逃れ出しつつある」と論じ、AI の支援によって書かれたコードのすべてにこの語を当てることは「語を薄めると同時に、責任ある AI 支援プログラミングで何ができるのかについて誤った印象を与える」と述べる。彼は Karpathy の元のツイートを全文引用し、「コードが存在することさえ忘れる」と「使い捨ての週末プロジェクトにはそう悪くない」という表現を強調したうえで、自身の作業上の定義を示す。バイブコーディングとは「LLM が書いたコードをレビューせずにソフトウェアを作ること」である。

この記事はバイブコーディングへの批判ではない。Willison は Karpathy の定義を気に入っていると述べ、Karpathy は AI の支援を必要としないほど経験を積んだプログラマであり、突飛なアイデアを素早く試すのが楽しいからこそ LLM をこのように使っているのだと指摘し、リスクの低いプロジェクトやプロトタイプなら思い切りやらない理由はないと論じる。彼が異を唱えるのは、この語がプロフェッショナルな実践までを覆うように広がっていくことであり、それとは別に、この語が無責任な AI 利用の同義語として固まってしまうリスクである。

## 要点

- 区別されるのはツールではなくコードへの関与である。LLM がコードを書き、それをあなたがレビューし、十分にテストし、どう動くのかを他人に説明できるのなら、「それはバイブコーディングではなくソフトウェア開発であり」、その支えとして LLM を使ったかどうかは本質的な問題ではない。
- Willison は本番品質の AI 支援プログラミングについての黄金律を示す。他人に正確に説明できないコードは、自分のリポジトリにコミットしない。
- 彼はこの律を、自分が仕事だと考えているもの——実際に動くことを示せて、他の人間にも機械にも理解でき、その後の開発を支えるコードを生み出すこと——に根拠づけ、そのうえで性能、アクセシビリティ、セキュリティ、保守性、コスト効率をトレードオフとして釣り合わせるのだとしている。
- バイブコーディングの真価はアクセスにあると彼は論じる。コンピュータサイエンスの学位やブートキャンプの経験がなくても、面倒な作業をコンピュータで自動化できてよいはずであり、バイブコーディングは「最初の障壁をほとんど平らに削る」。
- またそれは、経験ある開発者が LLM に何ができて何ができないのかの直観を養うための、現在利用可能な最良の手段でもあると論じ、この方法で作った80を超える実験を公開してきたと報告している。
- バイブコーディングが適切な場面についての彼の条件は次のとおりである。プロジェクトのリスクを低く保つこと。秘密情報の露出や、私的なデータが手元のマシンの外へ出ていくことに気を配り、セキュリティを慎重に扱うこと。外向きのリクエストは他のサービスに負荷とコストをかけるのだから、ネットワークの良き市民であること。そして従量課金の API に注意すること——請求上限を設けないまま数千ドルの請求を積み上げてしまった恐ろしい事例を挙げている。
- バイブコーディングで作ったソフトウェアを他人に共有しようとする初心者には、まず自分より経験のある人に相談することを勧めている。

## 背景

Willison は、執筆時点でこの語がすでに『ニューヨーク・タイムズ』『Ars Technica』『ガーディアン』に取り上げられていたことに触れ、コードに LLM を使う自身の全プロセスを説明した以前の記事を読者に案内している。彼によれば、バイブコーディングはそのごく一部を指すにすぎない。

記事の結びの節は、安全なバイブコーディングを未解決の設計課題として扱い、サンドボックス化を出発点に据える。Willison は [[SoftwareApplication/claude-artifacts]] のサンドボックスを、初心者が害を及ぼすことを非常に難しくしていると同時に、そうしたプロジェクトにできることを厳しく限ってもいるとして評価し、それを [[SoftwareApplication/cursor]] と対比する。Cursor は当初プロフェッショナルな開発者に向けられたものであり、安全のための手すりははるかに少ないと彼は説明する。そして、人々が生産的かつ安全にカスタムツールを作れるよう助ける「ツールのカンブリア爆発」を期待していると述べている。

その4日後、Willison は別の言葉づかいでこの定義をめぐる論争に立ち返り、語の拡大を [[DefinedTerm/semantic-diffusion]] に帰した。Karpathy はこの記事に直接返信し、定義が落ち着くには時間がかかるだろうという点に同意している。
