サイト上の著者プロフィールで Thoughtworks の技術エキスパートと紹介されている Phodal Huang が中国語で書いたこの記事は、2025 年半ば時点の AI コーディングを総括している。記事は冒頭で、2025 年は単なる「エージェントの年」ではなく体系的な飛躍の出発点であると述べ、その兆候として 3 つを挙げる。Cursor と Windsurf が AI エディタから AI IDE へと移行したこと、Claude Code がモデルの推論能力を中心にタスク実行を作り変えたこと、そして Augment のクローズドループ検証である。記事の主張は太字で示されている。エージェントがもたらすのは単純な効率化ではなく増幅であり、以前まずくやっていたことは、今やさらにまずくなる、というものだ。

本文は 8 つのトレンドを順に取り上げ、最後のまとめで主な警告を述べる。エージェントが約束する「10 倍の生産性」は本物だが、技術的負債という形で高く複利的に膨らむ「隠れた利息」を伴い、それを放置すれば、いずれはエンジニアリング組織を押しつぶすことになる、という警告である。

## 要点

- 著者は、エージェントが要件を理解し一連の開発タスク全体を遂行できるようになったため、過去半年でコード補完を使う頻度が大きく減ったと報告している。トップモデルは今やあらゆるツールベンダーが組み込める汎用的な「知能エンジン」となっており、競争の場はワークフロー、ユーザー体験、エコシステムとの統合へと移ったと論じる。
- 著者は、コードを直接生成するやり方から「まず計画し、それからコードを書く」やり方への移行を説明している。Markdown のロードマップで計画を立て、タスクごとに詳細で自己完結したプロンプトを書き、AI には一度に 1 つのタスクだけを渡し、次に進む前に各結果をレビューする、というものだ。作業しながらタスクリストを更新するツールの例として、[[SoftwareApplication/claude-code]] の `TodoRead`/`TodoWrite` ツールと [[SoftwareApplication/windsurf]] の `update_plan` を挙げている。
- 著者の説明では、自動検証が強化されており、特に Claude と Augment でそれが顕著である。単体テストだけでなく人間のような確認、つまり複数の検証アプローチを試すこと、複数回のテスト、無関係なエラーを切り分けるためのより軽量な使い捨てテストスクリプトの作成を行う。
- AI コーディングは前面での対話から非同期のバックグラウンド実行へと移行しつつあり、その例として Augment Remote Agent と Cursor Backend Agent を挙げている。これを支える 3 本の柱として、リモート開発インフラ、コンテキストエンジン、[[DefinedTerm/model-context-protocol]] を挙げている。
- エージェントを導入したら組織レベルの MCP 能力の構築が不可欠だと論じ、当時はプロトコルに認証の仕組みが欠けていたため、企業はそれを自力で解決しなければならなかったと指摘している。
- アーキテクチャについては、Augment と Cursor で作ったプロトタイプが、アーキテクチャの計画なしに漠然としたアイデアから生成された場合、密結合で保守しにくいコードになったと報告している。また、AI は意図したアーキテクチャ上の変更を誤りとみなして元に「修正」してしまうことがあるため、AI 支援のリファクタリングは信頼できないと論じる。
- AI 支援によるコード品質に関する第三者の調査を引用し、2024 年に重複コードが急増したことが示されているとしたうえで、エージェントを使った自身の経験からは、その影響はさらに大きい可能性があると述べている。AI は無差別に増幅する、つまり間違いを犯しているなら、AI はそれをより速く、より大規模に犯す手助けをする、という警告を Thoughtworks の同僚の言葉として紹介している。
- この増幅が最もはっきり表れる場として [[DefinedTerm/vibe-coding]] を挙げており、特に計画を立てずに AI の素早い応答に頼る経験の浅い開発者においてそうだとしている。

## 背景

この記事は研究ではなく実務家による意見記事であり、引用している重複コードの調査を除けば、その根拠は著者自身のツール使用経験である。検証のトレンドを位置づけるために、著者が以前「AI コーディングツール 2.0」について提唱していた 3 つの特徴、すなわちエージェント駆動、開発者体験優先、自動検証を再び用いている。また、SDLC の段階（調査、プロトタイピング、要件、コード生成、コード品質、テスト、運用）ごとに多くのツールを列挙し、[[SoftwareApplication/github-copilot]] や Atlassian Rovo のような統合型の製品も挙げているが、それらを評価してはいない。
