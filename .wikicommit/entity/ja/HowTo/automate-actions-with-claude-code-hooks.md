この手順は、[[SoftwareApplication/claude-code]] にフックを追加するものである。フックとは、Claude Code がライフサイクルの特定の時点で実行する、ユーザー定義のハンドラー（多くの場合はシェルコマンド）であり、これによってあるアクションが、モデルがそれを実行すると選ぶかどうかに左右されず、必ず行われるようになる（[[DefinedTerm/agent-hooks]] を参照）。Anthropic のガイドは、Claude がユーザーの入力を待っているときに毎回発火するデスクトップ通知を例に、この手順を順を追って説明している。

## 前提条件

- Claude Code と、フックを記述できる設定ファイルのいずれかへの書き込み権限。すべてのプロジェクトに適用するなら `~/.claude/settings.json`、プロジェクト単位でリポジトリを通じて共有するなら `.claude/settings.json`、プロジェクト単位で共有しないなら `.claude/settings.local.json` である。フックは、管理ポリシー設定、プラグインの `hooks/hooks.json`、あるいはスキルやサブエージェントのフロントマターから提供されることもある。
- フックの JSON 入力を解析するガイドのコマンド例を使う場合は `jq`。
- コマンドから呼び出すフックスクリプトは、macOS と Linux では実行可能になっていなければならない（`chmod +x`）。

## 手順

1. 目的のスコープの設定ファイルを開き、`hooks` ブロックを追加する。各イベント名は単一の `hooks` オブジェクト内のキーであり、省略可能な `matcher` と実行するハンドラーを持つグループのリストを保持する。通知の例では、空のマッチャーと、プラットフォームの通知コマンド（macOS では `osascript`、Linux では `notify-send`、Windows では PowerShell のダイアログ）を呼び出す `command` ハンドラーを持つ `Notification` イベントとなる。ファイルにすでに `hooks` キーがある場合は、オブジェクトを置き換えるのではなく、新しいイベントを兄弟要素として追加する。フックを書くよう Claude に依頼することもできる。
2. 必要に応じて、発火する条件を絞り込む。マッチャーがなければ、フックはそのイベントが発生するたびに発火する。マッチャーは、イベントによって異なるフィールドで絞り込む。ツールイベントではツール名（たとえば `Edit|Write`）、`Notification` では通知の種類、`SessionStart` ではセッションの開始方法である。ツールイベントでは、`Bash(git *)` のようなパーミッションルールの構文を用いる `if` フィールドによって、ツール名と引数を組み合わせて絞り込める。
3. `/hooks` と入力してフックブラウザーを開き、イベントを選択して、新しいフックがそのマッチャー、種類、ソースファイル、コマンドとともに表示されることを確認する。このメニューは読み取り専用であり、変更は設定の JSON で行う。
4. イベントを発生させてテストする。通知の例では、`Shift+Tab` で Claude Code を手動モードに切り替え、権限が必要なことを依頼し、ターミナルから別のウィンドウに切り替えて、通知が届くのを待つ。

## 補足

- コマンドフックはイベントのデータを JSON として stdin で受け取り、終了コードと出力によって応答する。終了コード 0 は異議なしを意味する（`PreToolUse` の場合、呼び出しを承認するわけではなく、通常のパーミッションフローが引き続き適用される）。終了コード 2 はアクションをブロックし、stderr がその理由となる。あるいは、フックは 0 で終了したうえで JSON オブジェクトを出力し、構造化された制御を行うこともできる。たとえば `hookSpecificOutput` の中にネストした、`allow`、`deny`、`ask` のいずれかの `PreToolUse` の `permissionDecision` である。
- フックの `type` には、`command` のほかに、`http`（イベントデータを URL に POST する）、`mcp_tool`、`prompt`（Claude モデルによる単一ターンの評価で、デフォルトは Haiku）、`agent`（ツールを使って条件を検証できるサブエージェントで、実験的とされている）を指定できる。
- ガイドの実例には、`PostToolUse` フックによる編集後のファイルの自動整形、2 で終了する `PreToolUse` スクリプトによる保護対象ファイルへの編集のブロック、`compact` マッチャーを指定した `SessionStart` フックによる [[DefinedTerm/compaction]] 後の重要なコンテキストの再注入、設定変更のログ記録、作業ディレクトリが変わったときの環境変数の再読み込み、そして `PermissionRequest` フックによる特定の権限プロンプトの自動承認が含まれる。最後のものについて、ガイドはマッチ対象を狭く保つよう警告している。
- 1 つのイベントに複数のフックが一致した場合、それらはすべて並列に実行され、その後で結果が統合される。`PreToolUse` では最も制限の厳しい判定が優先される。`PreToolUse` の deny は、`bypassPermissions` を含むあらゆる [[DefinedTerm/permission-modes]] の設定でツールをブロックするが、`allow` を返すフックが設定の deny ルールを上書きすることはできない。つまりフックは制限を強めることはできても、緩めることはできない。
- フックが発火しない場合は、`/hooks` で正しいイベントの下に表示されているか、マッチャーがツール名と正確に一致しているか（マッチャーは大文字と小文字を区別する）を確認する。JSON 出力が効かない場合は、シェルプロファイルの `echo` 行が stdout の先頭に付け加えられていないか、フィールドが誤った階層に置かれていないかを調べる。ブロックし続ける `Stop` フックは、進展のないまま 8 回連続でブロックすると無視されるため、入力フィールド `stop_hook_active` が true のときは早めに終了するようにすべきである。
