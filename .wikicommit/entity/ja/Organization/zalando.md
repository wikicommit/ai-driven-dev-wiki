Zalando は、この wiki では、エージェント型エンジニアリングの実践について同社自身が公開した記録の主題として登場する。その記録によれば、同社のエンジニアリング組織は 250 以上のチームからなり、会社の各事業ラインにわたってイノベーションに取り組んでいる。大規模言語モデルは事業ラインごとに異なる形で、異なるペースで価値をもたらしているという。同じ記録の後の節ではこの数字が 200 以上のチームとされており、ソースは両方の数字を記しているが、どちらとも整合させていない。

そこで説明されているエンジニアリング資産は、モノレポではなく主にマイクロサービスごとの個別リポジトリで構成されているが、同社はいくつかのモノレポも運用している。その中には、プルリクエストごとにライブデータに接続されたデプロイメントを立ち上げる Zalando の Web モノレポが含まれる。同社は Sunrise という Backstage ベースの開発者ポータルを運営し、Tech Radar を公開しており、そこには社内向けの AI セクションが追加されている。

## 活動と製品

この wiki のソースが Zalando について明らかにしている内容は、同社の社内エンジニアリングプラットフォームに関するものである。同社の ML プラットフォームチームは 2024 年 1 月に [[SoftwareApplication/litellm]] ベースの API プロキシをデプロイし、OpenAI、AWS Bedrock、Google Vertex のモデルへの API アクセスを提供した。チームは、それぞれ 2 CPU コアと 4 GB のメモリを持つ 6 つの Pod で月間 2,000 人のアクティブユーザーに対応していると報告している。記録はこのフットプリントを無条件のキャパシティの数字としてではなく、LiteLLM の安定性とメモリリークの問題を緩和するために 20,000 リクエストごとにプロキシの再起動を強制した結果として提示している。このプロキシを補完するのが、チャット UI（その後メンテナンスされなくなったオープンソースのコードベースのフォーク）と、pydantic-ai で構築された独自の CLI ツールである。この CLI ツールは、コーディングエージェントがまだ存在しなかった 2024 年 8 月のハッカソンで生まれ、その後メンテナーの小さなコミュニティを引き寄せた。彼らはこれに、インタラクティブモード、MCP 対応のエージェントモード、HTTP から stdio への MCP プロキシ、そして安全なコーディングエージェント設定をインストールするコマンドを追加した。

プラットフォームそのもの以外にも、記録は、低リスクと分類した 33% の PR を自動承認するリスクベースのプルリクエスト承認ボット、プラグインとして配布される [[DefinedTerm/agent-skills]] の一元的なコレクション、そして構築中のエージェントプラットフォームについて述べている。このエージェントプラットフォームは、Kubernetes のランタイム面を担う kagent を含むオープンソースのコンポーネントを組み合わせ、エージェントと MCP サーバーの間の委任チェーンや on-behalf-of フローのための Identity Broker を併せ持つ。

知識共有の形式も同じ詳しさで説明されている。LLM ギルド（記録によればそのチャットチャンネルは 2024 年に開設され、知識共有セッションは毎週 1 時間行われる）、2〜3 日間のテーマ主導のハッカソン、約 20 人を対象とした対面の *GenAI Labs* セッション、そして MCP サーバーの使い方や pydantic-ai によるエージェント構築についての月例トレーニング（トレーナーは過去の Lab 参加者から募られる）である。同社は年次の Software Engineering Community Conference も開催しており、そこでは初日の Agentic Engineering トラックと 2 日目の Engineering Fundamentals トラックとを意図的にバランスさせた。

これらすべてについての同社自身の振り返りは、[[BlogPosting/agentic-engineering-at-zalando-a-snapshot]] を参照。
