SpecStory は、意図をコーディングエージェントによってソフトウェアへと変換するワークフローである [[DefinedTerm/specflow]] を手がける企業であり、その背後にある論理を示したホワイトペーパー [[Report/beyond-code-centric]] の公刊元である。本ウィキにとっての関わりは、製品の機能一覧からではなく自社の実際の働き方から論じる、[[DefinedTerm/spec-driven-development]] についての実践者の声としてのものである。

## 沿革

ここで取り込んだ出典は、SpecStory の設立時期や企業としての沿革を扱っていない。出典は [[Person/greg-ceccarelli]] を共同創業者として挙げ、同社が Cursor、Copilot、Claude Code とともにエージェントを使った数千時間と自ら述べる経験を経て Specflow を定式化したことを記録している。

## 活動と製品

同社が掲げる開発の実践は、ホワイトペーパー自身がわざわざ言及するほどには珍しいものである。SpecStory はトランクベース開発を採用しているが、「ただし従来のトランクベースのチームとは異なり、われわれ自身がコードを書くことはめったにない」のであり、各役割はその代わりに単一の共有リポジトリへ仕様を寄せる——プロダクトマネージャーはテスト可能なユーザー挙動を書き、デザイナーは制約をコード化し、アーキテクトはインターフェース、契約、依存関係を宣言する。

同社は自社製品もこの方法で作っていると報告している。3人が4週間で Studio 製品の完全なエンドツーエンドの macOS アルファ版を届けたと述べ、これを従来の手段では不可能なスケジュールだったと呼んでいる。この数字は同社自身が自社の実践について公表したものであり、独立した検証はない。

ホワイトペーパーはまた、同社が直に目にしたと報告する観察も記録している。一人による手早いプロトタイプは機能要件を捉えていても、より深いアーキテクチャ上および UX 上の要求を取りこぼしうるのであり、そこに他の声が加わった瞬間、一人ではなめらかに機能していたものが調整の悪夢になる、というものである。同社は「次の実装セッションに向けてプロジェクトの記憶をリセットするために、任意のチャット UI へコピー&ペーストないし @ 参照できる決定版のファイルを1つ」求められることが頻繁にあると報告し、それをプロジェクトコンテキストの深い断片化の証拠と読んでいる。
