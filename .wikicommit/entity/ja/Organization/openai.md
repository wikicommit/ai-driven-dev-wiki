OpenAI は ChatGPT と、そのソフトウェアエンジニアリングエージェントである [[SoftwareApplication/codex]] を手がける企業である。本 wiki における関連性は、エージェンティックコーディングの実践を形づくる主要なベンダーの一つであるという点にある。同社はエージェントと、その背後にあるモデルと、そして自社のローンチ記事によればリポジトリに置かれた [[DefinedTerm/agents-md]] ファイルによって導かれるエージェントを提供している。

## 沿革

ここで取り込んだ出典は OpenAI の創業や企業としての沿革を扱っていない。それらが記録しているのはリリースの実践である。Codex は2025年5月16日に**リサーチプレビュー**として公開された。OpenAI はこれを「われわれの反復的デプロイ戦略に沿ったもの」と記述し、ユーザーが出力を検証できるよう設計においてセキュリティと透明性を優先したとしている——モデルがより複雑なコーディング作業を独立に扱うようになるにつれ、ますます重要になる安全策だと同社は呼んでいる。この公開に先立ち、Codex が多様なコードベース、開発プロセス、チームにわたってどう振る舞うかを理解するために少数の外部テスターと協働しており、そのなかに Cisco、Temporal、Superhuman、Kodiak を挙げている。

## 活動と製品

ここで扱われている製品は Codex であり、クラウドエージェントとして公開され、のちに ChatGPT、IDE 拡張、[[SoftwareApplication/codex-cli]] にまたがる1つのエージェントとして提示された。ローンチ記事で名指されているモデルは、ソフトウェアエンジニアリング向けに最適化された OpenAI o3 の一版である `codex-1` と、o4-mini から派生したより小さな variant であり、後者は CLI のデフォルトとして、また API では `codex-mini-latest` として公開された。

OpenAI はこのツールを社内でも使っている。ローンチ記事は、OpenAI の技術チームが Codex を日々の道具立ての一部として使い始めていたと報告している。最も多いのは、リファクタリング、リネーム、テストの作成といった、さもなければ集中を途切れさせる反復的でスコープの明確な作業を肩代わりさせる用途であり、同じくらい多いのは機能のスキャフォールディング、コンポーネントの結線、バグ修正、ドキュメントの草稿である。チームはオンコールの問題のトリアージ、1日の始めのタスク計画、バックグラウンド作業の委譲といった習慣を築いていったという。

これがどこへ向かうかについての同社の立場は、2つのモードの収束である。すなわち、リアルタイムのペアリングと非同期のタスク委譲が、IDE と日常のツールをまたぐ単一のワークフローへと畳み込まれていくというもので、OpenAI は非同期のマルチエージェントモードが「エンジニアが高品質なコードを生み出す事実上の方法」になると予測している。これは観測された結果ではなく同社自身の予測である。OpenAI はまた、エージェントの広範な普及が開発者のワークフローに、そして人・スキルレベル・地域をまたぐスキル開発に何をもたらすのかを理解するために、パートナーと協働していると述べている。
