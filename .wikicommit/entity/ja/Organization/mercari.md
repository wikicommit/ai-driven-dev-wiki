メルカリは、この wiki ではツールのベンダーとしてではなく、AI 駆動開発の実践を採り入れている企業として登場する。ここに記録している内容は同社のエンジニアリングブログへの投稿に基づいているため、そこから言えるのはエンジニアが組織をどう説明しているかであって、外部からの評価ではない。

投稿の 1 つが述べているのは、単一のツールに標準化することを意図的に避けるという姿勢である。投稿が AI-Native な開発原則と呼ぶものを同社が採り入れるなかで、誰もが自分の選んだツールを導入できるようにし、新しい技術を試すためのリソースも与えられた。掲げられた目標は、まったく異なる環境を強いることなく、エンジニアがこうしたツールを使えるようにすることだった。投稿はこの自由の利点だけでなく代償も報告している。チームは幅広いツールについて素早く学べた一方で、ツールの有効性や出力の形は、同じチーム内でさえ大きくばらついた。

2 本目の投稿は、同じ全体像のうち別に管理されている部分を説明している。同社はエンタープライズプランのもとで AI エージェントサービスを運用しており、そこでは Organization がチームや用途ごとに割り当てられている。その理由として、メルカリには複数の事業ドメインにまたがる多数のチームがあり、それぞれが扱う情報を分離して保護する必要があることが挙げられている。この投稿は 1 本目が説明するツール群には触れておらず、どちらも両者を 1 つの方針として示してはいない。

3 本目の投稿は、メルペイの VP of Engineering 室によるもので、別のものを標準化する全社的な取り組みを説明している。標準化の対象はエンジニアが使うツールではなく開発プロセスであり、しかもそのプロセスは特定のツールに依存しないものにしたいと明言している。投稿によれば、2025 年初頭には AI ツールや MCP サーバーがボトムアップで導入され、各開発者が独自のやり方を模索していた。投稿はこの段階を「発散」と呼ぶ。一部の開発者の生産性は劇的に向上したが、AI をうまく使える人とそうでない人との間に差が開き、共有される実践は個別のティップスや、共有された `CLAUDE.md` や Cursor Rules のファイルの水準にとどまっていた。これに対する答えが、プロダクト開発の生産性を倍増させることを使命として 2025 年 7 月ごろに始まった Project Double（pj-double）であり、高い生産性を再現できる全社標準の開発プロセスという「収束」の段階へ移ることを目指した。3 本の投稿はそれぞれ異なる時期の異なるチームを描いており、いずれも自らの説明を他の投稿と突き合わせてはいない。

4 本目の投稿は同社の CTO によるもので、これらの取り組みを全社的な枠組みの中に位置づけている。投稿は、メルカリが「AI-Native Company」になるために、プロダクト、働き方、組織を AI を前提に作り直すという社長の宣言を引用し、従業員の 95% が AI ツールを使っていること、コード生成の約 70% を AI が担っていること、開発スピードが前年比で 64% 向上したことを報告している。そのうえで、コーディングの生産性だけでは組織全体の生産性は上がらないため、同社はまだ自らを AI-Native だとは考えていないと述べている。同じ投稿は、ツールの発散を全社の視点からも説明している。まず Cursor が全社に展開され、その後 Claude Code のような新しいコーディングアシスタントが登場してエンジニアが別々のツールを使うようになったことで、ベストプラクティスの集約が難しくなったという。それへの対応の経緯は [[BlogPosting/choosing-ai-native-mercari-guiding-principles]] に記載している。

## 組織構成

これらの投稿には社内のいくつかのグループが登場するが、その総数は示されていない。Web チームは、多様なバックグラウンドを持ち、使うツールや環境が大きく異なる人々で構成されていると説明されており、メルカリの新しいグローバルアプリを開発してきた。そのモノレポはモジュール型のアプローチを採っており、pnpm ワークスペースとして構成され、モジュール境界はツールによって強制されている。AI Security チームは AI Agent Platform チームと協力して、後述するエージェント管理基盤を構築した。そのサービスの監査ログを同社内製のセキュリティ監視基盤に取り込む連携は、AI Security と Threat Detection and Response の Anna の功績とされている。この書き方では、1 つのチームを指しているのか 2 つのチームを指しているのかははっきりしない。

2 本目の投稿は、自らの取り組みが従わなければならなかった制約として、同社のエンジニアリング上の標準もいくつか挙げている。Terraform はインフラストラクチャ・アズ・コードによるリソース管理の標準ツールであり、エンジニアは日常的にこれを扱っている。Go は社内で広く使われている。そして Google Cloud が主要なクラウドであり、Google Cloud の公式のベストプラクティスに従って、Organization Policy によりサービスアカウントキーの発行が全面的に禁止されている。同じ投稿は、ポリシーの適用から除外した専用プロジェクトと、補完的な統制としてのキーの有効期限によって、この禁止を回避している。

## 活動・製品

1 本目の投稿は、Web チームで特によく使われているツールとして、Cursor、[[SoftwareApplication/claude-code]]、GitHub Copilot、そして最近では Codex CLI を挙げている。それぞれのルール形式がばらばらであることに対して、このチームは [[DefinedTerm/agents-md]] を唯一の信頼できる情報源（single source of truth）として統一するという対応をとった。その統一の経緯は [[BlogPosting/taming-agents-in-the-mercari-web-monorepo]] に記載している。同じ投稿は、チームの学びをメルカリ全体で共有し、AI-Native な開発を模索する他のチームを刺激したいという意図も述べており、この実践が会社として確立した標準ではなく、1 つのチームのものであることがわかる。

pj-double は、まずメルペイとメルカリモバイルの 30 を超えるバックエンドプロジェクトと 3 か月間にわたって協働し、週次のミーティングで AI の利用状況を追跡した。その成果をもとに、2025 年 9 月に [[DefinedTerm/agent-spec-driven-development]]（ASDD）を提案した。これは、エージェントが実装計画を生成し、その計画に沿って実装する手法である。2025 年 10 月からプロジェクトは 1 人から 10 人を超えるチームへと拡大し、対象もメルペイの一部から全社へ、そしてバックエンドの設計・実装から、要件定義、設計、iOS と Android のクライアント開発、QA へと広がった。ASDD が及ばなかった点も含めたこのプロジェクトの経緯は、[[BlogPosting/pj-double-mercari-development-productivity]] に記載している。デリバリーの高速化が品質を犠牲にしていないかを追跡するため、チームは同社が導入している開発者体験ツールの DX を使って、リバート率と MTTR を監視していると報告している。CTO の投稿は、ASDD を同社の開発プロセスの中核と位置づけ、Double プロジェクトの狙いを生産性の倍増としている。

CTO の説明では、これと並んで全社的な取り組みが 2 つある。1 つはナレッジマネジメントの取り組みで、意思決定の履歴などのコンテキストを AI エージェントが利用できるよう、情報を中央のナレッジベースとして Notion に集約している。もう 1 つは 2025 年 7 月に始まった AI Task Force で、会社を 33 のドメインに分け、各ドメインに 1〜2 人のエンジニア、1〜2 人のプロジェクトマネージャー、そしてドメインオーナーを置き、メンバーは約 100 人にまで増えた。2025 年末までに、これらのドメイン全体で約 4,000 のワークフローを棚卸しし、それらを AI 化するためのロードマップを策定した。同じ投稿は、ほかのエージェントプロジェクトも挙げている。自然言語での依頼に応じて社内データを取得・分析する BI 業務向けのエージェントである PJ Socrates と、同社内製のデザインシステムを使って UI を生成する PJ Aurora である。

これとは別に、[[SoftwareApplication/devin]] が社内の複数のチームに展開されており、執筆時点で 10 を超える Organization と多数のユーザーを抱えていた。AI Security チームは AI Agent Platform チームと協力し、Devin の Enterprise API の上に Go と GitHub Actions で社内の管理基盤を構築した。この基盤は、メンバーと権限の管理、シークレットのローテーション、API キーのライフサイクル管理、監査を担う。その取り組みの経緯は [[BlogPosting/enabling-ai-usage-at-mercari-with-secure-devin-management]] に記載している。
