ZOZO は、この wiki ではツールのベンダーとしてではなく、AI 駆動開発の実践の導入企業として登場する。ここに記録されているのは、同社のエンジニア自身が組織をどう描いているかである。同社のテックブログによれば、Claude Code をはじめとする開発用 AI エージェントは全社的な制度のもとで全エンジニアに提供されており、投稿ではこの制度は 1 人あたり月額 200 米ドルという金額を基準にしていると説明されている。この制度で利用できるツールは幅広いとされ、[[SoftwareApplication/claude-code]]、[[SoftwareApplication/openai-codex]]、[[SoftwareApplication/devin]]、[[SoftwareApplication/cursor]] の名前が挙げられている。Claude Code は数百人規模で利用されていると報告されている。

同社はその結果生じた状況を、普及の問題ではなくばらつきの問題として捉え、それを 2 つの形で述べている。ツールをうまく使いこなしたエンジニアは調査・設計・実装・レビュー観点の整理にわたって生産性を高めたと報告される一方、その知見は個人の実践の中にとどまり、再利用可能な形で蓄積されなかった。そのため、利用が広がっても組織全体の底上げはなかなか進まなかった。同じ懸念はチームのレベルでも述べられている。各チームが独自にスキルやエージェントを整備するにつれ、それらの資産は作ったチームの中にとどまり、AI 支援開発で前進するチームと取り残されるチームとの差が広がっていった。

## 測定

ZOZO はこれに対する社内指標として、All ZOZO AI Readiness Score（略称 AZARS）を定めている。同社自身の説明によれば、この指標の特徴は 1 つではなく 2 つのことを見る点にある。すなわち、個人がどこまで AI を業務に組み込んでいるかと、組織が AI を前提とした業務プロセスを仕組みとして定着させられているかである。掲げられている目標は、単に AI を使いこなす人がいることではなく、誰もが同じ入口から一定の水準で AI 駆動開発を始められる状態である。

## 活動と製品

この懸念に対しては、規模の異なる 2 つの取り組みが記録されている。

1 つの本部の中では、基幹システム本部が、Claude Code と Codex を組み合わせて設計から実装、レビュー、そして該当する場合はフロントエンドの検証までをカバーする標準コマンドの組 `/dev-init` と `/dev-resume` を構築した。両者を [[DefinedTerm/critical-dialogue-review]] のループで組み合わせる理由を含め、この取り組みの記録は [[BlogPosting/ai-driven-development-two-commands]] にある。コマンドは GitHub リポジトリで管理されており、Claude Code のプラグインコマンドで追加したマーケットプレイス URL からインストールすることもできる。本部が掲げる方針は、ユーザーが触れる表面をこの 2 つのコマンドに固定したまま、その背後にあるプロンプト、Skills、レビュー観点、MCP 連携を更新し続けることで、エンジニアがそのたびにインターフェースを学び直すことなく、組織をより新しい実践へ移行させられるようにするというものである。

チームをまたいだ取り組みとしては、2025 年後半から単一の [[DefinedTerm/claude-code-plugin-marketplace]] が構築され、共同で運用されている。関わっているチームには、データシステム部の MLOps ブロックや推薦基盤ブロックが含まれる。プラグインはチームごとのディレクトリに置かれ、チーム横断のものは共有ディレクトリに置かれる。スキル、エージェント、スケジュール実行される Routines、ループ、GitHub Actions から呼び出されるワークフローがすべてそこに保管されているが、著者らはこの配置は誰かが決めたのではなく自然に落ち着いたものだと述べている。約 10 か月を経て、記録は大きな問題なく運用できていると報告しており、主な利点としてチーム間での具体的な再利用を挙げている。加えて、新しいメンバーがスキルをゼロから作る代わりに、動作するスキルをインストールして読めるようになったことで、立ち上がりまでの道のりが短くなったとも述べている。この取り組みの記録は [[BlogPosting/shared-claude-code-plugin-marketplace]] にある。
