[[Organization/anthropic]] は、自社の社内チームが [[SoftwareApplication/claude-code]] をどのように
使っているかを説明するためにこの文書を公開した。文書によれば、その知見は同社の Claude Code
パワーユーザーへのインタビューを通じて集められたもので、各部門がこのツールをどう使っているか、
それが業務にどのような影響を与えているか、そして導入を検討している他の組織へのヒントを扱うものと
して提示されている。文書全体を貫く主張は、このツールによって開発者も非技術系のスタッフも、複雑な
プロジェクトに取り組み、タスクを自動化し、これまで生産性を制約していたスキルのギャップを埋め
られるようになる、というものである。

文書はチームごとに構成されており、データインフラストラクチャ、プロダクト開発、セキュリティ
エンジニアリング、推論、データサイエンスと可視化、API、グロースマーケティング、プロダクト
デザイン、RL エンジニアリング、法務の 10 のセクションからなる。各セクションでは、そのチームの主な
ユースケース、報告されている効果、そして最も重要なヒントが示されている。文書中の数値は、統制された
測定ではなく、各チーム自身が報告した削減時間や成果の増加である。

## 知見

- **非技術系スタッフによるツールの構築と運用。** 複数のチームにわたって報告されている変化は、
  コーディング経験のない人々が、以前はエンジニアを必要とした作業を自ら行うようになったことである。
  データインフラストラクチャチームは、財務部門のスタッフに、データワークフローをプレーンテキストの
  ファイルに記述して Claude Code に実行させる方法を示した。1 人だけの非技術系チームとして紹介されて
  いるグロースマーケティングチームは、文字数制限内で広告バリエーションを生成する 2 つの専門化された
  サブエージェントからなるエージェント型ワークフロー、1 回のバッチで最大 100 の広告バリエーションを
  生成する Figma プラグイン、そして Meta Ads のキャンペーンデータを照会するための MCP サーバーを構築し、
  広告コピーの作成時間が 2 時間から 15 分に短縮され、クリエイティブの産出量が 10 倍に増えたと報告して
  いる。プロダクトデザイナーは視覚面や状態管理の変更を自ら実装しており、作業時間の 80% は Figma と
  Claude Code を開いていると報告している。法務チームはプロトタイプのツールを構築しており、その中には、
  発話に困難を抱える家族のためのコミュニケーション支援ツールを 1 時間で作ったものも含まれる。
- **コードベースの把握とオンボーディング。** 各チームは、同僚に尋ねる代わりに、見慣れない
  コードベースを理解するために Claude Code を使っていると報告している。新しく加わったデータ
  サイエンティストは Claude Code を使うよう案内され、Claude Code がコードベースの
  [[DefinedTerm/claude-md]] ファイルを読むことで、大規模なコードベースを把握できるようにしている。推論、API、セキュリティの各チームは、関連するファイルを
  見つけ、アーキテクチャを素早く理解できると述べており、セキュリティエンジニアは、既存の
  プロジェクトへの貢献が数週間ではなく数日で可能になったと報告している。
- **タスクに合わせて調整される自律性。** Claude Code チーム自身は、プロトタイピングや周辺的な機能には、
  auto-accept モードと、Claude がコードを書き、テストを実行し、反復する自律的なループを使い、
  おおよそ 80% 完成した結果をレビューしてから引き継ぐと説明している。一方、中核となるビジネス
  ロジックについては、詳細なプロンプトを用いて同期的に作業するという。非同期で進めたプロジェクトの
  1 つである Vim のキーバインドは、およそ 70% が Claude の自律的な作業によって書かれたと報告されて
  いる。このチームのヒントは、どのタスクが非同期作業に向き、どのタスクが綿密な監督を必要とするかを
  見極められるようになることである。
- **チェックポイントとやり直し。** 複数のチームが、Claude に作業させる前に状態をコミットしておき、
  Claude が脱線したら元に戻すという方法を説明している。データサイエンスチームはこれをスロット
  マシンにたとえている。コミットし、30 分間走らせ、結果を受け入れるか最初からやり直す、という
  やり方で、Claude の誤りを直そうとするよりもうまくいくことが多いと報告している。RL エンジニアリング
  チームは、ワンショットの試行がうまくいくのはおよそ 3 回に 1 回であると報告し、まずワンショットを
  試してから、誘導的で協働的なアプローチに切り替えることを勧めている。
- **自己検証とテスト。** Claude Code チームは、ビルド、テスト、リントを実行して Claude が自分の作業を
  検証するように設定することを勧めており、Claude がコードより先にテストを書く場合に特に効果的だと
  述べている。セキュリティエンジニアリングは、「設計文書 → 雑なコード → リファクタリング → テストを
  諦める」というパターンに代えて、Claude をテスト駆動開発に沿って誘導していると説明している。
  また、複数のチームが単体テストの生成に Claude Code を使っている。
- **指示と再利用可能なコマンド。** 各チームは、詳細な CLAUDE.md ファイルを用意すること、そして
  繰り返されるツール呼び出しの誤りを防ぐための指示を追加することを勧めている。セキュリティ
  エンジニアリングは、モノレポ内のカスタムスラッシュコマンドの実装全体の 50% を占めていると報告されて
  いる（[[DefinedTerm/custom-slash-commands]]）。データインフラストラクチャチームは、Claude Code が
  アクセスできる範囲をより厳密に制御するために、機密データについては BigQuery CLI よりも MCP
  サーバーを使うことを勧めている。
- **報告されている時間の削減。** セキュリティエンジニアリングは、インフラストラクチャのデバッグが、
  10〜15 分かかっていた手作業によるコードの走査から約 5 分に短縮されたと報告している。推論チームは、
  機械学習の概念についての調査時間が 80% 削減され、1 時間から 10〜20 分になったと報告している。
  データサイエンスは、定型的なリファクタリングで 2〜4 倍の削減を報告している。プロダクトデザインは、
  1 週間の調整を要したはずのローンチメッセージングの変更が、30 分の通話 2 回で完了したと報告している。
- **チームが挙げている限界。** RL エンジニアリングチームは、デバッグでは結果がまちまちであること、
  そして Claude が時に妙な場所にコメントを追加したり、疑問の残る形でコードを整理したりすることを
  報告している。データサイエンスチームは、モデルがデフォルトではより複雑な解決策に傾きがちだが、
  より単純な解決策を求めればうまく応じると指摘している。法務チームは、プロダクト担当の弁護士として、
  MCP の深い統合がもたらすセキュリティ上の影響に注意を促し、AI ツールがより機密性の高いシステムに
  及ぶにつれて、保守的なセキュリティ姿勢が障壁を生むだろうと見込んでいる。
