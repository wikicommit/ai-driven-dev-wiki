OpenHands（旧称 OpenDevin）は、人間の開発者と同様のやり方、すなわちコードを書き、コマンドラインとやり取りし、Web を閲覧することで世界と関わる、強力かつ柔軟な AI エージェントを開発するためのプラットフォームである。[[ScholarlyArticle/openhands-an-open-platform-for-ai-software-developers-as-generalist-agents]] で紹介されており、同論文はこれを、周囲の環境とやり取りしそこに変化をもたらす AI エージェントが急速に発展しているという背景のもとに提示している。

寛容な MIT ライセンスの下で公開されており、紹介論文はこれを学術界と産業界にまたがるコミュニティプロジェクトとして説明している。執筆時点で 188 人を超えるコントリビューターによる 2.1K 件以上のコントリビューションがあったという。コードは <https://github.com/All-Hands-AI/OpenHands> にあるとされている。

プロジェクトの 1 周年記念の投稿 [[BlogPosting/one-year-of-openhands-a-journey-of-open-source-ai-development]] は、その起源を伝えている。プロジェクトは 2024 年 3 月 12 日に、ソフトウェア開発のためのオープンソースの AI エージェントを作ることを目的として始まった。当初は、オープンソースの言語モデル Qwen を開発するチームの Binyuan Hui と Junyang Lin によって OpenDevin として作られた。この名前は、投稿によればプロジェクトに着想を与えた [[Organization/cognition]] の [[SoftwareApplication/devin]] へのオマージュである。オープンソースコミュニティがこのプロジェクトのもとに結集し、初期のコントリビューターである Graham Neubig、Robert Brennan、Xingyao Wang の 3 人がその使命を引き継ぐために [[Organization/all-hands-ai]] を創業し、その時点でプロジェクトは OpenHands に改名された。

## 機能

紹介論文は、このプラットフォームで可能になる 4 つのことを挙げている。新しいエージェントの実装、コード実行のためのサンドボックス環境との安全なやり取り、複数エージェント間の協調、そして評価ベンチマークの組み込みである。

2026 年 3 月の投稿 [[BlogPosting/learning-to-verify-ai-generated-code]] で、OpenHands チームはこれに検証を加えたことを説明している。それは階層化された「検証スタック」であり、その第 1 層は、エージェントの軌跡全体を採点する小型で高速な [[DefinedTerm/critic-model]] である。このモデルはベンチマークのデータではなく、現実の本番環境のトレースで訓練されている。クリティックは OpenHands Software Agent SDK に統合されており、そのスコアはリランキング、早期停止、反復的な改善のためのカスタムループで利用できる。また OpenHands CLI にも統合されており、早期停止付きで有効にしたり、反復的な改善に使ったり、異なる受け入れしきい値を与えたりできる。投稿は、パッチレベルの第 2 層はまだこれからだとしている。

### コンテキストの圧縮

2025 年 4 月の投稿 [[BlogPosting/openhands-context-condensation-for-more-efficient-ai-agents]] は、OpenHands のコンテキストコンデンサーを紹介している。会話がしきい値を超えて長くなると、古いやり取りが要約される。要約には、ユーザーの目標、エージェントの進捗と残りの作業、そしてソフトウェアのタスクであれば重要なファイルや失敗しているテストといった詳細が含まれる。一方、最近のやり取りはそのまま保持される。SWE-bench Verified のインスタンスの一部において、投稿は、ターンごとの API コストがベースラインのエージェントの半分未満に落ち着き、平均解決率はベースラインの 53% に対して 54% だったと報告している。コンテキストの圧縮は、OpenHands Cloud を含む OpenHands で利用できると説明されている。

### セキュリティ制御

OpenHands チームによる 2025 年 8 月の投稿 [[BlogPosting/mitigating-prompt-injection-attacks-in-software-agents]] は、通常は人間が見守ることなく動作するエージェントのプロンプトインジェクションのリスクに、OpenHands がどう対処しているかを説明している。エージェントとの会話はすべて Docker コンテナの内部で行われるため、エージェントが破壊的なコマンドを実行したとしてもローカルのファイルシステムと環境は安全に保たれる。ただし投稿は、その環境内のシークレットやソースコードは依然として露出しうると注記している。OpenHands CLI はエージェントが行動する前にユーザーに確認を求めることができ、また OpenHands は Invariant Labs と共同開発したセキュリティアナライザーを追加している。これはエージェントが実行しようとしているアクションを潜在的な脅威について評価し、立ち止まって明示的な許可を求めたり、続行を拒否したりできる。Kubernetes のデプロイメントで OpenHands をセルフホストする組織は、さらにネットワークポリシーと eBPF のツールによってサンドボックス内のエージェントを制限できる。投稿はまた、エージェントが悪意のある指示をどれだけ容易に拒否するかは、それを動かすモデルに左右されると報告している。

## 採用とエコシステム

評価ベンチマークはプラットフォーム自体に組み込まれているため、そこに含まれるベンチマークも提供価値の一部である。紹介論文は、現在組み込まれているベンチマークに基づく 15 の難易度の高いタスクでエージェントを評価した結果を報告している。対象はソフトウェアエンジニアリング（[[Dataset/swe-bench]] などが挙げられている）と Web 閲覧（WebArena などが挙げられている）にわたる。

1 周年記念の投稿は、OpenHands が、定型作業を自動化する個人の開発者にも、複雑なリファクタリングプロジェクトに取り組む大規模なチームにも使われていると述べている。そして、プロジェクトの 2 年目に向けて 4 つの目標を掲げている。当時ベータ版だった OpenHands Cloud の一般公開（ユーザー自身のサーバーなしで OpenHands を動かし、ブラウザ、モバイルデバイス、GitHub から利用できる）、SWE-Bench などのベンチマークにおける中核的な精度と、確実にこなせるタスクの範囲の両面でのエージェントの継続的な改善、より優れた CLI や Jira、Linear といったタスク管理ツールを含む統合の拡充、そしてユーザーの好み、組織のポリシー、ワークフローに合わせたカスタマイズ性の向上である。
