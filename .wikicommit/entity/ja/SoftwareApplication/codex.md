Codex は [[Organization/openai]] のソフトウェアエンジニアリングエージェントである。2025年5月16日にリサーチプレビューとして公開され、「多数のタスクを並列に処理できるクラウドベースのソフトウェアエンジニアリングエージェント」と記述された。機能を書き、コードベースについての質問に答え、バグを修正し、プルリクエストを提案することができ、各タスクはユーザーのリポジトリをあらかじめ読み込んだ独自のクラウドサンドボックスで実行される。のちの OpenAI の製品ページは、Codex を3つの面——ChatGPT 内の Codex、Codex の IDE 拡張、[[SoftwareApplication/codex-cli]]——から到達できる単一のエージェントとして提示しており、それらはユーザーの ChatGPT アカウントによってつながっている。

公開時のモデルは `codex-1` で、ソフトウェアエンジニアリング向けに最適化された OpenAI o3 の一版であり、さまざまな環境における実世界のコーディング作業に対する強化学習で訓練されたと記述されている。掲げられた狙いは、人間のスタイルとプルリクエストの好みを映したコードを生成すること、指示に正確に従うこと、そしてテストが通るまで反復的に実行することである。OpenAI 自身の比較上の主張は、`codex-1` が o3 よりも「一貫して、人間のレビューと標準的なワークフローへの統合に即座に供せるきれいなパッチを生み出す」というものだ。

## 概要

公開時の設計では、エージェントには ChatGPT のサイドバーから仕事が割り当てられる。プロンプトに加えて、タスクを割り当てる **Code** か、コードベースについて質問する **Ask** である。各タスクは別個の隔離された環境で独立に処理され、そこでエージェントはファイルを読み書きし、テストハーネス、リンタ、型チェッカーを含むコマンドを実行できる。OpenAI は典型的な完了時間を複雑さに応じて1分から30分のあいだとし、進行はリアルタイムで観察できるとしている。完了時、エージェントは自身の環境で変更をコミットし、OpenAI が検証可能な証拠と呼ぶもの——ターミナルのログとテスト出力の引用——を提供するため、各ステップを追跡できる。その後ユーザーはレビューし、修正を求め、GitHub のプルリクエストを開き、あるいは変更をローカルへ取り込むことができる。

Codex はリポジトリに置かれた [[DefinedTerm/agents-md]] ファイルを読み、コードベースをどう辿るか、テストのためにどのコマンドを実行するか、プロジェクトの慣行にどう従うかを学ぶ。この依存についての OpenAI の枠づけはアナロジーである。「人間の開発者と同じく、Codex のエージェントは設定済みの開発環境、信頼できるテスト環境、明確なドキュメントが与えられたとき最も良く働く」。同時に、コーディングの評価と社内のベンチマークにおいては、AGENTS.md ファイルやカスタムのスキャフォールディングがなくても `codex-1` は高い性能を示すとも述べている。

公開時のサンドボックス化は厳格であった。エージェントは安全に隔離されたクラウドコンテナの内側で完全に動作し、タスクの実行中はインターネットアクセスが無効にされ、GitHub リポジトリ経由で提供されたコードと、ユーザーのセットアップスクリプトによって事前にインストールされた依存関係だけに限られ、外部のウェブサイト、API、サービスへのアクセスはなかった。2025年6月3日のローンチ記事への更新は、Codex の ChatGPT Plus ユーザーへの拡大と、タスク実行中のインターネットアクセスの有効化の双方を記録している。

## 機能

OpenAI の製品ページは、自らの枠づけで次の能力を述べている。

- 日常的なプルリクエストから、機能の構築、複雑なリファクタリング、移行にまで及ぶと記述される仕事の、端から端までのタスク完遂。
- マルチエージェントのワークフロー。組み込みの worktree とクラウド環境により、エージェントがプロジェクトをまたいで並列に働く——「数週間分の仕事を数日で」完了するという主張である。
- チームの標準、ワークフロー、働き方を Codex に教える仕組みとしての [[DefinedTerm/agent-skills]]。タスクをまたいで一貫して適用されるため、エージェントに必要な監督が減る。
- Issue のトリアージ、アラートの監視、CI/CD といった、スケジュールされた常時稼働のバックグラウンド作業。
- コードレビュー。より周到な設計、包括的なテスト、シグナルの強いレビューによって Codex が品質の基準線を引き上げ、問題が早期に捕捉されるという主張である。

ローンチ記事は、当時欠けていたものについて率直である。フロントエンドの作業のための画像入力と、タスクの途中でエージェントの進路を修正する手立てである。またリモートのエージェントへ委譲することは対話的な編集よりも時間がかかり、それには「慣れが要るかもしれない」とも述べている。

## 沿革

Codex は2025年5月16日にリサーチプレビューとして公開され、ChatGPT Pro、Enterprise、Business のユーザーへ世界的に展開された。Plus と Edu のサポートは近日中とされ、2025年6月3日の更新が Plus での提供開始を記録している。OpenAI は当初の一定期間は無償で寛大なアクセスを提供し、その後はレート制限付きのアクセスとオンデマンドの従量課金になると述べていた。

ローンチ記事は CLI 側の変更——o4-mini から派生した `codex-1` のより小さな版で、`codex-mini-latest` として利用可能——も発表しており、これは [[SoftwareApplication/codex-cli]] で扱われている。

述べられた方向性は収束である。OpenAI は、AI ツールとのペアリングはすでに業界の常態になっていると書きつつ、「ChatGPT の Codex が導入した非同期でマルチエージェントのワークフローが、エンジニアが高品質なコードを生み出す事実上の方法になる」と予測し、リアルタイムのペアリングとタスクの委譲は最終的に IDE と日常のツールにまたがる1つのワークフローへ収束するだろうと述べた。挙げられたロードマップの項目は、タスク途中での誘導、実装戦略についての協働、進捗の能動的な報告、そして Codex CLI、ChatGPT Desktop、あるいは Issue トラッカーや CI システムからのタスク割り当てであった。OpenAI はその後このローンチ記事を古いものと明示し、読者を現在の製品ページへ案内している。
