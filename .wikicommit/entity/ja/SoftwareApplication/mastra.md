Mastra は、[[DefinedTerm/llm-based-multi-agent-system]] を設計するための、Web 開発者を対象とした TypeScript ファーストのフレームワークである。ソースが比較する 6 つの協調フレームワークの 1 つであり、ソースの説明は、このフレームワークがどのように協調を行うかと同じくらい、このフレームワークが前提とする環境についてのものである。挙げられている利点は、TypeScript とのネイティブな統合、既存の REST API との連携、グラフベースのワークフロー、そして別個の AI インフラストラクチャを立ち上げる必要がないことである。

## 機能

ソースによる説明は短く、仕組みよりも適合性に関するものである。最適な用途として挙げられているのは Web アプリケーションと TypeScript プロジェクトであり、同じ章でフレームワークをアーキテクチャパターンに対応づけた箇所では、[[SoftwareApplication/langgraph]] と並んで **ハイブリッド** パターンに適したものとして名前が挙げられている。ハイブリッドパターンとは、グローバルな意思決定のための集中的な制御と、ローカルな最適化のための分散的な実行を組み合わせるものである。この対応づけの理由として括弧書きで示されているのは、Mastra がビジネスロジックと協調フローを組み合わせているという点である。

## 採用とエコシステム

フレームワークの選択についてのソースの捉え方は、他のフレームワークと同様に Mastra にも当てはまる。ソースは、その選択は機能の比較ではなくアーキテクチャ上の判断であり、市場にある協調フレームワークは、エージェント間での選択的かつ意味的なコンテキストの受け渡しという根本的な問題を解決していないと論じている。いずれのフレームワークも、すべてを共有する（遅く高コストである）か、要約を共有する（詳細が失われる）かのどちらかである。フレームワークが提供するのは仕組みであり、注意を払うべきなのは依然として協調のオーバーヘッドである。
