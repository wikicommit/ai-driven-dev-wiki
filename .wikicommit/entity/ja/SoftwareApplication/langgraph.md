LangGraph は、[[BlogPosting/agentic-engineering-swarms-of-ai-agents]] が LangChain のツール群のなかに見いだす 3 つの中核的な抽象化の 1 つであり、残りはエージェントの可観測性と評価のための LangSmith、そして長期記憶を通じてエージェントが学習し改善するのを助けるライブラリである LangMem である。そのなかでの LangGraph 自身の役割は、制御可能なエージェントオーケストレーションである。

同記事では、その中核的な抽象化は状態を持つノードからなるグラフとして説明されており、これによりエージェントが生成した計画に基づいてカスタムワークフローを構築できる。Jimmy Song のオンラインハンドブック『智能体构建指南』のある章は、同じ形をマルチエージェントの側から述べている。エージェントがノードであり、エージェント間の通信がエッジであり、状態がグラフ全体を流れる。

## 機能

同記事は、LangChain のツール群（LangGraph と LangSmith、LangMem）の上に構築した自らの実装を、エージェント型エンジニアリングを実験環境から外に出すための本番要件として挙げる特性に照らして評価した。その特性とは、ステップ・エージェント・リトライをまたいで永続する状態管理とチェックポイント、誰が何をいつなぜ決定したかを記録する監査証跡、外部の記録システムや MCP 形式のツールゲートウェイとのインターフェース互換性、エージェントが認可されたアクションを実行することを保証する決定論的な実行モデル、そしてエージェント間通信プロトコルをまたぐ相互運用性および他のフレームワークで構築されたエージェントとの相互運用性である。

同記事が示す具体例では、ワーカーエージェントが LangGraph を使って自らのワークフローをオーケストレーションし（エンジニアの自然言語による意図を分析し、MCP ツールを通じて関連するコンテキストを取得する）、次に LangGraph のチェックポイントと状態追跡の仕組みを使って、複数ステップの計画を 1 ステップずつ実行しながら実行状態を追跡する。実行の最後に、エージェントは実行された計画がメモリにチェックポイントされた状態と一致することを検証する。

ハンドブックの章は、グラフが特に協調にもたらすものを補足している。呼び出し順序と状態遷移を明示することで、サブタスク間の依存関係を制御し、並列処理の衝突を避けられる。また、グラフの永続化されたグローバル状態はエージェント同士が通信するチャネルを兼ねており、これにより各エージェントの意思決定の経路を分析しやすくなる。状態スナップショットとログを記録する場として、同章は LangSmith を挙げている。同章の説明における弱点はその柔軟性の代償、すなわち高い複雑性のオーバーヘッドであり、強みは完全な状態管理、ターンをまたぐ永続的な記憶、そしてエージェント間の相互作用を状態機械としてモデル化できることである。

## コンテキストエンジニアリングのサポート

LangChain のブログ記事 [[BlogPosting/langchain-context-engineering]] は、LangGraph の機能を、同記事が挙げる 4 つの [[DefinedTerm/context-engineering]] の戦略（書き込み、選択、圧縮、分離）に対応づけている。そこでは LangGraph は低レベルのオーケストレーションフレームワークとして提示されており、開発者はエージェントをノードの集合としてレイアウトし、各ノードのロジックを定義し、ノード間で受け渡される状態オブジェクトを定義する。コンテキストの書き込みについては、チェックポイントを使ってエージェントの全ステップにわたってエージェントの状態を永続化する、スレッド単位の短期記憶（スクラッチパッドとして利用可能）と、多数のセッションにわたってコンテキストを永続化する長期記憶（ユーザープロファイルのような少数のファイルの集合としても、より大きな記憶のコレクションとしても保持できる）を説明しており、LangMem ライブラリがさらなる抽象化を提供するとしている。コンテキストの選択については、各ノード内で状態を取得でき、各ステップでモデルが何を見るかをきめ細かく制御できること、長期記憶は記憶のコレクションに対する埋め込みベースの検索を含む取得をサポートすること、そして LangGraph Bigtool ライブラリがツールの説明に対してセマンティック検索を適用することを述べている。圧縮については、メッセージリストを要約またはトリミングする組み込みユーティリティと、要約ノード、あるいはツール呼び出しノード内の要約ロジックを挙げている。分離については、ツール呼び出しから得たコンテキストを必要になるまでモデルから隠しておく状態フィールドに格納すること、サンドボックスのサポート、そしてマルチエージェントアーキテクチャのための supervisor ライブラリと swarm ライブラリを説明している。これらは LangChain 自身による自社製品の説明である。

## エージェントランタイムとして

LangChain の Harrison Chase は [[BlogPosting/agent-frameworks-runtimes-and-harnesses]] において LangGraph を [[DefinedTerm/agent-runtime]] に分類し、[[DefinedTerm/agent-framework]] である [[SoftwareApplication/langchain]] や、[[DefinedTerm/agent-harness]] である [[SoftwareApplication/deep-agents]] と区別している。彼の説明によれば、LangChain は本番運用に耐えるエージェントランタイムをゼロから構築することを目指しており、それが提供するインフラストラクチャは主に永続的実行（durable execution）であり、あわせてストリーミング、ヒューマン・イン・ザ・ループのサポート、スレッドレベルおよびスレッド横断の永続化を提供する。彼はこれに最も近いプロジェクトとして、Temporal、Inngest、その他の永続的実行エンジンを挙げている。同じ記事は、LangChain 1.0 はそのランタイムを活用するために LangGraph の上に構築されていると述べ、LangGraph はおそらくランタイムとフレームワークの両方として説明するのが最も適切だと認めている。

## 採用とエコシステム

同記事の著者たちは、複数のエージェントフレームワークを本番要件への適合度に基づいて評価したうえで、自らのエージェント型エンジニアリングの研究に LangChain のフレームワークを選び、これを状態を持ち、協調的で、ガバナンス可能なエージェントシステムのための実行モデルと特徴づけている。彼らのリファレンス実装では、LangGraph は、長期的な状態の保存に使われる LangMem、そしてエンドツーエンドのトレーサビリティとエージェント型ワークフローのシステム全体の見通しを得るために実行トレースを記録する LangSmith と並んで配置されている。

ハンドブックの章は、LangChain 1.0 と歩調を合わせて 2025 年 10 月にリリースされた **LangGraph 1.0** について報告し、2026 年時点で最もインストールされているオープンソースのエージェントフレームワークだとしている。同章の説明によれば、1.0 リリースは単一エージェントの抽象化、ミドルウェア、記憶の仕組み、グラフによるオーケストレーションを安定させ、プロジェクトを急速に反復する研究用のコードベースから、チームが長期にわたって依存できるインフラストラクチャへと移行させた。同章の LangGraph に関する節は、グラフが 1 つのシステム内で報告関係とピア接続の両方を表現できることを根拠に、LangGraph を階層型とハイブリッド型のアーキテクチャパターンに対応づけている。また、4 つのパターンの比較表では、Map-Reduce 構成における集中制御のために集中型パターンの下にも LangGraph を挙げている。比較対象の代替として同章が挙げるのは [[SoftwareApplication/crewai]]、[[SoftwareApplication/agno]]、[[SoftwareApplication/mastra]]、[[SoftwareApplication/agent-development-kit]]、[[SoftwareApplication/strands-agents]] である。同章は、LangGraph についての説明を裏づける数値や測定結果を何も示していない。
