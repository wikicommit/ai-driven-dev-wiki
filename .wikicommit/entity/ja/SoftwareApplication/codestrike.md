codestrike は、CrowdStrike が MIT ライセンスで公開している、Go で書かれたオープンソースの AI 駆動型プルリクエストレビューツールである。プルリクエストを与えると、その差分に対して LLM によるレビューを実行し、結果を 1 件のコメントとしてプルリクエストに投稿する。

このプロジェクトは自らをパブリックプレビュー段階にあり、安定版 1.0 のリリースに向けて活発に開発中であると説明しており、機能はまだ変更される可能性がある。ユーザーには試用やテストを勧める一方で、当面は本番環境への導入を避けるよう求めている。

## 機能

codestrike は GitHub とは個人用アクセストークンで、モデルとは OpenAI 互換 API を通じてやり取りする。この API のベース URL は設定可能なため、モデルプロバイダーは固定されていない。レビューはコマンドラインから、`codestrike review` にプルリクエストの URL を指定して開始する。フラグを使うと、差分だけでなくファイルの内容全体を取得させる（より多くのトークンを使い、時間もかかるが、より充実したレビューになる）、セキュリティやパフォーマンスといったレビューのペルソナを選択する（各ペルソナはプロンプトファイルに対応する）、レビューをコメントとして投稿する代わりに出力するドライランを実行する、といったことができる。また、レビュー用エンドポイントを持つ常駐型の HTTP サービスとして動作させることもでき、CI パイプライン、Webhook、チャットボットといった外部システムが API 経由でレビューを起動できる。

レビューの振る舞いは YAML 設定ファイルで指定する。設定できるのは、システムプロンプト、トーン、最大パッチサイズや無視するパス（ベンダリングされた依存関係、ロックファイル、minify されたアセット）といったガードレール、そして各モデルのコンテキストウィンドウのうち入力に使用してよい割合として表されるトークン予算（応答用のトークンは確保される）である。CLAUDE.md などのプロジェクトファイルをレビュアー向けの追加コンテキストとして読み込むことができ、オプションによってこれをレビュー対象リポジトリ内の [[DefinedTerm/agents-md]] ファイルや Cursor のルールにまで広げられる。モデルは、レビューコメントを生成する前に各ファイルの変更についてステップバイステップで推論するよう求められ、その推論ブロックは最終出力から取り除かれる。README はこれを [[DefinedTerm/chain-of-thought]] プロンプティングと呼んでいる。

## 採用とエコシステム

codestrike は [[SoftwareApplication/cursor]] 向けのプラグインとして提供されており、Cursor のエージェントがチャットから直接プルリクエストをレビューできるようにするプルリクエストレビュースキルを含んでいる。このスキルは codestrike のコマンドラインツールを呼び出すため、ユーザーはそれをビルドしてパスの通った場所に置いておく必要がある。MCP サーバーは今後の予定作業として挙げられている。
