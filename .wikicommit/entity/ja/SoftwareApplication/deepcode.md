DeepCode は、香港大学の研究者が公開しているオープンソースのエージェント型コーディングフレームワークで、ドキュメントから完全かつ実行可能なコードリポジトリを合成するためのものである。その中心的な用途は、論文を唯一の仕様として、科学論文の実験をコードとして再現することにある。ソースコードは GitHub の HKUDS/DeepCode で MIT ライセンスのもとで公開されている。

プロジェクトの README は、その後の再構築について説明している。DeepCode v2.0 では、実際のソフトウェアプロジェクトを構築・修正・理解・改善するための汎用コーディングエージェントフレームワークが導入され、プロジェクト本来の研究方向であった論文再現ワークフローの Paper2Code は、研究再現専用のワークフローとして残されている。README はプロジェクトが目指す 4 種類の深さとして、コンテキスト、実行、検証、継続性を挙げ、エージェントを忙しそうに見せるためではなく、実際のソフトウェアエンジニアリング作業をより確実に完了させるために設計されていると述べている。

## 機能

汎用コーディングエージェントとしての DeepCode は、コードの読み取りと検索、ファイルの編集、パッチの適用、コマンドやテストの実行を行い、その結果をもとに作業を継続する。その際、ツール呼び出し、実行の進捗、ファイルの変更は可視化されたまま保たれる。クライアントはターミナルインターフェース、デスクトップアプリ、ブラウザベースの Web インターフェースの 3 種類があり、いずれも共有された 1 つのローカルバックグラウンドサービスに接続して、プロジェクト、セッション、モデル、スキル、権限、ゴールを共有する。クライアントを閉じても受け付け済みの作業は動き続け、別のクライアントから同じタスクに再接続できる。セッションはローカルに保存され、会話とともにツール呼び出し、権限の判断、ゴール、モデル設定、検証記録を保持する。長い会話は[[DefinedTerm/compaction]]によって短縮される。

1 回の応答では終わらない作業については、ユーザーが DeepCode に自然言語でゴールを与える。README はこの機能をゴール駆動の Loop Engineering と呼んでいる。エージェントはそのゴールを軸に分析・実装・検証・修復を続け、その間ユーザーは情報を追加したり、ゴールやその受け入れ基準を修正したり、次の指示をキューに入れたり、一時停止・停止・再開したりできる。完了判定はエビデンス駆動で行われる。ハードコードされた単一のルールではなく、DeepCode はテスト結果、ビルド出力、静的チェック、診断、差分など、タスクに合ったエビデンスを選択し、検証が失敗すればそれが次の修復への入力となる。README によれば、完了またはブロックの結果を要求するのは作業中のエージェント自身であり、DeepCode は汎用的なホスト側ルールがあらゆるコーディングタスクを検証できるかのように装うことなく、所有権、ライフサイクル、権限、予算の境界を強制する。

すべてのプロジェクトは、エージェントがその中で実行する前に明示的に信頼される必要があり、各セッションは ask、read only、full access の 3 つの[[DefinedTerm/permission-modes]]のいずれかで動作する。さらに個々のツールについても allow、ask、deny を設定できる。その他の機能として、ユーザー自身の API キーによるさまざまなモデルプロバイダーへの接続、再利用可能な [[DefinedTerm/agent-skills]]、ローカルプラグイン、[[DefinedTerm/model-context-protocol]] サーバー、分離された [[DefinedTerm/git-worktrees]] で作業する並列エージェント（競合は黙って上書きされるのではなく明示的に表示される）、外部サブエージェントとしての [[SoftwareApplication/openai-codex]] や [[SoftwareApplication/claude-code]] への委任、そして保存した指示を同じエージェントと権限のもとでオンデマンドまたはスケジュールに従って実行するオートメーションがある。

論文再現においては、このフレームワークは PDF または Markdown 形式の対象ドキュメントを受け取り、3 つのフェーズを経てリポジトリを生成する。Blueprint Generation フェーズでは、ドキュメントを構造化された実装ブループリント（プロジェクトのファイル階層、モジュールごとのコンポーネント仕様、検証プロトコル、実行環境の仕様）に落とし込む。Code Generation フェーズでは、生成済みファイルのステートフルなメモリ（CodeMem）と、必要なときにだけ外部リポジトリからパターンを取り込む検索拡張システム（CodeRAG）を用いて、ブループリントに沿ってファイルを反復的に合成する。Automated Verification フェーズでは、静的解析の後にサンドボックス内での実行を行い、実行時エラーを反復的な修復ループにフィードバックする。README は Paper2Code のアーキテクチャを、中央のオーケストレーションエージェントが、意図理解、ドキュメント解析、コード計画、コード参照マイニング、コードインデックス作成、コード生成を担う専門エージェントを調整する構成として説明している。

PaperBench Code-Dev ベンチマーク（ICML 論文 20 本、自動判定器による採点）では、平均 73.5±2.8 のスコアを記録したと報告されており、汎用 LLM エージェントの最良ベースラインの 43.3±1.1、科学コードに特化したエージェントのベースライン（PaperCoder）の 51.1±1.4 を上回る。5 本の論文によるサブセットでは 0.8541 を記録し、Claude Code の 0.5871、Cursor の 0.5841（いずれも DeepCode と同じベースモデルである Claude Sonnet 4.5-thinking で実行）、そして GPT-5 Codex-high で実行された Codex の 0.3997 を上回った。

## 採用とエコシステム

このフレームワークは、特に科学論文の再現と汎用的なドキュメントからソフトウェアへの合成を対象に評価されており、その論文 [[ScholarlyArticle/deepcode-open-agentic-coding]] では、汎用の商用コーディングエージェント（Cursor、Claude Code、Codex）と、科学コード再現に特化したツール（PaperCoder）の両方と比較されている。README は、PaperBench の結果はそのベンチマークに固有のものであり、汎用コーディングのベンチマークでも、継続的に更新される製品との比較でもないと注意を促している。

プロジェクトの指示は [[DefinedTerm/agents-md]] または DEEPCODE.md から読み込み、既存の DeepCode 形式および Claude 形式のスキルディレクトリを移行せずにそのまま読み込む。
