Superpowers は、自らをコーディングエージェントのための完全なソフトウェア開発方法論と説明している。これは、組み合わせ可能な一連の [[DefinedTerm/agent-skills]] と、エージェントが確実にそれらを使うようにするための初期指示の上に構築されている。作者と Prime Radiant のメンバーによって開発されており、Prime Radiant はエンタープライズ利用向けの商用サポートも提供している。GitHub 上で MIT ライセンスのもとで公開されている。

README は、ユーザー側から見た体験を次のように説明している。ユーザーが何かを作ろうとしているとエージェントが判断すると、エージェントはいきなりコードを書き始めるのではなく、ユーザーが本当にやろうとしていることを尋ね、会話から仕様を引き出し、読み切れる程度の短いまとまりに分けて提示する。設計が承認されると、エージェントは「熱意はあるがセンスが悪く、判断力がなく、プロジェクトの文脈を知らず、テストを嫌うジュニアエンジニア」でも従えるほど明確であることを意図した実装計画を書き、red/green のテスト駆動開発、YAGNI、DRY を重視する。ユーザーが開始を指示すると、[[DefinedTerm/subagent-driven-development]] のプロセスを実行し、エージェントが各タスクを進める一方でその作業が検査・レビューされる。README によれば、エージェントが計画から逸れることなく一度に 2 時間ほど自律的に作業することも珍しくない。スキルは自動的に発動するため、特別に何かを呼び出す必要はない。

## 機能

README は基本的なワークフローを、それぞれ特定の時点で発動する一連のスキルとして示しており、エージェントはどのタスクの前にも関連するスキルがないかを確認すると述べている（「提案ではなく、必須のワークフロー」）。

1. **brainstorming** — コードを書く前に、質問を通じて大まかなアイデアを練り上げ、代替案を検討し、検証のために設計をセクションごとに提示して、設計ドキュメントを保存する。
2. **using-git-worktrees** — 設計の承認後、新しいブランチ上に隔離されたワークスペースを作成し、プロジェクトのセットアップを実行して、テストがクリーンな状態から始まることを確認する（[[DefinedTerm/git-worktrees]] を参照）。
3. **writing-plans** — 承認された設計を 1 つあたり 2〜5 分程度の小さなタスクに分割し、それぞれに正確なファイルパス、完全なコード、検証手順を付ける。
4. **subagent-driven-development** または **executing-plans** — タスクごとに新しいサブエージェントを割り当てて各タスクの後にレビューを行う（最も徹底的とされる）か、現在のセッション内ですべてのタスクをインラインで実装し、最後にブランチ全体を新たな目で 1 回レビューする（最も安価）かのいずれかを行う。
5. **test-driven-development** — 実装中に RED-GREEN-REFACTOR を強制し、テストより先に書かれたコードは削除する。
6. **requesting-code-review** — タスクの合間に計画に照らしてレビューし、問題を深刻度別に報告する。重大な問題があると先へ進めない。
7. **finishing-a-development-branch** — テストを確認し、マージ、プルリクエストの作成、ブランチの保持または破棄といった選択肢を提示して、ワークツリーを片付ける。

より広いスキルライブラリには、体系的なデバッグ（4 段階の根本原因分析プロセス）、完了前の検証（verification-before-completion）、並列エージェントの割り当て、コードレビューの受け入れ、そして新しいスキルを作成するための writing-skills スキルが加わる。ライブラリ自身の説明では、サブエージェント駆動開発は 2 段階のレビュー、すなわちまず仕様への準拠、次にコード品質のレビューを行う。diagnosing-superpowers スキルは、スキルが発動すべきでないときに発動した、発動すべきときに沈黙した、あるいはエージェントが計画を無視したといった場合にセッションのトランスクリプトを読み、行単位の証拠を添えて何が起きたかを報告する。プロジェクトが掲げる哲学は、テストファーストの開発、当て推量よりも体系的なプロセス、複雑さの削減、主張よりも証拠である。

## 採用とエコシステム

インストール方法はハーネスごとに異なり、使うハーネスごとに繰り返す必要がある。README は、[[SoftwareApplication/claude-code]]（Anthropic の公式プラグインマーケットプレイス、またはプロジェクト独自のマーケットプレイス経由）、[[SoftwareApplication/google-antigravity]]、[[SoftwareApplication/openai-codex]] のアプリと CLI、[[SoftwareApplication/cursor]]、Devin CLI、Factory Droid、[[SoftwareApplication/gemini-cli]]、[[SoftwareApplication/github-copilot-cli]]、Grok Build CLI、Kimi Code、[[SoftwareApplication/opencode]]、Pi、Qwen Code、[[SoftwareApplication/hermes-agent]]、Muse へのインストール手順を示している。そのほとんどでは、セッション開始時にブートストラップが注入される。README は、Hermes にはコンパクション後のフックがないため、最初のターンを越えてコンパクションされるほど非常に長いセッションではブートストラップが失われ、スキルが発動しなくなる場合があると注記している。

このプロジェクトは原則として新しいスキルのコントリビューションを受け付けておらず、スキルへの変更はサポート対象のすべてのコーディングエージェントで動作することを求めている。スキルの振る舞いは、別途用意された評価ハーネスでテストされる。brainstorming スキルのオプションのビジュアルコンパニオンは、デフォルトでプロジェクトのウェブサイトから Prime Radiant のロゴを読み込み、そのリクエストには使用中の Superpowers のバージョンが含まれるが、プロジェクト、プロンプト、コーディングエージェントの詳細は含まれない。README の説明によれば、スキルやプラグインは作者に何のフィードバックも返さないため、これがどのバージョンが何人くらいに使われているかをプロジェクトが大まかに把握する手段となっている。これはオプションであり、環境変数、または Claude Code 自体のテレメトリのオプトアウト設定によって無効にできる。
