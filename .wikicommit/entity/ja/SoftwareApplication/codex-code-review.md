Codex Code Review は [[SoftwareApplication/openai-codex]] のコードレビュー機能である。OpenAI は GitHub リポジトリでこれを有効にする方法を文書化しており、`@codex review` で直接レビューを依頼することもできる。[[BlogPosting/custom-code-review-rules-for-codex]] は、この機能が [[DefinedTerm/agents-md]] に書かれたリポジトリ独自のルールを使って、コードベース固有の問題を検出し、各指摘の根拠となるガイダンスを作成者に示せるようになったと発表した。

OpenAI はこの機能を、コーディングエージェントがより多くのコードを生み出すようになった結果、レビューがボトルネックになっていることへの対応として位置づけている。リポジトリのルールによって、普段は少数の経験豊富なレビュアーの頭の中にある文脈（維持すべき API の契約、ログに出してはならないデータなど）を、それが適用されるコードのすぐそばに置くことができ、リポジトリのその部分に不慣れなコントリビューターやコーディングエージェントもその恩恵を受けられる。

## 機能

ルールは、Codex のコーディングタスクを導くのと同じファイルである `AGENTS.md` に記述する。リポジトリ全体に関わるルールはルートに、サービス固有のルールは該当するディレクトリに置く。レビューの際、Codex は変更されたファイルを対象とするガイダンスを適用し、指摘の中でそれを引用する。OpenAI が挙げる例は、Codex リポジトリにある破壊的変更に関するルールで、Codex Cloud が利用する app-server の通知を保護するものである。コンパイルは通るリネームであっても、利用側は既存の名前で待ち受けているため、作成者はその名前を維持するか後方互換性のあるイベントを追加すべきだと説明する指摘が付くことになる。

OpenAI の報告によれば、主要な評価スイートにおいて、ルールに導かれたバリアントは必要な独自の指摘の 98% を検出したのに対し、ベースラインの対照群では 58.3% であった。また、問題のない変更に対して不要な指摘を避けられるか、ルールの範囲外にある通常のバグも引き続き検出できるか、指摘が関連するガイダンス・場所・優先度を明示しているかについてもテストしたという。

## 採用とエコシステム

OpenAI のガイダンスは、決定的・機械的なチェックはテスト、リンター、CI に任せ、リポジトリのルールは判断を要する事柄のために取っておくこと、そして重大かつ自明でない不変条件に関する 2〜3 個のルールから始め、代表的なプルリクエストで得られた結果をもとにそれらを洗練していくことである。OpenAI はこのツールを強制の仕組みではなく追加のレビュアーとして説明しており、テスト、ブランチ保護、必須の承認が引き続き厳格な強制を担う。このツールは、このウィキで [[DefinedTerm/agentic-code-review]] のもとに扱われている他の AI レビューツールと並ぶものである。
