Claude Code はコマンドラインインターフェースを備えたエージェンティックな AI コーディングツールであり、2025年2月に、CLI とエージェントをローンチ時から利用可能な状態で公開された。[[ScholarlyArticle/configuring-agentic-ai-coding-tools]] はこれを主要な5つのエージェンティックコーディングツールの1つとして扱っており、その採用状況の調査は Claude Code をそれらのうち最も広く存在するものだと見出している。そうしたツールを何かしら使っている、標本となった 2,926 の GitHub リポジトリのうち 1,310 に現れたのである。

純粋に受動的な会話型のアシスタントとは異なり、この種のエージェンティックなツールは定められた目的を達成するために自ら動き、開発環境と自律的に関わり、プロジェクトの成果物、外部のデータ、コマンドラインのツールを用いる。Claude Code は、このかたちの中心的なエージェントループを実装した最初期のツールの1つだった。

## 概要

同研究は Claude Code を、検討されたツールのうち最も広い設定のフットプリントを持つもの——そのユーザーが最も幅広いリポジトリレベルの設定機構を用いているもの——と特徴づけている。これを採用したリポジトリはまた、別のツールと組み合わせて現れる可能性も最も高かった。観測された最も一般的な組み合わせは Claude Code と [[SoftwareApplication/github-copilot]] であり、128 のリポジトリに見られた。

## 機能

Claude Code は、同研究が目録化した8つの設定機構のうち7つを露出させており、それぞれがリポジトリレベルの成果物に裏づけられている。

- [[DefinedTerm/context-files]]——`CLAUDE.md`。標本中で最も一般的なコンテキストファイルの種別であり、1,661 ファイル、リポジトリの 45.4% に存在する
- 設定——`.claude/settings.json` と `.claude/settings.local.json`
- [[DefinedTerm/agent-skills]]——`.claude/skills/`
- [[DefinedTerm/subagents]]——`.claude/agents/`
- コマンド——`.claude/commands/`
- フック——`.claude/settings.json` の内部で定義される
- MCP サーバ——`.mcp.json`

Rules の機構は提供していない。同研究はこれが代わりに [[SoftwareApplication/cursor]] のリポジトリに集中していると注記している。Claude Code のサブエージェントに固有の能力の1つは、それぞれが自前の永続的なメモリのディレクトリを持てることであり、それはやり取りをまたいで残り、デバッグの洞察のような知識を蓄積するのに使える——もっとも同研究は、標本のなかで実際にそうしたメモリファイルを保存しているリポジトリを1つも見つけなかった。

Anthropic 自身のドキュメントは、それらの設定の成果物の上に位置するセッションと規模化の制御を加えている。**プランモード**（`Shift+Tab`、あるいは `claude --permission-mode plan`）は探索を実行から切り離し、ドキュメントは explore、plan、implement、commit という4段階のワークフローを勧める——ただし範囲が明確なときにはそのオーバーヘッドは見合わないとも注記する。「差分を一文で説明できるなら、計画は飛ばせ。」**権限モード**は、どれだけが人間によって承認されるかを決める。auto モードは Pro、Max、Team のプランにおける対話的な端末と VS Code のセッションの組み込みの初期モードであり、別の分類器モデルがほとんどの行動をレビューし、範囲の逸脱、未知のインフラ、敵対的なコンテンツに駆動された行動といった危険に見えるものだけを阻む。Manual モードは他のプランにおける初期モードであり、ファイルの書き込み、Bash のコマンド、MCP のツールの前に確認を求める。割り込みを減らすために権限の許可リストと OS 水準のサンドボックスが利用できる。**チェックポイント**は各変更の前にファイルのスナップショットを取るため、`/rewind`（あるいは `Escape` の二度押し）が会話、コード、あるいはその両方を復元できる——文書化された限界として、ファイル編集のツールを通じた変更だけが追跡されるため、Bash や外部のプロセスは対象外であり、git の代わりにはならない。**セッション**はローカルに保存され `claude --continue` や `claude --resume` で再開でき、`/rename` で名前を付けられる。**非対話モード**（`claude -p`）は、CI、コミット前のフック、多数のファイルにわたるファンアウトのループのために、プレーンテキスト、JSON、ストリーミング JSON の出力に対応する。並行作業についてドキュメントは、worktree、デスクトップアプリ、ウェブ版の Claude Code、そしてエージェントチームを挙げている。

2026年3月24日の Anthropic のウェビナー資料である [[PresentationDigitalDocument/claude-code-advanced-patterns]] は、大規模なコードベースにおけるそれらの成果物の規模化の実践を加えている。CLAUDE.md の発見を階層的なもの——Claude はディレクトリツリーを遡って CLAUDE.md ファイルを集める——と記述し、ルートのファイルがシステムの概観、近代化の戦略、チームの構成を保持し、`/packages/CLAUDE.md` がコンポーネントのアーキテクチャ、技術的負債、移行の計画を保持し、その下にパッケージごとのファイルが置かれるモノレポの構成を示している。掲げられた3つの実践は、各ファイルを 200 行未満に保つこと——長いファイルはより多くのコンテキストを消費し、指示の遵守に悪影響を与えうるという理由による——、指示を `.claude/rules/` ディレクトリへ分割すること——規則のフロントマターの `paths` フィールドがそれを特定のファイルパスへ限定する——、そして無関係な CLAUDE.md ファイルが矛盾する指示を持ち込まないよう `claudeMdExcludes` の設定を使うこと——管理ポリシーによる CLAUDE.md ファイルは除外できないと注記されている——である。同じ資料は2つの決定表を提示しており、各機構に順位ではなく別個の条件を割り当てている。プロジェクトの文脈と繰り返される指示には CLAUDE.md、ライフサイクルのイベントにおける決定的な自動化にはフック、外部のツールとデータへのアクセスには MCP（`mcp add <server-name>` で追加する）。そして並行作業については、無関係なタスクには `claude --worktree` を伴う別々の端末、隔離された文脈を持つ焦点の絞られたサブタスクにはサブエージェント、そして1つの大きなタスクを協調する作業の流れへ分けるにはエージェントチーム——そこではリサーチプレビューと記述されている——である。

2つの統合が、このツールを端末ではなくデリバリのパイプラインの内側へ置く。**GitHub Actions における Claude Code** は、資料によれば Claude Agent SDK に支えられており、`@claude` をタグ付けすることでプルリクエストと Issue への編集をリモートから起動でき、Claude Code の内部から `/install-github-app` を実行してインストールする。**Code Review** はエージェントチームに基づくレビューのシステムであり、その特化したエージェントはコードベース全体の文脈を担い、深刻度で評定されたバグとセキュリティ上の欠落についてインラインのコメントを投稿する。有効化は管理者の作業であり、Claude Code の設定、GitHub App、リポジトリごとのオプトインにまたがる。

Anthropic 自身のドキュメントは、それらの成果物を4つの名前の付いた拡張点へ整理し、互いの代替として相互参照している。モデルに追加の指示と実行可能なコマンドを与えるための [[DefinedTerm/agent-skills]]、隔離された文脈でタスクを走らせるための [[DefinedTerm/subagents]]、ライフサイクルのイベントにおける決定的な自動化のための [[DefinedTerm/agent-hooks]]、そしてプロジェクトをまたいで共有するために拡張をパッケージ化するプラグインである。

このうち2つは、あらかじめ中身の入った既定を伴って提供される。一組の**同梱スキル**がすべてのセッションで利用可能である——ドキュメントは `/doctor`、`/code-review`、`/batch`、`/debug`、`/loop`、`/claude-api` を挙げ、別に `/run`、`/verify`、`/run-skill-generator` の三つ組を挙げている。後者は、プロジェクトのアプリを起動し、テストだけでなく実際に動いているアプリに照らして変更を確認するために存在し、`/run-skill-generator` は動作する起動のレシピをプロジェクトごとのスキルとして記録するため、後の実行や他のエージェントはそれを再発見せずに従える。`disableBundledSkills` の設定は `/doctor` を除くすべてをオフにする。モデルが自動的に委譲する**組み込みのサブエージェント**もある。Explore はファイルの発見とコード検索のための読み取り専用のエージェントであり、徹底度の水準を指定して呼び出される。Plan はプランモード中に使われる読み取り専用の調査エージェントである。general-purpose はサブエージェントが使えるすべてのツールを持つ。そして補助のエージェントとして、包括的な `claude`、`statusline-setup`、`claude-code-guide` がある。

[[TechArticle/effective-context-engineering-for-ai-agents]] は、Claude Code が内部でどうコンテキストを管理しているかを記述している。ジャストインタイムの取得の実例として挙げられており、モデルは的を絞ったクエリを書き、結果を保存し、`head` や `tail` のような Bash のコマンドを使って、オブジェクト全体をコンテキストへ読み込むことなく大量のデータを分析する。またハイブリッドな戦略の例としても挙げられる——`CLAUDE.md` ファイルはあらかじめコンテキストへ落とし込まれ、その一方で glob と grep がファイルをジャストインタイムで取得する。投稿はこれが、古びたインデックスと複雑な構文木の問題を回避すると論じる。その [[DefinedTerm/compaction]] の実装は、メッセージの履歴をモデルへ渡して要約させ、アーキテクチャ上の決定、未解決のバグ、実装の詳細を保ちつつ冗長なツールの出力を捨て、その要約と直近にアクセスした5つのファイルから続行する。

## 推奨される実践

Anthropic はベストプラクティスのガイドを公表しており、その推奨は述べられた単一の制約——コンテキストウィンドウはすぐ埋まり、埋まるにつれて性能が劣化する。ガイドはこれを管理すべき最も重要な資源と呼ぶ——を軸に整理されている。その見出しとなる推奨は、エージェントに実行できるチェックを与えること——テストスイート、ビルドの終了コード、リンタ、フィクスチャの差分、あるいはブラウザのスクリーンショット——であり、これは「見張っていなければならないセッションと、席を立てるセッションの違い」と記述される。それがなければ「終わったように見える」ことだけが唯一の停止信号となり、人間が検証のループになってしまうからだ。そしてエージェントに、成功を主張させるのではなく、テストの出力や実行したコマンドといった証拠を示させることである。

ガイドはそのチェックを4つの強制の水準へと段階的に引き上げる。プロンプトで求めること、毎ターンの後に再評価される `/goal` の条件として設定すること、ターンの終了を阻む Stop フックとして組み込むこと、あるいは第二のモデルに結果を反駁させることである。またコンテキストを積極的に管理すること（無関係なタスクのあいだで `/clear`、指示を伴う `/compact`、履歴に入れるべきでない質問には `/btw`）、探索が主コンテキストを消費しないよう調査を [[DefinedTerm/subagents]] へ委譲すること、そして作業を完了と扱う前に、新しいサブエージェントの文脈で敵対的なレビューの段階を加えることを勧める。

よくある失敗のパターンの一覧は異例なほど具体的である。無関係なタスクが無関係な情報でコンテキストを埋める「台所の流し（kitchen sink）セッション」。何度も繰り返す訂正——これに処方される対処は、2回訂正に失敗したら `/clear` して、学んだことを織り込んだより良いプロンプトを書くべきだ、というもの。重要な規則が雑音のなかに埋もれてしまう、過剰に書き込まれた `CLAUDE.md`。もっともらしく見える実装がエッジケースを扱えていない、信頼してから検証するまでの隙間。そして範囲を絞られていない調査が数百のファイルを読む、際限のない探索である。ガイドは、これらすべてを規則ではなく出発点として枠づけて締めくくり、いつ計画し、いつ探索し、いつコンテキストを蓄積させるかについて、ユーザー自身の直観を育てることを促している。

## 観測された利用

[[Report/agentic-coding-and-persistent-returns-to-expertise]] は、このツールが実際にどう使われているかについての最初の大規模な像を、2025年10月から2026年4月のあいだの、およそ23万5千人によるおよそ40万の対話的なセッションのプライバシーを保護した分析から提供している——CLI、Claude.ai、デスクトップアプリの利用であり、非対話的な利用は除外されている。Claude Code のユーザーは週あたり平均20時間このツールを使っていると報告している。

そのデータにおけるセッションのかたちは、およそ4ターンであり、各ユーザーのプロンプトが平均でおよそ10、時には100を超える Claude の行動の連鎖を引き起こし、Claude は1ターンあたり平均 2,400 語の出力を書く。チェックインのあいだにどれだけのことが起きるかは、誰が決めているかを追う——ユーザーが実行の判断の 80% 超を下す場合は1ターンあたりおよそ8つの行動、Claude が計画の判断の 80% 超を下す場合はおよそ16である。

セッションが*何のためにあるか*は、この7か月で著しく移り変わった。壊れたコードの修正に費やされる割合は 33% から 19% へ下がり、ソフトウェアの操作は 14% から 21% へ伸び、執筆とデータ分析はおよそ 10% から 20% へほぼ倍増した——デバッグから離れ、端から端までの利用へ向かう動きである。期間全体では、レポートはおよそ 56% のセッションをコードの執筆・修正・テスト・オーケストレーション、17% をソフトウェアの操作、14% を計画あるいは探索、13% を分析や散文の作成と分類している。

同じ分析の職業のデータは、このツールを開発者向けのツールとする枠づけを複雑にする。職業はおよそ 70% のセッションで推定でき、コンピュータ・数学系の職業が最大のグループだった一方で、次に大きかったのはビジネス・財務のオペレーション、芸術・デザイン・メディア、マネジメント、そして生命・物理・社会科学であり、ソフトウェア以外で最も速く伸びているのはマネジメント、営業、法務だった。これらはベンダーが自社製品について示した自社の数値である。

### 並行実行の面

[[BlogPosting/the-code-agent-orchestra]] は、単一の端末セッションを超える2つの面を記録している。[[DefinedTerm/agent-teams]] は真の並行実行のための実験的なインプロセスの機能であり、`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効になり、共有のタスクリストを通じて協調する tmux の分割ペインのなかで、独立した Claude Code のインスタンスとしてチームメイトを生み出す。**ウェブ版の Claude Code** は `claude.ai/code` にあるブラウザ版の対応物である。GitHub のリポジトリを接続し、ブラウザでタスクを記述し、作業は Anthropic が管理するクラウドの VM で走り、実行中の操舵、プルリクエストの自動作成、iOS アプリからのアクセスを備える。両者を選び分けるために Osmani が述べる心的モデルは、端末はエージェントの傍らで働くためのものであり、ウェブは委譲して席を立つためのものだ、というものである。

## 沿革

Claude Code は2025年2月に公開された。同研究の2026年2月のスナップショットの時点で、著者らはこれがまだ [[DefinedTerm/agents-md]]——彼らのデータがツールをまたぐ標準として台頭しつつあると特定する、ツール非依存のコンテキストファイルの規約——に対応していなかったと注記している。彼らはこれを、観測された作成順序のパターン——CLAUDE.md が先に現れ、AGENTS.md が後から加えられる——のありうる説明の1つとして提示している。別途、CLAUDE.md が AGENTS.md を指し示すことは彼らのデータで最も強い参照のパターンであり、311 回現れた。Claude Code を使うリポジトリの築齢の中央値は 6.2 年であり、標本全体よりわずかに若かった。

[[Book/spec-driven-development-ai-native-software-engineering]] は、このプロジェクトの成熟度についての別の尺度——Claude Code のどれだけが Claude Code によって書かれているか——を追っている。[[Organization/anthropic]] でこのプロジェクトを率いる [[Person/boris-cherny]] は、2025年5月におよそ 80% がそうだと報告した。10月までに Dario Amodei は Marc Benioff に、その数字は 90% を超えたと語った。そして2026年3月7日、Cherny は公に「Claude Code が 100% Claude Code によって書かれていることを確認できる」と投稿した。[[Person/kevin-ryan]] はこの進行——10か月で80%から100%へ——を、OpenAI の Codex 5.3 が Codex 自身によって作られたという報告と並べて、「再帰のループは閉じた」ことの証拠として引いている。
