Claude Code はコマンドラインインターフェースを備えたエージェンティック AI コーディングツールであり、2025年2月に CLI とエージェントを公開時から利用可能な形でリリースされた。[[ScholarlyArticle/configuring-agentic-ai-coding-tools]] はこれを主要なエージェンティックコーディングツール5つのうちの一つとして扱っており、その採用調査は Claude Code を5つのなかで最も広く存在するものと見出した。何らかのそうしたツールを使うサンプル 2,926 の GitHub リポジトリのうち 1,310 に現れた。

純粋に受動的な会話型のアシスタントとは異なり、この種のエージェント的ツールは定められた目的を達成するために自ら主導権を取り、開発環境と自律的にやり取りし、プロジェクトの成果物、外部のデータ、コマンドラインのツールを用いる。Claude Code はこの形の中心的なエージェントループを実装した最初期のツールの一つであった。

## 概要

研究は Claude Code を、調査対象のツールのなかで最も広い設定のフットプリントを持つものと特徴づけている。そのユーザーはリポジトリレベルの設定メカニズムを最も幅広く用いている。またこれを採用しているリポジトリは、他のツールと組み合わせて現れる可能性も最も高かった。最も多く観測された組み合わせは Claude Code と [[SoftwareApplication/github-copilot]] で、128 リポジトリであった。

## 機能

Claude Code は、研究がカタログ化した8つの設定メカニズムのうち7つを、それぞれリポジトリレベルの成果物に裏づけられた形で提供している。

- [[DefinedTerm/context-files]] — `CLAUDE.md`。サンプル中で最も多いコンテキストファイルの種類で 1,661 ファイル、リポジトリの 45.4% に存在する
- Settings — `.claude/settings.json` および `.claude/settings.local.json`
- [[DefinedTerm/agent-skills]] — `.claude/skills/`
- [[DefinedTerm/subagents]] — `.claude/agents/`
- Commands — `.claude/commands/`
- Hooks — `.claude/settings.json` の内部で定義
- MCP サーバ — `.mcp.json`

Rules の仕組みは提供していない。研究は、それが代わりに [[SoftwareApplication/cursor]] のリポジトリに集中していると指摘している。Claude Code のサブエージェントに固有の能力の一つは、自身の永続的なメモリディレクトリを持てることであり、それはやり取りをまたいで残り、デバッグの知見のような知識を蓄積するのに使える。もっとも研究は、サンプルのなかで実際にそうしたメモリファイルを保存しているリポジトリを見つけられなかった。

Anthropic 自身のドキュメントは、これらの設定成果物の上に位置するセッションとスケーリングの制御を補っている。**Plan モード**（`Shift+Tab`、または `claude --permission-mode plan`）は探索を実行から分離し、ドキュメントは explore、plan、implement、commit という4フェーズのワークフローを推奨しつつ、スコープが明確なときはそのオーバーヘッドに見合わないとも述べている。「差分を1文で説明できるなら、計画は飛ばしてよい」。**権限モード**は、どれだけを人間が承認するかを決める。auto モードは Pro、Max、Team のプランにおける対話的なターミナルおよび VS Code のセッションの組み込みの初期モードで、別個の分類モデルがほとんどの行為をレビューし、スコープの逸脱、未知のインフラ、敵対的なコンテンツに駆動された行為など、危険に見えるものだけをブロックする。他のプランでの初期モードである Manual モードは、ファイルの書き込み、Bash コマンド、MCP ツールの前に確認を求め、割り込みを減らすために権限の許可リストと OS レベルのサンドボックス化が利用できる。**チェックポイント**は各変更の前にファイルのスナップショットを取り、`/rewind`（あるいは `Escape` の2回押し）によって会話、コード、またはその双方を復元できるようにする。ただし文書化された制限として、追跡されるのはファイル編集ツールを通じて行われた変更だけであり、Bash と外部プロセスは対象外で、git の代替にはならない。**セッション**はローカルに保存され、`claude --continue` や `claude --resume` で再開でき、`/rename` で名前を付けられる。**非対話モード**（`claude -p`）は、CI、プリコミットフック、多数のファイルにわたるファンアウトのループのために、プレーンテキスト、JSON、ストリーミング JSON の出力をサポートする。並行作業についてドキュメントは worktree、デスクトップアプリ、ウェブ版の Claude Code、エージェントチームを挙げている。

Anthropic 自身のドキュメントは、これらの成果物を4つの名前の付いた拡張ポイントに整理し、互いの代替として相互参照している。モデルに追加の指示と実行可能なコマンドを与えるための [[DefinedTerm/agent-skills]]、隔離されたコンテキストでタスクを走らせるための [[DefinedTerm/subagents]]、ライフサイクルのイベントにおける決定論的な自動化のための [[DefinedTerm/agent-hooks]]、そして拡張をプロジェクト間で共有できるようパッケージ化するためのプラグインである。

このうち2つには既定の中身が同梱されている。**バンドルされたスキル**の集合はあらゆるセッションで利用できる。ドキュメントは `/doctor`、`/code-review`、`/batch`、`/debug`、`/loop`、`/claude-api` を挙げ、さらに別途 `/run`、`/verify`、`/run-skill-generator` の3つを挙げている。後者はプロジェクトのアプリを起動し、テストだけでなく実際に動いているアプリに対して変更を確認するために存在し、`/run-skill-generator` は動作した起動のレシピをプロジェクトごとのスキルとして記録するため、その後の実行や他のエージェントはそれを再発見するのではなく従うことになる。`disableBundledSkills` の設定は `/doctor` を除くすべてを無効にする。またモデルが自動的に委譲する**組み込みのサブエージェント**もある。ファイルの発見とコード検索のための読み取り専用エージェント Explore（徹底度を明示して呼び出される）、plan モード中に用いられる読み取り専用の調査エージェント Plan、サブエージェントが使えるあらゆるツールを備えた general-purpose、そして万能の `claude`、`statusline-setup`、`claude-code-guide` を含む補助エージェントである。

[[TechArticle/effective-context-engineering-for-ai-agents]] は Claude Code が内部でコンテキストをどう管理しているかを記述している。ジャストインタイム取得の実例として挙げられており、モデルは的を絞ったクエリを書き、結果を保存し、`head` や `tail` といった Bash コマンドを使って大量のデータを、完全なオブジェクトをコンテキストへ読み込まずに分析する。ハイブリッド戦略の例としても挙げられている。`CLAUDE.md` ファイルはあらかじめコンテキストへ投入される一方、glob と grep がファイルをジャストインタイムで取得する。記事は、これが古びたインデックスと複雑な構文木の問題を回避すると論じている。その [[DefinedTerm/compaction]] の実装は、メッセージ履歴をモデルへ渡して要約させ、アーキテクチャ上の決定、未解決のバグ、実装の細部を保ちながら冗長なツール出力を捨て、その要約に直近アクセスした5つのファイルを加えたところから継続する。

## 推奨される実践

Anthropic は、述べられた1つの制約を軸に推奨を組織立てたベストプラクティスのガイドを公開している。コンテキストウィンドウはすぐに埋まり、埋まるにつれて性能が劣化する——ガイドはこれを管理すべき最も重要な資源と呼ぶ。その筆頭の推奨は、エージェントが自ら走らせられるチェック——テストスイート、ビルドの終了コード、リンタ、フィクスチャの差分、ブラウザのスクリーンショット——を与えることである。それは「見張っているセッションと、席を立てるセッションとの違い」だと記述される。それがなければ「できたように見える」ことだけが唯一の停止シグナルとなり、人間が検証のループになってしまうからだ。そしてもう1つは、成功を主張させるのではなく、テストの出力や実行したコマンドといった証拠をエージェントに示させることである。

ガイドはそのチェックを4段階の強制へと引き上げる。プロンプトで求めること。毎ターンの後に再評価される `/goal` の条件として設定すること。ターンの終了をブロックする Stop フックとして結線すること。あるいは第2のモデルにその結果を反証させることである。あわせて、コンテキストを積極的に管理すること（無関係なタスクのあいだで `/clear`、指示を添えた `/compact`、履歴へ入れるべきでない質問には `/btw`）、探索が主コンテキストを消費しないよう調査を [[DefinedTerm/subagents]] へ委譲すること、そして作業を完了と見なす前に新しいサブエージェントのコンテキストで敵対的なレビューの段階を加えることを推奨している。

よくある失敗パターンの一覧は異例なほど具体的である。「なんでも詰め込みセッション」——無関係なタスクが無関係な情報でコンテキストを埋めてしまう。何度も修正を重ねること——処方される対処は、2回修正に失敗したら `/clear` して、学んだことを取り込んだより良いプロンプトを書くべきだというもの。過剰に書き込まれた `CLAUDE.md`——重要なルールが雑音のなかに埋もれてしまう。信頼してから検証するまでの隙間——もっともらしく見える実装がエッジケースを扱えていない。そして無限の探索——スコープの定まらない調査が何百ものファイルを読んでしまう。ガイドは、これらすべてをルールではなく出発点として枠づけて締めくくり、いつ計画し、いつ探索し、いつコンテキストを積み上げるに任せるかについて、ユーザー自身の直観を養うことを勧めている。

## 沿革

Claude Code は2025年2月にリリースされた。研究の2026年2月時点のスナップショットにおいて、著者らは Claude Code がまだ [[DefinedTerm/agents-md]]——彼らのデータがツール横断の新たな標準として特定した、ツール非依存のコンテキストファイルの慣習——をサポートしていなかったと指摘している。彼らはこれを、観測された作成順序のパターン、すなわち CLAUDE.md が先に現れ AGENTS.md が後から追加されるというパターンの説明の一つとして提示している。また別途、CLAUDE.md が AGENTS.md を指し示すことは彼らのデータにおける最も強い参照パターンであり、311 回出現した。Claude Code を使うリポジトリの年齢の中央値は 6.2 年で、サンプル全体よりわずかに若かった。

[[Book/spec-driven-development-ai-native-software-engineering]] はこのプロジェクトの成熟についての別の尺度を追跡している。Claude Code のどれだけが Claude Code によって書かれているか、である。[[Organization/anthropic]] においてこのプロジェクトを率いる [[Person/boris-cherny]] は、2025年5月におよそ 80% がそうであると報告した。10月までに Dario Amodei は Marc Benioff にその数字は 90% を超えていると語った。そして2026年3月7日、Cherny は公開の場で「Claude Code は 100% Claude Code によって書かれていると断言できる」と投稿した。[[Person/kevin-ryan]] はこの推移——10か月で 80 パーセントから 100 パーセントへ——を、OpenAI の Codex 5.3 が Codex 自身によって作られたという報告とともに、「再帰的なループが閉じた」ことの証拠として引いている。
