Mini-Coding-Agent は、単一の Python ファイル `mini_coding_agent.py` として配布される最小限のローカルなエージェントループであり、`mini-coding-agent` という CLI エントリーポイントを備えている。リポジトリはこれを、コーディングエージェントの中核となる構成要素を説明するために書かれた読みやすいハーネス実装だと説明しており、プロジェクト自身の注記でも、意図的に小さく作られ、堅牢性よりも読みやすさを優先して最適化されていると明言している。したがって、これはツールであると同時に教材でもある。

このプロジェクトには標準ライブラリ以外の Python ランタイム依存がないため、スクリプトは `python mini_coding_agent.py` で直接実行できる。`uv` は、環境を管理し CLI エントリーポイントを提供するための任意の手段として用意されている。Python 3.10 以降、ローカルの Ollama のインストール、ローカルに取得済みのモデルが必要で、エージェントは Ollama の `/api/generate` エンドポイントにプロンプトを送ることでモデルにアクセスする。リポジトリは Apache-2.0 ライセンスで公開されており、README は、詳細なものだと説明する付属のチュートリアルへのリンクを掲載している。

## 機能

README は、ハーネスを 6 つの構成要素を軸に整理している。1 つ目はリポジトリのライブなコンテキストで、エージェントはリポジトリの構成、指示、git の状態といった安定したワークスペースの情報を最初に収集する。2 つ目はプロンプトの形とキャッシュの再利用で、安定したプロンプトプレフィックスを、変化するリクエスト、トランスクリプト、メモリから分離しておくことで、繰り返されるモデル呼び出しが静的な部分を効率よく再利用できるようにする。3 つ目は検証とパーミッションを備えた構造化ツールで、モデルは自由形式の任意の行動をとるのではなく、入力がチェックされ、承認ゲートの背後でワークスペースのパス検証が行われる名前付きのツールを通じて行動する。4 つ目はコンテキストの削減と出力の管理で、長い出力は切り詰められ、繰り返しの読み取りは重複排除され、古いトランスクリプトのエントリは圧縮される（[[DefinedTerm/compaction]]）ことで、プロンプトのサイズが抑えられる。5 つ目は、完全で永続的なトランスクリプトと、より小さなワーキングメモリの組み合わせで、重要な状態を保ったままセッションを再開できるようにする。6 つ目は範囲を限定した委任で、スコープを絞ったサブタスクが、役に立つのに十分なコンテキストを引き継ぎつつ制限の範囲内で動作するヘルパーエージェントに渡される。これは [[DefinedTerm/sub-agent-architecture]] の一形態である。

リスクのあるツール、すなわちシェルコマンドとファイルへの書き込みは、起動時に選ぶ承認モードの背後で実行される。`ask` はリスクのある行動のたびに確認を求めるもので、デフォルトであると同時に README が推奨するモードでもある。`never` はリスクのある行動を一律に拒否する。`auto` はそれらを自動的に許可するもので、README はこれにモデルによる任意のコマンド実行とファイル書き込みが含まれると注意を添え、信頼できるプロンプトと信頼できるリポジトリでのみ使うよう勧めている。この選択は、3 段階にまで絞り込まれた [[DefinedTerm/permission-modes]] の最小限の例である。

セッションは対象のワークスペースのルート配下に保存され、最新のものとして、または特定のセッション識別子を指定して再開できる。保存された状態から作業を再開することは、[[DefinedTerm/checkpoint-and-resume]] が扱う関心事である。REPL の中では、少数のスラッシュコマンドがモデルに渡されずにエージェント自身によって処理される。現在のタスク、追跡中のファイル、メモを含む要約されたセッションメモリの表示、保存されたセッションファイルへのパスの表示、REPL を終了せずに履歴とメモリを消去すること、そして終了である。その他の挙動はエージェントの起動前にフラグで設定する。ワークスペースのディレクトリ、Ollama のモデルとサーバーの URL、再開の挙動、承認モード、そして 1 つのリクエストが費やせるモデルとツールのターン数や、各モデル出力の長さの上限である。

エージェントは、モデルが `<tool>` ブロックか `<final>` ブロックのいずれかを出力することを想定している。README は、Ollama のモデルによってこの指示に従う確実性にばらつきがあることを指摘し、従わない場合には指示追従性のより高いモデルに切り替えることを提案している。

## 採用状況とエコシステム

プロジェクトのモデルバックエンドは現在 Ollama で、デフォルトは `qwen3.5:4b`、メモリに余裕がある場合にはより大きな Qwen 3.5 のバリアントが推奨されている。つまり、このエージェントはホスト型の API ではなく、完全にローカルでホストされたモデルに対して動作する。付属するチュートリアルのほかに、リポジトリには具体的な使用例として `EXAMPLE.md` のウォークスルーと、`tests` ディレクトリが含まれている。
