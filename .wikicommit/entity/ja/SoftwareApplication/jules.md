Jules は Google Labs による非同期のコーディングエージェントである。その自己規定はコード補完と並ぶものとしてではなく、それに対置するかたちで置かれている。Google はこれを「副操縦士でもなく、コード補完の相棒でもなく、あなたのコードを読み、あなたの意図を理解し、仕事に取りかかる自律的なエージェント」と記述する。既存のリポジトリと直接統合し、コードベースを安全な Google Cloud の仮想マシンへクローンし、開発者が別のことをしているあいだにバックグラウンドで作業し、完了時にその計画、その理由づけ、そして加えた変更の diff を提示する。

Google が挙げるタスクは、テストを書くこと、新しい機能を作ること、音声の変更履歴を提供すること、バグを修正すること、そして依存関係のバージョンを上げることである。パブリックベータの時点では Gemini 2.5 Pro 上で動作しており、Google によればこれが利用可能な最も先進的なコーディングの推論の一部へのアクセスを与えている。導入の時点では、Python と JavaScript のコーディングタスクに限られた、「Gemini 2.0 を用いる」実験的なエージェントと記述されていた。

## 概要

Google が強調する設計上の選択は、作業がどこで起きるか、そしてそのどれだけを開発者が目にするかに関わる。Jules は既定でプライベートであるとされる——プライベートなコードで学習せず、データは実行環境の内側に隔離されたままである。Google は Jules が「サンドボックスを必要としない」と主張し、既存プロジェクトの完全な文脈を取り込んで変更について推論すること、そしてクラウド VM の内部でタスクを走らせることが複数のリクエストの同時実行を可能にすることを述べる。統制については、変更を加える前に計画と理由づけを示し、開発者が実行の前・最中・後にその計画を変更できるようにする。導入時の投稿は、包括的な多段階の計画を作り、複数のファイルを変更し、修正を GitHub へ戻して着地させるプルリクエストを準備するものとして記述していた。

GitHub との統合は接点として提示されている。Jules は「あなたがすでに働いている場所で、GitHub のワークフローの内側で直接」働くのであり、Google の記述によれば文脈の切り替えも追加のセットアップも要らない。音声の変更履歴はより異色の機能である——直近のコミットの音声による要約であり、プロジェクトの履歴を開発者が耳で聞けるものへ変える。

これらは Google が自社製品について、ローンチとベータの発表のなかで述べた自社の主張である。ここでの情報源にはそれらの独立した評価は含まれておらず、導入時の投稿自身が「Jules は間違うことがある」という但し書きを付けていた。

## 機能

- 安全な Google Cloud の VM へのクローンを伴うリポジトリの統合。
- 非同期のバックグラウンド実行と、VM 内部での同時タスクの並列実行。
- 変更の前に提示される、目に見える計画と理由づけ、そして完了時の diff。
- ユーザーによる操舵性——計画は実行の前・最中・後に変更できる。
- プルリクエストの準備を含む、GitHub のワークフローとの統合。
- 直近のコミットの音声による変更履歴。
- 既定でプライベート——プライベートなコードでの学習はなく、データは実行環境に隔離される。

### Tier 3 のクラウドエージェントとして

[[BlogPosting/the-code-agent-orchestra]] は Jules をクラウドの非同期エージェント——タスクを割り当て、開発者はプルリクエストへ戻ってくるだけで、端末もローカルのセットアップも要らないツール——のなかに置く。そのワークフローの記述は、上の計画優先のかたちと一致する。GitHub のリポジトリを接続し、タスクを記述し、コードが1行も書かれる前に Jules が生成する計画を承認し、そのうえでクラウド VM の中で走らせ、完全な理由づけと端末のログを伴うプルリクエストを返させる。際立った機能として挙げられるのは、音声の変更履歴、タスク途中での割り込み、そして GitHub の Issue を直接流し込むための Jules Tools CLI であり、Jules がリポジトリの [[DefinedTerm/agents-md]] ファイルを追加の設定なしに自動的に読むことも記録されている。

## 沿革

Jules は2024年12月、[[Organization/google]] の「The next chapter of the Gemini era for developers」の投稿において、選ばれた信頼できるテスターのグループに提供される実験的な AI 駆動のコードエージェントとして Google Labs で導入され、2025年初頭には他の関心ある開発者へのより広い提供が約束された。同投稿はこれを、この分野についてのより広い主張——「AI のコード支援が単純なコード検索から、開発者のワークフローに埋め込まれた AI 駆動のアシスタントへ急速に進化するなかで、Gemini 2.0 を用いる最新の進展を共有したい」——のなかに位置づけ、あわせてコード実行のツールを備えた Gemini 2.0 Flash を用いた [[Dataset/swe-bench]] Verified での 51.8% という研究上の結果を報告した。

その導入時の投稿はまた、Google が自社の社内利用から報告した3つの便益を述べていた。これらは観測された帰結としてではなく、この製品についてのベンダーの当初の主張として記録しておく価値がある。**より高い生産性**——Issue とコーディングのタスクを非同期の実行へ割り当てることによる。**進捗の追跡**——開発者が注意を要するものに優先順位を付けられるようにする実時間の更新を通じて。そして**開発者の完全な統制**——Jules が途中で作る計画をレビューし、フィードバックを与えたり調整を求めたりし、マージの前にレビューすることを意味する。最後のもの——diff だけでなく計画のレビュー——は、このツールが保ち続けている人間のチェックポイントのかたちについての最も早い言明である。

2025年5月20日、Jules は [[BlogPosting/build-with-jules]] においてパブリックベータへ入り、待機リストなしで誰にでも、Gemini のモデルが利用可能な世界中どこでも提供された。そこでの Google の枠づけは、「エージェンティックな開発は試作から製品へ移りつつあり、ソフトウェアがどう作られるかの中心へ急速に近づいている」というものだった。ベータ期間中のアクセスは無償であり、利用の上限が適用され、Google はプラットフォームが成熟するにつれてベータの後に価格体系を導入する見込みだと述べた。
