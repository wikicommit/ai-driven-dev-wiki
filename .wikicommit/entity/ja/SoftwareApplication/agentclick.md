AgentClick は、ターミナルベースの AI エージェントと、それを監督する人との間に位置するレビュー層である。localhost 上の npm サーバーとスキルベースのプラグインの組み合わせとして動作し、エージェントの提案をターミナルのテキストとしてではなく、構造化された成果物として提示するブラウザインターフェースを提供する。エージェントが重要なステップに達すると、提案をバックエンドに送信し、バックエンドはレビューセッションを作成してブラウザに表示する。ユーザーはそれを承認する、直接編集する、内容を削除する、制約を調整する、あるいは的を絞った書き直しを依頼することができ、その結果がエージェントに返される。エージェントはフィードバックを取り込んで作業を続ける。

この設計は [[ScholarlyArticle/agentclick]] で説明されており、同論文はこのツールを、単に実行を関門で止めるのではなく協働を改善するものと位置づけている。介入はレビュー対象の成果物のレベルで行われ、著者らは、エージェントの出力がおおむね正しいものの局所的な変更を必要とする場合にこれが最も重要になると論じている。最終的な実行の前に中間成果物が表示されるため、同じ流れが進捗を追跡し、誤りを早期に見つける手段も兼ねる。

## 機能

エージェントの出力の種類によって必要なレビューの手段は異なるという原則のもと、5 つのタスク別レビューインターフェースが提供されている。メールインターフェースは、受信トレイの閲覧、メッセージ全体の表示、返信の下書きを組み合わせたもので、セクションごとの書き直し、編集、削除の操作を備え、送信は明示的な確認を経てはじめて行われる。計画インターフェースは、提案されたワークフローを最初に、ツール呼び出し、ファイル操作、コード実行を区別した種類別のステップカードとして提示し、各カードは実行開始前にその場で編集、並べ替え、制約付け、削除ができる。コードインターフェースは、提案された各変更を、コマンド、自然言語による説明、影響を受けるファイル、統合 diff を含むレビュー用成果物として表示し、ユーザーはファイルを展開して全体の文脈を見る、個々のハンクを承認する、特定の行に注釈を付ける、部分的な書き直しを依頼する、といった操作ができる。メモリインターフェースは、読み込まれたエントリーを一覧表示し、提案された更新を確定前にレビューのために表示し、1 つのパネルからメモリファイルを読み込んだり外したりできるようにする。軌跡インターフェースは、ツール呼び出し、失敗した試行、エラーからの回復をそれぞれ区別して強調しながら実行トレースを描画し、ユーザーはステップにガイダンスとなる注釈を付けることができ、それはメモリに書き込まれる。

統合には SDK ではなく、Markdown スキルの階層を用いる。メインのスキルは起動とディスパッチを担当する。つまり、ローカルサーバーを初期化する方法やそれに接続する方法をエージェントに指示し、提案を送信して結果を受け取るためのプロトコルを確立し、タスクの意図に応じて適切なサブスキルに振り分ける。一方、サブスキルはドメインごとのペイロードスキーマ、レビューアクション、結果の処理を定義する。著者らはその理由を 2 つ挙げている。スキルはエージェントのコードベースに計測用のコードを仕込む必要がなく、実行時の依存関係も追加しないこと、そして Markdown の指示を読んで従えるエージェントであれば、どれでも変更なしにこの層を採用できることである。

好みはセッションをまたいで保持される。ユーザーが成果物の一部を編集または削除し、明示的な理由を添えると、システムはそのフィードバックを構造化されたメモリファイルに記録し、エージェントは以降の実行でそれを取り込む。著者らは、これがメールのような繰り返し発生するタスク、つまりそうしなければ同じ文体上の修正を何度も繰り返すことになるタスクで最も役立つと述べている。

## 採用状況とエコシステム

インターフェースは HTTP で提供される。著者らはこれを、クラウドの VM、共有サーバー、コンテナなど、リモートやヘッドレスの基盤上で動くエージェントへの答えとして提示している。そうした環境では、ユーザーはターミナルに手軽にアクセスできず、テキストチャネルを通じてやり取りするしかない。彼らの例では、Mac Mini 上でエージェントを動かしているユーザーが Discord で承認の依頼を受け取り、スマートフォンで AgentClick の URL を開いて下書きや計画をレビューし、編集して確認するまでを、ターミナルに触れることなく行う。

論文のウォークスルーで採用例として挙げられているエージェントは [[SoftwareApplication/claude-code]] と [[SoftwareApplication/openclaw]] の 2 つである。Claude Code は計画のレビューとメールの書き直しのタスクに、OpenClaw は、トンネルの背後にあるサーバー上で動くエージェントに対してモバイルブラウザから行うリモートレビューに使われている。コードは GitHub で公開されている。
