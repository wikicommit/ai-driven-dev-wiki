Attractor は、[[Organization/strongdm]] の [[DefinedTerm/software-factory]] の中核にある非対話型のコーディングエージェントである。つまり、人間がコードを書くこともレビューすることもなく、エージェントがコードを書くという体制を動かすコンポーネントである。チームが自分たちの働き方について初めて説明したのとあわせて一般に公開された。

この公開で注目すべきなのは、その機能ではなく形式である。リポジトリにはコードが一切含まれていない。あるのは、ソフトウェアの仕様を細部まで綿密に記述した 3 つの Markdown ファイルと、読者はそれらの仕様を自分の好きなコーディングエージェントに与えるべきだという README の注記だけである。したがって配布される成果物は仕様であり、実行可能なものは、読者自身のエージェントがそこから生み出すものということになる。

## 機能

ここで確かめられているのはエージェントの役割だけである。チームは自分たちの体制を、仕様とシナリオがエージェントを駆動し、エージェントがコードを書き、ハーネスを実行し、人間のレビューなしに収束させるものと説明しており、コードは人間が書いてはならず、人間がレビューしてもならないというルールを掲げている。このエージェントが非対話型と呼ばれるのはこの意味においてであり、ソースはこの語について他に説明していない。バージョンは記録されておらず、ソースはインターフェース、フラグ、設定についても何も説明していない。これは、読者がそこから構築することを前提とした仕様だけが内容のすべてである公開形態と整合している。

## 採用とエコシステム

Attractor は、[[BlogPosting/how-strongdms-ai-team-build-serious-software-without-even-looking-at-the-code]] で説明されている体制のエンジンとして、それを書いたチーム自身によって使われている。そのチーム以外での採用は記録されていない。チームのもう 1 つの公開物である [[SoftwareApplication/cxdb]] と並ぶ存在であり、チームの説明によれば、それを駆動するシナリオはしばしばコードベースの外に置かれている。

この公開形態そのものが、このような働き方のもとでソフトウェアがどのように配布されるかについての主張 ― ビルド成果物ではなく仕様のリポジトリ ― となっており、それを報じた記事もそのように扱っている。ただしその読み方は、珍しい公開の判断に対する報告者側の捉え方であり、チームが表明した意図ではない。
