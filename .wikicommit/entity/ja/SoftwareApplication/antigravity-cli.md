Antigravity CLI は [[SoftwareApplication/google-antigravity]] 製品ファミリーのコマンドライン版であり、Antigravity 2.0 デスクトップアプリ、Antigravity IDE、[[SoftwareApplication/antigravity-sdk]] と並ぶ製品である。ターミナルユーザーインターフェースの中でコーディングエージェントを動かし、`agy` として起動する。製品の変更履歴は最初の一般公開リリースをバージョン 1.0.0 としている。1.0.0 から 1.0.3 までは 2026 年 1 月 1 日付けとされ、その後のエントリは 1.0.4（2026 年 6 月 1 日）から 1.2.9（2026 年 9 月 23 日）まで続く。

Google は 2026 年 5 月 19 日にこの CLI をすべてのユーザーに公開した。その発表（[[BlogPosting/transitioning-gemini-cli-to-antigravity-cli]]）では、一般消費者向けユーザーにとってこの CLI が [[SoftwareApplication/gemini-cli]] の後継になることも示された。Google が挙げた理由は、開発者がいまや複雑な作業を分担するために複数のエージェントを連携させることを求めており、そのためにはワークフローの他の部分と 1 つのバックエンドを共有するターミナルツールが必要だというものである。発表によれば、この CLI は実行を高速化するために Go で構築されており、大規模なリファクタリングや調査タスクがターミナルセッションを占有しないよう複数のエージェントをバックグラウンドでオーケストレーションする。また、Antigravity 2.0 デスクトップアプリケーションと同じエージェントハーネスを共有しているため、中核となるエージェントの改善はどこで使われていても反映される。Google が Gemini CLI の最も重要な機能と呼んだもの、すなわち Agent Skills、フック、サブエージェント、拡張機能（Antigravity のプラグインになる）は引き継がれているが、当初は機能が 1 対 1 で同等にはならないとも述べられている。

この CLI はファミリーの他の製品と設定を共有している。1.0.5 以降、権限はプロジェクトレベルのルール、Antigravity と共有されるユーザー設定、CLI 自身の `settings.json` を統合したものになり、フック、プラグイン、エージェントなどのカスタマイズは共有の `~/.gemini/config/` ディレクトリに置かれる。

## 機能

**実行モード。** 1.1.0 以降、デフォルトモードの `request-review` はファイルへの書き込みのたびに一時停止して行単位の差分を表示し、ユーザーは個々のコード変更をレビューし、受け入れ、または却下できる。`Shift+Tab` で `default`、`accept-edits`、`plan` を切り替えられる。同じリリースで、従来の `/planning` コマンドは `/plan` プレフィックスに置き換えられた。`proceed-in-sandbox` 権限モード（1.0.1）は、サンドボックス内で実行されるターミナルコマンドを自動承認し、コマンドがサンドボックスの外に出る場合にのみ確認を求める。

**ヘッドレスでの利用。** プリントモード（`-p` / `--print`）は、スクリプト化された単一のターンを実行する。1.1.8 以降は `text`、`json`、`stream-json`（型付きの NDJSON イベントストリーム）を出力でき、`--json-schema` で構造化された結果にスキーマを強制できる。1.1.15 以降は `--input-format stream-json` により、stdin から改行区切りで渡される複数のプロンプトにわたって 1 つの会話を開いたままにできるため、ドライバープログラムがセッションを保持できる。変更履歴はこれらを CI、評価ハーネス、スクリプトのための機能と位置づけている。いくつかのリリースでヘッドレス時の挙動が厳格化されている。実行に与えられていない権限を必要とするツールは、ハングせずに拒否されるようになり（1.1.3）、拒否されたアクションは `denied_actions` として報告され（1.1.27）、1.2.6 以降は失敗したターンが stderr に構造化された `AGY_ERROR` 行を出力し、終了コード 3 で終了する。

**委譲。** エージェントはサブエージェントやバックグラウンドタスクに作業を任せることができ、それらはプロンプトの下のステータスバーに表示され（1.0.15）、`/agents` パネルと `/tasks` パネルから管理される。カスタムエージェントは YAML フロントマターを持つ Markdown ファイルとして定義でき（1.1.6）、起動時に `--agent` で選択でき（1.1.1）、独自のモデルティアを割り当てられる（1.1.5）。1.2.9 以降は `@` プロンプト構文でサブエージェントの会話に直接メッセージを送ることができ、実行中および完了済みのサブエージェントがオートコンプリートで一覧表示される。

製品ドキュメントは、この CLI の委譲モデルを非同期型として説明している。長時間のビルド、大規模なコードベース検索、複数ファイルの編集の間にターミナルを占有するのではなく、主エージェントがそうした操作を並列のサブエージェントやバックグラウンドタスクに任せるため、ユーザーはその間もプロンプトを入力したりファイルを確認したりできる。`/agents` パネルはすべてのバックグラウンドエージェントを、その役割、状態（実行中、完了、強制終了、エラー）、現在のステップとともに一覧表示し、そのエージェントの推論ログ全体、ツール呼び出し、出力を示す詳細ビューを開ける。`/tasks` はシェルコマンドやテストスイートのような、エージェントによらないバックグラウンド作業を追跡する。カスタムエージェントは、ワークスペースの `.agents/agents/` とグローバルな `~/.gemini/config/agents/` から検出される。サブエージェントがツール呼び出しに承認を必要とする場合があるため、CLI には 2 つのショートカットが用意されている。`Alt+J` は承認待ちの次のサブエージェントに直接移動し、`Ctrl+K` はパネルを切り替えずにプロンプトの上に表示された保留中のアクションを承認する。

**拡張ポイント。** この CLI はスキル、ルール、プラグイン、ライフサイクルフック、[[DefinedTerm/model-context-protocol]]（Model Context Protocol）サーバーを読み込む。`mcp` サブコマンド（1.1.16）を使えば、`mcp_config.json` を手作業で編集せずにサーバー一覧を管理できる。

**その他の機能。** 変更履歴に挙げられているものとして、脇道の質問のための `/btw` コマンド、長期的なゴールのための `/goal`、会話とそのファイル編集を以前のステップまで巻き戻す `/rewind` コマンド、ワークスペースを対象とする `/codesearch`、`/voice` による音声入力、オプションの Vim 編集モード（1.1.11）、そして別のデバイスから実行中のターミナルセッションを追跡・操作できる Remote Control がある。Remote Control は 1.1.19 以降のリリースで言及されており、1.2.6 では `--remote-control` または `/remote-control` によってセッションごとに開始できるようになった。

## 採用とエコシステム

サインインの選択肢はリリースを重ねるにつれて広がった。個人（一般消費者）アカウント、Gemini API に対して CLI を直接実行する `GEMINI_API_KEY`（1.1.13）、Gemini Enterprise アカウント向けの Business サインイン、Workforce Identity Federation、Application Default Credentials（1.1.10）である。`remote-control` サブコマンド（1.2.0）は、CLI をオペレーティングシステムのサービスマネージャーにバックグラウンドデーモンとして登録し、ログアウトや再起動をまたいで存続させる。
