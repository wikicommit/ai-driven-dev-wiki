Omnigent は、Databricks が 2026 年 6 月に Apache 2.0 ライセンスで公開したオープンソースのオーケストレーション層である。
バージョン 0.4.0 のソースコードを調査した
[[ScholarlyArticle/harness-engineering-anatomy-architecture-and-evolution-of-coding-agents]] は、これを著者らが知る
限り最初の [[DefinedTerm/meta-harness]]（メタハーネス）と位置づけている。Omnigent は独自のエージェントループを実装する
のではなく、[[SoftwareApplication/claude-code]]、[[SoftwareApplication/openai-codex]]、
[[SoftwareApplication/cursor]]、[[SoftwareApplication/opencode]]、[[SoftwareApplication/hermes-agent]]、Pi、
そして YAML で定義されたカスタムエージェントなど、コーディングエージェントのハーネス全体を、共通 API の背後にある
交換可能なコンポーネントとして扱う。

同論文はこれを、[[DefinedTerm/agent-harness]]（エージェントハーネス）がコモディティ化したコンポーネントとなり、
持続的な価値はその一つ上の層にあるという賭けとして読み解いており、コーパスの一員ではなく対比のための参照点として
用いている。Omnigent は編集ループも、リポジトリのコンテキストも、編集適用の戦略も実装していないため、著者らは
研究対象のハーネスと同じサブシステムの観点でこれを評価することを控えている。

## 機能

論文の説明によれば、Omnigent はサーバー、ホストデーモン、ランナー、そして会話ごとのハーネスサブプロセスという
4 層のプロセストポロジーとして動作し、そのアダプタ境界は設計上、自身の公開 REST API の再帰的なサブセットになって
いる。レジストリには 23 の正規ハーネスアダプタに加えて、エイリアスとコミュニティ向けのエントリポイントグループが
含まれ、これらは 5 つの統合モードとして形式化されている。アダプタが宣言した能力は、基本的なターン、ツール呼び出し、
ストリーミング、割り込み、モデルの上書き、ポリシーによる拒否を検査する適合性ベンチと照合される。論文によれば、
主要な 4 つの SDK アダプタについてはライブでの検証が行われており、残りはベストエフォートの宣言にとどまる。

この境界の上に、論文は 4 つの追加機能を見いだしている。第一に合成であり、Claude を頭脳とするオーケストレーターが
作業を Codex に振り分け、それを Cursor にレビューさせることができる。第二にセッション、エージェント、管理者の
3 レベルからなるハーネス横断のポリシープレーンであり、Claude Code のフック、Cursor のフック、Hermes のフック、
ACP のパーミッション要求といった各ベンダー自身の拡張機構を通じて外部のハーネスに適用され、フェイルクローズの
セマンティクスを持つ。第三に統一されたサンドボックスであり、Linux では bubblewrap と seccomp、macOS では生成された
Seatbelt プロファイル、Windows では Job Objects を用い、実際のトークンをサンドボックスの外に保つ認証情報プロキシを
ホストするデフォルト拒否のエグレスプロキシを備える。第四にサーバー側で永続化されるセッションであり、複数デバイス
間の同期、アクセス権の付与、レビューコメント、フォーク、セッション途中でのハーネス切り替えに対応する。

論文は Omnigent が行わないことにも触れている。ベンダー固有の能力レコードやエンドポイントは設計上、共通 API を
通じて漏れ出しており、サンドボックス化の適用も一貫していない。Claude CLI は自前のサンドボックスで包む一方で、
Codex についてはそのネイティブのサンドボックスモードに委ねている。著者らはこれを、OS レベルの分離は共有サービス
として切り出すことが難しいことの証拠と捉えている。また、ベースラインの依存関係は claude-agent-sdk と
openai-agents の 2 パッケージであると報告されており、論文はこれを根拠に、ハーネスの SDK が 2026 年の
オーケストレーションシステムにとってのフレームワーク層になったと論じている。

## 導入とエコシステム

論文が紹介する代表的な事例である Polly は、ベンダー横断のコーディネーター・ワーカー構成である。Claude Code を
頭脳とするオーケストレーターは自らはコードを書かず、タスクごとの git worktree で 6 つのベンダーのハーネスに作業を
分散し、変更のレビュー担当者は実装担当者とは異なるベンダーのものでなければならないとプロンプトで義務づけている。
論文は Omnigent を、コーディングハーネスがプラットフォームへと変わったという自らの主張の証拠として用いており、
このような層の経済性、すなわち上位からのコモディティ化が価値を持続的に獲得できるかどうかを、未解決の問題として
挙げている。
