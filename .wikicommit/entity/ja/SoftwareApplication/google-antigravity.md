Google Antigravity は、[[Organization/google]] が公開したエージェント型開発プラットフォームであり、2025 年 11 月に
発表された。Google はこれを単なるエディタではなく、馴染みのある AI 搭載のコーディング体験とエージェントファーストの
インターフェースを組み合わせた開発プラットフォームだと説明しており、そこからエージェントを展開して、エディタ、
ターミナル、ブラウザをまたいで複雑なタスクを自律的に計画・実行・検証させることができる。

Google が掲げる設計上の前提は、エージェントはサイドバーに収まるのではなく作業のための専用の空間を持つべきであり、
開発者は個々のプロンプトやツール呼び出しのレベルではなく、より高いタスク指向のレベルで操作できるべきだというもので
ある。その結果生じる信頼の問題に対する答えは、エージェントに生のツール呼び出しログではなく、レビュー可能な成果物を
通じて報告させることである。製品チーム自身のローンチ記事（[[BlogPosting/introducing-google-antigravity]]）は、製品を
信頼、自律性、フィードバック、自己改善という 4 つの原則を軸に編成し、Gemini 3 のようなモデルが複数のサーフェスを
またいで介入なしにより長時間稼働できるようになったことを受けて、IDE がエージェントファーストの未来へと進化したものと
して提示している。

この名称はその後、製品ファミリーを指すようになった。製品のチェンジログは、最初のローンチを 2025 年 11 月 18 日の
リリース 1.11.2 として記載し、第 2 世代である Antigravity 2.0 が 2026 年 5 月に Antigravity 1.0 からのインポート手段を
伴ってローンチされたことを記録している。チェンジログは Antigravity IDE を独立した製品ラインとして掲載しており、同月の
その 2.0.1 のエントリは Antigravity IDE の最初のリリースと説明されている。ファミリーにはさらに
[[SoftwareApplication/antigravity-cli]] と Python 版の [[SoftwareApplication/antigravity-sdk]] も含まれる。以下の概要と
機能は、バージョンが明示されていない限り、ローンチ時点のプラットフォームを説明している。

## 機能

このプラットフォームは 2 つの異なるサーフェスを提示する。Editor View は、タブ補完とインラインコマンドを備えた AI 搭載の
IDE で、Google がすでに馴染みがあると説明する、同期的でハンズオンなワークフローのためのものである。ローンチ記事は、
サイドパネルに完全に機能するエージェントが搭載されていると付け加えている。Manager サーフェスはエージェントファーストの
インターフェースで、複数のエージェントを起動し、オーケストレーションし、それらが異なるワークスペースをまたいで非同期に
作業する様子を観察できる。Google はこれを、長時間かかる保守作業やバグ修正をバックグラウンドで振り分けるためのものと
位置づけており、問題の再現、テストケースの生成、修正の実装にまたがるタスクもそこに含まれる。ローンチ記事はこれを、
サーフェスにエージェントを組み込むのではなく、エージェントにサーフェスを組み込むというパラダイムの転換だと説明し、
ミッションコントロールになぞらえている。また、チームは Manager と Editor を 1 つに押し込むのではなく、両者の間で即座に
引き継げることを重視して、意図的に別々のウィンドウに分けたと述べている。

エージェントは 1 つのタスクの中で、エディタ、ターミナル、ブラウザをまたいで作業する。Google の作業例では、エージェントが
ある機能のコードを書き、ターミナルを使ってアプリケーションを起動し、次にブラウザを使って新しいコンポーネントをテスト・
検証するが、その間に人間の同期的な介入は必要ない。

Antigravity IDE の製品ドキュメントは、このうちブラウザ側について説明している。エージェントはローカルの Chrome
ブラウザを開き、読み取り、操作することができ —— 開発中のウェブサイトのテスト、ドキュメントの閲覧、ブラウザタスクの
自動化のために —— 、その作業はスクリーンショットを撮影し、操作の動画をアーティファクトとして保存する専用のブラウザ
サブエージェントを通じて行われる。ブラウザツールは設定で完全にオフにでき、URL へのアクセスは 2 層のデナイリストと
アローリストで制御され、エージェントはユーザー自身のものとは別の Chrome プロファイルで動作する。

検証は **Artifacts** —— タスクリスト、実装計画、ウォークスルー、スクリーンショット、ブラウザ録画など、エージェントが
生成する成果物 —— によって仲介される。Google が述べる理由は、生のツール呼び出しをスクロールするのは面倒な一方で、
これらがあれば開発者はエージェントの論理を一目で確認できるというものである。ローンチ記事はこれを、エージェントの作業を
タスクレベルの抽象度で提示し、ツール呼び出しをタスクの中にまとめるものと位置づけている。フィードバックは、ドキュメントに
コメントするのと同様に Artifact に直接残すことができ —— ローンチ記事は、テキストの Artifacts への Google ドキュメント風の
コメントや、スクリーンショットへの範囲選択によるフィードバックを挙げている —— 、エージェントは実行の流れを止めることなく
その入力を取り込む。Google はまた、このプラットフォームが学習を中核的なプリミティブとして扱っており、エージェントが
有用なコンテキストやコードスニペットをナレッジベースに保存して将来のタスクを改善できるとしている。ローンチ記事によれば、
その知識は、ある特定のサブタスクを完了させた一連の手順のような、より抽象的なものであってもよい。

### その後のリリース

ローンチ後のリリースとして、チェンジログは、2026 年 1 月のエージェントの Skills の登場（1.14.2）、サンドボックス内での
ターミナルコマンドの実行 —— 最初は macOS（1.15.6）、のちに Linux（1.21.6）、そして Windows でのファイルとネットワークの
サンドボックス化が 2.0 ラインで続いた（2.15.1） —— 、`GEMINI.md` に加えて `AGENTS.md` からもルールを読み込むように
なったこと（1.20.5）、そして統合されたエージェントのパーミッションシステム（1.22.2、2026 年 4 月）を記録している。

Antigravity 2.0 ラインでは、チェンジログは、任意のブラウザからローカルのエージェントセッションを操作するための Remote
Control（2.9.1）、サイドバーに組み込まれたターミナルと Git バージョン管理（2.10.0）、HTML アーティファクトのインライン
「生成 UI」レンダリング（2.11.0）、マルチエージェントによる推論パスのための `/boost` コマンド（2.12.0）、そしてコードが
書かれる前に計画を読んで編集でき、Plan Review Policy の設定によって制御される `/plan` コマンド（2.17.0）を記録している。

### Antigravity 2.0

製品ドキュメントは、Antigravity 2.0 が作業をどのように編成するかを説明している。以前の Agent Manager では各エージェントが
単一のワークスペースフォルダに対応づけられていたが、2.0 ではエージェントは **Projects** の中で作業する。プロジェクトは
複数のフォルダにまたがることができ、Git ワークツリーをサポートしているのでエージェントは隔離されたバックグラウンドの
フォルダで動作でき、プロジェクト固有のスコープの設定とパーミッションの付与を持つ —— そのため、信頼できるプロジェクトには、
信頼できないフォルダよりも許容度の高いセキュリティプリセットを与えることができる。ちょっとした単発の会話は、どの
プロジェクトにも属さず、隔離されたローカルのスクラッチフォルダで実行することもできる。

ドキュメントによれば、デフォルトでは、エージェントは macOS と Linux ではターミナルサンドボックスの外でターミナルコマンドを
実行する前に（Windows ではあらゆるターミナルコマンドの前に）明示的な許可を求め、ユーザーがその設定を広げない限り、
プロジェクトのフォルダ内でしか読み書きできない。ドキュメントが挙げるその他の 2.0 の機能には、タイマーでエージェントに
メッセージを送るスケジュールタスク、プロンプトと Artifact へのコメントのためのリアルタイム音声文字起こし、エージェントの
実行サイクルの各時点でローカルのシェルスクリプトを実行する JSON フック、`/browser` で呼び出され Chrome DevTools MCP と
統合された刷新版のブラウザサブエージェント、任意のウェブブラウザからのデスクトップのエージェントセッションの Remote
Control、統合ターミナル、そして未コミットの差分、ブランチの差分、エージェントが作成した差分をレビューするための Git
ネイティブなバージョン管理パネルがある。

Google の「Getting Started with Google Antigravity」コードラボは、同じ世代を、IDE に付属する Agent Manager ではなく、
同コードラボがエージェントファースト時代と呼ぶものに向けた製品ファミリーとして説明している。その中心にあるのが
Antigravity そのもので、macOS、Linux、Windows 向けのスタンドアロンアプリケーションである。コードラボはこれを、複数の
ローカルエージェントを並列に管理し、スケジュールタスクを実行するためのコマンドセンターと呼んでおり、前身の Agent Manager
とは異なり IDE から独立して動作する。その周囲に、Antigravity IDE —— 元々のエージェント型 IDE で、コードラボによれば
引き続き提供され、開発者に推奨されている —— 、[[SoftwareApplication/antigravity-cli]]、
[[SoftwareApplication/antigravity-sdk]]、そして Visual Studio Code、JetBrains の IDE、Zed などのエディタ向け拡張である
Antigravity for IDEs が配置されている。

コードラボは、プロジェクトを、エージェントの環境とスコープの両方を定義するフォルダの組み合わせとして説明している。各
プロジェクトはそのパーミッション —— アーティファクトのレビュー、許可されたツール、MCP サーバーの設定 —— をグローバル
設定から継承し、個別に上書きすることができる。上書きできるのは、ターミナルコマンドとファイルアクセスを先にレビュー
するかどうか、エージェントが実装計画を実行する前にその承認を必須とするかどうかを決めるセキュリティプリセット、許可された
ファイルパスと、許可またはブロックされた URL、そしてそのプロジェクトが使用できる MCP ツールである。ローカルまたは
リモートの MCP サーバーは `$HOME/.gemini/config/mcp_config.json` で設定され、コードラボは、Google Cloud のサービス向けに
ワンクリックでインストールできる事前パッケージ化された設定があり、個々のツールをオン・オフできると説明している。

コードラボは Artifacts を、信頼のギャップに対する Antigravity の答えとして提示している —— 以前は、バグを修正したという
エージェントの主張を確かめるために開発者がコードを読まなければならなかったが、今ではエージェントがそれを示すための
アーティファクトを生成する。主なものとしてタスクリスト、実装計画、ウォークスルー、スクリーンショットを挙げ、コードの差分も
それらと並んでレビューやコメントができるが、技術的にはアーティファクトではないとしている。Skills は
[[DefinedTerm/progressive-disclosure]] によって読み込まれると説明されている。最初に読み込まれるのはスキルのメタデータ
だけで、リクエストがその説明に合致したときに完全な指示が読み込まれる。グローバルなスキルは `~/.gemini/config/skills/`
に置かれ、Antigravity、Antigravity IDE、Antigravity CLI のすべてで利用できる。プロジェクトのスキルは
`<project-root>/.agents/skills/` に置かれる。

### サブエージェント

Antigravity 2.0 と Antigravity CLI のドキュメントは、並行して動作するバックグラウンドのサブエージェントへの委任について
説明している。親エージェントは `invoke_subagent` ツールでサブエージェントを起動し、役割と最初のプロンプトを与える。
サブエージェントは親の会話履歴ではなくクリーンなコンテキストから開始し、親のワークスペースを継承するか、隔離された Git
ワークツリーを得るか、ディレクトリのストレージを共有することができる。組み込みのサブエージェントは 3 つある ——
コードベースの探索のための `research`、対話的なブラウザテストのための `browser`、そして呼び出し元のエージェントの
クローンである `self` —— 。カスタムのサブエージェントは Markdown ファイルとして定義され、その YAML フロントマターで
ツール、モデルの階層、コマンド実行ポリシーを設定し、本文がシステムプロンプトとなる。

サブエージェントは、実行中、アイドル（完了して待機中で、メッセージによって再び起こされる）、終了済みのいずれかの状態に
ある。エージェントは会話 ID で互いにメッセージを送り合い、互いのトランスクリプトを読むことができ、入れ子はプライマリ
エージェントの下 10 階層までに制限されている。サブエージェントは親のコマンドのアローリスト、ファイルアクセスのスコープ、
サンドボックスの設定を継承し、ユーザーの承認を必要とするリクエストはメインのインターフェースへと上がっていく。その上に、
ドキュメントは 2 つのマルチエージェントのオーケストレーターを説明している。対話セッション内で難しい問題に取り組むための
3 層の推論階層である `/boost` と、マイルストーンへの分解、並列の実装、独立した検証を通じて、より大きなプロジェクトで
専門化されたエージェントのチームを調整する `/teamwork-preview` である。

## 採用とエコシステム

発表時点で、このプラットフォームはパブリックプレビューとしてリリースされ、個人は無料で、macOS、Windows、Linux の
クロスプラットフォームで利用できた。Google は、Gemini 3 Pro に対する十分なレート制限に加え、Anthropic の Claude Sonnet
4.5 と OpenAI の GPT-OSS を完全にサポートするという、モデルの選択肢を提供するとしていた。この提供形態とモデルの一覧は、
2025 年 11 月の発表時点のプラットフォームについてのものである。

ローンチ当日に書かれた記事で、Simon Willison はこのプラットフォームを一見したところ「またしても VS Code フォークの
Cursor クローン」—— Google アカウントでサインインし、Gemini モデルを相手にエージェント型コーディングを行う IDE を提供する
デスクトップアプリケーション —— だと評したが、よく見るとかなり興味深いものだと述べた。彼は、その 3 つのサーフェス
（エージェントマネージャーのダッシュボード、VS Code 風のエディタ、そして新しい Chrome 拡張による深いブラウザ統合。
最後のものについては、エージェントに自ら構築したウェブアプリケーションをテストさせるという役割の点で Playwright MCP に
なぞらえた）と、エージェントの作業中に自動的に作成される Markdown ドキュメントだと彼が説明する Artifacts を取り上げた。
自身の `llm-gemini` プラグインに Gemini 3 のサポートを追加するという彼の最初の試みは、当初はうまくいったものの、その後
「Agent execution terminated due to model provider overload」というエラーで停止した。彼は、ローンチ初期の不安定さが
解消されたらもう一度試すと述べている。
