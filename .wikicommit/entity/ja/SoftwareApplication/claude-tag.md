Claude Tag は、チームのコラボレーションツール向けの [[Organization/anthropic]] の Claude であり、最初に Slack で
ローンチされた。その開発者たちは [[BlogPosting/a-fireside-chat-with-cat-and-thariq-from-the-claude-code-team]] の中で、
これを社内的には [[SoftwareApplication/claude-code]] の進化形であり、自分たちの働き方の大きな転換だと説明している。
社内版は自分たちのプロダクトエンジニアリングのプルリクエストの 65% をマージまで持っていっていると報告しており、
これは半数を超えると彼ら自身が注記している。

従来のコーディングエージェントとの 3 つの違いが、このプロダクトの本質として挙げられている。1 つ目は
**デフォルトでマルチプレイヤー**であることである。チャンネルに追加されると、呼び出した本人とそのチームメイトが
全員で口を挟み、同じプルリクエストで協働できる。2 つ目は**受動的ではなく能動的**であることである。チャンネル内の
すべてのバグ報告を監視し、それぞれを修正するプルリクエストを作成し、コードベースの該当部分に最後に触れた
エンジニアをタグ付けするよう指示でき、再び話しかけられなくても、チャンネルが存続する限りそれを続ける。3 つ目は
**チームメモリ**を持つことである。チャンネル内で自然言語で述べられた好みは、それを言った本人だけでなくチーム全員の
ために、今後の投稿に向けて記憶される。

開発者たちが説明する役割分担は、人がエージェントと対話的に反復する最も複雑なタスクには引き続き Claude Code が
最適な場であり、Claude Tag は自分の代わりに能動的に作業を進めてもらうためのものだ、というものである。これにより、
バグ報告が届くたびにコーディングエージェントを手動で起動する必要がなくなる。

## 機能

- チャンネル内のマルチプレイヤーセッション。複数の人が 1 つのセッションを操縦し、その結果生まれるプルリクエストで
  協働する。開発者たちは自分たちのセッションの大きな割合がマルチプレイヤーであると報告しており、複数の人が同じ
  セッションを操縦する際の社会的な力学についてはまだ模索中だと述べている。
- チャンネルを範囲とする常設の能動的な指示。報告の監視、プルリクエストの作成、関係するエンジニアのタグ付けなどで
  あり、チャンネルが存続する限り持続する。
- チームメモリ。現在はチャンネルごとの markdown ファイルとして実装されており、そのチャンネル内のすべての
  インスタンスで共有され、個々のセッションがメインのメモリに書き戻すこともできる。
- 企業の公開 Slack チャンネル全体の検索。企業にとっての検索エンジンとして価値があると説明されており、誰が何を
  言っているか、またイベントストアに接続している場合には、メトリクスに関する質問に対するプロダクトのコンテキストを
  得られる。
- プログラマー以外の人のための作業。機能を説明するためにコードベースをクローンすることや、その機能が使われている
  様子の録画を作成することが、マーケティングチームがこれにさせてきたこととして挙げられている。
- 実装の録画をチャンネルに共有すること。これによってデザインとエンジニアリングが順にレビューし、変更を先に
  進められる。
- Claude に独自の認証情報を付与すること。これにより Claude は人の代理としてではなく独自のアイデンティティとして
  行動し、開発者たちによれば、その行動の監査や検査もしやすくなる。

## 導入とエコシステム

報告されている導入実績は開発者たち自身のものであり、しかもその度合いは大きい。プロダクトエンジニアリングの
プルリクエストの 65% であり、セッションには複数の人が関わることが多い。彼らは、チャンネルで機能が提案され、
Claude Tag が最初の実装を行い、録画がデザインに共有され、エンジニアリングがそれを本番環境まで持っていくという
ワークフローを説明しており、人々は他の人が使うのを見て規範を身につけたと述べている。そのうちの 1 人は、公開の場で
使うことで全員の Claude の使い方が向上し、スロップが減ると付け加えている。

[[DefinedTerm/permission-modes]] への依存は率直に述べられている。Claude Tag は承認の判断をモデルに委ねるモードを
使用しており、開発者たちはそれこそがこのプロダクトを成り立たせているものだとしている。その理由は、誰でも投稿
できるチャンネルを読むボットは、構造上 [[DefinedTerm/prompt-injection]] にさらされるというものであり、例として
ユーザーフィードバックのチャンネルを挙げている。そのため彼らは、独自の AI Slack ボットを構築しないよう助言している。
また、Claude Tag はアクセスできるものしか検索できないため、企業のチャンネルの大部分が公開されているときに最も
よく機能するとも述べている。これは回答の品質についての、ベンダーによる主張であり、先ほど述べたリスクへの露出と
並んでなされているものである。
