Open Code Review は、`ocr` として呼び出される AI 搭載のコードレビュー CLI である。README によれば、これは
Alibaba Group の社内公式 AI コードレビューアシスタントを起源とし、2 年間で数万人の開発者に利用されて数百万件の
コード欠陥を検出した後、コミュニティ向けにオープンソース化された。Apache-2.0 ライセンスで公開されている。

その動作は、Git の差分を読み取り、変更されたファイルをツール利用能力を持つエージェントを介して設定可能な LLM に
送り、行単位の精度で構造化されたレビューコメントを生成するものと説明されている。エージェントはファイルの内容全体を
読み、コードベースを検索し、他の変更ファイルを参照してコンテキストを得ることができる。差分レビューに加えて、
`ocr scan` モードはファイル全体をレビューするもので、README はこれを、馴染みのないコードベースや意味のある差分が
存在しないディレクトリの監査向けとして提示している。

README が展開する設計上の主張は、このタスクを汎用エージェントに頼ることへの反論である。README はそのアプローチに
起因するとする 3 つの問題 ― 大きな変更セットではエージェントが手を抜いて一部のファイルしかレビューしないこと、
報告された問題の位置が実際のコードの位置からずれること、プロンプトのわずかな違いでレビュー品質が変動すること ―
を挙げ、その原因を、レビュープロセスに対する厳格な制約を欠いた純粋に言語駆動のアーキテクチャにあると診断して
いる。これらは代替手法に対するプロジェクト自身の評価である。

## 機能

この診断に対する回答として示されているのが、README が Deterministic Engineering × Agent Hybrid と呼ぶ役割分担
である。モデルではなくエンジニアリングのロジックが担うのは次の 4 つである。どのファイルをレビューし、どのファイルを
除外するかを正確に決めること。関連するファイルを 1 つのレビュー単位にまとめ、それぞれを分離されたコンテキストを
持つサブエージェントとして実行すること（README はこれを、大きな変更セットでも安定し並行レビューにも対応する分割統治
戦略として提示している）。言語駆動の指示ではなくテンプレートエンジンによって、各ファイルの特性にレビュールールを
マッチングすること。そして、位置と内容の正確性のための独立したコメント位置決めモジュールとコメントリフレクション
モジュールである。エージェントの役割は動的な判断と動的なコンテキスト取得に限定され、README によればプロンプト
テンプレートとツールセットはコードレビュー向けに調整されている。ツールセットは、大規模な本番データにおける
ツール呼び出しトレースの分析 ― 呼び出し頻度の分布やツールごとの繰り返し率を含む ― から導かれたものだという。

インストールは npm で `@alibaba-group/open-code-review` として行い、その後 `ocr` がグローバルに利用可能になる。
インストールスクリプト、GitHub Release のバイナリ、ソースからのビルドも文書化されている。ツールは差分の生成、
コード検索、リポジトリ操作に Git を用いるため、Git 2.41 以降が必要である。設定は対話形式で、`ocr config provider`
と `ocr config model` がプロバイダーの選択、API キーの入力、モデルの選択を順に案内し、その後接続をテストする。

レビューの対象範囲はいくつかの方法で指定できる。`ocr review` はステージ済み・未ステージ・未追跡の変更を対象とし、
`--from`/`--to` は merge-base を用いてブランチが分岐して以降の変更をレビューし、`--commit` は単一のコミットを
対象とする。中断された範囲・コミット・スキャンのレビューは、`--resume` とセッション ID で再開できる。結果は
`--format json --output` でファイルに書き出すことができ、README はこれを AI ホストエージェント向けに推奨している。

委任モードはこの構成を逆転させる。`ocr delegate` では、ユーザー自身のコーディングエージェントが自らの LLM で
レビューを行い、Open Code Review はファイル選択とルールの解決を担当する。そのため、Open Code Review 自体の LLM
設定や API キーは不要である。

## 導入とエコシステム

プロジェクトは複数のコーディングエージェント向けのプラグイン ― README は Claude Code、Codex、Cursor、Kimi Code、
OpenCode、QCA Forward を挙げている ― に加え、スキル対応エージェント向けのポータブルなエージェントスキルを公開して
おり、他のツールの中からスラッシュコマンドやスキルとしてレビューを呼び出せるようになっている。また、外部ツールで
レビューエージェントを拡張するための MCP サーバー、GitHub Actions、GitLab CI、GitFlic CI、Gerrit 向けの CI 連携、
OpenTelemetry ベースのテレメトリー、そしてレビューを再生しコメントを修正済みまたは無視としてマークできる
ブラウザベースのセッションビューアも文書化している。

評価のために、プロジェクトは [[Dataset/aacr-bench]] を公開し、それに対する結果を報告している。その主張によれば、
Open Code Review は同じ基盤モデルを用いる汎用エージェントよりも有意に高い適合率と F1 を達成し、トークン消費は
およそ 9 分の 1 で、レビューもより速く完了する。再現率が低いのは、ノイズよりも適合率を優先する意図的な
トレードオフであるとしている。これはプロジェクト自身のベンチマークであり、それに対するプロジェクト自身の報告結果である。
README は比較対象の汎用エージェントとして Claude Code を挙げており、数値そのものは本文ではなく画像で示されている。

[[DefinedTerm/agentic-code-review]]（エージェント型コードレビュー）に照らして見ると、このプロジェクトは、
エージェント型レビューにおける主体性をどこに置くべきかについての一つの主張である。すなわち、ループ全体ではなく判断から恩恵を
受ける部分にのみ主体性を置き、残りは通常のコードによって固定しておくべきだということである。
