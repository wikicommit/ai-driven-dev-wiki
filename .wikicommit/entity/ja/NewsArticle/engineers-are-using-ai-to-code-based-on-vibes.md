「Engineers Are Using AI to Code Based on Vibes」は2025年4月8日の IEEE Spectrum のニュース記事であり、寄稿編集者の Matthew S. Smith によるもので、2025年6月の印刷版には「Engineers Are Using AI for 'Vibe Coding.'」として掲載された。[[Person/andrej-karpathy]] がこの手法を名づけてから2か月後、実践者が実際にどう使っていたのかを報じている。記事は、Karpathy のバイラルな投稿に対する著者自身の反応——「待ってくれ！自分はバイブコーダーなのか？」——から始まる。彼はプログラミングの知識が限られているにもかかわらず、すでに LLM を使って自分の個人サイトを刷新し、いくつかの小さな個人プロジェクトを作っていたのである。

記事の構成は、3人の実践者の証言と、そのいずれもが該当するのかどうかをめぐる意見の相違である。その報道としての価値は、インタビュー対象者が語る具体的なビフォー・アフターの数字と、2025年を通じて繰り返し現れることになる定義上の論争を浮かび上がらせた点にある。

## 要点

- **記事が述べる Karpathy の定義。** 2月2日、Karpathy——計算機科学者であり OpenAI の創設メンバーと記述される——はバイブコーディングを、ソフトウェアエンジニアが「バイブに身を任せ、指数関数を受け入れ、コードが存在することすら忘れる」プログラミングのスタイルとして定義した。
- **社内ツールを出荷する機械エンジニア。** Gripple の公認プロフェッショナル機械エンジニアである Prasad Naik は、もともと C 言語でほぼ1か月かけて書いた iPad アプリを、ChatGPT による段階的な指示を用いて約2時間でモダンな JavaScript のウェブアプリへ変換し、自分が使ったコードの 90 パーセント以上が生成されたものだったと見積もっている。彼はその後、サーバに接続するより複雑なアプリを1週間半ほどで構築し、AI ツールなしにそれができたとは思えないと述べている。
- **ユースケースとしての概念実証。** Corewell Health のデータエンジニアリングのリードである Jason Touleyrou は、アイデアを素早く検証するために AI 支援コーディングを用いている——「着想までの速さが決定的だ」——、そして仕事では一度も触れたことのない Google Cloud のサービスを使ってコーヒーの記録ツールを作った。彼が鍵だと述べるのはワークフローである。よく定義されたアイデアから始め、次に AI にコードを生成させ、それからデバッグにおいては助言役へと移す。その間、リンタのような品質ツールは使い続ける。
- **異論。** 25年の経験を持つソフトウェアエンジニアの Taher Vohra は、Naik と Touleyrou はまったくバイブコーディングをしていないと論じる。定義を文字どおりに——「コードを見ないということ」——受け取ったところ、彼は「AI に何をしてほしいかを指定することの方が、自分でやるよりも難しい問題になっている」と気づいた。彼はプログラミングへの AI の利用に反対しているわけではなく、Cursor を含む複数のアシスタントを使っているが、本番投入可能なコードを書く開発者はコードから目を離してはならないと強調する。
- **3人が一致する点。** インタビュー対象の3人全員が、バイブコーディングはエンジニアがまだ知らない言語やスタックのスキルを身につけるのに役立つという点で一致している。ジュニアエンジニアへの Vohra の助言は、すでに持っているスキルを速くするものとしてではなく、新しいスキルを獲得するための加速装置として扱え、というものである。彼の挙げる例は、フロントエンドのエンジニアが「2年ではなく数か月で」フルスタックになることである。

## 背景

この記事は、公開時点でまだ2か月ほどの歴史しかない語についての初期の報道であり、その枠組みとなる問いは、注意深くレビューを伴う AI 支援の作業がそもそもバイブコーディングに該当するのかどうかである。単一媒体による3件のインタビューに基づく記述であり、そこに含まれる生産性の数字は測定された結果ではなくインタビュー対象者自身の見積もりである。
