エージェント型ソフトウェアとは、意思決定ロジックがあらかじめ書かれているのではなく実行時に生成されるソフトウェアを指して、[[ScholarlyArticle/agentic-software-restructuring-paradigm]] が形式化した用語である。同論文はこの用語を自ら造ったとは主張しておらず、自らの貢献として提示しているのは、決定論的ソフトウェアとエージェント型ソフトウェアの区別を形式化したことである。この対比は形式的に描かれる。従来のソフトウェアシステムは、そこでは 3 つ組 — 計算資源、ソースコードに符号化された決定論的な意思決定ルールの集合、そしてそれらのルールを入力に対して評価する実行環境 — として特徴づけられ、その決定的な性質は、ルールが実行に対して静的であることにある。つまり、システムが何らかの入力に出会う前に、そのすべてを人間のエンジニアが書いておかなければならない。これに対して AI エージェントシステムは、推論エンジンとして機能する言語モデル、実行可能なツールの集合、メモリサブシステム、そしてユーザーの意図を行動の系列に分解する計画メカニズムとして特徴づけられる。

この用語に意味を与えている帰結は、コードに何が起こるかである。この説明では、モデルは動的にコードを生成し、ツールを呼び出し、途中の結果に応じて振る舞いを調整することができ、そのいずれもあらかじめプログラムされてはいない。そのため、モデルが書くコードはシステムそのものではなく、必要に応じて生成され破棄される一時的な成果物である。同論文はこの転換を凝縮して、「AI → Software → Result」が「Agent → Result」へと縮約されると述べる。これはソフトウェアが消えるからではなく、エージェントがソフトウェアシステムであると同時にその実行エンジンでもあるため、その間に別個の静的にコード化された成果物を置く必要がなくなるからである。

## 使われ方

この用語はソフトウェアの作り方ではなくソフトウェアの種類を指す。それが、同じ論文の枠組みにおける隣接する用語とこの用語を区別する点である。そこでは、[[DefinedTerm/agentic-engineering]] はそうしたシステムを構築・デプロイ・統制する分野を、[[DefinedTerm/agent-as-a-service]] はそれらが提供される商業モデルを指し、エージェント型ソフトウェアは成果物そのものを指す。この三分法は同論文独自のものである。

同論文はこの用語を Karpathy の「Software 2.0」と対比させて位置づけている。同論文は Software 2.0 を、手作りのプログラムロジックを学習された重みで置き換えるものと解釈し、エージェント型システムはさらに一歩進んでいると論じる。ネットワークは単にプログラムを置き換えるのではなく、より広い推論の目標に奉仕するツールとしてコードを使い、必要に応じてプログラムを書くからである。同論文はこのパターンを、推論のトレースとツール利用の行動を交互に行う ReAct フレームワーク、および Chain-of-Thought プロンプティングと結び付けている。

この方式がなぜ異なる形でスケールするのかについての同論文の議論は、複雑性に関するものである。従来のパラダイムでは、人間のエンジニアはタスクの解空間を頭の中でたどり、その経路を静的なプログラムとして符号化しなければならず、しかも固定された認知能力によって制約される。そのため、解空間がその能力を超えるタスクは、現実的などのようなコストでも実現できない。エージェント型のパラダイムでは、モデルが解空間をたどり、その能力はモデルの規模と学習の計算量に応じてスケールすると同論文は論じる。計画はタスクを独立に処理される部分問題へと分解し、コードはあらゆる不測の事態に備えてではなく、特定の解の経路に対してのみ生成される。ここから導かれる主張は、何パーセントの改善という話ではなく、どの問題が経済的に扱えるようになるかという質的な変化である。

## 適用される場面

同論文の形式的な定義から読み取ると、この概念が当てはまるのは、システムの振る舞いがあらかじめ指定された命令の系列からではなく、モデル、そのツール、そのメモリ、そしてその計画の相互作用から実行時に立ち現れる場合である。これは、タスクを分解して行動を選択できる推論エンジンと、それを通じて行動できるツールとを前提とする。同論文は定義を述べてはいるが、これらの適用条件そのものは述べていない。

同論文が述べる失敗条件は、同論文が最も楽観的でない箇所である。同論文は、エージェントの成功率が、独立したタスクでは 80% を超えるのに対し、継続的なソフトウェアの進化のもとでは最大でも 38% にまで低下するという [[Dataset/evoclaw]] ベンチマークの知見を報告し、そこから 4 つの課題を読み取っている。コードベースが実効的なコンテキストウィンドウを超えて大きくなることによるコンテキストのずれ。初期の小さな誤りが連鎖的に広がるのに、エージェントが頑健な回復手段を持たないという誤りの伝播。エージェントが長期的なコストをモデル化せずに目先のタスク完了に最適化するため、技術的負債への意識が欠けていること。そして、エージェントがテストに合格しながら、新しい入力に対してのみ表面化する意味上の誤りを持ち込みうるという、検証の忠実度である。同論文自身の結論は、このパラダイムは拡張（augmentation）のパラダイムとしては今日すでに現実のものであり変革的であるが、完全に自律的なソフトウェア開発は依然として複数年にわたる研究課題である、というものである。

この用語の確立度について言えば、この用語は 1 本の論文に依拠しており、その論文は独自の測定ではなく、第一原理と他の研究から引用した結果に基づいて議論している。同論文は区別の形式化を自らの貢献として提示しているが、用語そのものの出どころは述べていない。実行時にコードを生成しては破棄するモデルがプログラムとは異なる種類の成果物であるという根底の観察は、その出典の中では争われていない。一方、その観察を中心に組み立てられた 3 世代の枠組みは、同論文独自のものである。
