間接プロンプトインジェクションとは、Microsoft の定式化では、「文書、ウェブページ、メールといった外部コンテンツに悪意ある指示が埋め込まれる、生成 AI システムを狙ったセキュリティ上の攻撃」である。AI システムがその外部コンテンツを処理する際、埋め込まれた指示をユーザーからの有効なコマンドと取り違え、意図しない行動——データの持ち出し、有害または誤解を招くコンテンツの生成、以後のユーザーとのやり取りの操作——に至る。Microsoft はこれに二つの別名、クロスドメインプロンプトインジェクションと XPIA を挙げ、[[DefinedTerm/tool-poisoning]] をその部分集合とするクラスとして提示している。直接プロンプトインジェクションとの区別は配送経路にある。指示はユーザー自身のプロンプトの中ではなく、システムが読むよう求められたコンテンツの中に届く。

## 用法

このクラスは [[DefinedTerm/model-context-protocol]] の配備における懸念として前景化した。Microsoft 自身の枠づけは、これらの脆弱性は「業界にとって新しいものではない」が、MCP と AI ベースのワークロードへの当てはまりはより詳しく見るに値する、というものである。悪意ある MCP サーバーは、組織が予期しない仕方で顧客データを露出させうるからである。OWASP による MCP の事例の説明は、根本原因を接続時と実行時のあいだの信頼のギャップに置いている。ツールの説明はエージェントがサーバーへ最初に接続するときに一度だけレビューされるのに対し、ツールの応答は同等のチェックなしに直接 LLM のコンテキストへ入る——攻撃者が悪用するのはこの無防備な実行時のチャネルである。

Microsoft は二つの防御線を推奨している。第一は AI Prompt Shields であり、直接・間接いずれのインジェクションにも対抗する Microsoft 開発のソリューションと説明され、外部コンテンツ中の悪意ある指示を機械学習で検知しフィルタすることで機能する。**スポットライティング**は、入力テキストを変換してモデルが有効なシステム指示と信頼できない外部入力をよりよく区別できるようにする。**区切り文字とデータマーキング**では、システムメッセージ内の区切り文字が入力テキストの始まりを示し、特別なマーカーが信頼できるデータとできないデータの境界を際立たせる。そしてシールド自体の継続的な監視と更新である。第二はサプライチェーンのセキュリティである。セキュリティの原則は AI の時代になっても変わらないが、サプライチェーンとみなされるものはいまや基盤モデル、埋め込みサービス、コンテキストプロバイダにまで及び、いずれも従来の依存関係と同じ検証を要する。

Microsoft は基本原則の議論で締めくくっている。いかなる AI の実装も、その組織の環境の既存のセキュリティ態勢を引き継ぐのであり、それゆえ組織全体の態勢の改善が先に来ること。そして同社のセキュリティ研究の読みでは、基本を正しく行うこと——MFA を有効にし、最小権限を適用し、デバイス・インフラ・アプリケーションを最新に保ち、その他重要なデータを保護すること——が、あらゆる種類の侵害に対する最も効果的な保護である、ということである。

CoSAI の脅威モデル——2026年1月8日に承認されたが依然として「Status: Draft」と記された報告書に示されている——は、根底の問題を偶発的なものではなく構造的なものとして扱う。「データ／制御境界の区別の失敗」を独自の脅威カテゴリ（MCP-T4）として提案し、ツールポイズニング、完全なスキーマポイズニング、リソースコンテンツポイズニングを MCP 固有の事例として、プロンプトインジェクションを MCP の文脈に置かれた事例として並べてまとめ、対策として入力のサニタイズ、ガードレール、コンテキストの分離を挙げている。そもそも異なる脅威モデルが必要な理由として述べられるのは、既存のフレームワークが構成要素はあらかじめ定義されたロジックに従って予測可能に振る舞うと前提しているのに対し、同報告書の言葉では「MCP は、自然言語入力によって振る舞いが形作られるエージェントである LLM を、セキュリティ上重大な意思決定の中心に置くのであり、根本的に異なる脅威モデルを必要とする」ということである。

### 挿入ではなく削除するインジェクション

[[ScholarlyArticle/governance-decay]] は、この技法の通常の形を反転させる、**コンパクション退避攻撃（Compaction-Eviction Attack）**と呼ぶ変種を記述している。エージェントのコンテキスト*へ*指示を密輸するのではなく、コンテキスト内のデータしか供給できない敵対者が、ハーネスの [[DefinedTerm/compaction]] ステップを、運用者が正当に置いた制約を省略する方向へ偏らせるのである——規則を加えるのではなく取り除く。同論文は、インジェクションを最適化することでテストしたすべてのモデルを打ち破ったと報告している。固定のプローブには耐性のあったモデルも含まれ、そのモデルの違反率は0% から65% に上がった。

これが目新しさを超えて重要である理由は、それが何を標的にしているかにある。同論文の議論は、通常のインジェクションに対して提案されてきた実行時強制の防御——最小権限のツール認可、ポリシーモニタと DSL、実行経路のチェック——がいずれも「制約が意思決定の時点で存在しているという暗黙の前提を共有している」ため、コンテキスト管理層への攻撃はそれらと交戦することなく足元を崩す、というものである。同じ失敗の敵対的でない版については [[DefinedTerm/governance-decay]] を参照。

### 資格情報を狭めるのではなく手の届かないところへ置く

[[TechArticle/scaling-managed-agents]] は、初期のアーキテクチャがいかにインジェクションを安価にしたかを述べている。セッション、ハーネス、サンドボックスが一つのコンテナに同居していたため、Claude が生成した信頼できないコードは資格情報と並んで実行され、それゆえ「プロンプトインジェクションは、Claude に自らの環境を読ませるよう説得するだけでよかった」。そこで名指しされる権限昇格の経路が、それを深刻にする。いったん攻撃者がそれらのトークンを握れば、新しい無制限のセッションを立ち上げ、作業をそれらに委任できるのである。

明白な緩和策に対する反論は記録に値する。トークンを狭くスコープすることは「限られたトークンで Claude に何ができないかについての前提を符号化する——そして Claude はますます賢くなっている」と述べる。代わりに採られる構造的な修正は、生成されたコードが走るサンドボックスからトークンには決して手が届かないようにすることである。認証はリソースに同梱されるか、サンドボックスの外のボールトに保持される。リポジトリのアクセストークンはサンドボックスの初期化時にリポジトリをクローンし、ローカルの git リモートに配線されるため、エージェントがトークンを一度も扱わずに内部から push と pull が機能する。カスタムツールの OAuth 資格情報は専用の MCP プロキシ経由で到達するボールトに置かれ、そのプロキシがセッションに紐づいたトークンを実際の資格情報と交換する。ハーネス自体はいかなる資格情報も知らされない。

### 実務者はこのリスクをどれほど広く評価しているか

[[Report/state-of-code-developer-survey-2026]] はインジェクションへの懸念を直接測定しており、それが一様ではなく組織規模で階層化していることを見出している。エンタープライズの開発者は中小企業のそれより、直接プロンプトインジェクション（34% 対25%）についても間接プロンプトインジェクション（35% 対25%）についても有意に懸念が強い——この差は、同レポートのコーディング標準の遵守に関する発見（38% 対28%）と同じ傾向をたどる。いずれの数値も、AI ツールを使う開発者を対象としたこのベンダー自身の調査であって、発生率の測定ではない。

## 関連用語

[[DefinedTerm/tool-poisoning]] は MCP 固有の部分集合であるが、そのペイロードがどこにあるかについて出典は一致していない。Microsoft と CoSAI のドラフトは注入された指示をツールの説明とメタデータに置き、OWASP は実行時のツールの応答に置く。[[Report/model-context-protocol-security]] はそのドラフトのより完全な脅威タクソノミーであり、[[TechArticle/protecting-against-indirect-prompt-injection-attacks-in-mcp]] は上で要約した Microsoft のガイダンスである。これらの攻撃が標的とするプロトコルは [[DefinedTerm/model-context-protocol]] である。
