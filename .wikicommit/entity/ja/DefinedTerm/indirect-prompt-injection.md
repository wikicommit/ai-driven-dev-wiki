間接プロンプトインジェクションとは、Microsoft の定式化によれば「文書、ウェブページ、メールといった外部コンテンツに悪意ある指示が埋め込まれる、生成 AI システムを標的としたセキュリティ上の攻撃」である。AI システムがその外部コンテンツを処理するとき、埋め込まれた指示をユーザーからの有効なコマンドと誤解し、意図しない動作——データの持ち出し、有害あるいは誤解を招く内容の生成、その後のユーザーとのやり取りの操作——につながる。Microsoft はこれに対する2つの別名、クロスドメインプロンプトインジェクションと XPIA を挙げ、[[DefinedTerm/tool-poisoning]] がその部分集合であるようなクラスとして提示している。直接的なプロンプトインジェクションとの決定的な違いは配送経路にある。指示はユーザー自身のプロンプトの中ではなく、システムが読むよう求められたコンテンツの中に届くのである。

## 用法

このクラスは [[DefinedTerm/model-context-protocol]] の導入における懸念として注目されるようになった。Microsoft 自身の枠づけは、これらの脆弱性は「業界にとって新しいものではない」が、MCP と AI ベースのワークロードへの適用可能性ゆえに詳しく見る価値がある、というものである。悪意ある MCP サーバーは、組織が想定しない形で顧客データを露出させうるからだ。MCP の事例に関する OWASP の説明は、根本原因を接続時と実行時の間の信頼のギャップに求める。ツールの説明はエージェントが最初にサーバーに接続するときに一度だけレビューされるのに対し、ツールの応答は同等のチェックなしにそのまま LLM のコンテキストに入る——この無防備な実行時のチャネルこそ攻撃者が悪用するものである。

Microsoft は2つの防衛線を推奨する。第一は AI Prompt Shields であり、直接・間接の双方のインジェクションに対する Microsoft 開発のソリューションとして説明され、外部コンテンツ内の悪意ある指示を機械学習によって検知しフィルタすることで機能する。**スポットライティング** は入力テキストを変換し、モデルが有効なシステムの指示と信頼できない外部入力をより良く区別できるようにする。**デリミタとデータマーキング** は、システムメッセージ内のデリミタによって入力テキストがどこから始まるかを示し、特別なマーカーによって信頼できるデータと信頼できないデータの境界を際立たせる。そしてシールド自体の継続的な監視と更新である。第二はサプライチェーンのセキュリティである。セキュリティの原則は AI の時代になっても変わらないが、サプライチェーンとみなされるものは今や基盤モデル、埋め込みサービス、コンテキストプロバイダにまで及び、いずれも従来の依存関係と同じ検証を必要とする。

Microsoft は基本の重要性を説く議論で締めくくる。あらゆる AI の実装は組織の環境の既存のセキュリティ態勢を引き継ぐのだから、まず組織全体の態勢を改善することが先であり、セキュリティ研究についての同社の読みでは、基本を正しく行うこと——MFA を有効にし、最小権限を適用し、デバイス・インフラ・アプリケーションを最新に保ち、重要なデータをそれ以外の手段でも保護すること——が、あらゆる種類の侵害に対する最も効果的な防護である。

CoSAI の脅威モデル——2026年1月8日に承認されたが依然として「ステータス：ドラフト」と記された報告書に示されている——は、根底の問題を偶発的なものではなく構造的なものとして扱う。「データ／制御境界の区別の失敗」を独立した脅威カテゴリ（MCP-T4）として提案し、ツールポイズニング、完全なスキーマポイズニング、リソースコンテンツポイズニングを MCP 固有の事例として、プロンプトインジェクションを MCP の文脈に置かれた事例としてまとめ、対策として入力のサニタイズ、ガードレール、コンテキストの分離を挙げている。そもそも異なる脅威モデルが必要な理由として述べられているのは、既存のフレームワークが構成要素は事前に定義されたロジックに従って予測可能に振る舞うと前提しているのに対し、同報告書の言葉によれば「MCP は、自然言語の入力によって振る舞いが形作られるエージェントである LLM を、セキュリティ上決定的な判断の中心に据えており、根本的に異なる脅威モデルを必要とする」からである。

## 関連用語

[[DefinedTerm/tool-poisoning]] は MCP 固有の部分集合だが、そのペイロードがどこにあるのかについて情報源の見解は分かれている。Microsoft と CoSAI のドラフトは注入された指示をツールの説明とメタデータに位置づけるのに対し、OWASP は実行時のツールの応答に位置づける。[[Report/model-context-protocol-security]] はそのドラフトのより完全な脅威の分類であり、[[TechArticle/protecting-against-indirect-prompt-injection-attacks-in-mcp]] は上に要約した Microsoft のガイダンスである。これらの攻撃が標的とするプロトコルが [[DefinedTerm/model-context-protocol]] である。
