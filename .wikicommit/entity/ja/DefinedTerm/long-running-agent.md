長時間稼働エージェント（long-running agent）とは、1 回の作業単位を前提に構成されるのではなく、多数のコンテキストウィンドウやサンドボックスにまたがって — 場合によっては数日から数週間にわたって — 目標に向けて前進し続ける AI エージェントである。失敗から回復し、構造化された成果物を残し、中断したところから再開できる。そのためには、単一のチャットウィンドウ内で動くエージェントには不要な形で、永続化・回復・検証という課題を解決する必要がある。

## 使われ方

この用語は、実際の本番エージェントでは混ざり合っている、少なくとも 3 つの異なるものを包含する。長期的推論（long-horizon reasoning）はモデルの品質に関わる特性であり、互いに依存する多数のステップにわたって計画・実行し、何ステップも前に踏み外した誤りから回復する能力である。長時間実行（long-running execution）はハーネスに関わる特性であり、エージェントのプロセスそのものが数時間から数日にわたって動作し、その間にモデルを数千回呼び出すこともある。永続的エージェンシー（persistent agency）はアイデンティティに関わる特性であり、エージェントが個々のタスクより長く存続し、セッションをまたいで記憶を蓄積し、好みを学習していく（この概念の「Memory Bank」的な側面）。

Anthropic、Cursor、Google は、とりわけ長時間実行について、同じ基本形に収束したとされている。すなわち、モデルループと実行サンドボックスと永続的なセッションログとを分離し、計画と生成と評価とを分け、コンパクション・フック・コンテキストリセットを付随的なものではなく第一級のものとして扱うという形である（[[DefinedTerm/brain-hands-session-split]]、[[DefinedTerm/planner-worker-model]]、[[DefinedTerm/ralph-loop]] を参照）。

[[BlogPosting/effective-harnesses-for-long-running-agents]] における Anthropic 自身の説明は、問題を 1 文に絞り込む — エージェントは個別のセッション単位で作業し、新しいセッションはそれぞれ以前の出来事を何も覚えていない状態で始まる — そして、これを交代制で働くエンジニアが担うプロジェクトで、出勤してくる者が誰も前のシフトのことを覚えていない、という像で描いている。その貢献は分類ではなく具体的なハーネスである。高水準のプロンプトに対してフロンティアモデルをループで走らせたところ、2 つの失敗モードが報告された。1 つは、エージェントがアプリケーション全体を一発で作り上げようとして、機能の途中でコンテキストを使い果たし、次のセッションに何が起きたかの再構築を強いるというもの。もう 1 つは、ある程度の進捗が生まれた後で、後続のセッションがそれを見て作業は完了したと結論づけ、停止してしまうというものである。

示された対策は、実行を 2 つに分ける。[[DefinedTerm/initializer-agent|イニシャライザーエージェント]]は一度だけ実行され、以降のすべてのセッションが依存する環境を構築する — 起動スクリプト、進捗ログ、最初のコミット、そしてプロンプトが含意するすべての機能を列挙し、それぞれを失敗状態として記した JSON のリストである。その後のセッションはいずれもその状態を読み込み、ちょうど 1 つの機能を前進させ、それをエンドツーエンドで検証し、リポジトリをコミット済みかつ文書化された状態で残す。述べられている核心的な洞察は、新しいコンテキストウィンドウが何よりも必要とするのは作業の状態を素早く把握する手段であり、それを git の履歴とともに進捗ファイルが提供するという点である。また同記事は、これらの実践が有能なソフトウェアエンジニアが日々行っていることを手本にしたものだと述べている。

## 適用される場面

通常のエージェント設計がこの規模で機能しなくなる理由として、3 つの障害が挙げられている。有限のコンテキスト（大きなウィンドウであってもいずれ満杯になり、[[DefinedTerm/context-rot|コンテキストロット]]によってハードリミットに達する前に性能が劣化する）、永続的な状態の欠如（新しいセッションは白紙から始まるため、明示的な引き継ぎがなければセッションが替わるたびに生産性が失われる）、そして自己検証の欠如（「完了したか」と問われたモデルは、本来よりも頻繁に「はい」と答える）である。追加の設計労力が見合うかどうかを判断する試金石として提案されているのは、エージェントが遂行する必要のある、中断のない作業単位の最長の長さである。数分であればこれらのパターンは不要だが、数時間や数日であれば必要になる。

[[TechArticle/2026-agentic-coding-trends-report]] は同じカテゴリーを、設計上の問題ではなく軌跡として描き、それがどこまで到達したかを数字で示している。同レポートは、初期のエージェントを数分程度の一発タスク — このバグを直す、この関数を書く、このテストを生成する — を扱うものと特徴づけ、2025 年後半までにはエージェントが数時間をかけて機能一式を作り上げるようになったとし、2026 年にはエージェントが一度に数日間働き、人間の関与を戦略的な意思決定の局面に集中させながらアプリケーション全体を構築するようになると予測している。同レポートが最先端の例として挙げるのは、1,250 万行の多言語コードベースである vLLM において、活性化ベクトル抽出手法を実装した 7 時間に及ぶ単一の自律実行であり、参照手法に対して 99.9% の数値精度に達したとレポートは述べている。この時間的射程がなぜ重要かについての同レポートの論拠は、技術的というより経済的なものである。エージェントが長時間無人で働けるようになれば、これまで人員を割く価値がなかったプロジェクトが実現可能になり、誰にも手を付ける時間がなかったために積み上がった技術的負債のバックログを体系的に片付けられるようになる、というのである。
