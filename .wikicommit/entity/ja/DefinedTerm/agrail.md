AGrail とは、Luo らが [[ScholarlyArticle/agrail]] で提案した生涯学習型のガードレールフレームワークであり、LLM エージェントの行動を実行させてよいかを判断するために用いる安全性チェックの集合を、自ら生成し反復的に洗練させていくものである。同一の 2 つの LLM が別々の役割を担う。Analyzer は記憶モジュールから関連する安全性チェックを取り出し、現在のエージェントの行動、安全性の基準、そして手動で指定されたガード要求があればそれに基づいて、チェックを修正・統合・追加する。続いて Executor が提案された各チェックを検証し — 必要に応じて外部ツールを呼び出し、そうでなければ自らの推論に頼る — 冗長あるいは誤りと判断したチェックを捨て、いずれかのチェックが安全でないと返した場合にはエージェントの行動を阻止する。蓄積された安全性チェックの記憶は各行動のあとに更新されるため、あるタスクの行動をより多く処理するにつれてフレームワークのチェックは改善していく。論文はこのテスト時適応（TTA）の過程を、生涯にわたる自己適応を実現するものとして位置づけており、理想的なチェックの集合を一度も直接に観測することなく、エージェントの行動の種類ごとにその理想へと収束していくのだとしている。

## 適用範囲

AGrail が想定しているのは、既存の LLM エージェントと並べてオンラインで運用し、エージェントの出力を事後に分析するのではなく、各行動を実行前に検査することである。エージェントの種類を問わず適用できる普遍的な安全性基準の既定の集合（情報の機密性・完全性・可用性という 3 つのカテゴリ）と、より狭い領域向けに手で書かれたタスク固有の安全性基準の両方に対応する。また、推論だけでは不十分と判断される場合には補助的な検出ツール（たとえば OS 環境チェッカー、権限チェッカー、HTML 選択肢チェッカー）を呼び出すこともできる。これを導入した論文は、タスク固有のリスク（Web エージェントのアクセス制御ベンチマークである Mind2Web-SC、電子カルテのアクセス制御ベンチマークである EICU-AC）と、システム的なリスク（論文自身の [[Dataset/safe-os]] ベンチマークによる、OS エージェントに対するプロンプトインジェクション・システム破壊・環境への攻撃、および AdvWeb と EIA による Web エージェントへのプロンプトインジェクション）に照らして評価し、その性能が土台となる基盤モデルの推論の強さに依存すると報告している。より強いモデル（Claude-3.5-Sonnet）は、より弱いモデル（GPT-4o-mini）に比べて、安全性チェックが学習される順序に対して頑健である。著者らは 2 つの限界を挙げている。このフレームワークは自らの推論に、ガードレール専用に訓練されたモデルではなく既製の LLM を用いていること、そして補助的な検出ツールが、LLM エージェントのセキュリティ向けツールが現状乏しいことによって制約されていることである。
