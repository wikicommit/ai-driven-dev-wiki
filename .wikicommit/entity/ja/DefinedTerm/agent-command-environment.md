エージェントコマンド環境（Agent Command Environment、ACE）は、[[DefinedTerm/structured-agentic-software-engineering]] においてエージェンティックな時代における従来型 IDE の置き換えとして提案された、人間向けのワークベンチである。人間の認知に最適化されたコマンドセンターとして説明され、そこでは「エージェントコーチ」として振る舞う開発者が意図を指定し、複雑なワークフローをオーケストレーションし、証拠に裏づけられた結果をレビューする。エージェントの活動とそれに伴うコストは完全に可観測である。

## 用法

この提案の出発点にある主張は、従来型の統合開発環境はエージェントを介した作業には力不足だ、というものである。[[ScholarlyArticle/agentic-software-engineering-foundational-pillars]] は、[[SoftwareApplication/cursor]] のような今日の AI-IDE ツールは依然としてコード中心に過ぎ、コード以外のエンジニアリング成果物を伴うメンターシップを中心的な活動として扱うには至っていない、と論じる。

ACE は、1人の開発者が多数のエージェントと働く 1対N の協働と、人間のチームが AI チームメイトの共有フリートを調整する N対N の協働の両方を支えるものとして規定されている。チームレベルの設定においては、多役割のガバナンス、証拠に基づくレビュー、部門横断的なコンサルテーションを提供する。エージェントは [[DefinedTerm/consultation-request-pack]] を通じて人間の専門家を呼び出すことができ、ACE がその要求をルーティングし、提示し、記録する。論文はこれを、説明責任に必要なコンテキストを保持したまま、ACE が人間を呼び出し可能な専門知識のエンドポイントとして扱うことだと特徴づけている。

標準的な開発ツールに現在欠けており、ACE に統合されるべきだと論文が論じる能力には、次のものが含まれる。

- 規律ある N バージョンプログラミング——複数のエージェント生成解からコンポーネントを可視化し、比較し、混ぜ合わせること
- 単純なテキスト差分ではなく、生成された変更のアーキテクチャ上の影響を示すプログラム理解のためのビュー
- [[DefinedTerm/briefing-script]]、MentorScript、LoopScript といった成果物のオーサリング、バージョン管理、アーカイブ、分析
- エージェントが必要とする複雑なコンテキストのキュレーション。論文は、それが人間の必要とするコンテキストとしばしば異なることを指摘する
- 戦略的なエージェント管理——能力とコストからエージェントチームを編成し、パフォーマンスを評価し、成績の振るわないエージェントを再学習させ、降格させ、あるいは引退させること
- コーチが「飛び込む」能力——外科手術的なコード変更のために従来型の IDE ビューへ切り替え、その後コーチングのワークフローに戻ること

論文はさらに、ACE を補完する対話モダリティとして音声を提案している。開発者が現在の作業コンテキストを離れることなく、短い指示を出したり、意図を口述したり、フィードバックを与えたりしたい場合の、高レベルなオーケストレーションとメンターシップに有用だとする。音声が入力よりも速くなりうること、そして音声支援によるデバッグがコンテキストスイッチを減らしうることを示す研究を引き、音声認識のレイヤー自体は推論を行う必要がない——開発者の意図を捉え、その結果のテキストを下流の ACE ツールやエージェントに渡せばよい——とも述べている。

## 関連用語

ACE は対をなす一方であり、その相方は人間ではなくエージェントのために作られたワークベンチである [[DefinedTerm/agent-execution-environment]] である。AEE から提出された作業は、監査されるべき [[DefinedTerm/merge-readiness-pack]] として ACE 上のコーチのもとに届く。
