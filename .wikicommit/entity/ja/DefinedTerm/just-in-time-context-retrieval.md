ジャストインタイムのコンテキスト取得とは、関連しうるすべてのデータを事前に前処理しておくのではなく、エージェントがファイルパス、保存されたクエリ、Web リンクといった軽量な識別子だけを保持し、それらの参照を使って実行時にツールを通じてデータを動的にコンテキストへ読み込むアプローチである。Anthropic はこれを、アプリケーションがよりエージェント的になるにつれてエンジニアたちが向かっている方向だと説明している。各チームは、AI ネイティブなアプリケーションで一般的な、埋め込みに基づく推論前の検索システムを、こうした実行時の戦略で補強しているという。

## 用法

Anthropic はこのアプローチを人間の認知になぞらえている。人は一般に、情報の全体を丸ごと記憶するのではなく、ファイルシステム、受信トレイ、ブックマークといった外部の整理・索引の仕組みを導入し、必要に応じて関連するものを取り出す。保存の効率にとどまらず、参照そのもののメタデータもシグナルを担う。ファイルシステム上で動くエージェントにとって、`tests` フォルダ内の `test_utils.py` というファイルは、`src/core_logic/` の下にある同名のファイルとは異なる目的を示唆する。フォルダの階層、命名規則、タイムスタンプはいずれも、情報をいつどのように使うべきかを示している。

エージェントに自律的にデータを探索・取得させることで、段階的開示も可能になる。これは探索を通じて関連するコンテキストを少しずつ発見していくことであり、ファイルサイズは複雑さを、命名規則は目的を示唆し、タイムスタンプは関連性の代理指標として働く。各インタラクションが次の判断に役立つコンテキストをもたらすため、エージェントは理解を一層ずつ組み立てていき、ワーキングメモリには必要なものだけを保持し、それ以上に残しておく必要があるものにはノートテイキングの戦略を用いる。

## 適用される場面

- データが大きいか変化しており、エージェントにそこへ到達するためのツールを与えられる場合に当てはまる。Anthropic 自身のエージェント型コーディングツールである [[SoftwareApplication/claude-code]] は、このアプローチを使って大規模なデータベースに対する複雑なデータ分析を行う。モデルは的を絞ったクエリを書き、結果を保存し、`head` や `tail` といった Bash コマンドを活用することで、データオブジェクト全体をコンテキストに読み込むことなく大量のデータを分析する。
- エージェントが情報の風景を探索するために使うツールとヒューリスティクスが、明確な方針のもとで思慮深く設計されていることを前提とする。Anthropic は、適切な導きがなければ、エージェントはツールを誤用したり、行き止まりを追いかけたり、重要な情報を見つけ損ねたりしてコンテキストを浪費しうると明言している。
- そのコストは速度である。実行時の探索は、事前に計算されたデータを取得するよりも遅い。Anthropic は、最も効果的なエージェントは、速度のために一部のデータを事前に取得し、さらなる自律的な探索は自らの裁量で行うというハイブリッド戦略を採るかもしれないと示唆しており、このハイブリッドは法務や金融の業務のように、内容の変化が少ない文脈により適しているかもしれないとしている。その例として挙げられているのが Claude Code であり、CLAUDE.md ファイルは最初からコンテキストに投入される一方、glob や grep といったプリミティブがファイルをジャストインタイムで取得することで、インデックスの陳腐化や複雑な構文木の問題を回避している。
- これは、測定された比較からではなく、Anthropic 自身の製品経験と顧客との協働から導かれた、この分野がどこへ収束しつつあるかについての Anthropic の見立てとして提示されている。Anthropic は、モデルの能力が向上するにつれて、エージェントの設計は人間によるキュレーションが次第に少なくなる方向に向かうと予想している。
