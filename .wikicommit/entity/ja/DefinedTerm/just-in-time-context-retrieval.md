ジャストインタイムのコンテキスト取得とは、エージェントが軽量な識別子（ファイルパス、保存されたクエリ、Web リンクなど）だけを保持し、関連しうるすべてのデータを事前に前処理しておくのではなく、それらの参照を使って実行時にツール経由でデータを動的にコンテキストへ読み込むアプローチである。Anthropic はこれを、アプリケーションがよりエージェント的になるにつれてエンジニアが向かっている方向だと説明しており、チームは AI ネイティブなアプリケーションで一般的な、埋め込みベースで推論前に行われる検索システムを、こうした実行時の戦略で補強しているという。

## 用法
Anthropic はこのアプローチを人間の認知になぞらえている。人は一般に情報のコーパス全体を暗記するのではなく、ファイルシステム、受信箱、ブックマークといった外部の整理・索引の仕組みを導入し、必要に応じて関連するものを取り出す。ストレージ効率にとどまらず、参照そのもののメタデータもシグナルを担う。ファイルシステム上で動作するエージェントにとって、`tests` フォルダ内の `test_utils.py` という名前のファイルは、`src/core_logic/` 配下にある同名のファイルとは異なる目的を示唆し、フォルダ階層、命名規則、タイムスタンプはいずれも、情報をどのように、いつ使うべきかを示している。

エージェントに自律的にデータを探索・取得させることは、段階的開示（progressive disclosure）も可能にする。すなわち、探索を通じて関連するコンテキストを少しずつ発見していくことであり、そこではファイルサイズが複雑さを示唆し、命名規則が目的を暗示し、タイムスタンプが関連性の代理指標として機能する。各インタラクションが次の判断に役立つコンテキストをもたらすため、エージェントは理解を一層ずつ積み上げ、作業記憶には必要なものだけを保持し、それ以上に永続させる必要があるものにはノート取りの戦略を用いる。

## 適用される場面
- データが大規模または変化し続けるもので、エージェントにそこへ到達するためのツールを与えられる場合に当てはまる。Anthropic 自身のエージェント型コーディングツールである [[SoftwareApplication/claude-code]] は、大規模なデータベースに対する複雑なデータ分析を行うためにこのアプローチを用いている。モデルは対象を絞ったクエリを書き、結果を保存し、`head` や `tail` といった Bash コマンドを活用して、データオブジェクト全体をコンテキストに読み込むことなく大量のデータを分析する。
- エージェントが自らの情報環境を探索するために使うツールとヒューリスティクスを、明確な方針をもって入念に設計することを前提とする。Anthropic は、適切な指針がなければエージェントがツールの誤用、行き止まりの追跡、重要な情報の見落としによってコンテキストを浪費しうると明言している。
- その代償は速度である。実行時の探索は、事前に計算されたデータを取得するよりも遅い。Anthropic は、最も効果的なエージェントはハイブリッド戦略――速度のために一部のデータを事前に取得し、さらなる自律的な探索は自らの裁量で行う――を採用するかもしれないと示唆し、このハイブリッドは法務や金融の業務のように内容の変化が少ない文脈により適しているかもしれないと述べている。その例として Claude Code が挙げられており、CLAUDE.md ファイルは事前にコンテキストへ投入される一方、glob や grep といったプリミティブがファイルをジャストインタイムで取得することで、古くなったインデックスや複雑な構文木の問題を回避している。
- これは計測された比較からではなく、Anthropic 自身のプロダクト経験と顧客との協働から導かれた、分野が収束しつつある方向についての Anthropic の見立てとして提示されている。Anthropic は、モデルの能力が向上するにつれて、エージェントの設計は人間によるキュレーションが次第に少なくなる方向へ進むと予想している。
