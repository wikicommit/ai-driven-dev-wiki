ジャストインタイムのコンテキスト取得（just-in-time context retrieval）とは、関連しうるすべてのデータを事前に前処理するのではなく、エージェントがファイルパス、保存済みクエリ、Web リンクなどの軽量な識別子だけを保持し、それらの参照を用いて実行時にツールを通じてデータを動的にコンテキストへ読み込むアプローチである。Anthropic はこれを、アプリケーションがよりエージェント的になるにつれてエンジニアが進みつつある方向として描いており、チームは AI ネイティブなアプリケーションで一般的な、埋め込みベースで推論前に行う検索システムを、こうした実行時の戦略で補強しているという。

## 使われ方
Anthropic はこのアプローチを人間の認知になぞらえる。人は一般に、情報のコーパス全体を記憶するのではなく、ファイルシステム、受信トレイ、ブックマークといった外部の整理・索引システムを導入して、関連するものを必要に応じて取り出す。ストレージ効率を超えて、参照そのもののメタデータも信号を担う。ファイルシステム内で動作するエージェントにとって、`tests` フォルダ内の `test_utils.py` というファイルは、`src/core_logic/` 配下にある同名のファイルとは異なる目的を示唆し、フォルダ階層、命名規則、タイムスタンプはいずれも、情報をどのように、いつ使うべきかを示している。

エージェントに自律的にデータを探索・取得させることは、段階的開示（progressive disclosure）も可能にする。これは探索を通じて関連するコンテキストを漸進的に発見していくことであり、そこではファイルサイズが複雑さを示唆し、命名規則が目的をほのめかし、タイムスタンプが関連性の代理指標として働く。個々のインタラクションが次の判断に役立つコンテキストをもたらすため、エージェントは理解を 1 層ずつ組み上げ、ワーキングメモリには必要なものだけを保持し、さらに持続させる必要のあるものについてはノートテイキングの戦略を用いる。

## 適用される場面
- データが大きい、あるいは変化しており、エージェントにそこへ到達するためのツールを与えられる場合に適用される。Anthropic 自身のエージェント型コーディングツールである [[SoftwareApplication/claude-code]] は、このアプローチを用いて大規模なデータベースに対する複雑なデータ分析を行う。モデルは的を絞ったクエリを書き、結果を保存し、`head` や `tail` といった Bash コマンドを活用して、データオブジェクト全体を一度もコンテキストに読み込むことなく大量のデータを分析する。
- エージェントが自らの情報環境を探索するために用いるツールとヒューリスティクスが、明確な方針のもとで思慮深く設計されていることを前提とする。Anthropic は、適切な誘導がなければ、エージェントはツールを誤用したり、行き止まりを追いかけたり、重要な情報を見出せなかったりしてコンテキストを浪費しうると明言している。
- その代償は速度である。実行時の探索は、事前に計算されたデータを取得するよりも遅い。Anthropic は、最も効果的なエージェントはハイブリッド戦略 — 速度のために一部のデータを事前に取得し、さらなる自律的な探索は自らの裁量で行う — を採用しうること、そしてこのハイブリッドは、法務や金融の業務のように動的なコンテンツが少ない文脈により適しているかもしれないことを示唆している。例として Claude Code が挙げられており、CLAUDE.md ファイルは事前にコンテキストへ投入される一方、glob や grep といったプリミティブがファイルをジャストインタイムで取得し、古くなった索引や複雑な構文木の問題を回避している。
- これは、計測された比較からではなく、自社の製品経験と顧客との協働から導かれた、この分野がどこへ収束しつつあるかについての Anthropic の読みとして提示されている。Anthropic は、モデルの能力が向上するにつれて、エージェントの設計は人間によるキュレーションを次第に減らす方向へ向かうと見込んでいる。
