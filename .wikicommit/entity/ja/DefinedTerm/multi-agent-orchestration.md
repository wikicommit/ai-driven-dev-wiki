マルチエージェントオーケストレーションとは、それぞれが自分のコンテキストウィンドウを持つ複数のエージェントに作業を分割し、主導するエージェントあるいはオーケストレーターがそれらを調整する実践である。掲げられている2つの動機は、コンテキストの分離——単一のウィンドウがすべてを溜め込まないこと——と、並列性である。別々のエージェントは問題の異なる部分を同時に探索できるからだ。これは、コンテキストウィンドウが有限の資源であることに対する標準的な答えの一つであり、[[DefinedTerm/compaction]] と [[DefinedTerm/agentic-memory]] と並ぶ。

## 用法

[[TechArticle/effective-context-engineering-for-ai-agents]] はこのアーキテクチャを具体的に説明する。1つのエージェントがプロジェクト全体にわたって状態を維持するのではなく、専門化されたサブエージェントがきれいなコンテキストウィンドウで焦点の絞られたタスクを扱い、メインのエージェントが高水準の計画で調整する。各サブエージェントは数万トークン以上を使って広範に探索するかもしれないが、返すのは凝縮された要約だけである——記事はおよそ 1,000〜2,000 トークンという数字を挙げている。掲げられている利点は関心の明確な分離であり、詳細な検索のコンテキストがサブエージェントの内側に隔離される一方、主導するエージェントが結果を統合し分析する。同記事はまた、このアプローチをタスクの形に対応づけ、並行した探索が報われる複雑な調査と分析に推奨している。対話的なやり取りにはコンパクション、明確なマイルストーンを伴う反復的な開発にはノートテイキング、という具合である。

[[BlogPosting/context-engineering]] は同じアーキテクチャを、4分類の枠組みにおいてコンテキストを *分離する* 最も広く用いられる方法として扱い、各エージェントが自分のツール、指示、コンテキストウィンドウを持つことを指摘し、OpenAI の Swarm ライブラリの背後にある動機として関心の分離を挙げている。またコストも率直に述べている。Anthropic が報告するチャットの最大15倍のトークン、サブエージェントの作業を計画するための入念なプロンプトエンジニアリングの必要性、そして調整のオーバーヘッドである。

[[Report/2026-agentic-coding-trends-report]] は、単一のエージェントから協調するチームへの移行を、予測する 2026年の8つの潮流の一つとして扱い、それを採用するために何が必要かを説明している。タスクの分解、エージェントの専門化、調整のプロトコルにおける新しいスキル、さらには複数の同時進行するエージェントのセッションの状態を表示する開発環境と、同時並行のエージェント生成の貢献を扱えるバージョン管理のワークフローである。顧客の例として挙げられているのは Fountain の階層的なオーケストレーションであり、中央のオーケストレーションエージェントが、候補者のスクリーニング、文書の生成、感情分析のための専門化されたサブエージェントを調整している。

すべての実践者がこれに手を伸ばすわけではない。[[Person/geoffrey-huntley]] は [[BlogPosting/ralph-wiggum-as-a-software-engineer]] において、エージェント間の通信と多重化は当時必要ではなかったと論じ、非決定論的なエージェントをマイクロサービスとして扱うことを単一のモノリシックなプロセスと比べて否定的に捉えている——それでいて、その単一のプロセスの内側では [[DefinedTerm/subagents]] を多用し、スケジューラとして振る舞う主コンテキストウィンドウから派遣している。

## 関連用語

これが組み立てられる元の仕組みは [[DefinedTerm/subagents]] で、それを適用する一つの具体的な規律は [[DefinedTerm/subagent-driven-development]] で扱われている。これは [[DefinedTerm/context-engineering]] の戦略の一つであり、通常組み合わされる評価のステップが [[DefinedTerm/llm-as-judge]] である。そのための構成要素を提供するフレームワークには [[SoftwareApplication/langgraph]] と [[SoftwareApplication/context-engineering-kit]] がある。これを土台とする具体的な実践が [[custom/Practice/parallel-coding-agents]] である。
