AGENTS.md は、エージェンティック AI コーディングツールが読む、リポジトリレベルの Markdown 形式の [[DefinedTerm/context-files]] である。OpenAI によって導入され、[[ScholarlyArticle/configuring-agentic-ai-coding-tools]] によれば、現在ではオープンでツール非依存の慣習として、ツールをまたいで支持を広げつつある——CLAUDE.md、GEMINI.md、copilot-instructions.md といったベンダー固有の代替物とは対照的である。

## 用法

この研究は、3つの方向からの証拠に基づいて AGENTS.md を台頭しつつある相互運用可能な標準として同定している。ファイル数では CLAUDE.md にわずかに及ばず——1,572 ファイル（32.3%）に対して 1,661（34.2%）——、コンテキストファイルを含む 2,634 リポジトリのうち 1,069（40.6%）に現れる（CLAUDE.md は 1,195、45.4%）。作成順では、両方が存在する場合、典型的には CLAUDE.md が先に現れ、AGENTS.md が後から追加される。そして参照のパターンでは、大差をつけて最も参照されているコンテキストファイルであり、368 件の被参照を受けている。観測された中で最も強いパターンは CLAUDE.md が AGENTS.md を指し示すもので、311 回出現した。

著者らはこれを、ベンダーの命令によるものではなく、開発者の実践と互換性のニーズに駆動されたボトムアップの収束と読む。copilot-instructions.md から始まったリポジトリが、Copilot がすでに主要なコンテキストファイル形式すべてをサポートしていたにもかかわらず、後に CLAUDE.md や AGENTS.md を導入することが多かったことを指摘している。彼らは、AGENTS.md のネイティブサポート——Cursor と Codex はすでに提供している——がツールベンダーにとっての基本的な期待水準になるかもしれないと示唆する。研究の 2026年2月時点のスナップショットでは Claude Code はまだこれをサポートしていなかったと著者らは注記しており、これを、CLAUDE.md が先に現れて AGENTS.md が後から追加されるという作成順のパターンに対する一つの説明として挙げている。

そこから導かれる実務者向けの指針はこうである。複数のツールに依存する開発者は、共有の設定のベースラインとして AGENTS.md ファイルを維持することを検討すべきであり、ツール固有のファイルは共有のコアファイルを参照するアダプタとして働かせる。同じ研究は、1つのリポジトリに複数のコンテキストファイルを重ねると、成果物をまたいで冗長あるいは矛盾する指示が生じるリスクが高まると警告している。

実務者向けの資料も、この研究が統計的に導いたのと同じ相互運用性の言葉でこのファイルを枠づけている。[[Person/arun-gupta]] の [[PresentationDigitalDocument/spec-driven-development-using-coding-agents]] はこれを「エージェントのための README」——AI 向けの指示を置く明確で予測可能な場所——と説明し、その価値として、持続するコンテキストによってエージェントがセッションをまたいでプロジェクトを記憶すること、多くのエージェントで動く1つのファイルであること、オンボーディング時間がゼロで新しいセッションが即座に生産的に始まること、そしてよくある誤りが起こる前に防ぐ組み込みのガードレールであることを挙げる。このスライドが提案する仕様駆動のワークフローにおいて、`AGENTS.md` はエージェントが *知っておくべきこと* を担い、エージェントが *すべきこと* を担うスキル、そして何が作られつつあるのかを担う実装計画とは区別される。

### OpenAI 自身による説明

[[BlogPosting/introducing-codex]] における OpenAI 自身の説明は、上記の実証的な記述より簡潔であり、それらとは分けて捉える価値がある。AGENTS.md ファイルはリポジトリ内に置かれる「README.md に類するテキストファイル」であり、開発者はそこでエージェントに、コードベースをどう辿るか、テストのためにどのコマンドを実行するか、プロジェクトの標準的な慣行にどう従うのが最善かを伝えられる。OpenAI はこの依存関係を類比によって枠づける。「人間の開発者と同じように、Codex のエージェントは、設定済みの開発環境、信頼できるテスト環境、明確なドキュメントが与えられたときに最も力を発揮する」——一方で、自社の `codex-1` モデルは AGENTS.md ファイルやカスタムの足場がなくてもコーディングの評価や社内ベンチマークで高い成績を示すとも主張しており、このファイルは要件ではなく補助として提示されている。

同じ記事は、このファイルがツールにとどまらずモデルの振る舞いにまで及ぶことを示している。OpenAI は `codex-1` のシステムメッセージを公開し、その透明性がなぜ有用かの例として、システムメッセージが AGENTS.md ファイルに記載されたテストをすべて実行するようエージェントに促していること——時間のないユーザーはそれを飛ばすよう明示的に頼める——を挙げている。
