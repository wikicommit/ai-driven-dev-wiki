Agent2Agent プロトコル（略称 A2A）は、エージェントどうしがどう通信するかを定める標準である。これは
[[TechArticle/model-ai-governance-framework-for-agentic-ai]] がエージェントの中核的な構成要素の 1 つとして挙げる
プロトコル — エージェントがツールや他のエージェントと通信するための標準化された方法 — の 1 つであり、そこでは
エージェントがツールと通信するために開発された [[DefinedTerm/model-context-protocol]] に対する、エージェントどうしの側の
対応物として位置づけられている。このフレームワークは、ここが急速に発展している領域であり、とりわけエージェント型の
コマースにおいて、エージェント間のやりとりを標準化するプロトコルがさらに開発されつつあると述べている。

## 用法

このフレームワークではプロトコルは構成要素であると同時にリスクの源としても扱われている。プロトコルはずさんに配備されたり
侵害されたりしうるからで、挙げられている例は、ユーザーのデータを持ち出すコードを含んだ信頼できない MCP サーバーである。
マルチエージェントのやりとりについての推奨される統制は A2A を名指ししてはいないものの、あらゆるエージェント間のチャネルに
関わるものである。エージェント間で意図しない指示が渡ることを減らすために、自由文ではなく型付きの関数呼び出しのような
構造化されたスキーマを通じて通信することを求めること、そしてエージェント間で共有されるメモリへのアクセスを制限すること
である。

報告されているある配備は、実際にこれを使う際の代償を示している。
[[BlogPosting/agentic-engineering-swarms-of-ai-agents]] は、すべてのワーカーエージェントが A2A で通信し、それをサポート
しないエージェントには [[DefinedTerm/model-context-protocol]] のラッパーを介して到達するマルチエージェントの
エンジニアリングシステムを説明している。その著者らは、統合したかった AI コーディングエージェントにネイティブの A2A の
ケイパビリティがないことを見いだし、そのコーディングエージェントからワーカーエージェントへリクエストを中継する MCP の
アダプタツールを作った。彼らはこの構成によってシステムが IDE 非依存になると述べている。

3 つ目のソースは、このプロトコルがどこまで来たかを報告し、それが何と組み合わされているかを名指ししている。Jimmy Song の
オンラインハンドブック 智能体构建指南 のある章は、A2A を Google 主導のものとして説明し、2026 年のアップデートが
エージェントのディレクトリを導入したと述べ、それによって組織をまたぎフレームワークをまたいだエージェントの発見と呼び出しが
可能になると位置づけている。また、主要な Python のエージェントフレームワークが最初にネイティブの A2A サポートを得たとも
報告している。その章はこれら 2 つの出来事について、リリース日とバージョン番号をついでに挙げているが、それらを支える発表は
このページのソースに含まれていないため、ここでは述べ直さない。

その章がこの結果に与えている枠組みは、業界が落ち着きつつあると同章が述べる 2 つのプロトコルからなるスタックである。
**MCP がツールをつなぎ、A2A がエージェントをつなぐ** — 前者はエージェントが外部のケイパビリティにどう到達するかに、後者は
エージェントどうしがどう相互運用するかに答えるものであり、両者は合わさって
[[DefinedTerm/llm-based-multi-agent-system]] のプロトコルの基盤をなす。2026 年のまとめの表では、MCP は事実上の標準に
なったものとして、A2A は Google 主導のものとして挙げられ、エージェントのディレクトリがその際立った追加点とされている。
これらはそこで、測定された知見としてではなく、エコシステムの現状についての評価として述べられている。
