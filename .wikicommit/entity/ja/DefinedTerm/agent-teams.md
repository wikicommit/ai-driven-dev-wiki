Agent Teams は、複数のエージェントに 1 つのタスクを真に並列で実行させるための Claude Code の実験的機能であり、単純なサブエージェント構成にはない調整のためのプリミティブを追加する。環境変数 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効化され、作業を 3 つの層で構成する。作業を分解し、タスクリストを作成し、結果を統合するチームリード。各タスクの状態（pending、in-progress、completed、blocked）を依存関係の追跡とファイルロックとともに管理する共有タスクリスト。そしてチームメイトである。チームメイトはそれぞれが独自のコンテキストウィンドウを持つ独立した Claude Code インスタンスで、[[BlogPosting/code-agent-orchestra]] では別々の tmux ペインで動作すると説明されており、リストから自らタスクを取得する。

## 用法

チームメイトはリードを経由せず互いに直接メッセージをやり取りするため、あるチームメイトがタスクを終えて完了にすると、それに依存していたタスクは、リードが仲介することなく自動的にブロックが解除される。ファイルロックにより、2 人のチームメイトが同じファイルを同時に編集することが防がれる。報告されているプラクティスとして、lint、テスト、セキュリティスキャンのツールに制限され、タスクが完了するたびに自動的に起動される、読み取り専用の専任「@reviewer」チームメイトを生成するというものがある。これにより、リードが統合するのは常にレビュー済みのコードだけになる。

この機能がリサーチプレビューとして公開された時点で書かれた [[BlogPosting/claude-code-swarms]] は、コミュニティがこのような協調するチームを「swarms」と呼んでいたことに触れている。同記事は、チームが自然言語で要求され、リードがチームメイトを生成し、チームメイト間の直接のメッセージングのためのメールボックスがあると説明している。共有タスクリストの状態としては pending、in progress、completed を挙げ、未解決の依存関係を持つ pending のタスクは、それらが完了するまで取得できないこと、そして競合状態を防ぐためにタスクの取得にファイルロックが使われることを述べている。チームとタスクは `~/.claude/teams/` と `~/.claude/tasks/` の下にローカルに保存される。同記事は 2 つの表示モード、すなわちすべてのチームメイトがメインのターミナル内で動作するインプロセス（デフォルト）と、tmux または iTerm2 による分割ペインについて説明しているほか、リードがアプローチを承認するまでチームメイトが読み取り専用モードで作業する任意の計画承認と、リードを調整役に限定するデリゲートモードについても説明している。

同記事は Agent Teams をサブエージェントと対比している。サブエージェントは結果を単一の親に報告し、互いに会話することはできないのに対し、チームメイトは発見を共有し、互いのアプローチに異議を唱え、独立して調整を行う。ただし各チームメイトが別個の Claude インスタンスであるため、トークンのコストはより高くなる。同記事はこの実験的機能の制約として、インプロセスのチームメイトはセッションの再開時に復元されないこと、タスクの状態の反映が遅れることがあること、リードが管理できるのはセッションごとに 1 チームだけで、チームメイトは自分のチームを生成できないこと、そしてすべてのチームメイトがリードの権限設定で開始することを挙げている。
