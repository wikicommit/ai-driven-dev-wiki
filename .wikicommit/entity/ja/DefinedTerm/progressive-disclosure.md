段階的開示は、エージェントがスキルを読み込むやり方——一度にすべてではなく3つの段階に分けて——に対して Agent Skills 仕様が用いる用語である。仕様は、それによって狙う帰結を直截に述べている。完全な指示はタスクがそれを求めたときにのみ読み込まれるため、エージェントはわずかなコンテキストの占有量で多数のスキルを手元に置いておける、というものだ。

## 用法

仕様は3つの段階を挙げる。**発見（discovery）**では、起動時にエージェントが利用可能な各スキルの名前と説明だけを読み込む。それがいつ関連しうるかを知るのにちょうど足りるだけの情報である。**起動（activation）**では、タスクがあるスキルの説明に合致したときに、エージェントが完全な `SKILL.md` の指示をコンテキストに読み込む。**実行（execution）**では、エージェントがその指示に従い、必要に応じて同梱されたコードを実行したり、参照されたファイルを読み込んだりする。

この仕組みを導入した記事である [[TechArticle/equipping-agents-for-the-real-world-with-agent-skills]] は、段階的開示を「Agent Skills を柔軟かつスケーラブルにしている中核の設計原則」と呼び、*段階*ではなく*成果物*によって区分する。その説明では、**第一のレベル**は `name` と `description` のメタデータであり、エージェントは起動時にインストール済みのすべてのスキルについてこれをシステムプロンプトへ事前読み込みする。**第二のレベル**は `SKILL.md` の本文であり、エージェントがそのスキルを現在のタスクに関連すると判断した場合にのみコンテキストへ読み込まれる。そして**第三のレベル以降**は、スキルのディレクトリに同梱され `SKILL.md` から名前で参照される追加のファイルであり、エージェントは必要になったときにのみそれらをたどって発見する。2つの枠組みは同じ読み込みの振る舞いを説明している——仕様の発見・起動・実行の各段階はこれらのレベルと対応する——が、レベルのほうは再帰性を明示的にする。参照されたファイルがさらに別のファイルを参照しうるからだ。

その記事の類比は、目次から始まり、次に個別の章、最後に詳細な付録へと進む、よく整理されたマニュアルである。掲げられている見返りは、占有量の削減より強いものだ。ファイルシステムとコード実行のツールを持つエージェントはスキル全体をコンテキストに読み込む必要が決してないため、「スキルに同梱できるコンテキストの量は事実上無制限である」。

### リポジトリ自身のコンテキストファイルへの適用

[[DefinedTerm/dotagents]] は、スキルやツールの定義ではなくプロジェクトのコンテキストに段階的開示を適用したものである。一画面分のルーティングルールが前もって読み込まれ、その後にタスクが合致する特定のファイルだけが引き込まれる。[[BlogPosting/dotagents-standard-agent-skill]] はこの原則を、デバッグ専用の診断エンドポイントを本番ビルドから外しておくことや、すべてを返す一つのエンドポイントではなく関心事ごとに一つのエンドポイントを設けて API を設計することになぞらえる——「必要なものを、必要なときに読み込む。それより前ではなく」。

同じ記事は、この原則を自己言及的に適用した鮮やかな実演も提供している。この規約を教えるスキル自体がそのように構造化されており、入口のファイルを一画面分——メンタルモデル、分類、2つのワークフロー、ルーターのパターン——に保つ一方で、深い素材はタスクが要求したときにのみ読まれる参照ファイルに置かれているのだ。
