「制御平面とデータ平面の混同」は、NVIDIA の記事
[[BlogPosting/securing-llm-systems-against-prompt-injection]] が、プロンプトインジェクションが通常の防御に抗う理由を
言い表すために用いている語句である。同記事は、標準的なセキュリティのベストプラクティスに反して、LLM を扱うときには
制御平面とデータ平面が分離できないと論じる。単一のプロンプトが制御とデータの両方を含んでおり、プロンプトインジェクションは
その分離の欠如につけ込んで、データが期待されている場所に制御の要素を挿し込む。この説明によれば、この脆弱性はある特定の
アプリケーションの欠陥ではなく、同記事が現在の LLM に内在すると呼ぶものであり、だからこそ同記事はプロンプト
インジェクションを、修正すべきものではなく、それを織り込んで設計すべきものとして扱う。この語句は、確立した用語として
提示されているのではなく、同記事自身の結論部に一度だけ現れる。

## 用法

この語句は、技法を名指すためではなく、ある帰結を説明するために用いられる。プロンプトにテキストを送り込める攻撃者は
出てくるものを確実に操れるため、同記事が述べる結論は、LLM のあらゆる出力を潜在的に悪意あるもの、そして入力にテキストを
注入しうるいかなる主体の支配下にあるものとして扱わねばならない——下流の何かがそれをパースする前に検査し、
サニタイズせよ——というものである。損害が着地するのはその下流である。同記事の 3 つの具体例は、モデルの出力を受け取って
そこからインタプリタ、HTTP エンドポイント、データベースへの呼び出しを組み立てる連鎖であり、したがって出力の支配は
サービスの支配になる。

NVIDIA の AI レッドチームがそこで推奨する防御の構えは、入力を浄化しようとすることからではなく、出力を信頼できないものと
扱うことから導かれる。外部サービスへの呼び出しは厳密にパラメータ化され、最小権限の文脈で行われねばならず、現在の
プロンプトに寄与したいずれかの主体のうち最も低い権限が、後続の各呼び出しに適用されねばならない。プラグインの
テンプレートは可能なかぎりパラメータ化すべきであり、入力はこの混同を悪用しようとする試みがないか特に精査すべきである。
避けられる場合には、モデルを外部資源にそもそも接続しないよう同記事は助言し、複数のサービスを呼ぶ多段の連鎖を、厳格な
レビューを要するものとして名指ししている。
