エージェントステアリングとは、プルリクエストにおける人間の関与のうち、コードを評価するのではなくコーディングエージェント
を指揮する形をとるものである。[[ScholarlyArticle/these-arent-the-reviews-youre-looking-for]] が用いる分類では、
エージェントステアリングのコメントは、エージェントの名前 — Copilot、CodeRabbit、Devin、Claude、Gemini、Sourcery-AI
など — を「run」「fix」「rebase」「test」「update」といった命令形の動詞と組み合わせたものである。インラインのコマンド
（たとえば「@coderabbit fix lint failure」）も、単にエージェントに呼びかけて始まるコメントも、このカテゴリーに入る。
これは、LLM エージェントではなくインフラに宛てられている点を定義上の特徴とする自動化や CI とのやりとりとは区別され、
また、実質的な評価のフィードバックと短いプロセス寄りの発言の双方を含む残余のカテゴリーである人間による直接のレビューとも
区別される。

## 用法

この用語は、プルリクエスト上の人間のコメントを単に数えただけでは一緒くたになってしまう 2 つのもの、すなわち変更を評価
している人間と、変更を生み出すエージェントを操作している人間とを切り分けるために用いられる。その切り分けこそがこの概念の
眼目である。この分類を導入した論文は、どちらも PR の履歴上では人間が書いたコメントとして現れるのだから、コメント数に基づく
レビューの指標は監督と操作とを区別できず、それゆえプロジェクトのレビュー活動がどれだけの人間による評価を表しているかを
過大に見積もる、と論じる。

このカテゴリーはまた、その論文が報告する最も強い対比を担ってもいる。エージェントステアリングは、エージェントが書いた
プルリクエストにおける人間のレビューコメントの 25.92% を占めたのに対し、同じリポジトリ群の人間が書いたプルリクエストでは
1.63% にとどまり、この差は大きな効果量（Cramér's V = 0.34）を伴っていた。人気のあるリポジトリのエージェント作成 PR 全体
では、人間のコメントの 28.37% がエージェントステアリングであった。

## 適用される場面

エージェントステアリングが記述するのは、変更の作成者自身が、スレッドに残された指示に応じて行動できるエージェントである
ときに人間が行うことであり、したがってこの実践は、自分のプルリクエストを監視するエージェントと、コマンドのチャネルを
兼ねるレビューの場とを前提としている。著者らは、PR のコメントをこのように再利用することには現実の利点があるとも述べて
いる。既存のインフラを再利用でき、フィードバックループを短くできるのである。

その失敗モードは、著者らの見立てでは運用上のものではなく解釈上のものである。それは評価とやりとりの境界をぼかしてしまい、
観察可能なレビュー活動がもはや人間による直接の評価に対応しなくなる。沈黙のレビューや記録に残らないレビューと組み合わ
さると、これは PR の記録における人間の監督の追跡可能性を低下させる。

この分類は単一の実証研究に基づく。その境界は先行理論からではなくコーパスから導かれたもので、正規化したテキストでコメント
をまとめ、最も頻出する形を検査し、パターンを反復的に広げていく手法による。手作業で再ラベル付けした 800 件のコメントでの
検証では、この 3 クラスの枠組みは全体で 96.5% の正確度を示し、エージェントステアリングは適合率 94.5%、再現率 95.0% で
あった。著者らは、残る誤分類は主にエージェントステアリングと人間による直接のレビューのあいだに生じており、これは命令形の
表現と非形式的な話し言葉との語彙上の重なりを反映していると報告している。
