Model Context Protocol（MCP）は、AI アプリケーションを外部システム——ローカルファイルやデータベースといったデータソース、検索エンジンや計算機といったツール、専門的なプロンプトといったワークフロー——に接続するためのオープン標準である。[[Organization/anthropic]] は 2024年11月25日にこれを発表し、問題を孤立の問題として枠づけた。高度なモデルでさえ「情報のサイロとレガシーシステムの背後に閉じ込められて」おり、新しいデータソースはどれも「それぞれ独自の実装を必要とし、真に接続されたシステムをスケールさせることを困難にしている」——Wikipedia の記述が、Anthropic が説明したとする「N×M」のデータ統合問題として表現している問題である。MCP はこうした断片化した連携を単一のプロトコルで置き換え、開発者がエージェントに MCP を一度実装すれば、連携のエコシステム全体にアクセスできるようにする。公式ドキュメントの類比は AI アプリケーションのための USB-C ポートである。USB-C が電子機器を接続する標準化された方法を提供するのと同じように、MCP は AI アプリケーションを外部システムに接続する標準化された方法を提供する。

## 用法

### アーキテクチャ

プロトコルは3つの役割を区別する。**ホスト** は接続を開始する LLM アプリケーション——AI アシスタント、IDE、ワークフロー自動化ツール——である。必要なサーバーごとに、ホストはそのサーバーと通信する専用の **クライアント** を作る。**サーバー** は機能を提供するサービスである。ホストとクライアントは通常同じマシン上で動作し、サーバーはローカルにもリモートにも置かれうる。クライアントとサーバーの各接続は、初期化と機能のネゴシエーションから始まる専用のステートフルなセッションであり、メッセージには JSON-RPC 2.0 を用いる。トランスポートはローカルプロセスには stdio、ネットワーク越しの通信には Streamable HTTP を用いる。HTTP 上の Server-Sent Events は仕様の 2025-06-18 版で非推奨となった。

仕様は機能を、どちら側が提供するかによって分類する。サーバーは **Resources**（ユーザーやモデルのための文脈とデータ）、**Prompts**（ユーザーのためのテンプレート化されたメッセージとワークフロー）、**Tools**（モデルが実行する関数）を提供しうる。クライアントは **Sampling**（サーバー発のエージェンティックな振る舞いと再帰的な LLM とのやり取り）、**Roots**（動作すべき URI やファイルシステムの境界についてのサーバー発の問い合わせ）、**Elicitation**（ユーザーへの追加情報を求めるサーバー発の要求）を提供しうる。追加のユーティリティは、設定、進捗の追跡、キャンセル、エラー報告、ロギングを扱う。

動作としては、クライアントがサーバーに、提供するツールとリソースの一覧を問い合わせる。サーバーは各機能の自然言語による説明と期待される呼び出し形式を返す。その情報が LLM に与えられ、モデルがツールを必要としたときにホストが該当のクライアントにそれを呼び出すよう指示し、返ってきた結果を会話に注入する。

仕様は、プログラミング言語のサポートを開発ツールのエコシステム全体にわたって追加する方法を標準化した Language Server Protocol からいくらかの着想を得ていると述べている——MCP は同じやり方で、追加の文脈とツールが AI アプリケーションのエコシステムに統合される方法を標準化する。Wikipedia の記述によれば、これ以前の間に合わせのアプローチは似た問題を解いていたがベンダー固有のコネクタを必要とした。[[Organization/openai]] の 2023年の function-calling API と ChatGPT のプラグインのフレームワークである。

### 配布とエコシステム

Anthropic の発表は3つの構成要素を出荷した。仕様と SDK、Claude デスクトップアプリにおけるローカル MCP サーバーのサポート、そして Google Drive、Slack、GitHub、Git、Postgres、Puppeteer 向けの構築済みサーバーを含む、MCP サーバーのオープンソースリポジトリである。プロトコルは Python、TypeScript、C#、Java などの言語の SDK とともに、サーバー実装の例を添えて公開された。`modelcontextprotocol/modelcontextprotocol` リポジトリは仕様、プロトコルのスキーマ、公式ドキュメントを保持し、MIT License の下でライセンスされ、スキーマをまず TypeScript で定義したうえで、より広い互換性のために JSON Schema としても公開している。ドキュメントサイトは Mintlify を用いて構築されている。

発表で名指しされた初期の採用企業は Block と Apollo、そして開発ツール企業の Zed、Replit、Codeium、Sourcegraph だった。Block の最高技術責任者である Dhanji R. Prasanna は、MCP のようなオープンな技術を「AI を現実世界のアプリケーションにつなぐ橋」と表現したと引用されている。Wikipedia が報告するその後の採用には、OpenAI が ChatGPT デスクトップアプリを含む自社プロダクト全体に統合したうえで 2025年3月に MCP を公式に採用したこと、2025年9月に ChatGPT アプリへ MCP のサポートを追加したこと、Microsoft Semantic Kernel および Azure OpenAI との統合、そして Cloudflare への MCP サーバーの展開が含まれる。公式ドキュメントは、対応クライアントとして Claude、ChatGPT、Visual Studio Code、[[SoftwareApplication/cursor]]、MCPJam を挙げている。とりわけ [[DefinedTerm/ai-assisted-software-development]] においては、IDE、Replit のようなコーディングプラットフォーム、Sourcegraph のようなコードインテリジェンスのツールが、AI コーディングアシスタントにプロジェクトの文脈へのリアルタイムなアクセスを与えるために MCP を採用した。

Wikipedia はガバナンスと規模に関する2つの動きを記録している。2025年12月、Anthropic は MCP を [[Organization/agentic-ai-foundation]] に寄贈した。これは Anthropic、Block、OpenAI が他社の支援を得て共同設立した、Linux Foundation の下の指定基金である。2026年4月、同財団はニューヨーク市で MCP Dev Summit North America を開催し、およそ 1,200 名を集めた。同じ月、Salesforce の Headless 360 プラットフォームが顧客とエージェントのやり取りを MCP 経由でルーティングし始め、5月下旬に Salesforce はローンチ以来 450 万件の MCP 呼び出しを処理したと報告した。mcp-ui の上に構築された公式拡張である MCP Apps は、ダッシュボード、フォーム、データ可視化といった対話的なユーザーインタフェースをサーバーからホストアプリケーションへ配送する方法を標準化する。これはテキストと構造化データに限定された基本仕様が扱っていない領域である。

2025年11月までに Anthropic 自身は、コミュニティが数千の MCP サーバーを構築し、主要なプログラミング言語すべてに SDK が存在し、業界がエージェントをツールとデータに接続するための事実上の標準として MCP を採用した、と特徴づけていた。

### セキュリティ

仕様は、MCP が「任意のデータアクセスとコード実行の経路を通じて強力な機能を可能にする」ことを明言し、実装者に向けた4つの主要な原則を示している。ユーザーの同意と制御、データのプライバシー、ツールの安全性、そして LLM のサンプリングの制御である。ツールの安全性については、ツールは任意のコード実行を表すものであり、「アノテーションのようなツールの振る舞いの説明は、信頼できるサーバーから得たものでない限り、信頼できないものとみなすべきである」と述べている。また MCP 自身がプロトコルのレベルでこれらの原則を強制することはできないとも認めており、代わりに実装者は堅牢な同意と認可のフローを構築し、セキュリティ上の含意を文書化し、アクセス制御とデータ保護を実装し、セキュリティのベストプラクティスに従い、機能の設計においてプライバシーへの影響を考慮す **べきである（SHOULD）** としている。

独立した分析はすぐに続いた。Wikipedia は、2025年4月にセキュリティ研究者が分析を公開し、MCP には未解決のセキュリティ上の問題が複数あると結論づけたことを記録している。プロンプトインジェクションや、他の接続されたツールを通じたデータの持ち出しを許す汚染されたツールなどである。Microsoft 自身のガイダンスは、名前の付いた2つのリスクを [[DefinedTerm/indirect-prompt-injection]] と、その部分集合としての [[DefinedTerm/tool-poisoning]] として枠づけている。[[Report/model-context-protocol-security]] は、2026年1月8日に CoSAI のプロジェクト運営委員会によって承認されながら依然として「ステータス：ドラフト」と記されており、40 近い脅威を3つの階層にわたる12のカテゴリに整理し、MCP には既存の AI リスクのフレームワークとは異なる脅威モデルが必要だと論じる。それらのフレームワークは構成要素が事前に定義されたロジックに従って予測可能に振る舞うと前提しているのに対し、MCP は「自然言語の入力によって振る舞いが形作られるエージェントである LLM を、セキュリティ上決定的な判断の中心に据えている」からである。

### 学術的な分析

2つの査読向けサーベイは MCP を、採用すべきツールではなく研究対象として扱っており、いずれもセキュリティから接近している。

[[ScholarlyArticle/mcp-landscape-security-threats]]（2025年10月）は、公式ドキュメントと運用上のワークフローから導いたサーバーの4フェーズのライフサイクル——作成、配備、運用、保守——に分析を基礎づけ、4種類の攻撃者にわたる16の脅威シナリオを、単一のフェーズにではなく各リスクの *起点* に対応づける。ツールポイズニングやラグプルのような攻撃は「作成の段階で持ち込まれるが、運用の段階で発火する」という理由からである。MCP を以前のものと区別するものについての説明は、従来の function-calling の仕組みとは異なり、MCP が「アクセス制御、機能のネゴシエーション、スキーマの発見をプロトコルのプリミティブとして組み込んでいる」という点である。構造的な診断としては、サーバーが独立した開発者によって管理されており、ベースラインを監査する中央の権威が存在しないため、このエコシステムには集中的なセキュリティの監督がないこと、そして MCP は「現在、クライアントとサーバーにまたがる認証と認可の標準化されたフレームワークを欠いている」ことを挙げている。

[[ScholarlyArticle/sok-security-and-safety-in-the-mcp-ecosystem]]（2025年12月）は、プロトコルの形についてより強い主張をする。MCP が Resources（読み取り専用の文脈）、Tools（外部への行動）、Prompts（再利用可能なテンプレート）を独立したホスト、クライアント、サーバーに分離しているために「従来の『単一の安全境界』が溶解する」というのである。したがって、あるプリミティブにおける失敗が、別のプリミティブによって実行される有害な行動へとエスカレートしうる。そこから生じる文脈と行動の結合を「意味的な攻撃面」と呼び、中心的な主張は、MCP のもとではセキュリティとセーフティの区別が崩壊するというものである——ツールのパラメータについてのハルシネーションが侵害を生みうるし、注入された文書が、モデルが「正直に、しかし誤って、自分にはデータベースを削除する権限があると信じている」状態を残しうる。

### 規模におけるトークンのコスト

接続されるツールの数が増えるにつれて、セキュリティとは別の問題が現れる。[[TechArticle/code-execution-with-mcp]] における Anthropic のエンジニアリングの記述は、エージェントのコストとレイテンシを増やす2つのパターンを指摘する。大半のクライアントはすべてのツール定義を事前にコンテキストへ読み込むため、数千のツールに接続されたエージェントはリクエストを読む前に数十万トークンを処理することになる。そして中間的なツールの結果はすべてモデルを経由しなければならないため、データが繰り返しコンテキストを流れ、コンテキストウィンドウを完全に超えてしまいかねない。そこで提案される答えが [[DefinedTerm/code-execution-with-mcp]] であり、サーバーを直接のツール呼び出しとしてではなく、エージェントがコードを書いて呼び出すコード API として提示する。

## 関連用語

MCP は、コーディングツールについて整理された設定機構の一つであり、[[DefinedTerm/context-files]]、[[DefinedTerm/agent-skills]]、[[DefinedTerm/subagents]] と並ぶ——そして Anthropic は同じアプローチに従う姉妹オープン標準として Agent Skills を公開した。MCP サーバーを利用するツールは [[DefinedTerm/coding-agent]] で扱われており、MCP のツール定義が生むコンテキスト予算への圧迫は [[DefinedTerm/context-engineering]] の関心事の一つである。
