アクションスペースとは、エージェントが実行できるトランザクションを含め、エージェントが取りうるアクションの
範囲であり、使用を許されたツールと、それらのツールに対する権限によって決まる。この語は権限（authority）または
ケイパビリティ（capabilities）とも言い換えられる。[[TechArticle/model-ai-governance-framework-for-agentic-ai]]
は、エージェントに何ができるのかを問う際に区別しておくべき 2 つの概念の 1 つとしてこれを提示しており、もう 1 つ
が自律性、すなわちエージェントが目標に向けてどう行動するかを（たとえば取るべき手順を自ら定義するなどして）
決められる度合いであり、これは与えられた指示と人間の関与の水準によって決まる。

## 用法

エージェントのアクションスペースは主に、そのツールが到達する先のシステム — 他に何の影響も及ぼせない
サンドボックス化されたツール、組織自身のデータベースのような内部システム、サードパーティ API を通じて到達する
外部システム — と、それらのシステムに対して読み取りしかできないのか書き込みや変更もできるのかによって決まる。
コンピュータ利用エージェントは、アクションスペースを大きく広げる新興のモダリティとして説明されている。
コンピュータとブラウザへのアクセスがあれば、個別に定義されたツールや API に頼らずとも、人間がそれらを使って
できるあらゆるアクション（スクロール、クリック、タイピング）を取れるからである。

もう一方の軸である自律性は、指示がどれだけ規定的か（詳細な SOP か、エージェント自身の判断を用いよという指示か）
と、その運用が人間の関与のスペクトラム上のどこに位置するかによって決まる。そのスペクトラムは *エージェントが
提案し、人間が操作する* から、*エージェントと人間が協働する*、*エージェントが操作し、人間が承認する* を経て、
*エージェントが操作し、人間が観察する* へと至る。2 つの軸は独立したものとして扱われる。フレームワークはこれを
2 つのソフトウェアエンジニアリングエージェントの対比で例示している。問題を診断するためにあらゆるファイルを
検索・閲覧できるが書き込み権限をもたないもの（自律性は高く、アクションスペースは小さい）と、ウェブを閲覧して
ファイルを変更できるが各ステップで人間の承認を要するか固定された SOP の下でしか動けないもの（自律性は低く、
アクションスペースは大きい）である。

軸を分けることはリスク評価において意味をもつ。両者は異なる側から入ってくるからである。エージェントのアクション
の範囲とその可逆性は、失敗の *影響* を左右する要因として挙げられるのに対し、エージェントの自律性の水準は、その
*蓋然性* を左右する要因として挙げられる。自律性が高いほど予測不可能性が増す、というのがそこで述べられている
理由である。
