アクションスペース（action-space）とは、エージェントが実行できるトランザクションを含め、エージェントが取りうる
アクションの範囲であり、使用を許可されたツールとそれらのツールに対する権限によって決まる。権限（authority）や
能力（capabilities）とも言い換えられる。[[TechArticle/model-ai-governance-framework-for-agentic-ai]] はこれを、
エージェントに何ができるかを問う際に区別しておくべき 2 つの概念の一方として示している。もう一方は自律性
（autonomy）であり、目標に向けてどう行動するか — たとえば取るべきステップを定めること — をエージェントが
どの程度自ら決められるかを指し、指示の内容と人間の関与の度合いによって決まる。

## 用法

エージェントのアクションスペースは主に、そのツールが到達するシステム — 他に一切影響を及ぼせないサンドボックス化
されたツール、組織自身のデータベースのような内部システム、あるいはサードパーティ API を通じて到達する外部システム
— と、それらのシステムから読み取れるだけなのか、書き込みや変更もできるのかによって決まる。コンピュータ操作
エージェントは、アクションスペースを大きく広げる新たなモダリティとして説明されている。コンピュータとブラウザに
アクセスできることで、特別に定義されたツールや API に頼ることなく、人間がそれらを使って行えるあらゆる操作
（スクロール、クリック、入力）を行えるようになるからである。

もう一方の軸である自律性は、指示がどれだけ規定的か — 詳細な SOP か、エージェント自身の判断に委ねる指示か —
と、デプロイが人間の関与のスペクトラム上のどこに位置するかによって左右される。このスペクトラムは
*エージェントが提案し、人間が操作する* から、*エージェントと人間が協働する*、*エージェントが操作し、人間が
承認する* を経て、*エージェントが操作し、人間が観察する* にまで及ぶ。2 つの軸は互いに独立したものとして
扱われている。フレームワークはこれを、問題を診断するために任意のファイルを検索・閲覧できるが書き込み権限を
もたないソフトウェアエンジニアリングエージェント（自律性は高く、アクションスペースは小さい）と、ウェブを閲覧し
ファイルを変更できるが、各ステップで人間の承認を得るか固定された SOP の下でしか動かないエージェント（自律性は
低く、アクションスペースは大きい）とを対比して示している。

軸を分けることはリスク評価において重要であり、2 つの軸は異なる側に入ってくる。エージェントのアクションの範囲と
その可逆性は、失敗の*影響*に関わる要因に挙げられている一方、エージェントの自律性の度合いは失敗の*発生可能性*に
関わる要因に挙げられている。その理由として、自律性が高いほど予測しにくさが増すことが述べられている。
