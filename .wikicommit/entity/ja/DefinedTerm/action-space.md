アクション空間（action-space）とは、エージェントが実行できるトランザクションを含め、エージェントが取りうるアクションの範囲であり、使用を許可されたツールとそれらのツールに対する権限によって決まる。この語は権限（authority）や能力（capabilities）とも言い換えられる。[[TechArticle/model-ai-governance-framework-for-agentic-ai]] は、エージェントに何ができるかを問う際に区別しておくべき 2 つの概念の 1 つとしてこれを提示しており、もう 1 つは自律性である。自律性とは、取るべきステップを定めるなどして、目標に向けてどう行動するかをエージェントが決められる度合いであり、指示の内容と人間の関与の度合いによって決まる。

## 用法

エージェントのアクション空間は、主として、そのツールが到達するシステム — 他に何の影響も及ぼせないサンドボックス化されたツール、組織自身のデータベースのような内部システム、あるいはサードパーティ API を通じて到達する外部システム — と、それらのシステムを読み取るだけなのか、書き込みや変更もできるのかによって決まる。コンピュータ操作エージェントは、アクション空間を大きく広げる新たなモダリティとして説明されている。コンピュータとブラウザへのアクセスによって、個別に定義されたツールや API に頼ることなく、人間がそれらを使って行えるあらゆるアクション（スクロール、クリック、入力）を取れるようになるからである。

もう一方の軸である自律性は、指示がどれほど規定的であるか — 詳細な SOP か、エージェント自身の判断に任せるという指示か — と、デプロイメントが人間の関与のスペクトラム上のどこに位置するかによって左右される。このスペクトラムは *エージェントが提案し、人間が操作する* から、*エージェントと人間が協働する*、*エージェントが操作し、人間が承認する* を経て、*エージェントが操作し、人間が観察する* にまで及ぶ。2 つの軸は互いに独立したものとして扱われる。フレームワークはこれを、問題の診断のためにあらゆるファイルを検索・読み取りできるが書き込みアクセスは持たないソフトウェアエンジニアリングエージェント（自律性は高く、アクション空間は小さい）と、Web を閲覧しファイルを変更できるが、各ステップで人間の承認を受けるか固定された SOP に従う場合に限られるエージェント（自律性は低く、アクション空間は大きい）とを対比して示している。

軸を分けることはリスク評価において重要であり、2 つの軸はそれぞれ異なる側に入ってくる。エージェントのアクションの範囲とその可逆性は、失敗の *影響* を左右する要因に挙げられる一方、エージェントの自律性のレベルは、失敗の *可能性* を左右する要因に挙げられている。自律性が高いほど予測不可能性が増す、というのがその理由として述べられている。
