アクション空間（action-space）とは、エージェントが実行できるトランザクションを含め、エージェントが取りうるアクションの範囲であり、エージェントが使用を許可されたツールと、それらのツールに対するパーミッションによって決まる。この語は権限（authority）や能力（capabilities）とも言い換えられる。[[TechArticle/model-ai-governance-framework-for-agentic-ai]] は、エージェントに何ができるかを問う際に区別しておく価値のある 2 つの概念の 1 つとしてこれを提示している。もう 1 つは自律性であり、エージェントが目標に向けてどう行動するか — たとえば取るべきステップを定めること — を自ら決められる度合いで、エージェントへの指示と人間の関与の程度によって決まる。

## 用法

エージェントのアクション空間は、主にそのツールが到達するシステム — 他の何にも影響を及ぼせないサンドボックス化されたツール、組織自身のデータベースのような内部システム、あるいはサードパーティの API を通じて到達する外部システム — と、そのシステムから読み取ることしかできないのか、それとも書き込みや変更もできるのかによって決まる。コンピュータ操作エージェントは、アクション空間を大きく広げる新たなモダリティとして説明されている。コンピュータとブラウザへのアクセスによって、特定に定義されたツールや API に頼ることなく、人間がそれらを使って取りうるあらゆるアクション（スクロール、クリック、入力）を取れるようになるからである。

もう一方の軸である自律性は、指示がどれだけ規定的であるか — 詳細な SOP か、エージェント自身の判断に委ねる指示か — と、デプロイメントが人間の関与のスペクトラム上のどこに位置するかによって決まる。このスペクトラムは、*エージェントが提案し、人間が操作する* から、*エージェントと人間が協働する*、*エージェントが操作し、人間が承認する* を経て、*エージェントが操作し、人間が観察する* にまで及ぶ。2 つの軸は独立したものとして扱われる。このフレームワークはそれを、問題を診断するために任意のファイルを検索・閲覧できるが書き込みアクセスを持たないソフトウェアエンジニアリングエージェント（自律性は高く、アクション空間は小さい）と、Web を閲覧しファイルを変更できるが、各ステップで人間の承認を得るか固定の SOP に従う場合に限られるエージェント（自律性は低く、アクション空間は大きい）とを対比して示している。

軸を分けることはリスク評価にとって重要であり、両者はそこで異なる側に入る。エージェントのアクションの範囲とその可逆性は、失敗の *影響* を左右する要因に挙げられる一方、エージェントの自律性のレベルは、失敗の *可能性* を左右する要因に挙げられている。自律性が高いほど予測不可能性が増す、というのがその理由として述べられている。
