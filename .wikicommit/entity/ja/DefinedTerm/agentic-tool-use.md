**エージェント型ツール利用**とは、エージェント型システムにおいて行動を実現する仕組みである。推論の中核として機能する言語モデルが、API、データベース、コードインタプリタなどの外部ツールを呼び出すことで、検索を通じて最新の知識にアクセスし、プログラムによる実行を通じて計算の正確さを高め、外部システムを通じて現実世界の操作を行えるようにする。[[ScholarlyArticle/agentic-tool-use-in-large-language-models]] は、標準的なモデルが単独ではできないことを動機としてこれを説明している。モデルの知識は学習データに制約されており、それが事実の誤りやハルシネーションを生みうるうえ、モデルはリアルタイムの情報へのアクセス、正確な計算の実行、外部システムとの信頼できるやり取りを苦手とする。

## 使われ方

同サーベイは、この実践を、最適化のシグナルがどこから来るかによって区別される 3 つのパラダイムに整理し、それらを順に置き換わっていくものではなく、互いに補完的なものとして並べて示している。

- **プラグアンドプレイとしてのプロンプティング。** モデルのパラメータは凍結されたままで、ツール利用の振る舞いは、指示、デモンストレーション、環境からのフィードバックによって引き出される。同サーベイはこれを、推論と行動の交互実行（熟考と外部操作を交互に行い、各観察を次の判断の手がかりにするループ）、計画と実行の分離（まず構造化された計画を作り、それから実行することで、各ステップで熟考を繰り返すことを減らす）、そしてプログラム支援型推論（中間表現がテキストから実行可能なコードへと移り、プログラム実行器が補助的なユーティリティではなく推論過程の一部になる）に細分している。
- **教師ありツール学習。** ツール利用のパターンを、ラベル付きまたは合成された教師データを用いてモデルのパラメータに直接組み込む。同サーベイはこれを、プロンプトエンジニアリングからデータエンジニアリングへの移行として位置づけている。その 3 つの流れは、自己教師ありのデータ生成、幅広い API コーパスにわたる大規模なインストラクションチューニング、そしてツール呼び出しの正しさだけでなく、ツール呼び出しに至る推論そのものを最適化する、プロセス指向またはアライメント重視のチューニングである。
- **報酬駆動のツール方策学習。** ツール利用を、模倣ではなく環境からのフィードバックを通じて最適化される逐次的意思決定問題として扱う。その流れは、戦略的な意思決定の最適化（ツールを呼び出すべきか、内部知識に頼るべきか）、複数ターンのやり取りにわたるエンドツーエンドの方策学習、そしてメモリモジュールやツール選択器も含めたエージェントシステム全体を 1 つの方策として最適化する、包括的またはマルチモーダルなフレームワークである。

同サーベイは評価を横断的な次元として扱い、パラダイムとともに共進化してきたとする 3 つのレベルを挙げている。**ツール利用の正しさ**（構造的に妥当な呼び出しを生成し、適切なツールを検索・選択し、そもそもツールが必要かどうかを判断できるか）、**タスクの完了**（ツールを解決策の機能的な構成要素として用い、エンドツーエンドのタスクを完了できるか）、そして**ツール駆動のインタラクション**（自らの行動が外部世界を変える、動的で状態を持つ環境において、敵対的な条件下も含めて信頼できる形で行動できるか）である。

## 適用される場面

- タスクが、モデルのパラメータでは提供できない情報、計算、効果 — 最新の知識、正確な算術、外部システムへの変更 — を必要とする場合に当てはまる。同サーベイの捉え方では、これらは偶発的な欠落ではなく、モデルが得意とすることと実運用で求められることの間に繰り返し現れるミスマッチである。
- モデルが正しく扱えるようにできるツールのインターフェースを前提とする。同サーベイの評価の節は、スキーマへの準拠、大規模な候補プールからの検索、引数の正しいグラウンディングを、それぞれ独立に失敗しうる別個の能力として扱っており、これが診断的なベンチマークとエンドツーエンドのベンチマークを分けている理由である。
- 失敗の仕方はパラダイムによって異なり、これが 3 つすべてを視野に入れておくべきだという同サーベイの主張の根拠である。プロンプティングは柔軟で導入コストが低いが、レイテンシとトークンコストが高く、長期にわたるタスクでは脆くなる。教師あり学習はより効率的で安定しているが、大規模で高品質な軌跡データを得られるかどうかに依存する。報酬駆動の学習は探索と誤りからの回復に対処するが、初期の誤りが伝播していく長い軌跡にわたる信用割り当ての問題に直面する。
- 必要のない場面で適用した場合にも失敗する。同サーベイは、以前のベンチマークの多くがツールを呼び出すべきだと暗黙のうちに想定していることを指摘し、ツールが利用可能であっても不要な呼び出しが全体の性能を低下させうることを示した研究を報告している。ツールを*使わない*と判断することが正しさの一部として扱われるのはこのためである。
- 相当な規模のベンチマークのエコシステムを持つ研究領域として十分に確立されているが、同サーベイは、実運用レベルのシステムは 3 つのパラダイムすべてを組み合わせることになるという自らの統一的な主張が、測定された結果ではなく著者らによる統合であることを明言している。
