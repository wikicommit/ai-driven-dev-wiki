**エージェント型ツール利用**とは、エージェント型のシステムにおいて行動を実際に成り立たせる仕組みである。推論の中核として働く言語モデルが、外部のツール — API、データベース、コードインタプリタなど — を呼び出すことで、検索を通じて最新の知識にアクセスし、プログラムの実行を通じて計算の正確さを高め、外部システムを通じて現実世界の操作を行えるようにする。[[ScholarlyArticle/agentic-tool-use-in-large-language-models]] は、標準的なモデルが単独ではできないことからこれを動機づけている。モデルの知識は訓練データによって限界づけられており、そこから事実の誤りやハルシネーションが生じうる。また、リアルタイムの情報へのアクセス、正確な計算の実行、外部システムとの安定したやりとりのいずれにも苦戦する。

## 用法

このサーベイは、この実践を最適化の信号がどこから来るかによって区別される 3 つのパラダイムへと整理し、それらを順に取って代わるものとしてではなく、互いに補い合うものとして並べて示している。

- **プラグアンドプレイとしてのプロンプティング。** モデルのパラメータは凍結されたままで、ツール利用の振る舞いは指示・実演・環境からのフィードバックによって引き出される。サーベイはこれを、推論と行動を交互に織り交ぜるもの（熟慮と外部への操作を交互に行うループで、各観測を次の判断の手がかりにする）、計画と実行を切り離すもの（まず構造化された計画を作り、それから遂行することで、各ステップごとの熟慮の繰り返しを減らす）、そしてプログラムに支援された推論（中間表現がテキストから実行可能なコードへと移り、プログラムの実行系が補助的な道具ではなく推論の過程の一部になる）へと細分している。
- **教師ありのツール学習。** ラベル付きあるいは合成された教師信号を用いて、ツール利用のパターンをモデルのパラメータへ直接に符号化するもので、サーベイはこれをプロンプトエンジニアリングからデータエンジニアリングへの移行として位置づける。その 3 つの流れは、自己教師ありのデータ生成、広範な API コーパスにまたがる大規模な指示チューニング、そしてツール呼び出しの正しさだけでなくそこへ至る推論を最適化する、プロセス志向ないしアラインメント志向のチューニングである。
- **報酬駆動のツール方策学習。** ツール利用を模倣ではなく、環境からのフィードバックによって最適化される逐次的な意思決定問題として扱う。その流れは、戦略的な意思決定の最適化（ツールを呼ぶのか内部知識に頼るのか、その判断のタイミング）、複数ターンのやりとりにわたる端から端までの方策学習、そして記憶モジュールとツール選択器までを含めたエージェントシステム全体を 1 つの方策として最適化する、包括的ないしマルチモーダルなフレームワークである。

同じサーベイは評価を、これらのパラダイムと共に発展してきたと述べる 3 つの水準からなる横断的な次元として扱う。**ツール利用の正しさ**（モデルは構造的に妥当な呼び出しを生成し、正しいツールを検索して選び出し、そもそもツールが必要かどうかを判断できるか）、**タスクの完遂**（ツールを解の機能的な構成要素としながら、端から端までのタスクを完了できるか）、そして**ツールを介した相互作用**（自らの行動が外界を変えていく、動的で状態を持つ環境の中で、敵対的な条件下も含めて、安定して行動できるか）である。

## 適用範囲

- 適用されるのは、モデルのパラメータでは供給できない情報・計算・作用 — 最新の知識、厳密な算術、外部システムへの変更 — をタスクが必要とする場合である。サーベイの捉え方では、これらはモデルが得意なこととデプロイが要求することとの間に繰り返し現れるずれであって、偶発的な隙間ではない。
- 前提となるのは、モデルが正しく扱えるようにできるツールの表面が存在することである。サーベイの評価に関する節は、スキーマへの適合、大きな候補集合からの検索、そして引数の正しい接地を、それぞれ独立に失敗しうる別々の能力として扱っており、それが診断的なベンチマークと端から端までのベンチマークを分けている理由である。
- 失敗の仕方はパラダイムによって異なり、それが 3 つすべてを視野に入れておくべきだというサーベイの論拠になっている。プロンプティングは柔軟でデプロイも安価だが、レイテンシとトークンのコストが高くつき、長い時間軸の上では脆くなる。教師あり学習はより効率的で安定しているが、大規模で質の高い軌跡データを手に入れられるかに依存する。報酬駆動の学習は探索と誤りからの回復に取り組むが、序盤の誤りが伝播していく長い軌跡にわたる信用割り当ての問題に直面する。
- 必要でないところに適用したときにも失敗する。サーベイは、初期のベンチマークの多くがツールは呼ばれるべきものだと暗黙に前提していたことを指摘し、ツールが使える場合であっても不要な呼び出しが全体の性能を下げうることを示した研究を報告している。ツールを使わ*ない*という判断が正しさの一部として扱われているのは、そのためである。
- 研究領域としては十分に確立しており、ベンチマークの生態系も厚い。ただしサーベイは、それ自身の統合的な主張 — 実運用水準のシステムは 3 つのパラダイムすべてを組み合わせることになる — が測定された結果ではなく著者らの総合であることを明言している。
