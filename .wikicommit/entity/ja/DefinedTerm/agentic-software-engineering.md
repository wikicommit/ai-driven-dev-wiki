エージェンティックソフトウェアエンジニアリング（agentic SE）は、エージェンティック AI をソフトウェアエンジニアリングに適用すること——そして相互に、エージェンティック AI のためのソフトウェアエンジニアリング——に関わる新興の研究領域および実践である。その範囲も、価値観も、語彙も、定まっているというよりまだ議論の最中にあるほど萌芽的である。[[ScholarlyArticle/toward-agentic-software-engineering-beyond-code]] は、2026年1月時点でこの領域について提案された枠づけの多くが依然として査読中であったと指摘している。

## 用法

いくつもの異なるビジョンが並行して提案された。Hoda の論文はそれらを概観し、一つの共通点を持つものとして特徴づける。いずれも主として単一のソフトウェアエンジニアリング活動、すなわちコーディングに焦点を当て、その周辺に集中しているという点である。論じられている提案の中には次のものがある。Roychoudhury らが説明する *エージェンティック AI ソフトウェアエンジニア* という新しい役割——コーディング、テスト、デバッグを一貫した説明可能なワークフローに統合する自律的な LLM ベースのコーディングエージェントであり、関心が「大規模なプログラミング」から「信頼を伴うプログラミング」へ移行すると予測する。Applis らによる *統合ソフトウェアエンジニアリングエージェント*（USEagent）——複数のプログラミングタスクにまたがる能力を持ち、AI と人間が混在するチームの一員となりうる将来の AI ソフトウェアエンジニアの最初の草案として枠づけられる。そして Hassan らによる *構造化されたエージェンティックソフトウェアエンジニアリング*（SASE）——SE for Humans と SE for Agents という2つの共生的なモダリティを扱う概念フレームワークであり、レベル 0 の手作業のコーディングから、ゴール・エージェンティック（Agentic SE、すなわち SE 3.0 と呼ばれる）を経て、レベル 5 の汎用ドメイン自律（SE 5.0）に至る、自律性が増していく階層として組織され、従来型の IDE を置き換える専用のエージェントコマンド環境とエージェント実行環境を構想する。

これらに対して Hoda は、エージェンティック SE をコーディングの加速としてではなく、倫理的整合、要求工学、設計、開発、運用を含む「プロセス全体」の分野として範囲づけるべきだと論じる。彼女が挙げる理由は歴史的なものである。ウォーターフォールからアジャイルに至るまで、これまでのソフトウェアエンジニアリングのプロセスモデルはいずれもプロセス全体を扱うアプローチによって定義されてきた。彼女は、ライフサイクル全体とプロジェクト管理上の関心事をカバーしていた Scrum がエクストリームプログラミングを大きく上回った理由の一端がここにあるのではないか、と示唆している。

彼女はまた、実証的な証拠からの論拠も挙げる。初期の研究は AI の役割を、コーディング、文章作成、ドキュメント作成のタスクにおける「個人の加速装置」として特徴づける一方で、チームワーク、協調、説明責任、文化における限界を示している——コード中心の枠づけでは届かない、社会技術的な関心事である。

## SE 3.0 という枠づけ

[[DefinedTerm/structured-agentic-software-engineering]] の提案は [[ScholarlyArticle/agentic-software-engineering-foundational-pillars]] で全体が示されており、そこでは「Agentic Software Engineering」という語が、扱う時代全体を指すとともに、自律性の階層における特定のレベルの名前としても用いられている。その階層において、レベル 3——*ゴール・エージェンティック*、SE 3.0 と呼ばれる——は、「キャッシュ層を追加する」といった技術的なゴールをコード変更の詳細な計画に対応づける段階であり、計画されたコード変更が生成されたコードブロックに対応づけられるレベル 2 のタスク・エージェンティックな AI 拡張 SE（SE 2.0）と、特定のドメインに対する広範な技術的マンデートが具体的な技術ゴールのリストに対応づけられるレベル 4 の特化ドメイン自律（SE 4.0）の間に位置する。

この階層を組み立てている区別は、*エージェンシー*——与えられたゴールを達成するために行動し計画を実行するシステムの能力——と、*自律性*——自らを統べ、そのゴールを独立に定式化する能力——の間にある。Hassan らは、完全な自律性を追い求めるよりも SE 3.0 の時代を使いこなすことにこそ、目下の、産業を定義づける挑戦があると論じる。レベル 2 からレベル 3 への移行が人間とコンピュータの関係を根本的に変え、ワークフローのオーケストレーション、信頼、検証において複雑さを持ち込むからである。

この論文はまた、この分野の語彙がしばしば曖昧にしている一線を引いている。*エージェンティックコーディング* は開発者と AI アシスタントの間の1対1のやり取りを指し、個人の生産性を高めることを狙った単独作業の拡張である。これに対して *エージェンティックソフトウェアエンジニアリング* は、多数の人間と多数のエージェントが協調したチームとして働く N対N の協働を支えなければならない。その前提として述べられているのは、ソフトウェアエンジニアリングは常にチームスポーツであった、ということだ。したがって集団的な課題——複雑さの管理、役割をまたいだ協調、競合するステークホルダーのニーズの調停、共有される成果物の維持——は、個人の加速だけでなく、構造化された協働の加速を要求する。

## 関連用語

この領域の語彙自体が争われている。Hoda の論文は、統語的なずれがすでに見えていること——agentic AI software engineer と AI software engineer と agentic software engineer——、そしてその食い違いの一部はより深い意味論的・哲学的な問題を反映していることを指摘する。何が懸かっているのかの一例として、カバレッジのテストが示される。ソフトウェアエンジニアはコーダー以上の存在である。したがって「AI ソフトウェアエンジニア」という肩書きがふさわしくなるには、自律的なコーディングエージェントはコーディング以上のことができなければならない。
