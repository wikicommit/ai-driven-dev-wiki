エージェンティックメモリとは、コンテキストウィンドウの外側のストレージに情報を書き出し、後でそれを読み戻す実践であり、エージェントの連続性がすべてをコンテキストに保ち続けることに依存しないようにするものである。[[TechArticle/effective-context-engineering-for-ai-agents]] はこの語を **構造化されたノートテイキング** と互換的に用い、エージェントが定期的にノートを書き、それをコンテキストウィンドウの外側のメモリに永続化し、後の時点で引き戻す技法として定義している。[[BlogPosting/context-engineering]] は同じ考えを4つの分類のうちの2つに分けている。コンテキストを *書く* とはそれをウィンドウの外に保存することであり、コンテキストを *選ぶ* とはその適切な部分を引き戻すことである。

## 用法

[[BlogPosting/context-engineering]] はこの考えをスコープによって整理している。その記述では、**スクラッチパッド** はエージェントが単一のタスクに取り組む間だけ情報を保持し、ファイルに書き出すツールとして、あるいはセッション中に持続する実行時状態オブジェクトのフィールドとして実装できる。この違いが、エージェントがそれをどう読み戻すか——ツール呼び出しによるか、開発者が各ステップで状態のどの部分を露出させるかを選ぶことによるか——を決める。同じ記述において **メモリ** は多数のセッションをまたいで持続する。この記事はこの考えの起源を、エージェントの各ターンの後に振り返り、自ら生成したメモリを再利用することを導入した Reflexion と、過去のフィードバックの集まりから定期的にメモリを統合した Generative Agents に求め、ChatGPT、Cursor、Windsurf がいずれもユーザーとのやり取りから長期メモリを自動生成する仕組みを備えていることを指摘している。

Anthropic の記述は、長い時間軸の作業における見返りを強調する。このパターンは最小限のオーバーヘッドで永続的なメモリを提供し、エージェントが複雑なタスクをまたいで進捗を追跡し、そうでなければ何十回ものツール呼び出しの中で失われてしまう決定的なコンテキストと依存関係を維持できるようにする。例として挙げられているのは、Claude Code が ToDo リストを作ること、そしてカスタムエージェントが `NOTES.md` ファイルを維持することである。最も印象的な例はコーディングの外にある——ポケモンをプレイする Claude である。エージェントは数千のゲームステップにわたって正確な集計を維持し、探索した地域の地図を作り、解除した実績を記憶し、どの攻撃がどの相手に効くかについての戦略的なノートを保ち続ける。しかもメモリの構造について指示されることは一切ない。コンテキストのリセット後は自らのノートを読み、数時間に及ぶ手順を続行する。記事はこれを、要約のステップをまたいだ一貫性が、コンテキストだけでは不可能な戦略を可能にしている例として提示している。

より難しいのは「選ぶ」ほうである。LangChain の記事は、エピソード記憶（望ましい振る舞いの少数事例）、手続き記憶（振る舞いを方向づける指示）、意味記憶（タスクに関連する事実）を区別し、多くのコードエージェントが、常に固定された狭い一群のファイル——Claude Code の `CLAUDE.md`、Cursor と Windsurf のルールファイル——を読み込むことで選択の問題を完全に回避していると指摘する。より大きなコレクションを保存する場合には、インデックス作成に埋め込みやナレッジグラフがよく用いられるが、記事は選択が依然として困難であることを認めている。Simon Willison が挙げた、ChatGPT がメモリから彼の所在地を取り出し、依頼した画像に予期せずそれを織り込んでしまった例を伝え、この種の望まない検索によって、ユーザーがコンテキストウィンドウを「もはや自分のものではない」と感じかねないことを指摘している。

## 関連用語

エージェンティックメモリは、長い時間軸のタスクに対する3つの標準的な技法の一つであり、他には [[DefinedTerm/compaction]] と [[DefinedTerm/multi-agent-orchestration]] がある。Anthropic はこれを、明確なマイルストーンを伴う反復的な開発に特に適合するものとしている。その最も単純な形態として機能する常時読み込まれるファイルは [[DefinedTerm/context-files]] で、それを取り巻く規律は [[DefinedTerm/context-engineering]] で扱われている。[[SoftwareApplication/langgraph]] は、チェックポイント化された短期状態と長期メモリのストアを通じて、両方のスコープを明示的に実装している。
