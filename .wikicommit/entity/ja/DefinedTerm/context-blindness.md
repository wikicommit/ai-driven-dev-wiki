コンテキスト盲目性とは、[[ScholarlyArticle/spec-kit-agents-context-grounded-agentic-workflows]] が、
構造化されたエージェント型ワークフローを採用してもなお生き延びる失敗モードに与えた名称である。エージェントの
中間成果物——仕様、実装計画、タスクのチェックリスト——は、それ自体としては筋が通っていながら、なお実際に存在する
リポジトリと噛み合わないことがありうる。この用語は、成果物それ自体の内部の不整合ではなく、成果物とコードベースの
間の不一致を名指すものであり、それこそがこの失敗モードがワークフローの構造を生き延びる理由である。仕様は内部の
一貫性について査読を受けて通過しうる一方で、それが記述しているリポジトリのほうが仕様と一致していないのである。

## 用法

この用語を導入した出典は 3 つの症状を挙げている。存在しない API を参照すること、存在しないファイルパスを提案すること、
そしてローカルのアーキテクチャ上ないし文体上の慣習に違反することである。また、進化し続けるコードベースにおいて
複数手順のタスクが失敗する理由として、現在のアーキテクチャについてのコンテキストの欠落、依存関係についての古びた
想定、そしてリポジトリの慣習との不一致を挙げている。

この状態を高くつくものにしているのは、その説明によれば、それが起きること自体よりも、いつ発見されるかである。
誤りは実装やテストの実行の最中という遅い段階で表面化し、その時点でエージェントは後戻りし、以前の成果物を改訂し、
あるいはさらなる不整合を持ち込む。したがって失敗は計画、タスク分解、実装といった段階をまたいで積み重なっていき、
その出典はこれが無駄な反復と信頼できない結果を生むと述べている。

この用語は是正策を動機づけるために導入されており、それゆえ暗黙の診断を伴っている。すなわち、接地（グラウンディング）を
計画と生成を行うのと同じエージェントのトラジェクトリ内の振る舞いとして扱うと、それはプロンプトの設計とコンテキスト
ウィンドウ内のノイズに左右されやすい、という診断である。あわせて提案されている対応は、接地と検証をワークフローの
明示的な操作にすること——各フェーズの前にリポジトリを探索し、その後に各中間成果物を環境と突き合わせて確認すること——で
ある。そうすれば、存在しないパスを参照する計画は、そこからコードが生成される前に捕捉される。

用語としては新しく、単一の出典に依拠している。その出典はこれを、他者がすでに用いている用語として確立するためではなく、
自らの貢献を枠づけるために用いている。
