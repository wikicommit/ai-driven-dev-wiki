MCP を用いたコード実行とは、エージェントを [[DefinedTerm/model-context-protocol]] サーバーに接続するためのパターンであり、サーバーをコンテキストウィンドウに読み込まれて直接呼び出されるツール定義としてではなく、エージェントがコードを書いて呼び出すコード API として露出させるものである。Anthropic は [[TechArticle/code-execution-with-mcp]] でこのパターンを示し、接続するサーバーの数とともに増大する2つのコストへの応答として枠づけている。事前に読み込まれるツール定義がコンテキストウィンドウを圧迫すること、そして中間的なツールの結果がすべてモデルを経由しなければならないことである。Cloudflare も同様の知見を公開し、同じアプローチを「Code Mode」と呼んでいる。Anthropic は共通する洞察を、LLM はコードを書くのが得意なのだから、開発者はその強みと戦うのではなく活用すべきだ、と要約している。

## 用法

Anthropic が説明する具体的な実装は、接続されたサーバーから利用可能なツールのファイルツリーを生成する——サーバーごとにディレクトリ、ツールごとにファイルがあり、各ファイルは基となる MCP のツール呼び出しに転送する薄い型付きラッパーである。エージェントはファイルシステムを探索することで機能を発見する。サーバーのディレクトリを一覧して何が利用可能かを見て、それから目下のタスクに必要な特定のツールファイルだけを読む。具体例——Google Drive から会議のトランスクリプトを読み出し、Salesforce のレコードに添付する——では、これによってトークン使用量が 150,000 トークンから 2,000 トークンに減ったと報告されており、Anthropic はこれを時間とコストの 98.7% の削減だとしている。

Anthropic は利点を5つの見出しにまとめている。

- **段階的な開示**: モデルはファイルシステムを辿るのが得意なので、ツール定義をすべて事前に読み込むのではなく必要に応じて読める。代替として `search_tools` ツールが示されており、名前だけ、名前と説明、あるいは完全なスキーマのいずれをエージェントが要求できるよう、詳細度のパラメータを持たせるのが理想的だとされる。
- **コンテキスト効率のよいツール結果**: 大きな結果は、モデルに何かが返る前に実行環境の中でフィルタし変換できる。そのため 10,000 行のスプレッドシートを扱うエージェントは、1万行ではなく5行を見れば済む。集計、複数ソースにまたがる結合、フィールドの抽出についても同様である。
- **より強力な制御フロー**: ループ、条件分岐、エラーハンドリングが、個々のツール呼び出しの連鎖ではなく通常のコードになる。これは最初のトークンまでのレイテンシも節約する。if 文を評価するのがモデルではなく実行環境になるからである。
- **プライバシーを保護する操作**: 中間結果は既定で実行環境に留まるため、モデルは明示的にログ出力または返却されたものしか見ない。Anthropic はさらに、より機微なワークロードについてはハーネスが PII をモデルに届く前にトークン化し、データが引き渡される際にクライアント側の参照でトークンを戻せるため、実際の値がモデルのコンテキストに一切入ることなく2つのサービスの間を流れると付け加える。そしてこれは、データがどこへ流れてよいかについて決定論的なルールを定めるのにも使えるとしている。
- **状態の永続化とスキル**: ファイルシステムにアクセスできれば、エージェントは中間結果をファイルに書き出して後で再開でき、自ら書いた動作するコードを再利用可能な関数として永続化できる。Anthropic はこれを [[DefinedTerm/agent-skills]] に直接結びつけ、そうして保存された関数に `SKILL.md` ファイルを加えれば、モデルが参照できる構造化されたスキルになると指摘する——こうしてエージェントは徐々により高水準の能力の道具箱を築き、自らの足場を進化させていく。

Anthropic はコスト面についても明言している。エージェントが生成したコードを実行するには、サンドボックス化、リソース制限、監視を備えたセキュアな実行環境が必要であり、これは直接のツール呼び出しなら避けられる運用上のオーバーヘッドとセキュリティ上の考慮を加える。したがってトークン、レイテンシ、合成可能性の利点は、こうした実装コストと秤にかけるべきだとしている。締めくくりの枠づけは、ここでの問題——コンテキスト管理、ツールの合成、状態の永続化——は目新しく感じられるがソフトウェアエンジニアリングには既知の解があり、このパターンはそうした確立されたパターンをエージェントに適用したものだ、というものである。
