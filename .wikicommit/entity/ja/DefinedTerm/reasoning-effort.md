推論エフォートは、モデルがどれだけ長く思考するかを、レイテンシおよびトークン消費とトレードオフする設定である。[[BlogPosting/update-on-recent-claude-code-quality-reports]] は、それが [[SoftwareApplication/claude-code]] でどう構成されているかを説明している。エフォートのレベルはモデルごとに、テスト時計算量の曲線上で選ばれた点として較正される。プロダクト層はそのうちの 1 点をデフォルトとして選び、エフォートのパラメータとして Messages API に送り、残りの点はコマンドを通じてユーザーに提供される。Anthropic が述べる一般的な関係は、モデルが長く思考するほど出力が良くなるというものである。

## 用法

この設定が存在するのは、このトレードオフの両側がいずれもユーザーにとって現実のものだからである。その記事によれば、Opus 4.6 がエフォートのデフォルトを `high` として Claude Code に搭載されたとき、ユーザーは、それがときどきあまりに長く思考するためにインターフェースがフリーズしたように見えることに気づいた。Anthropic はこれを、そうしたユーザーにとって不釣り合いなレイテンシとトークン使用量だったと述べている。デフォルトを `medium` に下げることは、社内の測定では、ほとんどのタスクでわずかに知能が下がる代わりにレイテンシが大幅に減り、ときおり生じる非常に長い思考の裾もなくなり、ユーザーの利用上限もより長くもつようになるとされた。

Anthropic は 2026 年 3 月 4 日にデフォルトを `medium` に下げ、この変更は Opus 4.6 だけでなく Sonnet 4.6 にも影響したと述べている。その後の経緯こそが、この説明の中でより広い教訓をもつ部分である。ユーザーは Claude Code の知能が下がったように感じると報告し、Anthropic は 4 月 7 日にこの決定を撤回した。ユーザーからは、デフォルトは高い知能にしておき、単純なタスクでは下げる方を選びたいと言われたという。撤回後のデフォルトは、Opus 4.7 では `xhigh`、それ以外のすべてのモデルでは `high` とされている。Anthropic は、デフォルトを通じてではなく可視性を通じてまず問題を解決しようとしたこと（起動時の通知、インラインのエフォート選択 UI、ultrathink の復活）を記録しており、それでもほとんどのユーザーは medium のデフォルトのままだったと報告している。

## 適用される場面

この設定が当てはまるのは、同じモデルを異なる思考量で有用に動かせるあらゆる場面であり、その選択肢を公開するハーネスと、エフォートのレベルが較正済みのモデルを前提とする。どこに設定すべきかについての Anthropic 自身の結論は率直で、デフォルトを下げたのは誤ったトレードオフだったというものである。ユーザーのフィードバックに対する同社の読みは、人々はデフォルトを高い知能にしておき、単純なタスクでは低いエフォートを選ぶ方を好む、というものである。

この説明には、念頭に置いておくべき限界が 2 つある。これは 1 つのベンダーが自社製品について書いたものであり、元の変更とその撤回の双方の根拠となった測定は、独立に報告されたものではなく社内の評価とユーザーのフィードバックである。また、ここで述べられている出来事は特にデフォルトの問題であり（どのエフォートのレベルも終始利用可能だった）、その点について記録されていることは限定的である。すなわち、通知、選択 UI、ultrathink の復活によって変更できると知らされた後でも、ほとんどの Claude Code ユーザーは medium のデフォルトのままだった、ということである。
