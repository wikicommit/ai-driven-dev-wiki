推論エフォート（reasoning effort）は、モデルがどれだけ長く考えるかを、レイテンシやトークン消費量とトレードオフする設定である。[[BlogPosting/update-on-recent-claude-code-quality-reports]] は、[[SoftwareApplication/claude-code]] においてそれがどのように構成されているかを説明している。エフォートレベルはモデルごとに、テストタイムコンピュートの曲線上で選ばれた点として較正され、プロダクト層がそれらの点の 1 つをデフォルトとして選んでエフォートパラメーターとして Messages API に送り、残りの点はコマンドを通じてユーザーに提供される。Anthropic が述べる一般的な関係は、モデルが長く考えるほど出力は良くなるというものである。

## 用法

この設定が存在するのは、トレードオフの両側がどちらもユーザーにとって現実的なものだからである。同記事によれば、Opus 4.6 がエフォートのデフォルトを `high` として Claude Code に搭載されたとき、ユーザーは、モデルがときおり非常に長く考え込んでインターフェースがフリーズしたように見えることに気づいた。Anthropic はこれを、そうしたユーザーにとって不釣り合いなレイテンシとトークン使用量だったと説明している。デフォルトを `medium` に下げることは、社内の測定では、ほとんどのタスクで知能がわずかに低下する代わりにレイテンシが大幅に短くなり、ときおり生じる非常に長い思考のテールもなくなり、ユーザーの使用量上限もより長く持つものとされた。

Anthropic は 2026 年 3 月 4 日にデフォルトを `medium` に下げ、この変更は Opus 4.6 だけでなく Sonnet 4.6 にも影響したと述べている。その後に起きたことが、この記述のうちより広い教訓を持つ部分である。ユーザーは Claude Code の知能が下がったように感じると報告し、Anthropic は 4 月 7 日にこの決定を撤回した。その際、ユーザーからは、デフォルトは高い知能にして、単純なタスクのときに自分で下げる方がよいと伝えられたと述べている。撤回後のデフォルトは、Opus 4.7 では `xhigh`、それ以外のすべてのモデルでは `high` とされている。Anthropic は、最初はデフォルトではなく可視性によって問題を解決しようとしたこと、すなわち起動時の通知、インラインのエフォート選択 UI、ultrathink の復活を試みたことを記録しており、それにもかかわらずほとんどのユーザーが medium のデフォルトのままだったと報告している。

## 適用される場面

この設定は、同じモデルを異なる量の思考で有用に実行できる場面であればどこにでも当てはまり、その選択肢を公開するハーネスと、エフォートレベルが較正されたモデルを前提とする。どこに設定すべきかについての Anthropic 自身の結論は率直である。デフォルトを下げたのは誤ったトレードオフだった、というものであり、ユーザーのフィードバックについての同社の解釈は、人々はデフォルトを高い知能にし、単純なタスクでは低いエフォートを選ぶ方を好むというものである。

この記述には、念頭に置いておくべき限界が 2 つある。1 つは、これが 1 つのベンダーが自社製品について書いたものであり、当初の変更とその撤回の双方の裏付けとなる測定は、独立に報告されたものではなく、社内の評価とユーザーのフィードバックだという点である。もう 1 つは、ここで描かれている出来事が特にデフォルトの問題であり、すべてのエフォートレベルは終始利用可能だったという点である。この点について記録されていることは限定的で、通知、選択 UI、ultrathink の復活によって変更できることが伝えられた後でも、ほとんどの Claude Code ユーザーが medium のデフォルトのままだったということである。
