コンテキストロットとは、モデルのコンテキストウィンドウ内のトークン数が増えるにつれて、そのコンテキストから情報を正確に想起する能力が低下するという観察である。[[TechArticle/effective-context-engineering-for-ai-agents]] はこの概念を、干し草の山から針を探す（needle-in-a-haystack）形式のベンチマーク研究に帰し、劣化の緩やかさにはモデルによって差があるものの、この特性はすべてのモデルに現れると述べている。これは、コンテキストウィンドウを、公称の上限まで埋めるべきバッファとしてではなく、限界効用が逓減する有限の資源として扱うことの実証的な前提である。

## 用法

Anthropic が示す説明はアーキテクチャに基づくものである。モデルは、新しいトークンが入るたびに消費される「アテンション予算」を持つものとして説明され、これは限りある人間のワーキングメモリとの類比から引かれている。その希少性はトランスフォーマーのアーキテクチャに帰される。そこではすべてのトークンが他のすべてのトークンに注意を向けうるため、n 個のトークンに対して n² の対関係が生じる——したがってコンテキスト長が伸びるにつれ、それらの関係を捉えるモデルの能力は薄く引き伸ばされ、コンテキストの大きさとアテンションの集中の間に緊張が生まれる。第二の原因として挙げられているのは学習データの分布である。短い系列のほうが長い系列より多いため、モデルはコンテキスト全体にまたがる依存関係についての経験が少なく、それに特化したパラメータも少ない。位置符号化の補間といった技法は、より長い系列を、元々学習された小さいコンテキストに適応させることで扱えるようにするが、トークンの位置の理解にはいくらかの犠牲を伴う。記事はこの効果の形について慎重であり、断崖ではなく性能の勾配だと説明している。モデルは長いコンテキストでも依然として非常に有能だが、情報の検索と長距離の推論において精度の低下を示す、というのである。

実践上の帰結は、コンテキストウィンドウを大きくすること自体は解決策ではない、ということである。Anthropic は、最強のエージェント性能が求められる場面では、当面のあいだ、あらゆるサイズのコンテキストウィンドウがコンテキストの汚染と情報の関連性の問題を免れないと論じている。

[[BlogPosting/context-engineering]] は、同じ領域に仕組みではなく失敗のモードから接近し、Drew Breunig の文章から4つの名前付きのパターンを伝えている。**コンテキスト汚染**（ハルシネーションがコンテキストに入り込むとき）、**コンテキスト散漫**（コンテキストが学習内容を圧倒するとき）、**コンテキスト混乱**（余計なコンテキストが応答に影響するとき）、そして **コンテキスト衝突**（コンテキストの各部分が食い違うとき）である。記事はこれらを、長いコンテキストのより平凡なコスト——ウィンドウの超過、コストとレイテンシの膨張——と並べて提示している。

Claude Code 自身のドキュメントは、この語を使わずに実践的な形を述べている。コンテキストウィンドウを管理すべき最も重要な資源だと説明し、それが一杯になってくるとモデルは以前の指示を「忘れ」始めたり、誤りを増やしたりしうると注記している。
