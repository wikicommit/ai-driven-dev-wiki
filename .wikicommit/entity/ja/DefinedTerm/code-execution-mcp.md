Code Execution MCP（CE-MCP）は [[DefinedTerm/model-context-protocol]] の実行モデルの 1 つであり、エージェントは自然言語のやり取りを通じてツールを反復的に呼び出すのではなく、制御フロー、ツール呼び出し、データ変換を記述した単一の自己完結した実行可能プログラムを生成し、それを隔離されたランタイム環境内で実行する。エージェントのコンテキストに戻ってくるのはそのプログラムの最終結果だけであるため、コンテキストの消費量は、タスクの複雑さやツールエコシステムの規模にかかわらずほぼ一定に保たれる。Anthropic や Cloudflare のものを含む業界の主要な導入事例がこの実行パラダイムを採り入れている。CE-MCP は従来の MCP を置き換えるのではなく拡張するものであり、ツールを実行環境内で呼び出し可能な関数として公開する。

## 用法

10 個の MCP-Bench サーバーと 3 つの GPT-4 系モデルにわたる実証的な比較では、CE-MCP は従来の MCP と比べて、トークン使用量、実行時間、対話ターン数を一貫して削減しつつ、ほとんどの設定でタスク達成度、ツール選択の精度、パラメータの精度を同等に保つことが分かった（[[ScholarlyArticle/from-tool-orchestration-to-code-execution]]）。同じ研究によれば、CE-MCP は、ツールの利用を並列化して結果をプログラム的に集約できるため、構造化されたデータ並列型のワークフローをもつ、複数のツールを使う複雑なタスクに最も適している。一方で、ターン間の段階的な推論や局所的なリトライが役立つ、コンテキストに敏感なタスク、テキストが大半を占めるタスク、反復性の高いタスクでは、従来の MCP が優位を保つ。

この研究はまた、宣言的なツール呼び出しからモデルが生成したコードの実行へと移行することで、システムのセキュリティ上の姿勢が根本的に変わることも明らかにした。信頼できないツール出力や例外メッセージが実行可能なセマンティクスへと格上げされるためである。MAESTRO 脅威モデリングフレームワークを CE-MCP に適用したところ、ツールの発見、コード生成と計画、コード実行、結果の返却と検証、ランタイムへの影響という 5 つの実行フェーズにわたって 16 の攻撃クラスが特定された。そのうちいくつかは、サンドボックスからの脱出を一切伴わずに実際に悪用可能であることが検証された。これには、誘発された終わらない再生成ループによるサービス拒否や、汚染された例外メッセージによる不正な権限昇格が含まれる。研究は 3 段階の多層防御アーキテクチャ（実行前の静的検証とセマンティックゲーティング、隔離され監視された実行、実行後のセマンティックゲーティング）を提案し、これはテストしたすべての攻撃を阻止したが、その防御を知っている攻撃者に対しては評価されていないことも付記している。
