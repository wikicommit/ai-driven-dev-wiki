Code Execution MCP（CE-MCP）は [[DefinedTerm/model-context-protocol]] の実行モデルであり、エージェントは自然言語のやり取りを通じてツールを反復的に呼び出すのではなく、制御フロー、ツール呼び出し、データ変換を記述した単一の自己完結した実行可能プログラムを生成し、それを隔離されたランタイム環境内で実行する。エージェントのコンテキストに戻ってくるのはそのプログラムの最終結果だけであるため、コンテキストの消費量はタスクの複雑さやツールエコシステムの規模にかかわらずほぼ一定に保たれる。Anthropic や Cloudflare のものを含む業界の主要な導入事例が、この実行パラダイムを採り入れている。CE-MCP は従来の MCP を置き換えるのではなく拡張するものであり、ツールを実行環境内で呼び出し可能な関数として公開する。

## 用法

10 個の MCP-Bench サーバーと 3 つの GPT-4 モデルのバリアントにわたる実証的な比較では、CE-MCP は従来の MCP と比べて、トークン使用量、実行時間、やり取りのターン数を一貫して削減し、しかも大半の設定でタスクの達成度、ツール選択の正確さ、パラメータの正確さは同程度に保たれた（[[ScholarlyArticle/from-tool-orchestration-to-code-execution]]）。同じ研究は、CE-MCP はツールの利用を並列化し、結果をプログラムで集約できるため、構造化されたデータ並列のワークフローを伴う、複雑で複数のツールを使うタスクに最も適している一方、従来の MCP は、ターン間での段階的な推論や局所的なリトライが有益な、コンテキストに敏感なタスク、テキスト量の多いタスク、あるいは反復の多いタスクで優位を保つことを見出した。

同研究はまた、宣言的なツール呼び出しからモデル生成コードの実行へと移行すると、システムのセキュリティ態勢が根本的に変わることも見出した。信頼できないツール出力や例外メッセージが実行可能な意味論にまで格上げされるためである。MAESTRO 脅威モデリングフレームワークを CE-MCP に適用したところ、ツールの発見、コード生成と計画、コード実行、結果の返却と検証、ランタイムへの影響という 5 つの実行フェーズにわたって 16 の攻撃クラスが特定された。そのうちのいくつかは、サンドボックスからの脱出を一切伴わずに実際に悪用可能であることが検証された。たとえば、終了しない再生成ループを誘発することによるサービス妨害や、汚染された例外メッセージによる無許可の権限昇格である。同研究は 3 段階の多層防御アーキテクチャ（実行前の静的検証と意味的ゲーティング、隔離され監視された実行、実行後の意味的ゲーティング）を提案し、それは検証したすべての攻撃を阻止したが、防御の存在を知っている攻撃者に対しては評価されていないことも付記している。
