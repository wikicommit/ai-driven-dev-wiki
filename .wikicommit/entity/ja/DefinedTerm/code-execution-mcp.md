Code Execution MCP（CE-MCP）は [[DefinedTerm/model-context-protocol]] の実行モデルであり、そこではエージェントが、自然言語
のやり取りを通じてツールを反復的に呼び出すのではなく、制御フロー・ツールの呼び出し・データ変換を符号化した単一の自己完結型の
実行可能プログラムを生成し、それが分離されたランタイム環境の中で走る。そのプログラムの最終結果だけがエージェントのコンテキスト
へ戻るので、タスクの複雑さやツールのエコシステムの規模にかかわらず、コンテキストの消費はほぼ一定に保たれる。Anthropic や
Cloudflare のものを含む主要な産業界の実装がこの実行パラダイムを導入している。CE-MCP は従来の MCP を置き換えるのではなく拡張
するものであり、実行環境の中でツールを呼び出し可能な関数として公開する。

## 用法

10 の MCP-Bench サーバーと 3 つの GPT-4 モデル変種にわたる実証的比較によれば、CE-MCP は従来の MCP と比べてトークン使用量・
実行時間・やり取りのターン数を一貫して削減しつつ、ほとんどの設定においてタスクの達成度・ツール選択の正確さ・パラメータの
正確さを同等に保っていた（[[ScholarlyArticle/from-tool-orchestration-to-code-execution]]）。同じ研究は、CE-MCP が、構造化
されデータ並列なワークフローを持つ複雑な複数ツールのタスクに最も適していることを見出した——ツールの利用を並列化し、結果を
プログラム的に集約できるからである——一方、従来の MCP は、ターン間の逐次的な推論と局所的な再試行から恩恵を受ける、文脈に
敏感で、テキスト量が多く、あるいは反復性の高いタスクにおいて優位を保っている。

この研究はまた、宣言的なツール呼び出しからモデル生成コードの実行へ移ることが、システムのセキュリティ上の構えを根本的に変える
ことも見出した。信頼できないツールの出力や例外メッセージが実行可能な意味論へ引き上げられてしまうため、MAESTRO 脅威モデリング
フレームワークを CE-MCP に適用したところ、5 つの実行フェーズ——ツールの発見、コード生成と計画、コードの実行、結果の返却と
検証、実行時の影響——にわたる 16 の攻撃クラスが特定された。そのうちいくつかは、サンドボックスからの脱出を一切伴わずに実際に
悪用可能であることが検証されており、終了しない再生成ループを誘発することによるサービス拒否や、汚染された例外メッセージを
介した不正な権限昇格が含まれる。研究は 3 段階の多層防御アーキテクチャ（実行前の静的検証と意味的ゲーティング、分離され監視
された実行、実行後の意味的ゲーティング）を提案しており、それは試験したすべての攻撃を阻止したが、これらの防御はその存在を
知っている攻撃者に対しては評価されていないと注記している。
