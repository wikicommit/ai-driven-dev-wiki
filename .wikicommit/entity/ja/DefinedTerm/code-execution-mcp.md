Code Execution MCP（CE-MCP）は [[DefinedTerm/model-context-protocol]] の実行モデルの 1 つであり、自然言語のやり取りを通じてツールを反復的に呼び出すのではなく、エージェントが制御フロー、ツール呼び出し、データ変換を記述した単一の自己完結した実行可能プログラムを生成し、それを隔離されたランタイム環境内で実行する。エージェントのコンテキストに戻ってくるのはそのプログラムの最終結果だけであるため、コンテキストの消費量はタスクの複雑さやツールエコシステムの規模にかかわらずほぼ一定に保たれる。Anthropic や Cloudflare のものを含む業界の主要な導入事例がこの実行パラダイムを採り入れている。CE-MCP は従来の MCP を置き換えるのではなく拡張するものであり、ツールを実行環境内で呼び出し可能な関数として公開する。

## 用法

10 個の MCP-Bench サーバーと 3 種類の GPT-4 モデルバリアントにわたる実証的な比較では、CE-MCP は従来の MCP と比べてトークン使用量、実行時間、対話ターン数を一貫して削減し、ほとんどの設定でタスク達成度、ツール選択の精度、パラメータの精度を同等に保つことが分かった（[[ScholarlyArticle/from-tool-orchestration-to-code-execution]]）。同じ研究では、CE-MCP はツールの使用を並列化し、結果をプログラム的に集約できるため、構造化されたデータ並列のワークフローを持つ複雑なマルチツールのタスクに最も適している一方、従来の MCP は、ターン間での段階的な推論や局所的な再試行が役立つ、コンテキスト依存の、テキスト量の多い、あるいは反復性の高いタスクにおいて優位を保つことが分かった。

同研究はまた、宣言的なツール呼び出しからモデルが生成したコードの実行へと移行することが、システムのセキュリティ態勢を根本的に変えることも見出した。信頼できないツール出力や例外メッセージが実行可能なセマンティクスへと格上げされるためである。MAESTRO 脅威モデリングフレームワークを CE-MCP に適用したところ、ツールの発見、コード生成と計画、コード実行、結果の返却と検証、ランタイムへの影響という 5 つの実行フェーズにわたって 16 の攻撃クラスが特定された。そのうちのいくつかは、サンドボックスからの脱出を一切伴わずに実際に悪用可能であることが検証された。これには、終了しない再生成ループを誘発することによるサービス拒否や、汚染された例外メッセージによる不正な権限昇格が含まれる。同研究は 3 段階の多層防御アーキテクチャ（実行前の静的検証とセマンティックゲーティング、隔離され監視された実行、実行後のセマンティックゲーティング）を提案し、それはテストしたすべての攻撃を阻止したが、これらの防御は防御の存在を知っている敵対者に対しては評価されていないことも付記している。
