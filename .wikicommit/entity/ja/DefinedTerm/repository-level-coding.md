リポジトリレベルのコーディングとは、[[ScholarlyArticle/codeplan-repository-level-coding-using-llms-and-planning]] が、1 か所の局所的な箇所で問題を解決するのとは対照的に、コードのリポジトリ全体に広くわたる編集を伴うソフトウェアエンジニアリングの活動に対して用いる用語である。その論文がこの定式化のもとにまとめる活動は、パッケージの移行、静的解析やテストから来るエラーレポートの修正、そしてコードベースへの型アノテーションやその他の仕様の追加である。

## 用法

この定式化は、大規模言語モデルに直接頼めることの境界を示すために導入されている。同じ論文は、GitHub Copilot のような LLM を活用したツールが局所的なコーディングの問題に対して高品質な解決策を提供することに成功してきたと述べたうえで、リポジトリレベルのタスクはより込み入っており、LLM を使って直接解決することはできないと論じる。その理由として 2 つの性質が挙げられている。リポジトリ内のコードは相互に依存しているため、ある箇所の編集が別の箇所に影響を及ぼすこと、そしてリポジトリ全体がプロンプトに収まらないほど大きい場合があることである。

これら 2 つの性質のために、この用語が指すのは、個々の編集が難しいことによるのではなく、構造的な難しさをもつタスクである。この定式化とともに報告された評価では、調べられたリポジトリレベルのタスク（C# でのパッケージ移行と Python での時間的なコード編集）は、リポジトリあたり 2 から 97 個のファイルにわたる相互依存的な変更を必要とした。
