Harness-as-a-Service（HaaS）は、Viv Trivedy によるものとされる、エージェントの構築方法の変化についての捉え方である。すなわち、補完を返す LLM API の上に構築することから、ランタイムを返すハーネス API の上に構築することへの移行である。この捉え方では、ハーネスフレームワークがエージェントループ、ツール呼び出し、コンテキスト管理、フック、サンドボックスのプリミティブを最初から提供し、構築者はループ、ツール呼び出し、会話状態、承認フローを一から組み立てるのではなく、システムプロンプト、ツール、コンテキスト、サブエージェントという 4 つの柱に沿ってそれらをカスタマイズする。

## 用法

情報源は、この方向を示す例として Claude Agent SDK、Codex SDK、OpenAI Agents SDK を挙げている。そして、この移行こそがエージェントの設計の反復を扱いやすくするものだと位置づけている。何かがうまくいかなくなるたびにエージェントを一から作り直すのではなく、すでにうまく整理された設定の表面を調整すればよくなるからである。

## 適用される場面

これが当てはまるのは、ループ、ツール実行、コンテキスト管理の要件をハーネスフレームワークがすでに満たしており、差別化のための作業がドメイン固有のプロンプトとツールの設計に残されているような、新しいエージェントベースのプロダクトやワークフローを構築する場合である。情報源は、いずれにせよ不完全な最初のバージョンから始めるべきだという Viv Trivedy の主張 ——「良いエージェント構築とは反復の営みである。v0.1 がなければ反復はできない」—— を、ハーネスが完全に固まるまでこのパターンの採用を遅らせない理由として引用している。
