Harness-as-a-Service（HaaS）とは、Viv Trivedy によるものとされる、エージェントの構築方法の転換を捉えた考え方である。すなわち、補完を返す LLM API の上に構築することから、ランタイムを返すハーネス API の上に構築することへの転換である。この捉え方のもとでは、ハーネスのフレームワークがエージェントループ、ツール呼び出し、コンテキスト管理、フック、サンドボックスのプリミティブを最初から提供し、構築者はループ、ツール呼び出し、会話状態、承認フローを一から組み立てるのではなく、システムプロンプト、ツール、コンテキスト、サブエージェントという 4 つの柱に沿ってそれらをカスタマイズする。

## 使われ方

情報源は、この方向を示す例として Claude Agent SDK、Codex SDK、OpenAI Agents SDK を挙げている。同情報源はこの転換を、エージェントの設計の反復を扱いやすくするものとして位置づけている。構築者は、何か問題が起きるたびにエージェントを一から作り直すのではなく、すでによく整理された設定面を調整することになるからである。

## 適用される場面

ハーネスのフレームワークがループ、ツール実行、コンテキスト管理の要件をすでにカバーしており、差別化のための作業がドメイン固有のプロンプトとツールの設計に委ねられるような、エージェントベースの新しいプロダクトやワークフローを構築する場合に当てはまる。情報源は、ともかく不完全な最初のバージョンから始めるべきだという Viv Trivedy の主張 — 「よいエージェント構築とは反復の営みである。v0.1 がなければ反復はできない」 — を引用し、ハーネスが完全に仕上がるまでこのパターンの採用を先延ばしにすべきでない理由としている。
