Addy Osmani は基調講演「Own the Outer Loop」において、アウターループを、エージェント型コーディングのワークフローのうち人間が所有権を保持し続ける部分として位置づけ、コーディングエージェントが自力で実行する「インナーループ」、すなわちタスクの調査、計画の実装、結果の検証と区別している。インナーループが能力の問題、つまりモデルとそのハーネスに何ができるかの問題であるのに対し、アウターループはエージェンシーの問題である。何を構築すべきかを決め、それが安全に構築されたことを検証し、承認し、その結果に責任を負うことだ。彼の主張は、エージェントがインナーループの中での支援から、インナーループ全体を自ら実行する段階へと移ったというものであり、それゆえにアウターループを所有することが、エンジニアに残された仕事の部分になるという。

別のソースは同じインナー／アウターの対を別の事柄に用いており、両者は互いに還元できない。[[BlogPosting/how-to-build-reliable-ai-workflows-with-agentic-primitives-and-context-engineering]] は、誰が責任を負うかではなく*作業がどこで実行されるか*で線を引く。インナーループは VS Code と GitHub Copilot による対話的な開発、テスト、ワークフローの改良であり、アウターループは再現可能な実行、CI/CD 統合、本番デプロイを提供するエージェント CLI ランタイムである。その要約としての助言は、迅速な対話的作業にはインナーループを、信頼性が高く反復可能な自動化にはアウターループを使うというものだ。この説明にはアウターループを人間に割り当てる記述はどこにもなく、むしろそのアウターループは二つのうちでより自動化された側であり、上記の意味とは逆である。この用語に出会った読者は、あるソースの主張を持ち出す前に、そのソースがどちらの対を意味しているのかを確かめるべきである。

## 用法

Osmani は、基調講演で名付けた三つの用語を軸にアウターループを整理している。Quality（品質）は、システムの稼働を許可する前に導入されるチェックであり、証拠を生み出す。Verdict（判定）は、その証拠に基づいて下される本番運用上の判断であり、出荷する、ブロックする、方向を変える、対応範囲を絞る、ガードレールを追加する、あるいは全面的に却下する、のいずれかである。Answerability（説明責任）は、Verdict を下した人が求められればそれを説明できるという保証である。彼は、アウターループを握るために人間がインナーループの中にいる必要はないとし、人間はその代わりに、彼が名付けた四つのより狭いループを担うと位置づける。制約ループ（どのような入力、アーキテクチャ、指示、不変条件を設定するか）、サンプリングループ（出力をどれだけサンプリングしてレビューするか）、監査ループ（どのような証拠を保持し、監査ログが有効かどうか）、そして所有権ループ（本番の境界のどの部分を誰が所有するか）である。

## 適用される場面

これが当てはまるのは、エージェントがインナーループを無人で実行することを任され、その規模や速度が人間がターンごとにレビューできる範囲を超えたときである。この投稿は、コミットされるコードのうち AI が生成した、あるいは AI の支援を受けたものの割合が大きく、かつ増え続けていることを示す調査結果や、レビューとガバナンスがボトルネックになっており、それらは通常、コードがすでに作成されリスクがすでに受け入れられた後になってようやく行われることを示す別の研究を引用している。また、型チェック、テスト、フック、サンドボックスの制限、監査ログ、モニターといった通常のエンジニアリング上のシグナルからなるバックプレッシャーの仕組みが前提とされており、それがエージェントに実際に与えられる自律性を、エージェントが行使しうる最大限の自律性よりも意図的に低く抑える。これを省くと、認知的降伏、認知的負債、オーケストレーション税という三つの隠れたコストが生じるとされる。

実行環境という意味では、アウターループが必要とするものはまた異なる。エディタの外で指示ファイルを実行できるエージェント CLI ランタイムと、どちらの場所でもそのまま実行できるだけの移植性を持つファイルである。この説明はこの移行を、IDE に縛られたファイルを独立して実行可能なワークフローへと変えることだと述べ、ランタイムが提供するものとしてコマンドラインでの実行、CI/CD 統合、環境の一貫性、MCP サーバーのネイティブサポートを挙げている。この構成についての評価は報告されていない。
