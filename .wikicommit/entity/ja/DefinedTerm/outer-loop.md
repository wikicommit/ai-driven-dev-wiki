Addy Osmani は基調講演「Own the Outer Loop」で、アウターループを、エージェント型コーディングのワークフローのうち人間が所有権を保持する部分として位置づけ、コーディングエージェントが自ら回す「インナーループ」、すなわちタスクの調査、計画の実装、結果の検証と区別している。インナーループが能力の問題——モデルとそのハーネスに何ができるか——であるのに対し、アウターループは主体性（agency）の問題である。つまり、何を作るべきかを決め、それが安全に作られたことを検証し、承認し、その結果に責任を負うことである。主張の要点は、エージェントがインナーループの内側で支援する立場から、インナーループ全体を自ら回す立場へと移ってきたということであり、それゆえにアウターループを所有することが、エンジニアに残された仕事の部分になっている。

2 つ目のソースは同じインナー／アウターという対を別の意味で使っており、両者は互いに還元できない。
[[BlogPosting/how-to-build-reliable-ai-workflows-with-agentic-primitives-and-context-engineering]]
は、誰が責任を負うかではなく *作業がどこで実行されるか* で線を引く。インナーループは VS Code と GitHub Copilot
による対話的な開発、テスト、ワークフローの洗練であり、アウターループは、再現可能な実行、CI/CD との統合、本番デプロイを
提供するエージェントの CLI ランタイムである。その要約としての助言は、素早い対話的な作業にはインナーループを、信頼性が
あり反復可能な自動化にはアウターループを使え、というものである。この説明にはアウターループを人間に割り当てる記述は一切
なく、むしろ、そこでのアウターループは 2 つのうちより自動化された側であり、上述の意味とは逆になっている。この用語に出会った
読者は、ある主張を別の文脈に持ち込む前に、そのソースがどちらの対を意味しているのかを確かめるべきである。

## 用法

Osmani はアウターループを、基調講演で名前を挙げる 3 つの用語を軸に組み立てている。Quality は、システムの実行が許可される前に設けられるチェックであり、証拠を生み出す。Verdict は、その証拠にもとづいて下される本番上の判断であり、出荷する、ブロックする、方向を変える、対応範囲を絞る、ガードレールを追加する、あるいは完全に却下する、のいずれかである。Answerability は、Verdict を下した人物が、問われればそれを説明できるという保証である。彼は人間の役割を、アウターループを保持するためにインナーループの内側にいる必要はないものと位置づけ、代わりに自らが名前を挙げる 4 つのより狭いループを担うものとしている。すなわち、制約ループ（どの入力、アーキテクチャ、指示、不変条件を設定するか）、サンプリングループ（出力のどれだけをサンプリングしてレビューするか）、監査ループ（どの証拠を保持するか、監査ログが有効かどうか）、所有権ループ（本番の境界のどの部分をある人物が所有するか）である。

## 適用される場面

これが当てはまるのは、エージェントがインナーループを無人で回すことを任され、その規模や速度が、人間が 1 ターンずつレビューできる範囲を超えたときである。記事は、コミットされるコードのうち AI が生成した、あるいは AI の支援を受けたものの割合が大きく、しかも増えつつあることを示す調査結果と、レビューとガバナンスがボトルネックになっており、典型的にはコードがすでに作られリスクがすでに受け入れられた後になってようやく行われることを示す別の研究を引いている。これは、型チェック、テスト、フック、サンドボックスの制限、監査ログ、モニターといった通常のエンジニアリング上のシグナルからなる背圧（back-pressure）の仕組みを前提としており、それがエージェントに実際に与えられる自律性の大きさを制約する。その自律性は、エージェントが行使しうる最大限の自律性よりも意図的に小さく抑えられる。これを省くと、認知的降伏、認知的負債、オーケストレーション税という 3 つの隠れたコストが生じると説明されている。

実行環境という意味では、アウターループが必要とするものはさらに異なる。すなわち、エディタの外で指示ファイルを実行できる
エージェントの CLI ランタイムと、どちらの場所でも変更なしに実行できるだけの可搬性をもつファイルである。この説明は、この
移行を IDE に縛られたファイルを独立して実行可能なワークフローに変えることとして描き、コマンドラインでの実行、CI/CD との
統合、環境の一貫性、ネイティブな MCP サーバーのサポートを、ランタイムが提供するものとして挙げている。この構成についての
評価は何も報告していない。
