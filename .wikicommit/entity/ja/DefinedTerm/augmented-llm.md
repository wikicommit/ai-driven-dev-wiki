Augmented LLM（拡張された LLM）とは、ツールなどの拡張を備えた大規模言語モデルのことである。Simon Willison はエージェント型システムの構築について論じた Anthropic の記事からこの語を紹介し、自分がとても気に入っている語のひとつとして取り上げている。その理由は、人々がまさにこれ — ツールを取りつけただけのモデル — を指して「エージェント」と呼ぶのを見てきたが、それが彼にはどうにも腑に落ちなかったからである。したがって、彼にとってのこの語の価値は境界を引くことにある。最も単純なケースに固有の名前を与えることで、「エージェント」がそこまで引き受けずに済むようにするのである。

## 使われ方

Willison がこの記事を評価しているのは、そもそも用語を定義している点である。「エージェント」という語についての彼のかねてからの不満は、この語には取りうる定義がいくつもあるのに、それを使うほとんどの人が、自分の選んだ定義を誰もが共有していると思い込んでいる、という点にあり、彼はこの記事が冒頭からその風潮に抗っていることを評価している。彼の紹介によれば、記事は「エージェント型システム（agentic systems）」を上位の語として扱い、そのうえで「ワークフロー」 — あらかじめ定義されたパターンを用いて複数の LLM がまとめてオーケストレーションされるシステム — と「エージェント」 — LLM が自らのプロセスとツール利用を動的に方向づけるもの — を区別している。Augmented LLM は彼が同じ記事から取り上げたもうひとつの語であり、そのどちらとも異なる種類のものを名指している。複数の LLM をひとつのシステムへと組み上げたものではなく、ツールなどの拡張を備えた単一の LLM である。

この区別が最も効いてくるのは、「エージェント」という語が主張されている場面である。Willison が伝える記事自身の助言も同じ方向を指している。LLM を用いてアプリケーションを構築する際には、可能な限り最も単純な解を見つけ、必要なときにだけ複雑さを増やすべきであり、それはエージェント型システムをまったく構築しないという結論になるかもしれない。また、直接の API アクセスと単純なコードを汲み尽くす前に、複雑なエージェントフレームワークに投資することは避けるべきだ、というものである。最も単純な構成に名前を与えることこそが、あるシステムは「それだけのもの」だと言えるようにするのである。

ここに Willison 自身の造語はない。彼は他者の記事についてのリンク記事の中で、他者の語を紹介し支持しているにすぎない。その出典を通して得られる定義は、それに応じて簡潔である — ツールなどの拡張を備えた LLM、というものだ。彼が紹介しているその記事は、このページ自身も直接に保持しており、以下で読まれる。

## 一次的な説明

Willison が紹介している記事は [[BlogPosting/building-effective-agents]] であり、このページはこれを直接にも保持するようになったため、この語を又聞きではなく、それを導入した当の言葉で読むことができる。

そこでは Augmented LLM は、エージェント型システムの**基本的な構成要素**として提示されている。検索、ツール、記憶といった拡張によって強化されたモデルのことである。Anthropic が現行世代のモデルについて強調しているのは、それらの能力を受動的に駆動されるのではなく能動的に使えるという点である — 自ら検索クエリを生成し、適切なツールを選択し、どの情報を保持するかを決定する。記事が挙げる実装上の推奨は 2 つ、これらの能力を具体的なユースケースに合わせて仕立てること、そしてモデルがそれらに到達するための、扱いやすく十分に文書化されたインターフェースを与えることであり、[[DefinedTerm/model-context-protocol]] がそのインターフェースを供給する一つの方法として名指されている。

これを複数の選択肢のひとつではなく構成要素たらしめているのは、記事の構成におけるその位置である。記事がこの後に記述していくすべて — プロンプトチェイニング、ルーティング、並列化、オーケストレーター・ワーカー、評価者・最適化者、そして自律エージェント — は、そこから先のあらゆる LLM 呼び出しがこれらの拡張された能力を利用できるという、明示的に述べられた前提の上に築かれている。つまり Augmented LLM は、アーキテクチャの一覧の中で最も単純な項目なのではない。その一覧全体が、そこから組み立てられる単位なのである。

このことは、Willison が重んじる境界をも鋭くする。Anthropic はワークフローとエージェントをエージェント型システムとしてひとまとめにしたうえで、プロセスを誰が方向づけるかによって両者を分けている — ワークフローではあらかじめ定義されたコードパス、エージェントではモデル自身である（[[DefinedTerm/ai-agent]] を参照）。Augmented LLM をその分岐の下位に位置するもの — 能力を取りつけられた単一の呼び出しであって、まだ何かがオーケストレーションされるシステムではないもの — として読むことは、それが構成要素という位置を占めていることからのこのページ自身の推論である。記事はそれを各パターンの手前に置いてはいるが、その分岐そのものに対して位置づけてはいない。
