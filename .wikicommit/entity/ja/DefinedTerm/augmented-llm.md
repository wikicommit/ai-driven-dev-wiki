拡張された LLM（augmented LLM）とは、ツールなどの拡張（augmentation）を備えた大規模言語モデルのことである。Simon Willison はこの用語をエージェント型システムの構築に関する Anthropic の記事から紹介し、自分が本当に気に入っている用語として取り上げている。その理由として彼は、まさにこのもの——ツールを取り付けたモデル——を人々が「エージェント」と呼ぶのを見てきたが、それがどうにもしっくりこなかったと述べている。したがって彼の説明におけるこの用語の価値は、境界を引くことにある。最も単純なケースに独自の名前を与えることで、「エージェント」という語がそれまで含まなくてよくなるのである。

## 用法

Willison がこの記事を評価しているのは、そもそも用語を定義していること自体である。「エージェント」について彼が常々抱いている不満は、この語には多くの定義がありうるのに、使う人の大半が、自分の選んだ定義を誰もが共有していると思い込んでいることだ。彼はこの記事が冒頭からその傾向に逆らっていると評価している。彼の紹介によれば、記事は「エージェント型システム（agentic systems）」を上位の用語として扱ったうえで、「ワークフロー」——複数の LLM があらかじめ定められたパターンでオーケストレーションされるシステム——と、「エージェント」——LLM が自らのプロセスとツールの使い方を動的に指揮するもの——とを区別している。拡張された LLM は、彼が同じ記事からさらに取り上げた用語であり、そのいずれとも種類の異なるものを名指す。すなわち、複数の LLM をシステムとして配置したものではなく、ツールなどの拡張を備えた単一の LLM である。

この区別が最も意味を持つのは、「エージェント」という語が名乗られる場面である。記事自身の助言についての Willison の紹介も同じ方向を指している。LLM を使ったアプリケーションを構築する際には、可能な限り単純な解決策を見つけ、必要な場合にのみ複雑さを増すことが推奨されており、それはエージェント型システムをまったく構築しないことを意味する場合もある。また、直接の API アクセスと単純なコードを試し尽くす前に複雑なエージェントフレームワークへ投資することは避けるべきだとされる。最も単純な構成に名前を付けることで、あるシステムが「それだけのものにすぎない」と言えるようになる。

ここにあるものはどれも Willison 自身の造語ではない。彼は他者の記事を紹介するリンク投稿の中で、その用語を紹介し支持しているにすぎない。その情報源から得られる定義も相応に簡潔で、ツールなどの拡張を備えた LLM というものである。彼が紹介している記事そのものも本ページは直接保持しており、以下でそれを読む。

## 一次資料での説明

Willison が紹介している記事は [[BlogPosting/building-effective-agents]] である。本ページはこれも直接保持するようになったため、この用語を一段階離れた紹介を通してだけでなく、それを導入した言葉そのもので読むことができる。

そこでは、拡張された LLM はエージェント型システムの**基本的な構成要素（basic building block）**として提示されている。すなわち、検索（retrieval）、ツール、メモリといった拡張によって強化されたモデルである。Anthropic が現世代のモデルについて強調しているのは、それらの能力を通じて外から動かされるのではなく、それらを能動的に使えるという点である。モデルは自ら検索クエリを生成し、適切なツールを選択し、どの情報を保持するかを判断する。同記事の実装上の推奨は二つある。これらの能力を具体的なユースケースに合わせて調整すること、そしてモデルにそれらへの使いやすく十分に文書化されたインターフェースを与えることである。そのインターフェースを提供する方法の一つとして [[DefinedTerm/model-context-protocol]] が挙げられている。

これを数ある選択肢の一つではなく構成要素たらしめているのは、同記事の構成における位置づけである。記事がその後に説明するもの——プロンプトチェイニング、ルーティング、並列化、オーケストレーター・ワーカー、評価者・最適化者（evaluator-optimizer）、そして自律型エージェント——はすべて、以降のあらゆる LLM 呼び出しがこれらの拡張された能力を利用できるという、明示的に述べられた前提の上に築かれている。したがって拡張された LLM は、アーキテクチャの一覧の中で最も単純な項目なのではなく、一覧の残りを組み立てる単位なのである。

このことは、Willison が重視する境界をさらに鮮明にもする。Anthropic はワークフローとエージェントをまとめてエージェント型システムとし、両者をプロセスを誰が指揮するかによって分ける。ワークフローではあらかじめ定義されたコードパスが、エージェントではモデル自身が指揮する（[[DefinedTerm/ai-agent]] を参照）。拡張された LLM をこの区分より下に位置するもの——能力を取り付けた単一の呼び出しであって、まだ何かがオーケストレーションされるシステムではないもの——と読むのは、構成要素という位置づけから導いた本ページ自身の推論である。同記事はこれを各パターンの前に置いてはいるが、この区分そのものとの関係で位置づけてはいない。
