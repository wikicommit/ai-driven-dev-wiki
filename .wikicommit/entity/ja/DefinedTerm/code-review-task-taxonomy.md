コードレビュータスクの分類とは、[[ScholarlyArticle/a-survey-of-code-review-benchmarks-and-evaluation-practices]] で提案
された多層的な分類であり、コードレビューの研究が何を測っているかを整理するためのものである。研究を 5 つの高次領域——
レビューの優先順位づけ／選択、変更の理解と分析、ピアレビュー、レビューの評価と分析、コードの改良——に分け、それらを 18 の
名前の付いたサブタスクへ細分する。5 つの領域はコードレビューのプロセス自体の段階と揃えられており、どの変更がレビューに値する
かを決めるところから、フィードバックを受けてコードを改訂するところまでを覆う。したがってある分類上の位置は、そのベンチマーク
がレビュアーの仕事のどの部分を働かせているかを示す。

## 用法

この分類はまず、ある与えられたデータセットが実際には何を評価しているのかを問うために使われ、またレビューのプロセスのうち
どの部分をどのデータセットも覆っていないかを可視化するために使われる。

5 つの領域は、それらが消費する入力と生み出す出力によって定義される。**レビューの優先順位づけ／選択**は、どの変更をどの順序で
レビューすべきかを決めるもので、パッチの内容、開発者とレビュアーの履歴、テストのシグナルに対する予測やランキングとして定式化
される。そのサブタスクはレビューの優先順位づけと変更品質の予測である。**変更の理解と分析**は、変更の意図・影響・構造を
レビュアーが解釈するのを支援するもので、関連する変更の特定、影響分析、変更の分解、可視化を覆う。**ピアレビュー**は、人間の
レビュアー自身の判断を支援あるいは模倣するタスクを覆う——問題箇所の特定、レビューコメントの生成、問題のラベル付けと分類、
リファクタリングの識別、欠陥のある変更の予測、セキュリティの検出である。**レビューの評価と分析**は、検査の矛先をレビュー
そのものへ向けるもので、レビュー品質の評価、コメントとコードの整合、レビューの要約、感情分析や有害性の分析を覆う。**コードの
改良**はレビュー後の改訂段階を覆い、コードの改訂とコードのリファクタリングに分かれる。

調査対象の文献全体に適用したとき、この研究におけるこの道具の主たる用途は比較にある。同じサブタスクのラベルが、大規模言語
モデルの登場以前と以後のデータセットに適用されるので、この分野が何を測っているかの変化が数えられるようになる。その読みに
おいて、出典はピアレビューが LLM 時代のデータセットのほぼ 60% を占めるまで伸びた一方、変更の理解と分析は 14 件のデータ
セットから 1 件へ落ち込み、変更の分解と影響分析は完全に消失したと報告している。

この研究はまた、この分類を逆方向に使うことも提案している。すなわち、まだ存在しないベンチマークのための仕様としてである。
モデルのコード改訂能力を単一の集約値として測るのではなく、サブタスクごとにデータセットを整備し、リファクタリング、ドキュメント
と可読性の改善、正しさの確保、パフォーマンスの最適化といった能力を別々に採点できるようにすることを示唆している。
