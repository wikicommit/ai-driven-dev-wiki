コーディングエージェントとは、単一の応答を返して止まるのではなく、指定されたゴールを達成するまで能動的にテストと修正を繰り返しながらコードを反復的に改善していくツールである。[[Person/simon-willison]] は [[BlogPosting/vibe-engineering]] でこの特徴づけを示し、例として Claude Code（2025年2月リリース）、OpenAI の Codex CLI（4月）、Gemini CLI（6月）を挙げ、これらの台頭が現実のコーディング問題に対する LLM の有用性を劇的に高めたとしている。これは彼が落ち着いたエージェントの一般的な定義——ゴールを達成するためにループの中でツールを呼び出す LLM——の特殊ケースであり、Anthropic のエンジニアリング記事も独立に同じ定義に収束し、LLM が自律的にループの中でツールを使うことと表現している。

## 用法

決定的な性質はインタフェースではなくループである。Anthropic の Claude Code のドキュメントは、同じ対比をプロダクトの言葉で示す。質問に答えて待つチャットボットとは異なり、エージェンティックなコーディング環境はファイルを読み、コマンドを実行し、変更を加え、ユーザーが見守るなり方向を修正するなり席を外すなりしている間に自律的に問題を解き進められる——これが作業の組み立て方を変える。人間はコードを書いてレビューを求めるのではなく、何が欲しいのかを記述するようになるからである。

Anthropic の [[TechArticle/effective-context-engineering-for-ai-agents]] は、自律性がモデルの能力とともにスケールすると付け加える。基盤となるモデルが高性能になるほどエージェントの自律性の水準も上げられ、微妙な問題空間を独力で辿り、誤りから回復できるようになる。Willison は、経験あるエンジニアが複数の問題を並行して扱うためにエージェントの複製を同時に走らせていると報告し、当初は懐疑的だったが今では自分でもそうしていると述べ、精神的には消耗するが驚くほど効果的だと説明している。

実務者の文章は、コーディングエージェントを以前の AI コーディングツールと連続体の上で区別している。Anthropic の [[Report/2026-agentic-coding-trends-report]] はこの進展をタスクの時間軸で説明する。初期のエージェントは数分で終わる一発のタスク——このバグを直す、この関数を書く、このテストを生成する——を扱っていたが、2025年後半までにエージェントは数時間かけて機能一式を作るようになり、レポートは 2026年には数日にまたがる作業になると予測している。

### 非同期への転回

ループとは別の第二の軸は、開発者が待つかどうかである。同じ時期に2つのベンダーがクラウドホスト型のエージェントを発表したが、その決定的な性質は開発者が待たないことだった。[[Organization/openai]] は 2025年5月16日に [[SoftwareApplication/codex]] を「多数のタスクを並行して処理できるクラウドベースのソフトウェアエンジニアリングエージェント」として立ち上げ、各タスクはリポジトリがあらかじめ読み込まれた専用の隔離されたサンドボックスで動く。Google Labs は 2025年5月20日に [[SoftwareApplication/jules]] をパブリックベータに移し、コードベースをクラウド VM にクローンして「非同期に動作し、バックグラウンドで作業している間あなたは他のタスクに集中できる」エージェントとした。

両ベンダーとも、非同期性が強いる同じ要求について述べている。エージェントが何をしたのかの証拠と、何かが取り込まれる前の人間によるレビューのステップである。Google の Jules は「立てた計画、その推論、そして加えた変更の差分を提示する」し、開発者は実行の前・最中・後に計画を変更できる——検査可能な計画は、ローンチ時点の OpenAI の Codex にはなかったものであり、Codex はタスク途中の軌道修正を欠けている機能として挙げ、対話的な協働を将来の計画として挙げていた。Codex が代わりに提供したのは事後のトレーサビリティである。自身の環境で変更をコミットし、「ターミナルのログとテスト出力の引用を通じて、その行動の検証可能な証拠」を提供し、進捗はリアルタイムで監視できる。そのうえで「統合・実行の前に、エージェントが生成したすべてのコードをユーザーが手作業でレビューし検証することが依然として不可欠である」と強調している。

いずれもこれを機能ではなく、作業の組み立て方の転換として枠づけている。OpenAI は「ChatGPT の Codex が導入した非同期・マルチエージェントのワークフローが、エンジニアが高品質なコードを生み出す事実上の方法になる」と予測し、リアルタイムのペアリングとタスクの委譲は最終的に一つのワークフローに収束するだろうとした。Google の枠づけは「エージェンティック開発はプロトタイプからプロダクトへと移行しつつあり、ソフトウェアの作られ方の中心に急速になりつつある」というものだった。どちらもローンチ時になされた自社プロダクトについてのベンダーの予測であり、観測された結果ではない——そして OpenAI は同じ記事の中で、リモートのエージェントに委譲すると対話的な編集よりも時間がかかり「慣れが必要かもしれない」と認めている。

Jules を紹介した 2024年12月の Google の先行記事は、何を基準に測っていたのかも記録している。コード実行ツールを備えた Gemini 2.0 Flash を用いた研究で [[Dataset/swe-bench]] Verified において 51.8% を記録したと報告し、その結果の一因を、推論の速さによってエージェントが数百の候補解をサンプリングし、既存の単体テストとモデル自身の判断を用いて最良のものを選べたことに帰し、その研究を開発者向けプロダクトに転化しつつあると述べていた。OpenAI の Codex の記事は自身の SWE-bench スコアを一切示さず、用いた構成だけを述べている。
