コーディングエージェントとは、単一の応答を返して止まるのではなく、指定された目標を達成するまでコードを能動的にテストし変更しながら反復するツールである。[[Person/simon-willison]] は [[BlogPosting/vibe-engineering]] でこの特徴づけを与え、例として Claude Code（2025年2月リリース）、OpenAI の Codex CLI（4月）、Gemini CLI（6月）を挙げ、その台頭が現実世界のコーディング問題に対する LLM の有用性を劇的に高めたとしている。これは、彼がエージェントについて落ち着いた一般的な定義——目標を達成するためにループのなかでツールを呼び出す LLM——の特殊な場合であり、Anthropic のエンジニアリング記事も独立に同じ定義へ収束し、ループのなかで自律的にツールを使う LLM と表現している。

## 用法

区別を生む性質はインターフェースではなくループである。Anthropic の Claude Code のドキュメントは、同じ対比を製品の言葉で示している。質問に答えて待つチャットボットとは異なり、エージェンティックなコーディング環境はファイルを読み、コマンドを実行し、変更を加え、ユーザーが見守るか、方向を修正するか、席を外しているあいだに自律的に問題を進められる——これが作業の組み立て方を変えるのであり、人間はコードを書いてレビューを求めるのではなく、何が欲しいかを述べることになる。

Anthropic の [[TechArticle/effective-context-engineering-for-ai-agents]] は、自律性がモデルの能力とともに拡大することを付け加えている。基盤となるモデルがより有能になるにつれてエージェントの自律性の水準も拡大でき、微妙な問題空間を自力で渡り歩き、誤りから回復できるようになる。Willison は、経験を積んだエンジニアたちが複数の問題に並行して取り組むためにエージェントを同時に複数走らせていると報告しており、当初は懐疑的だったが今では自分もそうしていると述べ、精神的には消耗するが驚くほど効果的だと説明している。

実務者の記述は、コーディングエージェントを初期の AI コーディングツールからスペクトルに沿って区別している。Anthropic の [[Report/2026-agentic-coding-trends-report]] はその進展をタスクの時間幅で説明している。初期のエージェントは数分で済むワンショットのタスク——このバグを直す、この関数を書く、このテストを生成する——を扱っていたのに対し、2025年後半までにエージェントは数時間かけて機能一式を作るようになっており、同レポートは2026年には数日にわたる作業を予測している。

### 非同期への転回

ループとは別の第二の軸は、開発者が待つかどうかである。同じ時期に二つのベンダーがクラウドホスト型のエージェントを発表しており、その定義的な性質は開発者が待たないことである。[[Organization/openai]] は2025年5月16日に [[SoftwareApplication/codex]] を「多数のタスクを並行して処理できるクラウドベースのソフトウェアエンジニアリングエージェント」として立ち上げ、各タスクはリポジトリがあらかじめ読み込まれた専用の隔離されたサンドボックスで走る。Google Labs は2025年5月20日に [[SoftwareApplication/jules]] を公開ベータへ移し、コードベースをクラウドの VM にクローンして「非同期に動作し、それが背後で作業するあいだ、あなたは他のタスクに集中できる」エージェントとした。

両ベンダーとも、非同期性が強いる同じ要件を述べている。エージェントが何をしたかの証拠と、何かが取り込まれる前の人間によるレビューのステップである。Google の Jules は「計画、推論、加えられた変更の差分を提示する」うえ、実行の前・最中・後に開発者が計画を修正できるようにしている——OpenAI の Codex はローンチ時にはこの検査可能な計画を持たず、タスク途中での軌道修正を欠けている機能として、対話的な協働を将来計画として挙げていた。Codex が代わりに提供したのは事後の追跡可能性である。自らの環境で変更をコミットし、「ターミナルのログとテスト出力の引用を通じて、その行動の検証可能な証拠」を提供し、進捗はリアルタイムで監視できるとしつつ、「統合と実行の前に、エージェントが生成したすべてのコードをユーザーが手作業でレビューし検証することが依然として不可欠である」と強調している。

いずれもこれを機能ではなく、作業の組み立て方の変化として枠づけている。OpenAI は「ChatGPT の Codex が導入した非同期・マルチエージェントのワークフローが、エンジニアが高品質なコードを生み出す事実上の方法になる」と予測し、リアルタイムのペアリングとタスクの委任が最終的には一つのワークフローへ収束するとした。Google の枠づけは「エージェンティックな開発はプロトタイプからプロダクトへ移りつつあり、ソフトウェアがどう作られるかの中心へ急速に近づいている」というものであった。いずれもローンチ時に自社製品についてなされたベンダーの予測であり、観測された成果ではない——そして OpenAI は同じ記事で、リモートのエージェントへ委任することは対話的な編集より時間がかかり、「慣れが必要かもしれない」と認めている。

Jules を紹介した Google の2024年12月の先行記事は、何を基準に測っていたかも記録している。コード実行ツールを備えた Gemini 2.0 Flash を用いた研究で [[Dataset/swe-bench]] Verified において51.8% を記録したと報告し、その結果の一因を、推論速度によってエージェントが数百の候補解をサンプリングし、既存の単体テストとモデル自身の判断を用いて最良のものを選べたことに帰し、その研究を開発者向け製品へ移す途上にあると述べていた。OpenAI の Codex の記事は自らの SWE-bench のスコアを述べておらず、用いた構成のみを記している。

### 最小限の定義

[[TechArticle/what-is-agentic-engineering]] は、この語をより小さな二つの語の合成として定義する。**エージェント**とは「目標を達成するためにループのなかでツールを走らせる」ソフトウェアである——ユーザーのプロンプトとツール定義の集合を添えて LLM を呼び、LLM が要求したツールを何であれ呼び出し、その結果を LLM へ戻す。**コーディングエージェント**とは、そのツールのなかにコードを実行できるものが含まれる構成であり、同章は普及した例として Claude Code、OpenAI Codex、Gemini CLI を挙げている。ユーザーは目標をプロンプトとして与え、それは目標が満たされるまでループのなかでコードを生成し実行する。

同章は、この実践全体を可能にしている能力としてコードの実行を挙げている。それなしには LLM が出力するものの価値は限られ、それがあればエージェントは実際に動くと示せるソフトウェアへ向けて反復できる。また自らが立っている定義上の地盤も認めており、「エージェント」を明確に定義することが少なくとも1990年代から AI 研究者を悩ませてきたと指摘している。

### なぜエージェントが最初に着地したのがソフトウェアだったのか

[[TechArticle/building-effective-agents]] は、コーディングをエージェントのパターンによく適合させる四つの性質を挙げている。解が自動テストによって検証可能であること、エージェントがテスト結果をフィードバックとして反復できること、問題空間が明確に定義され構造化されていること、そして出力の質を客観的に測定できることである。同記事が報告する自らの実装は、[[Dataset/swe-bench]] Verified の実際の GitHub の課題を、プルリクエストの説明だけから解決した。

その留保は同じ息で述べられている。自動テストは機能を検証するが、「解がより広いシステムの要件に沿っていることを確かめるには、人間のレビューが依然として決定的である」——テストが確立するのはコードが何かをするということであって、それが加わるシステムにとって正しいことをするということではない。

同記事はまた、コーディングの事例が具現する一般的なエージェントのループも説明している。作業は人間からのコマンドまたは対話から始まり、次いでエージェントが計画を立てて自律的に動作し、各ステップで環境から——ツール呼び出しの結果、コードの実行から——グラウンドトゥルースを得て進捗を評価し、チェックポイントや行き詰まりで人間のフィードバックを待って一時停止する。制御を保つために最大反復回数といった停止条件を推奨し、自律性がより高いコストと誤りの累積の可能性をもたらすことを指摘している。
