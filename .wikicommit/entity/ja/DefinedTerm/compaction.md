コンパクションとは、コンテキストウィンドウの上限に近づいた会話の内容を要約し、その要約とともに新しいコンテキストウィンドウを再開する実践である。[[TechArticle/effective-context-engineering-for-ai-agents]] はこの定義を与え、より良い長期的な一貫性を得るために [[DefinedTerm/context-engineering]] において通常最初に手が伸びるレバーだと説明する。その核心は、コンテキストウィンドウの内容を高い忠実度で蒸留し、エージェントが性能の劣化を最小限に抑えて作業を続けられるようにすることである。

## 用法

Anthropic は Claude Code における実装を、メッセージ履歴をモデルに渡して最も重要な詳細を要約・圧縮させるものだと説明している——アーキテクチャ上の決定、未解決のバグ、実装の詳細を保持し、冗長なツール出力やメッセージは捨てる——。その後エージェントは、圧縮されたコンテキストに直近でアクセスした5つのファイルを加えたところから作業を続ける。掲げられている目標は、ユーザーがコンテキストウィンドウの上限を意識せずに連続性を得られることである。

Claude Code のドキュメントは、これをコンテキストの上限に近づいたときの自動コンパクションとしてユーザーに露出させ、さらに手動の制御も提供している。何を保持するかを方向づける `/compact <指示>`（例として `/compact API の変更に注目して`）、会話の一部だけを凝縮するための「ここから要約」「ここまで要約」を提供する巻き戻しメニュー、そして振る舞いをカスタマイズするための `CLAUDE.md` 内の指示（例として「コンパクションの際は、変更されたファイルの完全な一覧とすべてのテストコマンドを必ず保持すること」）である。また、より大雑把な代替として、無関係なタスクの間に `/clear` を使うことも推奨している——要約するのではなくコンテキストを完全にリセットするやり方である。

[[BlogPosting/context-engineering]] はコンパクションを「圧縮する」分類に置き、モデルを使って蒸留する要約と、古いメッセージを取り除くといったハードコードされたヒューリスティックによってフィルタや刈り込みを行う **トリミング** を区別している。要約は会話の末尾以外の地点でも適用できる——トークンを多く消費するツール呼び出しの後や、知識の受け渡しの際にトークンを減らすためのエージェント間の境界で——と指摘し、Cognition がこのステップにファインチューニング済みのモデルを使っていることを伝え、これをこの工程にどれだけの手間をかけうるかの一つの目安として提示している。

名指しされているリスクは損失である。Anthropic は、過度に積極的なコンパクションが、重要性が後になって初めて明らかになるような微妙だが決定的なコンテキストを捨ててしまいかねないと警告し、複雑なエージェントのトレース上でコンパクションのプロンプトを調整する際は、まず再現率を最大化してから適合率を改善するよう推奨している。安全で手をつけやすいコンパクションの例として挙げられているのはツール結果のクリアである。メッセージ履歴の奥深くで一度呼び出されたツールについて、エージェントが生の結果を再び見る必要はめったにない。

## 関連用語

コンパクションは長い時間軸の作業に対する3つの標準的な技法の一つであり、他には [[DefinedTerm/agentic-memory]] と [[DefinedTerm/multi-agent-orchestration]] がある。Anthropic はこれを、広範なやり取りを要するタスクに特に適合するものとしている。[[DefinedTerm/adaptive-context-compaction]] は、削減をハードリミットにおける単発の事象としてではなく、コンテキストの圧迫が高まるにつれて段階的に適用する、より具体的な変種を説明している。これが管理するために存在する根底の問題が [[DefinedTerm/context-rot]] である。
