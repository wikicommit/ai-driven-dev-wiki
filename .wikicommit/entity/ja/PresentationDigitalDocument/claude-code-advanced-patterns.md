「Claude Code Advanced Patterns: Subagents, MCP, and Scaling to Real Codebases」は、[[Organization/anthropic]] が公開した2026年3月24日付のウェビナー用スライドである。スライドには個人の発表者のクレジットはない。事務連絡のスライドからは、Q&A タブと後日の録画を伴うライブセッションであったことがうかがえ、いくつかのスライドには CONFIDENTIAL の表示がある。

スライドは5つの学習成果を挙げている。CLAUDE.md とフックによって Claude の挙動を制御すること、生産性のために Claude を並列化すること、機能調査から CI/CD に至る SDLC 全体へ Claude Code を組み込むこと、ツールの作成がその手間に見合うのはいつかについてのメンタルモデルを形づくること、そして組織にとって高度な実装がどのようなものになりうるかを構想することである。その構成はこれらの成果に沿った3つのセクション——カスタマイズ、並列化、組み込み——をとる。最初の2つはそれぞれ「どの機能をいつ使うか」の表で締めくくられ、各機構に優劣をつけるのではなく、それぞれ異なる使用条件を割り当てている。組み込みのセクションはその代わりに GitHub Actions とコードレビューのスライドを含み、その後にライブデモが続く。

これは散文ではなくスライドであるため、その内容の多くは短い表のセルへと圧縮されている。以下はスライド自体が主張していることのみを記録する。

## 要点

- **CLAUDE.md は「README に似ているが、Claude 向けのもの」と説明されている**——プロジェクト構造、よく使うコマンド、個人的なスタイルの助言について Claude に指示を与える、強制的な README ファイルである。大規模コードベースについては、Claude がディレクトリツリーを上へたどって CLAUDE.md ファイルを発見する階層的な配置が示されている。モノレポのルートのファイルがシステム全体の概観、モダナイゼーション戦略、チーム構成を持ち、`/packages/` のファイルがコンポーネントのアーキテクチャ、技術的負債、移行計画を持ち、その下にパッケージごとのファイルが置かれる。
- **大規模コードベース向けの3つの CLAUDE.md 実践。** ファイルを200行未満に保つこと——長いファイルほどコンテキストを消費し、指示の遵守に悪影響を与えうるという理由が挙げられている。`.claude/rules/` ディレクトリの下の複数ファイルへ指示を整理すること——そこではフロントマターの `paths` フィールドを通じてルールを特定のファイルパスへスコープできる。そして `claudeMdExcludes` 設定を用いて、プロジェクトに無関係な CLAUDE.md ファイルを除外し、矛盾する指示を持ち込めないようにすること。マネージドポリシーの CLAUDE.md ファイルは除外できないことがスライドに注記されている。
- **3択のカスタマイズの意思決定。** CLAUDE.md は、プロジェクトに関連するコンテキストと、同じことを繰り返し言わずに済ませるための指示のためのものである（「npm ではなく pnpm を使え。テストは pytest で実行せよ。PEP8 に従え。」）。[[DefinedTerm/agent-hooks]] は、特定のライフサイクルイベントで常に実行されなければならない決定論的な自動化のためのものである（保存時の自動フォーマット、編集後のテスト実行、完了時の通知送信）。そして [[DefinedTerm/model-context-protocol]] は、標準化されたプロトコルを通じた外部ツール、データベース、API へのアクセスのためのものである（データベースへの問い合わせ、GitHub からの取得、Slack メッセージの送信、Google Drive へのアクセス）。スライドはサーバーを追加する方法として `mcp add <server-name>` を挙げ、MCP の理想的なユースケースを、コピー&ペーストに頼ることなく Claude が外部の状態について推論する必要がある場合——Figma のデザインの取得、チケットの作成——であると述べている。
- **3択の並列化の意思決定。** Parallel Claude とは、複数の Claude Code インスタンスを同時に実行することであり、それぞれが自分のターミナルと自分のコンテキストを持ち、互いに無関係な別々のタスクに取り組む。スライドは隔離の機構として git worktree を挙げ、その作成方法として `claude --worktree` を示している。[[DefinedTerm/subagents]] は、隔離されたコンテキストのもとでメインセッションから焦点の絞られたサブタスクを委譲するためのものである。Agent Teams は、1つの大きなタスクを、協調しあう独立したワークストリームへ分割するためのものである。
- **サブエージェントに手を伸ばす3つの条件。** サブエージェントに、明確で比較的専門化された役割を、定められたツールアクセスレベルと成功ないし完了の基準とともに与えられるとき。サブエージェントの作業を検査したりそれとやり取りしたりすることが優先事項ではなく、完了したタスクといくつかの結論だけが必要なとき。そしてメインセッションのコンテキストを管理するため。スライドは理想的なユースケースとして、メインエージェントへ返す情報が比較的軽くて済むような、コードベースの並列的な実験や調査を挙げ、サブエージェントを CLAUDE.md と並ぶ `agents/` ディレクトリ内の Markdown ファイルとして示している。
- **Agent Teams はスライド作成時点でリサーチプレビュー中であると説明されている。** 互いに通信し、協調し、並列化された作業を分割統治する複数のエージェントであり、タスクを独立したワークストリームへ分解でき、各エージェントが他をブロックせずに一区画を担当できるときに真価を発揮するとされる。
- **2つの CI/CD 統合。** GitHub Actions における Claude Code は、Claude Agent SDK によって動くと説明されており、`@claude` をタグ付けすることでプルリクエストやイシューへの編集をリモートからトリガーできる。Claude Code のなかから `/install-github-app` を実行することでセットアップする。コードレビューは、エージェントチームに基づくレビューシステムとして説明されている。その専門化されたエージェント群はコードベース全体についてのコンテキストを持ち、バグやセキュリティ上の穴について深刻度で格付けしたインラインコメントを投稿し、見落としやすいエッジケースとリグレッションを見つけることを狙いとする。有効化は Claude Code の設定、GitHub App、リポジトリごとのオプトインを伴う管理者の作業である。

## 背景

スライドは、時間のかかる3つのタスクを同時に処理するものとして枠づけられたライブデモで締めくくられる。チケッティングツールへの @メンション機能の追加、スプリントの優先順位の決定とチケットの割り当て、そして大きな追加に対する初回のコードレビューをやり切ることである。互いに無関係な3つのタスクを一度に、というその枠づけは、並列化の表における Parallel Claude の行についてのスライド自身による例示である。

ベンダー自身の製品についてのベンダーのスライドであるから、その推奨は Claude Code がどのように使われることを意図しているかについての Anthropic の説明であって、独立した評価ではない。その内容は [[SoftwareApplication/claude-code]] にすでに記録されている文書版の Claude Code ドキュメントと大きく重なる。スライドがそれを超えて加えているのは、明示的な横並びの意思決定の枠づけと、CLAUDE.md のサイズおよび除外にかかわる実践である。
