This page compares the coding agents that this wiki's pages describe as running in the terminal. It sets them side by side on who makes them, how open they are, which models they run, what surfaces they share, how they ask for permission, how they are configured and extended, and how they run without a person at the keyboard. It closes with the studies that have measured several of them at once. It does not rank them.

The tools fall into four groups:

- **Built by a model provider or platform vendor**: [[SoftwareApplication/claude-code]] (Anthropic), the Codex CLI recorded on the [[SoftwareApplication/openai-codex]] page (OpenAI), [[SoftwareApplication/gemini-cli]] and its successor [[SoftwareApplication/antigravity-cli]] (Google), [[SoftwareApplication/github-copilot-cli]] (GitHub), [[SoftwareApplication/mistral-vibe-cli]] (Mistral AI) and [[SoftwareApplication/kimi-cli]] (Moonshot AI).
- **Independent or community-built agents**: [[SoftwareApplication/opencode]], [[SoftwareApplication/crush]], [[SoftwareApplication/goose]], [[SoftwareApplication/cline]], [[SoftwareApplication/kilo-code]], [[SoftwareApplication/plandex]], [[SoftwareApplication/opendev]], [[SoftwareApplication/openharness]], and deepagents-cli, which is recorded on the [[SoftwareApplication/deep-agents]] page.
- **Minimal or teaching implementations**: [[SoftwareApplication/mini-coding-agent]] and [[SoftwareApplication/llm-coding-agent]].
- **Command-line tools around an agent rather than agents themselves**: [[SoftwareApplication/jules-tools]], a CLI for Google's cloud agent; [[SoftwareApplication/claude-squad]], which runs several Claude Code instances in tmux panes; [[SoftwareApplication/agents-cli]], a Google Cloud CLI designed to be driven by coding agents; and [[SoftwareApplication/entire-cli]], which records coding-agent sessions and links them to commits.

The last group appears below only where it bears on the agents in the first three groups.

## Openness

Several agents across the groups are published under a named open-source licence: Apache 2.0 for Mistral Vibe CLI, Kimi CLI, goose, Cline and Mini-Coding-Agent, and MIT for Plandex and OpenHarness. OpenAI's repository describes Codex CLI as Apache-2.0, and [[BlogPosting/codex-as-a-platform]] adds that the Codex CLI, app-server and official SDK are published as open-source components, while model access and managed services remain separate from that layer.

Openness is often partial. Cline's JetBrains plugin talks to the shared agent core but is not open-sourced. Kilo Code's component matrix separates its MIT-licensed clients from a Gateway and Cloud backend that is only source-available, with the security and abuse-protection code excluded.

Claude Code's status is described differently on different pages. [[ScholarlyArticle/dive-into-claude-code]] says it worked from Claude Code's "publicly available TypeScript source", and the [[SoftwareApplication/claude-code]] page repeats this. [[ScholarlyArticle/building-effective-ai-coding-agents-for-the-terminal]] describes Claude Code as CLI-native but "neither open-source nor accompanied by" a technical report. [[ScholarlyArticle/harness-engineering-anatomy-architecture-and-evolution-of-coding-agents]] says its own Claude Code analysis drew on "a circulated source snapshot from March 2026 rather than an official release".

## Models

The provider-built agents start from the provider's own models, and each page records a different amount of room beyond them:

- **Claude Code**: most surfaces require a Claude subscription or an Anthropic Console account, while the terminal CLI, VS Code and JetBrains also support third-party providers.
- **Codex CLI**: OpenAI recommends signing in with a ChatGPT account and says an API key works with additional setup. Its page records that a smaller version of codex-1 derived from o4-mini became the CLI's default model, exposed in the API as `codex-mini-latest`.
- **Antigravity CLI**: sign-in broadened across its releases to personal accounts, a `GEMINI_API_KEY`, Business sign-in for Gemini Enterprise, Workforce Identity Federation and Application Default Credentials.
- **Mistral Vibe CLI**: built for the Devstral family, while local models and providers are configured through `config.toml`.

The independent agents mostly make model choice their point. OpenCode's handbook chapter calls it an open-source alternative to closed-source assistants such as Claude Code. It corrects the idea that OpenCode "provides free models": its architecture lets community, local or low-cost models be brought in. Kilo Code states more than 500 models and makes bring-your-own-key a standing commitment. goose and OpenHarness both accept an existing Claude or Codex/ChatGPT subscription as well as API keys.

At the far end, Mini-Coding-Agent runs only against a locally hosted Ollama model. OpenDev binds five specialised model roles to distinct models, so that its report calls changing provider a configuration change rather than a code change.

A user's account of Crush, [[BlogPosting/testing-out-crush-tui-coding-agent]], treats model-agnosticism as the tool's most important feature besides its TUI. That author wanted to use locally hosted models, "which he says is not possible with tools like Claude Code". The page records $23.04 in API fees for one small feature.

## One engine behind many surfaces

Several agents treat the terminal as one client of a shared engine rather than the product itself:

- **Claude Code**: Anthropic's documentation says every surface connects to the same underlying engine, so CLAUDE.md files, settings and MCP servers work across all of them. [[ScholarlyArticle/dive-into-claude-code]] reports a single loop feeding the interactive CLI, headless CLI, Agent SDK and IDE/desktop/browser.
- **Codex**: the App, CLI and IDE extension are, in OpenAI's words, powered by the same open-source Codex harness.
- **Antigravity CLI**: Google describes it as sharing the same agent harness as the Antigravity 2.0 desktop application. Its customisations live in a `~/.gemini/config/` directory shared across the product family.
- **Cline**: the VS Code extension, JetBrains plugin, CLI and desktop app share one agent core.
- **Kilo Code**: the same session and context are said to carry across VS Code, JetBrains, the CLI and Cloud Agents.
- **OpenCode**: available as a terminal interface, a desktop app or an IDE extension. Cloudflare chose it for CI review because it is "structured server-first", which let the team drive sessions through an SDK rather than script a CLI ([[BlogPosting/orchestrating-ai-code-review-at-scale]]).

Others connect to editors through a protocol rather than a shared engine:

- **Kimi CLI** supports the Agent Client Protocol (ACP), in which the IDE is the client and the agent runs as a server subprocess. It starts as an ACP agent server with `kimi acp`.
- **Mistral Vibe CLI** integrates with an IDE through what its page calls the Agent Communication Protocol, and ships as a Zed extension.

goose also uses ACP, but its page mentions it for a different purpose: reaching a user's existing Claude, ChatGPT or Gemini subscription.

[[BlogPosting/acp-protocol-and-multiple-ai-coding-agents]] describes how one team's own ACP integration handled agents that do not speak the protocol: agents "such as Claude Code, are adapted by parsing their own streaming output". The harness study reports ACP in six of its eleven systems. It also reports ACP hosting whole harnesses, "as when OpenHands runs Claude Code, Codex or Gemini CLI as interchangeable backends".

[[BlogPosting/future-of-agentic-coding-conductors-to-orchestrators]] places CLI assistants among the "conductor" tools, where the developer triggers each action and reviews the output immediately. It contrasts them with "orchestrator" cloud agents that return a pull request, and notes that tools are blurring the line.

## Asking before acting

Every agent here can edit files and run commands, and they differ in how they ask first:

- **Claude Code**: its documentation lists four permission modes cycled with `Shift+Tab` — Auto, Manual, Accept edits and Plan. [[ScholarlyArticle/dive-into-claude-code]] counts up to seven modes in the source. It describes deny-first rule evaluation, an ML-based auto-mode classifier and shell sandboxing among seven independent safety layers. [[DefinedTerm/permission-modes]] describes the modes themselves. Anthropic documents that sandbox as Seatbelt on macOS and bubblewrap on Linux and WSL2, with native Windows and WSL1 unsupported ([[DefinedTerm/sandboxing]]).
- **Antigravity CLI**: its default `request-review` mode pauses before each file write to show a line-level diff. A `proceed-in-sandbox` mode auto-approves terminal commands that stay inside the sandbox and asks only when one would leave it.
- **Cline**: by default every file edit and terminal command needs the developer's approval, with an auto-approve toggle to run autonomously instead.
- **Crush**: asks before making an edit, so each change can be allowed or denied.
- **Mistral Vibe CLI**: tool execution can be auto-approved or left gated, and tool permissions restricted.
- **OpenHarness**: three modes — ask before writing or executing, allow everything (meant for sandboxed environments), and a plan mode that blocks all writes — plus path-level rules.
- **Mini-Coding-Agent**: reduces the choice to `ask` (the default and the one its README recommends), `never` and `auto`.
- **llm-coding-agent**: offers `--yolo` and per-command `--allow` patterns such as `pytest*`.
- **OpenDev**: layers five independent safety mechanisms. Its report argues that safety is better enforced by removing tools from the agent's schema than by checking permissions at call time.
- **Plandex**: keeps AI-generated changes in a cumulative diff review sandbox, separate from the project's files until they are applied.

How far the operating system is involved varies too. The harness study found OS-level sandboxing among the most code-expensive capabilities in its corpus. It calls it a choice rather than a consequence of scale, since two of the largest systems it read, Hermes and OpenCode, "ship no OS-level isolation primitives".

## Plan first, then build

Several of the agents separate planning from changing code, under different names:

- **Claude Code**: plan mode.
- **OpenCode**: a read-only **plan** agent and a full-access **build** agent, switched with Tab.
- **Cline**: Plan and Act modes.
- **Antigravity CLI**: a `plan` mode and a `/plan` prefix.
- **GitHub Copilot CLI**: `/plan` to work out a feature, then `/autopilot` to implement it.
- **Kilo Code**: goes further, with separate architect, code, debug and review agents.

OpenDev's report records the opposite move: its main agent now stays in normal mode throughout and delegates planning to a Planner subagent, the earlier plan mode having been removed.

## Instruction files

The agents whose pages name a project-instruction file use different names for it:

- **Claude Code**: `CLAUDE.md`.
- **Gemini CLI**: `gemini.md` / `GEMINI.md`; both spellings appear in the Codelabs workshop its page draws on.
- **Cline**: `.clinerules`.
- **Codex**: [[DefinedTerm/agents-md]], a file [[ScholarlyArticle/on-the-impact-of-agents-md-files-on-the-efficiency-of-ai-coding-agents]] says was first used with Codex before becoming an open format.
- **OpenCode**: `/init` generates an `AGENTS.md`. When none exists it falls back to Claude Code's `CLAUDE.md` and skills directories, preferring `AGENTS.md` when both are present.

GitHub Copilot CLI's page describes a different kind of file: custom agents defined as `.agent.md` profiles in `.github/agents`, selected with `/agent`.

Whether Claude Code reads `AGENTS.md` is recorded differently on two pages. The [[SoftwareApplication/claude-code]] page says that, besides `CLAUDE.md`, Claude Code can read "an AGENTS.md written for other coding agents … on its own or alongside CLAUDE.md". The [[DefinedTerm/agents-md]] page says the format's own recommended pattern is to make `AGENTS.md` the real file and `CLAUDE.md` a symlink, "because Claude Code reads `CLAUDE.md` and not `AGENTS.md`".

## Extending the agent

The extension mechanisms are converging. The same names — skills, hooks, subagents, MCP servers, plugins — recur across these pages.

**Skills and MCP.** Of the eleven harnesses in [[ScholarlyArticle/harness-engineering-anatomy-architecture-and-evolution-of-coding-agents]], skills in the SKILL.md format appear in nine and MCP in eight. The paper attributes the change from an April tie to Pi, which implements skills while rejecting MCP. Among the pages here:

- Claude Code defers MCP tool definitions and loads them on demand through tool search.
- OpenDev discovers MCP tools lazily, which its report says cut baseline context overhead from 40% of the budget to under 5%.
- Cline, Kimi CLI and Antigravity CLI each have their own `mcp` subcommands for managing servers.
- goose says it connects to more than 70 extensions over MCP.

**Hooks.** [[DefinedTerm/agent-hooks]] describes Claude Code as having shipped hooks ahead of its competitors and as still having the deepest implementation. It reports that Gemini CLI and GitHub Copilot CLI shipped hook systems of their own. It also reports that OpenAI Codex added experimental hooks behind a feature flag, with five events mirroring Claude Code's naming, and that Claude Code's JSON-on-`stdin`, `exit 2`-to-block design has become the de facto convention. Among the other agents:

- Antigravity CLI and OpenDev load lifecycle hooks.
- Cline's plugins register lifecycle hooks through its SDK.
- OpenHarness implements PreToolUse and PostToolUse hooks.

**Borrowing.** The harness study reads the convergence as having turned into imitation: Codex adopted Claude Code's hook event vocabulary verbatim and shipped an importer for its sessions and settings. OpenHarness states compatibility with Claude Code plugins and discovers skills from `.claude/skills`. Antigravity CLI carried over Gemini CLI's Agent Skills, hooks and subagents, with extensions becoming Antigravity plugins.

**Third-party packs.** Packs meant to run on many of these agents still have to be installed host by host:

- [[SoftwareApplication/superpowers]] gives separate install routes for more than a dozen harnesses.
- [[SoftwareApplication/cc-sdd]] marks Claude Code and Codex as stable, and Cursor, GitHub Copilot, Devin, OpenCode, Gemini CLI and Antigravity as beta.
- [[SoftwareApplication/context-engineering-kit]] notes that neither Gemini CLI nor Antigravity CLI supports per-plugin selection.

## Running without a person at the keyboard

Several of these agents also have a non-interactive mode for scripts and CI:

- **Claude Code**: `claude -p` with plain-text, JSON and streaming-JSON output.
- **Codex**: `codex exec`, for scripts, CI jobs and one-off background tasks that return structured output.
- **Antigravity CLI**: print mode can emit `text`, `json` or `stream-json` and enforce a schema with `--json-schema`. It keeps a session open across newline-delimited prompts on stdin. From 1.2.6, a failing turn prints an `AGY_ERROR` line and exits with code 3.
- **Cline**: the headless CLI accepts piped input and can emit JSON.
- **OpenHarness**: text, JSON or streaming-JSON output, plus a dry-run mode that checks configuration without calling the model.
- **Mistral Vibe CLI**: can be invoked programmatically.

[[SoftwareApplication/github-agentic-workflows]] uses several of these agents as interchangeable engines inside GitHub Actions. Copilot CLI is the default, and Claude Code, OpenAI Codex and Gemini CLI are alternatives, each run on an API key stored as a repository secret. That page records GitHub's criticism of running a coding agent CLI directly inside a standard Actions workflow, which it says often grants more permission than a task requires.

## Context management

Claude Code's documentation says it clears older tool outputs first and summarises the conversation if needed. [[ScholarlyArticle/dive-into-claude-code]] reads five sequential context shapers in the source. OpenDev moves observations through active, faded and archived states, which its report credits with a roughly 54% reduction in peak context consumption. Plandex states an effective context window of 2M tokens with its default model pack, loading only what each step needs.

Across the harness study's corpus, seven of eleven systems use threshold-triggered LLM compaction. In [[ScholarlyArticle/tracelab]]'s trace of real sessions, compaction happened far more often in Codex (18.4% of sessions) than in Claude Code (4.5%). The authors relate this to Codex's shorter context length.

## Lineage and churn

Several of these tools changed identity within the period this wiki covers:

- **Gemini CLI**: Google announced on May 19, 2026 that consumer users would move to Antigravity CLI. The same announcement set June 18, 2026 as the date Gemini CLI would stop serving requests for Google AI Pro and Ultra subscribers and for free users of Gemini Code Assist for individuals, while keeping it available under enterprise licences ([[BlogPosting/transitioning-gemini-cli-to-antigravity-cli]]).
- **Kimi CLI**: its repository is archived. Kimi Code CLI replaces it and offers to migrate its configuration, MCP servers, history and sessions, but not credentials or plugins.
- **Crush**: built by Kujtim Hoxha, it "came home" to Charm, which says the project is "now called Crush".
- **Kilo Code**: its site carries a banner announcing that Anaconda has acquired Kilo.
- **Plandex**: its managed cloud was winding down as of 10/3/2025, leaving self-hosted and local mode.

## What comparative studies found

Few studies put several of these agents under the same measurement, and each carries its own limits:

- **Adoption at one company.** [[ScholarlyArticle/adoption-and-impact-of-command-line-ai-coding-agents]] studied Microsoft's early-2026 rollout of Claude Code and Copilot CLI. Among single-tool users, weeks of Copilot CLI use showed a +24.9% lift in merged pull requests against +11.4% for Claude Code. The authors offer two hypotheses: different task mixes, and Microsoft's ownership of GitHub aligning the Copilot CLI harness with how its engineers work. The findings come from one company in one window.
- **Adoption across developers.** JetBrains' Developer Ecosystem Survey 2026, as summarised in [[BlogPosting/ai-coding-agents-adoption-trends]], reports these shares of professional developers using each tool at work:
  - Claude Code: about 39%
  - Codex: 16%, up roughly fivefold since January 2026
  - OpenCode: 7%, which the post highlights for a tool without a large company behind it

  These are self-reported survey figures published by a tool vendor.
- **Feature development.** On [[ScholarlyArticle/featurebench-benchmarking-agentic-coding-for-complex-feature-development]]'s 200-task set, Claude Code with Claude Opus 4.5 resolved 11.0% of tasks and Codex with GPT-5.1-Codex resolved 12.5%. Both scaffolds ran on different models, so the pair compares scaffold–model combinations rather than scaffolds alone.
- **Long-horizon loops.** On [[ScholarlyArticle/loopsbench-from-harness-engineering-to-loop-engineering-in-coding-agent-evaluation]], the strongest configuration, Opus-4.7 under Claude Code with outer continuation, resolved 25.00% of 112 tasks. Every configuration remained well below full resolution.
- **Bugs in the tools themselves.** [[ScholarlyArticle/engineering-pitfalls-in-ai-coding-tools]] analysed over 3.8K publicly reported bugs in Claude Code, Codex and Gemini CLI. It found more than 67% related to functionality, with tool invocation (37.2%) and command execution (24.7%) the stages where bugs concentrated.
- **CLI against IDE.** [[ScholarlyArticle/how-coding-agents-fail-their-users]] found CLI sessions more prone to constraint violations (49.49% against 32.26% in IDE sessions), with damage reaching project and external state. IDE sessions more often surfaced faulty implementations. The authors present these as differences between deployment settings rather than causal effects, since the groups also differ in agent identity and task mix.
- **Security.** [[ScholarlyArticle/red-teaming-coding-agents-tool-invocation]] achieved remote code execution on each of six agents it tested, Claude Code and Cline among them, in at least one configuration. It found that newer Claude Code versions using progressive disclosure blocked one attack channel, while the same two-channel attack still succeeded against Cline with certain newer backend models. Its own results show vendors shipping mitigations between releases, so these rates are version- and configuration-specific rather than a fixed property of any product.
- **Loops in public repositories.** [[ScholarlyArticle/loop-engineering-building-blocks-adoption-and-impact]] confirmed autonomous agent loops in 217 open-source repositories. Claude Code accounted for 189 of the confirmed tool attributions, followed by OpenAI Codex, OpenCode, Gemini CLI, Cursor and GitHub Copilot.

Several pages caution that a benchmark score measures an agent and its model together:

- [[ScholarlyArticle/coding-benchmarks-are-misaligned-with-agentic-software-engineering]] reproduces Terminal-Bench entries in which one fixed model scores from roughly 58% to roughly 80% across different harnesses.
- [[BlogPosting/the-anatomy-of-an-agent-harness]] reports that on Terminal Bench 2.0, Opus 4.6 in Claude Code scored far below Opus 4.6 in other harnesses. It suggests products post-trained with their harness in the loop can overfit to it.
- LangChain moved its own deepagents-cli from just outside the top 30 to the top 5 on Terminal Bench 2.0 by changing only the harness, from 52.8 to 66.5 ([[BlogPosting/improving-deep-agents-with-harness-engineering]]).
- [[DefinedTerm/infrastructure-noise]] adds that differences below 3 percentage points deserve skepticism until the evaluation configuration is documented and matched.
