The page states the attestation's custom data commitment as covering "the input and the output" without qualification, in both the body and the frontmatter description. The source states this as the default but gives an alternative in Section 3.2 — "d = Hash(x,r) (or Hash(r), if binding of x is not required)" — and Appendix A notes that in the agent-skill-based implementation "the input x is omitted from the application data field d". Nothing on the page is unsupported, but the commitment's contents read as fixed where the source treats binding the input as optional.
The Usage section's "without the verifier having to inspect the machine or trust the prover" is supported (Section 2.1's "even though the verifier cannot directly inspect the machine" and the analysis that the document "cannot be modified or forged by the prover"), but stated alone it is easy to read as trustless. The source's Trust Assumptions paragraph is explicit that trust is relocated rather than removed: "We trust the cloud provider (AWS's Nitro hypervisor) to correctly measure the code and protect the TEE's private keys."
