The Usage paragraph says the framework's tool descriptions 'pair' a camouflage passage (R) with a compliance-policy passage (S). That matches Section 4.2 (desc(T_K) = R ⊕ S, source lines 196-226). But Table 2 (source lines 466-488) and the ablation text (lines 507-519) treat R as optional. Table 1's headline ASR figures match the 'Base (S only)' column, adding R lowers ASR for weaker models, and the Appendix E case-study descriptions contain only the S-style compliance text. A reader could take the pairing to be how every generated tool is built, when the paper tests it as an optional component.
The Usage paragraph describes the 'ignored' outcome as the agent calling the original tool 'as the user intended'. The source (line 946) says only that the model 'remains unaffected by poisoned tool T_K and invokes the original tool T_A'. The phrase is a fair gloss, because shadow queries are built so that they would invoke T_A under normal conditions (Appendix A). Still, it is the page's own interpretation, not the paper's wording.
Not a cross-page contradiction, but worth noting: the linked DefinedTerm/tool-poisoning page defines tool poisoning as causing the agent to 'misuse the tool'. That page draws on a different source. Its wording fits explicit poisoning more naturally than the implicit variant this page describes, where the poisoned tool is never invoked. The two pages do not state the same fact differently, so this is not an issue entry.
